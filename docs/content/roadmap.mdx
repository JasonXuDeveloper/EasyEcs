What is planned, in order. An item leaves this page when it ships: the [changelog](/en/docs/changelog) and the guides
describe it from then on. A dropped item stays here as one line, its reasons in the
[design decisions](/en/docs/decisions). Every performance item is proven with BenchmarkDotNet before and after, and
ships only as a net win in time and allocations.

## Planned [#planned]

### Less code through the generator [#less-code-through-the-generator]

The generator already writes `entity.Health`, `HasHealth`, `SetHealth(…)`, `SetHealthIfChanged(…)`, `IsDead`, singleton members,
`world.XIndex`, buffer members, named query items, prefab buffer writers, jobs and access sets. Before each release
the API, the [battle server](/en/docs/example) and the guides are scanned again: every line users write twice is a
candidate for a generated member, and every generated member nobody uses goes. A candidate ships when it saves lines
in real code at no cost per call; one that only changes style is rejected
([D26](/en/docs/decisions#d26-generated-members-and-a-suggestion-to-use-them)).

### Toolchain and runtime [#toolchain-and-runtime]

The floor is the .NET 10 SDK (C# 14, Roslyn 5.0), which the generator builds against. EasyEcs moves to a newer runtime
feature only where it measures ([D21](/en/docs/decisions#d21-net-10-features-only-where-they-measure)).

### Evaluate Unity support [#unity]

Unity runs C# on Mono and IL2CPP, which have none of the .NET 10 features EasyEcs is built on
([D15](/en/docs/decisions#d15-net-10-only)). Unity is moving to CoreCLR; once a Unity release runs .NET 10 code, the
evaluation covers what support would take: the generator and the analyzer in Unity's compilation, player builds
(IL2CPP and its ahead-of-time limits), the editor's domain reload against the types EasyEcs registers at startup,
and the headline benchmark measured inside a player. Godot needs none of this: a Godot 4 .NET project that targets
`net10.0` runs EasyEcs already ([FAQ](/en/docs/faq#unity-godot)).

### Push halos for grid neighbours [#push-halo]

A grid simulation over chunks (the water of the [voxel server](/en/docs/samples/voxel-server#water)) loads the
edges of each flowing chunk's neighbours into its tile on every step (`Tile<TCell, TTile>.Load`). The planned design turns that around: a chunk hands its
edges to its neighbours' halos when they change, so a step reads only its own components and a chunk whose
neighbours are still holds nothing to copy ([D73](/en/docs/decisions#d73-survey-items-not-added)).

## Dropped [#dropped]

- `Added<T>`: `[Changed<T>]` selects added rows too; a tag the reacting system removes tells new from written
  ([D4](/en/docs/decisions#d4-no-addedt-filter)).
- Command buffers for parallel jobs: a parallel job writes data, a system after it changes structure
  ([D3](/en/docs/decisions#d3-no-command-buffer-for-parallel-jobs)).
- Interceptors for query call sites: the call's arguments are still evaluated, so a filter built at the call is built
  anyway ([D18](/en/docs/decisions#d18-no-interceptors-for-query-calls-filters-carry-no-references)).
  `AddEmbeddedAttributeDefinition`: the generators write no attribute types (the attributes are EasyEcs.Core's).
- Settable tag properties (`entity.IsDead = true`): C# 14 rejects assigning an extension property of a struct on a
  `foreach` variable, an indexer result or a field of an `in` parameter, where ECS code holds its entities
  ([D19](/en/docs/decisions#d19-no-settable-tag-properties)).
- A flat `[InlineArray]` memo, `FrozenDictionary` for saved types, `OverloadResolutionPriority`, `field`: measured or
  weighed, no net win ([D21](/en/docs/decisions#d21-net-10-features-only-where-they-measure)).
- Multi-type `Disable` / `Enable` and bulk calls
  ([D26](/en/docs/decisions#d26-generated-members-and-a-suggestion-to-use-them)).
- A generated `world.AddSystems()`: systems run in registration order, so the list is the tick's order and is read
  where the world is built
  ([D56](/en/docs/decisions#d56-not-added)).
- Singletons added when a read finds them missing (`world.X`, `GetSingleton<T>()`, a `[ForEach]` parameter): a
  missing singleton is a forgotten setup, and its default is rarely right (a clock with no step), so every read
  throws; `GetOrAddX()` adds the default where one is meant
  ([D27](/en/docs/decisions#d27-reading-a-missing-singleton-throws-everywhere)).
- Cached filters from attributes, counting members per component (`world.CountPlayer()`) and a named `TryGetXRef`:
  no line saved, more surface ([D56](/en/docs/decisions#d56-not-added)).
- `[ForEach(Parallel = true)]` on span methods, `entity.LastWriteTick<T>()`, public access sets and one parallelism budget for several worlds
  ([D36](/en/docs/decisions#d36-not-added)).
- Run conditions (`[RunIf]`): system groups and the host already decide when a group runs, and a predicate per
  system is code the scheduler cannot see ([D51](/en/docs/decisions#d51-not-added)).
- `UpdatePeriod` and a system time: the host's fixed-step loop owns time, `UpdateInterval` counts updates and stays
  deterministic ([D51](/en/docs/decisions#d51-not-added)).
- `[Requires<B>]`: a prefab per kind of entity brings the full set in one copy, without hidden structural changes
  ([D51](/en/docs/decisions#d51-not-added)).
- An entity map from an external key: `IUniqueIndexed<TKey>` is that map, kept by every write
  ([D51](/en/docs/decisions#d51-not-added)).
- A built-in `Meter`: `SystemStats` holds the numbers, and publishing them is a documented pattern of the host's own,
  with no metrics dependency in EasyEcs ([D51](/en/docs/decisions#d51-not-added)).
- A world checksum: a hash of `world.Save` output does it in user code, without fixing an algorithm for everyone
  ([D51](/en/docs/decisions#d51-not-added)).
- A chunk grid beside the unique index, `InChunk` written only when it changed, presence bits copied a word at a
  time, and a halo that copies only the changed edges: measured, no net win, or superseded by `IDirectIndexed<TKey>`
  and the push-halo design ([D73](/en/docs/decisions#d73-survey-items-not-added)).
- A generated per-cell kernel for grid tiles: byte arithmetic promotes to `int`, and stencils reduce per row; the
  tile loads the halo and the method keeps the rule ([D77](/en/docs/decisions#d77-tiles)).
- A partial-snapshot API: a system that copies the needed values into a ring held by a singleton (the
  lag-compensation pattern) copies exactly what is needed ([D51](/en/docs/decisions#d51-not-added)).
