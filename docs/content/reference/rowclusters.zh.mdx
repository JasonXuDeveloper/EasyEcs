一张有序表的簇（邻居对方法推断出的顺序，或 [[OrderBy]](/zh/docs/reference/orderbyattribute)）：表的行按键排序，每 [`RowClusters.Size`](/zh/docs/reference/rowclusters#size) 行一簇，每簇一个轴对齐的包围盒，盒子罩住簇里各行声明的点，再向外扩大余量。空间搜索读的就是它：离查询远的盒子整簇跳过，近的盒子从表的列里逐行读（或一个向量读一簇，[`RowClusters.Read`](/zh/docs/reference/rowclusters#read)）。从 [`World.Clusters`](/zh/docs/reference/world#clusters)（按某个组件排序的每张表）或 [`EntitySpan.Clusters`](/zh/docs/reference/entityspan#clusters)（批处理方法这段行所在的表，第 0 个元素是 [`EntitySpan.FirstRow`](/zh/docs/reference/entityspan#firstrow) 行）得到。

包围盒由排序画出，只要没有行移动超过余量，就一直有效到下一次排序：[0, [`RowClusters.SortedRows`](/zh/docs/reference/rowclusters#sortedrows)) 的行在簇里；[[`RowClusters.SortedRows`](/zh/docs/reference/rowclusters#sortedrows), [`RowClusters.RowCount`](/zh/docs/reference/rowclusters#rowcount)) 的行是之后加入的，不在任何簇里（搜索逐行读它们，或等下一次排序）。排序后移进某簇的行会扩大那簇的包围盒。遍历中被这次遍历销毁或移走的行是墓碑：它的 id 下标为负（[`RowClusters.Ids`](/zh/docs/reference/rowclusters#ids)）。簇里的行可能在排序后失去了这个组件（[`RowClusters.Has`](/zh/docs/reference/rowclusters#has)）。到 World 下一次结构变更前有效（指向表数组的 ref struct）。

### `Pairs` [#pairs]

```csharp
public int Pairs(RowClusters other, float cutoff, Span<ClusterPair> destination);
public int Pairs(float cutoff, Span<ClusterPair> destination);
```

这张表里包围盒在每个轴上相距不超过 `cutoff` 的簇对：搜索相距 `cutoff` 以内的行时的候选，之后内核每对读 [`RowClusters.Size`](/zh/docs/reference/rowclusters#size) × [`RowClusters.Size`](/zh/docs/reference/rowclusters#size) 行（其余的行对都离得更远）。每簇和自己配一对（行全都没有这个组件的簇除外），其余每对只写一次，小的簇在前。写到 `destination` 写满为止；返回总对数，缓冲不够的调用方扩大缓冲再调用一次。按簇在轴 0 上的低边排序后扫一遍：O(簇数 × log 簇数 + 候选数)。排序用的缓冲来自共享数组池：稳定状态零分配，多个线程同时调用也安全（它不改任何东西）。

**参数**

- `cutoff`：每个轴上两行不再相互作用的距离：0 或更大。
- `destination`：簇对写到这里。

**返回值**：簇对的个数，可能超过 `destination` 的长度。

**异常**

- `ArgumentOutOfRangeException`：`cutoff` 为负数、无穷大或 NaN。
- `InvalidOperationException`：包围盒不覆盖任何轴。
