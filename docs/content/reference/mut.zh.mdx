```csharp
public readonly ref struct Mut<T> where T : struct, IComponent
```

`[ForEach]` 方法所访问实体的一个组件，只有方法真的写了它才算写入：`static void Aim(Mut<Target> target, in Position p) => target.SetIfChanged(new Target(Nearest(p)))`。被追踪组件（[`ITrackChanges`](/zh/docs/reference/itrackchanges)）的 `ref` 参数会给方法访问的每一行打 tick，于是 `[Changed<T>]` 的读者会访问值从没变过的行；通过 [`Mut`](/zh/docs/reference/mut)，只有方法写过的行（[`Mut.Write`](/zh/docs/reference/mut#write)、改变了值的 [`Mut.SetIfChanged`](/zh/docs/reference/mut#setifchanged)）才打 tick，每行的 tick 和 [`Entity.Get`](/zh/docs/reference/entity#get) 打的完全一样。读 [`Mut.Value`](/zh/docs/reference/mut#value) 不打 tick。

调度器把这个参数当作写 `T`（并行阶段不会让这个系统和读它的系统同时运行）。逐实体方法都能用，包括 `[ForEach(Parallel = true)]` 方法和会做结构变更的方法（实体移动之后的写入给它的新行打 tick）；批处理方法接收 span，按段打 tick。对不追踪变更的组件，它就是普通的 `ref`。只在传入的那次调用内有效（ref struct）。被索引或分组的组件不能通过 ref 写（EECS015）。

## 方法 [#methods]

### `SetIfChanged` [#setifchanged]

```csharp
public bool SetIfChanged(in T value);
```

只有 `value` 和组件当前的值不同时，才存入它并给这一行打 tick：存了就返回 true。`T` 实现了 `IEquatable` 时（record struct 都实现了）用它判定相等，否则比较非托管 `T` 的字节；没有实现 `IEquatable` 的托管 `T` 抛 `NotSupportedException`。O(T 的大小)，零分配。

字节比较的是存下来的内容，不是它的含义：字段之间的填充字节、`-0.0` 与 `0.0`、负载不同的两个 NaN 都算不同，所以这样的值明明相等也会被写入并打 tick（最多多打一次，绝不会漏掉变化）。带 `float` 或 `double` 字段的组件请写成 `record struct`（或实现 `IEquatable`），按数值比较。

**复杂度**（[API 表](/zh/docs/api)）：O(`T` 的大小)，值不同时再加一次 `Write()`

### `Write` [#write]

```csharp
public ref T Write();
```

按 `ref` 返回组件，并记为写入（被追踪组件：给它的行打 tick；方法可能移动实体时，这一行要查一次实体记录才能找到）。方法确定要写时，每次写入调用一次。O(1)。

**复杂度**（[API 表](/zh/docs/api)）：O(1)：一次打 tick（方法会做结构变更或并行运行时，再加一次实体查找）
