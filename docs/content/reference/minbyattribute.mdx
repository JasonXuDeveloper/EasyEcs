The key of a reduction that keeps the row with the lowest key (MPI's `MINLOC`, LINQ's `MinBy`): the other fields travel with it. On one numeric field, auto-property with a setter or record's positional parameter (an integer, `float`, `double`, `decimal`) of a partial struct: `public partial record struct Weakest(EntityId Player, [MinBy] int Health) : ISingletonComponent;`. The generator writes the struct's `IReduction<T>`: `Identity` holds the key's `MaxValue` (+∞ for `float` and `double`) and every other field at its default, `Combine` keeps `right` only when its key is lower (`right.Health < left.Health ? right : left`). A tie keeps the left side, the earlier rows, so the result is the same on any number of threads; a NaN key never replaces another. The method keeps the lowest of its chunk the same way: `if (hp.Value < weakest.Value.Health) weakest.Value = new(player.Id, hp.Value);`. One field of the struct carries [`MinByAttribute`](/en/docs/reference/minbyattribute) or [`MaxByAttribute`](/en/docs/reference/maxbyattribute), and no field another reduction attribute.
