The layers of a tall tile a cell method's pass covers, from a component of the tile's entity that the method takes (`in TLayers`): the pass exchanges the halo of layers [`ITileLayers.From`](/en/docs/reference/itilelayers#from) to [`ITileLayers.To`](/en/docs/reference/itilelayers#to) only (with their halo layers, as [`Tile.ExchangeHalo`](/en/docs/reference/tile#exchangehalo-2) does) and walks only those, for a stencil whose data sits in a few layers that the user's own summary knows (the layers a chunk's water reaches):

```csharp
public record struct FlowLayers(int From, int To) : IComponent, ITileLayers;

[ForEach(Parallel = true)]
static void Flow(Cell<Fluid, Chunk> w, Cell<Block, Chunk> g, in FlowLayers layers, out NextFluid next) => ...
```

The rows outside get what the method computes on blank cells, as the rows the walk skips do: so the layers must hold every row whose stencil reads a cell that is not zero (the tile's own, the neighbors' beside, and the layers the stencil reaches up and down). The layers are clamped to the tile (0 to Height - 1); [`ITileLayers.From`](/en/docs/reference/itilelayers#from) above [`ITileLayers.To`](/en/docs/reference/itilelayers#to) exchanges nothing and fills every row. The generator bounds the pass only where it proved what the method computes on a blank row (the schedule line says "layers of '...'"); elsewhere every layer runs (EECS123).
