public struct DynamicBuffer<T> : IComponent, ITracked

A list of `T` per entity, held as a component: an inventory, a path, the hits of this tick. Writes go through a `ref` to the component (`ref` parameters of `[ForEach]` methods and jobs, [`Entity.Get`](/zh/docs/reference/entity#get)), so they are tracked like any write of an [`ITracked`](/zh/docs/reference/itracked) component and `[Changed<DynamicBuffer<T>>]` selects the entities whose list changed. Through `in` or [`Entity.Read`](/zh/docs/reference/entity#read) the list is read-only: the mutating methods ([`DynamicBufferExtensions`](/zh/docs/reference/dynamicbufferextensions)) take `ref this`, so a write through a read-only reference does not compile. Prefab instances, clones and snapshots ([`World.Capture`](/zh/docs/reference/world#capture)) share the list until one of them writes it, which first copies it (copy-on-write); a moved row keeps its list. Adding within the capacity allocates nothing.

#### 备注 [#remarks]

A `new DynamicBuffer<T>()` holds no list: each entity's list is made by its first write (reserve room with [`DynamicBufferExtensions.EnsureCapacity`](/zh/docs/reference/dynamicbufferextensions#ensurecapacity)), so one value can create many entities; an instance of a prefab whose buffer is empty holds none either, so its first write takes a list from the pool. The list lives in an object the component refers to, and a copy of the component would refer to the same list: the analyzer rejects copies (EECS012), reach the list through the entity.

### `MaxPooledLength` [#maxpooledlength]

```csharp
public static int MaxPooledLength { get; set; }
```

`T` 的缓冲被销毁或移除时，最长多少个元素的列表会还给回收池，留给下一个缓冲第一次写入时重用，免得再分配，不论在哪个线程：拥有者线程收回的列表，也能给并行 `[ForEach]` 的第一次写入用（默认是 4,096 字节能放下的元素个数，`byte` 或单字节枚举就是 4,096）。更长的列表交给 GC。同样大小、大量反复出现又消失的缓冲可以调高它，比如玩家周围加载又卸载的区块里的方块；设为 0 则什么都不回收。池里最多保留“没人取用期间销毁的列表”那么多个，所以它占用的内存是这个峰值乘以这个容量。对整个进程、所有 World 和线程生效：在启动时、World 用到这个类型之前设置。

**异常**

- `ArgumentOutOfRangeException`：值为负数。

### `FillPool` [#fillpool]

```csharp
public static void FillPool(int lists);
```

往池里补列表，直到池里有 `lists` 个，每个能放 [`DynamicBuffer.MaxPooledLength`](/zh/docs/reference/dynamicbuffer#maxpooledlength) 个元素，这么多个缓冲第一次写入时就从池里取列表，不用分配：知道自己峰值时要保留多少个 `T` 缓冲（玩家周围的区块）的服务器，在启动时一次付清，世界增长到峰值的过程中 tick 也不分配。和回收池一样对整个进程生效；池里已有的列表也算数。一次 O(`lists`) 次分配；池里已经够了就什么都不做。

**异常**

- `ArgumentOutOfRangeException`：`lists` 为负数。
