```csharp
public readonly ref struct Lookup<T> where T : struct, IComponent
```

从 `[ForEach]` 方法只读访问任意实体的组件 `T`（MPI 的单边 `Get`，Unity 的 `ComponentLookup`）：`static void Chase(ref Velocity v, in Target target, Lookup<Position> positions)` 用 `positions[target.Id]` 读目标的位置。方法不需要 World，所以可以并行运行（[`ForEachAttribute.Parallel`](/zh/docs/reference/foreachattribute#parallel)），也可以和不写 `T` 的系统共享一个并行阶段。

约定：遍历运行期间没有人写 `T`，所以每次读到的都是遍历之前的值。系统被调度为 `T` 的读者，所以写它的系统不会和它在同一阶段；自己写 `T` 的方法（`ref`、`Mut`、可写的 `Maybe` 或 span 参数）不能查找它（EECS059：遍历中被写的行会在写之前或之后被读到，或在另一个线程上读到写了一半的值）；遍历不做结构性修改，所以 id 一直对应同一行。

带索引的 `T`（[`IIndexed`](/zh/docs/reference/iindexed)）还可以按键查找（[`LookupExtensions`](/zh/docs/reference/lookupextensions)：在参数本身上调用 `TryFind`、`Find`、`Count`）：它的索引在遍历之前、在系统所在的并行阶段之前创建并建好，所以遍历中的查找从不修改它。（值索引原本在第一次查找时构建；在并行阶段或并行遍历中通过其他途径访问尚未构建的索引会抛出异常，而不是构建它。）

每次查找是一次实体查找（[`World.TryGetEntity`](/zh/docs/reference/world#trygetentity)，然后读该行的列）。只在传入它的那次调用内有效（ref struct）。
