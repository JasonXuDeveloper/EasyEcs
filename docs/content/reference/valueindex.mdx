```csharp
public sealed class ValueIndex<T, TKey> where T : struct, IComponent, IIndexed<TKey> where TKey : IEquatable<TKey>
```

The value index of component `T` in one world ([`World.Index`](/en/docs/reference/world#index)). It is kept current as values are written: `Set` and `CreateEntity` re-index the entity at once (O(1)), and entities leave it as soon as they are destroyed or lose the component, so a lookup does no catching up. The first lookup (and the first after [`World.Restore`](/en/docs/reference/world#restore)) indexes every row once. Lookups allocate nothing once every key has been seen; the index belongs to the world's owner thread, like component values (systems that look up from `OnUpdate` or instance methods run alone).

### `Find` [#find]

```csharp
public ValueIndex<T, TKey>.Matches Find(TKey key);
```

The entities whose `T` has key `key` (none for a null key): O(1), then O(1) per entity (the first lookup indexes every row once). Owner thread only. Destroying entities during the loop is allowed, changing `T` is not.

**Complexity** ([API table](/en/docs/api)): O(1), then O(1) per entity
