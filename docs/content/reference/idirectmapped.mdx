A unique component whose keys map to a bounded range of slots (grid cells, tiles, rooms, player slots): its index keeps an array of [`IDirectMapped.Slots`](/en/docs/reference/idirectmapped#slots) entries beside the hash, the entry [`IDirectMapped.SlotOf`](/en/docs/reference/idirectmapped#slotof) of a key holding the key's entity, so `Get` / `TryGet` and the uniqueness check of a write read one array entry instead of probing the hash. The hash stays the index: a key whose slot is out of range, or taken by another key (two keys of one slot: a collision), is found through it, and `Find`, `Count` and the ordered walks use it as for any unique index. A slot function folds the keys a world holds at once onto distinct slots (a chunk coordinate modulo the side of the loaded area); its array costs [`IDirectMapped.Slots`](/en/docs/reference/idirectmapped#slots) times the key and 12 bytes, allocated with the index.

```csharp
public record struct Cell(int X, int Y) : IComponent, IDirectMapped<(int, int)>
{
    public (int, int) Key => (X, Y);
    static int IDirectMapped<(int, int)>.Slots => 64 * 64;
    static int IDirectMapped<(int, int)>.SlotOf((int, int) key) => (key.Item2 & 63) * 64 + (key.Item1 & 63);
}
```

### `SlotOf` [#slotof]


The slot of `key`, 0 to [`IDirectMapped.Slots`](/en/docs/reference/idirectmapped#slots) - 1; any other value leaves the key to the hash. Called on every lookup and write of a key: keep it a few instructions, with no state.
