Declares a system: a `ref struct` whose static methods are the logic that runs on a world. A system is never an object (a ref struct cannot be boxed, stored or captured); the world keeps its bookkeeping as data ([`SystemHandle`](/en/docs/reference/systemhandle)), and the generator writes the code that runs it, called directly by the world.

Lifecycle: the [[OnCreate]](/en/docs/reference/oncreateattribute) method when it is added ([`World.AddSystem`](/en/docs/reference/world#addsystem)), then every update its [[OnUpdate]](/en/docs/reference/onupdateattribute) method followed by its [[ForEach]](/en/docs/reference/foreachattribute) methods in declaration order, and its [[OnDestroy]](/en/docs/reference/ondestroyattribute) method when it is removed or the world is disposed. Everything runs synchronously within [`World.Update`](/en/docs/reference/world#update) (or [`World.Update`](/en/docs/reference/world#update-2) for systems in a [group](/en/docs/reference/updateingroupattribute)): on the calling thread, or with [`WorldOptions.ParallelSystems`](/en/docs/reference/worldoptions#parallelsystems) on a thread-pool thread next to systems whose [access](/en/docs/reference/systemaccess) does not conflict.

```csharp
[EcsSystem, UpdateAfter<Input>]
ref struct Movement
{
    [ForEach] static void Move(ref Position p, in Velocity v) { p.X += v.X; p.Y += v.Y; }
}

world.AddSystem<Movement>();
```

A system declares static members only (state belongs in components and singletons); what several systems share is a generic system (`[EcsSystem] ref struct Regen<T>`) or a static helper, and what a constructor argument configured is a singleton.
