An ECS world: entities, their components, singletons and the systems that update them. Worlds are fully isolated; the recommended server layout is one world per thread, which needs no synchronization at all.

### `DestroyedSince` [#destroyedsince]

```csharp
public bool DestroyedSince(ulong since, Span<EntityId> into, out int count);
```

The entities destroyed at a change tick of `since` or later (the rule of `QueryFilter.Since`: take [`World.ChangeTick`](/en/docs/reference/world#changetick) as a mark, pass it later), from the log of [`WorldOptions.DestroyLogCapacity`](/en/docs/reference/worldoptions#destroylogcapacity). Each reader keeps its own mark, so readers that acknowledged different ticks share one log. `count` is how many there are; the first `min(count, into.Length)` are written to `into`, oldest first, each with the version it had (a recycled index names the new entity with another version). A span of [`WorldOptions.DestroyLogCapacity`](/en/docs/reference/worldoptions#destroylogcapacity) ids always holds them all.

An entity counts as destroyed when its id stops being alive ([`World.IsAlive`](/en/docs/reference/world#isalive) turns false): at `Destroy`, `DestroyEntities`, `DestroyAll`, a hierarchy or relation cascade, a `MoveEntities` out of this world; an entity holding [`ICleanupComponent`](/en/docs/reference/icleanupcomponent)s when its last one is removed (until then it is retired: alive, tagged [`Retired`](/en/docs/reference/retired)); a [`World.Restore`](/en/docs/reference/world#restore) or `Load` for every entity alive before it and not after it (with the same version). [`World.Dispose`](/en/docs/reference/world#dispose) records nothing.

Returns false, writing nothing and `count` 0, when `since` is older than [`World.DestroyLogOldestTick`](/en/docs/reference/world#destroylogoldesttick): records the reader needs were overwritten, and it must resynchronize (send the whole state again). O(count). Allocates nothing. Owner thread, or a thread of a parallel stage.

**Exceptions**

- `InvalidOperationException`: The log is off ([`WorldOptions.DestroyLogCapacity`](/en/docs/reference/worldoptions#destroylogcapacity) is 0).
- `ObjectDisposedException`: The world was disposed.

**Complexity** ([API table](/en/docs/api)): O(count)

### `Load` [#load]

```csharp
public void Load(ReadOnlySpan<byte> input, bool markWritten = true);
```

Replace this world's entities, components and singletons with those [`World.Save`](/en/docs/reference/world#save) wrote (in this process or another). Entities keep their ids and versions, so [`EntityId`](/en/docs/reference/entityid)s stored in components still point at the same entities, and handles made before the save work again. Components and singletons this process has no type for are skipped (their slices); a type is found by its type id when the process used it or the generator registered it (every component and singleton of a compilation using EasyEcs). Indexes rebuild; groups follow this world's [`World.GroupBy`](/en/docs/reference/world#groupby). O(entities × components). Not while a pass iterates.

**Parameters**

- `input`: The bytes of the save.
- `markWritten`: True (the default): every loaded row counts as written now, so `[Changed<T>]` systems and `Changed<T>(since)` queries see it. False: the loaded components have no change tick, as if never written, and no row counts as removed; a system added after the load skips them on its first run too (its `[Changed<T>]` looks at ticks from 1). For a restart that resumes a world saved by another process, whose records already hold the loaded values.

**Exceptions**

- `InvalidDataException`: The bytes are not a save or are damaged, or a component's fields changed since the save (an unmanaged one's size or layout, a managed one's Nino layout), or the save gives one key of a unique component ([`IUniqueIndexed`](/en/docs/reference/iuniqueindexed)) to several entities. The world is then left as it was.

**Complexity** ([API table](/en/docs/api)): O(entities × components)

A [`ChildOf`](/en/docs/reference/childof) whose parent stayed behind is removed: the entity is a root here. Indexes and groups learn the entities; tracked components count as written. **Exceptions**

### `LoadEntitiesInto` [#loadentitiesinto]

```csharp
public int LoadEntitiesInto(ReadOnlySpan<byte> input, ReadOnlySpan<Entity> targets, bool markWritten = true);
```

Put the components [`World.SaveEntities`](/en/docs/reference/world#saveentities) wrote onto entities that exist already (an actor whose entity was made before its record arrived): the components of the i-th saved entity are set on `targets`[i], added or replacing the values it has, each entity moving table at most once; components the save does not hold stay as they are. Indexes, groups and change ticks follow as with `Set` (every loaded component counts as written); a disabled component arrives disabled with its value. [`EntityId`](/en/docs/reference/entityid) fields that named an entity of the group name the entity of `targets` it became, every other one is [`EntityId.Null`](/en/docs/reference/entityid#null), and a [`ChildOf`](/en/docs/reference/childof) whose parent stayed behind is not set. - `ArgumentException`: `targets` does not hold one living entity of this world per saved entity, each once.
- `InvalidDataException`: The bytes are not a save, or give a unique key to several entities.

O(entities × components + archetypes + singletons). Not while a pass iterates.

**Complexity** ([API table](/en/docs/api)): O(entities × components + tables + singletons)

### `Save` [#save]

```csharp
public void Save(IBufferWriter<byte> output);
```

Write the entities (ids and versions), their components and the singletons into `output`, for [`World.Load`](/en/docs/reference/world#load). Unmanaged components are their raw rows (a layout change makes old saves unloadable) unless they are `[NinoType]`s, whose formatter writes them (its format decides what a type may change: fields appended with `VersionTolerant`, any change of members with `Keyed`); managed components and singletons need a Nino formatter. Types are recorded by Nino type id: a type renamed with `[NinoFormerName]` loads its old rows. Allocates nothing once its buffers are large enough. O(entities × components). Not while a pass iterates.

**Complexity** ([API table](/en/docs/api)): O(entities × components)

### `SaveEntitiesWith` [#saveentitieswith]

### `TrimExcess` [#trimexcess]

```csharp
public void TrimExcess();
```

Give back the memory a peak left: drop every empty table (it leaves the registry and the match list of every cached query, and a later change that needs it creates it again), shrink the rows of the others to their entities rounded up to a power of two (64 at least) with their columns, presence bits and change-tick summaries, and release the reusable buffers of saves, loads, migrations and prefab lookups (they are rebuilt on demand). The empty table and the tables a [`WorldSnapshot`](/en/docs/reference/worldsnapshot) of this world holds rows of stay, and snapshots keep restoring. The entity records keep their length (handles index them unchecked), as do indexes, relations and singletons.

On request only, at a quiet moment (after a wave despawned, between matches, from a maintenance task): what it drops, the next structural changes allocate again (cold), so calling it every tick trades the steady state's zero allocations for churn. Handles, queries, systems, indexes, groupings and change tracking are unaffected. Owner thread only, not during a pass or inside a parallel stage. O(tables × (cached queries + snapshots) + rows of the shrunk tables × columns); allocates (cold).

**Complexity** ([API table](/en/docs/api)): O(tables × (cached queries + snapshots) + rows of the shrunk tables × columns)
