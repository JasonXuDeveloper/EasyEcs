An ECS world: entities, their components, singletons and the systems that update them. Worlds are fully isolated; the recommended server layout is one world per thread, which needs no synchronization at all.

One overload per number of components, 1 to 9 (generated from one template); this is the text of the two-component one.

Run `job` with the components for every entity having all of `T1, T2` (and matching `filter`). The fastest iteration: walks each matching archetype's columns front to back, O(matching archetypes + rows), allocation-free. Structural changes inside the job are allowed and take effect immediately: an entity is visited at most once (entities that enter a matching archetype during the pass are not visited, entities that leave before their turn are skipped), and when the job changes the archetype of the entity it visits, its writes through the refs are carried over to the entity's new row (`IForEach.Writes`). A job implementing [`INoStructuralChanges`](/en/docs/reference/inostructuralchanges) skips that bookkeeping.

**Complexity** ([API table](/en/docs/api)): O(M + S)

```csharp

Entities keep their ids and versions, so [`EntityId`](/en/docs/reference/entityid)s stored in components still point at the same entities, and handles made before the save work again. ```csharp
public void RemoveTypes(Assembly assembly);
```

Remove from this world everything of the types of `assembly`: its systems (OnDestroy runs), singletons, indexes and groupings, and its components from every entity (the entities stay, without them). Tables that had such a column are dropped, with every cache that names them, so the world holds no reference to the assembly any more: once every world removed it, its collectible context can unload, and when it does, EasyEcs reuses its component bits.

To reload game logic and keep its data: [`World.Save`](/en/docs/reference/world#save), remove the types, unload the old context, load the new version, then [`World.Load`](/en/docs/reference/world#load) (types are saved by name, so the new version's components take the values). Owner thread only, not during a pass or an update. O(entities with such components + tables + cached queries); allocates (cold).

**Complexity** ([API table](/en/docs/api)):

- `world.RemoveTypes(assembly)`: O(entities with such components + tables + cached queries)
- `RemoveTypes(context)`: O(entities with such components + tables + cached queries)

```

### `Restore` [#restore]

```csharp
public void Restore(WorldSnapshot snapshot);
```

Put the world back to `snapshot` (taken from this world). Handles of entities alive in the snapshot are valid again; every other handle is stale, also handles of entities created after the capture. Archetypes created after the capture stay, empty. Singletons keep their boxes (a [`World.SingletonRef`](/en/docs/reference/world#singletonref) still works) and get the snapshot's values; singletons added after the capture are removed. O(entities × components + archetypes + singletons). Not while a pass iterates.

**Complexity** ([API table](/en/docs/api)): O(entities × components + tables + singletons)

### `Save` [#save]

```csharp
public void Save(IBufferWriter<byte> output);
```

Write the entities (ids and versions), their components and the singletons into `output`, for [`World.Load`](/en/docs/reference/world#load). Unmanaged components are their raw rows (a layout change makes old saves unloadable: add a new component type instead); managed components and singletons need a Nino formatter (`[NinoType]`). Allocates nothing once its buffers are large enough. O(entities × components). Not while a pass iterates.

**Complexity** ([API table](/en/docs/api)): O(entities × components)

### `SaveEntities` [#saveentities]

```csharp
public void SaveEntities(IBufferWriter<byte> output, ReadOnlySpan<EntityId> entities);
```

Write `entities` (stale ids and repeats are skipped) and their components into `output`, for [`World.LoadEntities`](/en/docs/reference/world#loadentities): a group of entities that moves to another world (a player and what it owns, to another server). Singletons and the other entities are not written; collect a hierarchy with [`World.Children`](/en/docs/reference/world#children). Allocates nothing once its buffers are large enough. O(entities given × components). Not while a pass iterates.

**Complexity** ([API table](/en/docs/api)): O(entities given × components)

### `SetAll` [#setall]

### `SingletonRef` [#singletonref]
