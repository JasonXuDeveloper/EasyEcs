一个 ECS World：装着实体、实体的组件、单例，以及更新它们的系统。World 之间完全隔离；服务器推荐每个线程一个 World，完全不需要同步。


把 `system` 挂到它的分组（[`UpdateInGroupAttribute`](/zh/docs/reference/updateingroupattribute) 指定的分组，没有就是默认分组），然后调用它的 [`EcsSystem.OnCreate`](/zh/docs/reference/ecssystem#oncreate)。

### `Descendants` [#descendants]

```csharp
public World.Subtree Descendants(EntityId root);
```

`root` 的后代，深度优先，每个实体排在它自己的子实体之前：它的子实体、子实体的子实体，依此类推（`root` 本身不算）。保存一棵子树时这样收集：`ids.Add(root.Id); foreach (var e in world.Descendants(root.Id)) ids.Add(e.Id);`。每个实体 O(1)；第一次遍历会把每个 [`ChildOf`](/zh/docs/reference/childof) 索引一次。预热后不分配内存（遍历用的栈由 World 保留）。遍历中被销毁的实体会跳过。只能在所有者线程调用。

**复杂度**（[API 表](/zh/docs/api)）：

- `world.Descendants(root)`：子树里每个实体 O(1)
- `world.Descendants(root).AddTo(ids, includeRoot)`：子树里每个实体 O(1)

### `Load` [#load]

```csharp
public void Load(ReadOnlySpan<byte> input, bool markWritten = true);
```

用 [`World.Save`](/zh/docs/reference/world#save) 写出的数据（本进程或别的进程写的）替换这个 World 的实体、组件和单例。实体保留原来的 id 和版本号，所以组件里存的 [`EntityId`](/zh/docs/reference/entityid) 仍然指向原来的实体，存档前拿到的句柄也重新可用。本进程没有对应类型的组件和单例直接跳过（跳过它们那段数据）；进程用过某个类型，或者生成器登记过它（使用 EasyEcs 的程序集里的每个组件和单例都会登记），就能按类型 id 找到它。索引重建；分组按这个 World 自己的 [`World.GroupBy`](/zh/docs/reference/world#groupby) 来。O(实体数 × 组件数)。遍历进行中不能调用。

**参数**

- `input`：存档的字节。
- `markWritten`：为 true（默认）时，加载的每一行都算刚写入，`[Changed<T>]` 系统和 `Changed<T>(since)` 查询都会看到它。为 false 时，加载的组件没有变更 tick，如同从未写过，也没有哪一行算作移除；加载之后才加进来的系统第一次运行时同样跳过它们（它的 `[Changed<T>]` 从 tick 1 开始看）。用于重启后接着跑另一个进程存下的 World：存储里的记录已经是这些值。

**异常**

- `InvalidDataException`：字节不是存档，或者已经损坏，或者某个组件的字段在存档之后改过（非托管组件的大小或布局，托管组件的 Nino 布局），或者存档把唯一组件（[`IUniqueIndexed`](/zh/docs/reference/iuniqueindexed)）的同一个键给了多个实体。这时 World 保持原样。

**复杂度**（[API 表](/zh/docs/api)）：O(实体数 × 组件数)

### `LoadEntities` [#loadentities]

```csharp
public int LoadEntities(ReadOnlySpan<byte> input, Span<Entity> entities = default);
```

创建 `SaveEntities` 写出的实体（本进程或别的进程写的），分配新的 id，按存档顺序把句柄写进 `entities`（放得下多少写多少）；返回创建的数量。组件和缓冲元素里的 [`EntityId`](/zh/docs/reference/entityid) 字段，原来指向组内实体的，改为指向那个实体的新实体；其余的一律变成 [`EntityId.Null`](/zh/docs/reference/entityid#null)（字段在哪里由生成器告诉 World；集合里的 id 不改写）。父实体没有一起过来的，移除它的 [`ChildOf`](/zh/docs/reference/childof)：实体在这里成为根。索引和分组收录这些实体；被追踪组件算作写入。O(实体数 × 组件数)。遍历进行中不能调用。

- `InvalidOperationException`：存档里的某个实体有一个唯一键（[`IUniqueIndexed`](/zh/docs/reference/iuniqueindexed)），而这个 World 里已有实体持有它：什么都不创建。

### `LoadEntitiesInto` [#loadentitiesinto]

```csharp
public int LoadEntitiesInto(ReadOnlySpan<byte> input, ReadOnlySpan<Entity> into, bool markWritten = true);
```

把 [`World.SaveEntities`](/zh/docs/reference/world#saveentities) 写出的组件放到已经存在的实体上（Actor 的实体先建好、记录后到的情形）：存档里第 i 个实体的组件设到 `into`[i] 上，没有的加上，已有的覆盖，每个实体最多换一次表；存档里没有的组件保持不变。索引、分组和变更 tick 的表现和 `Set` 一样（加载的每个组件都算写入）；被禁用的组件读进来仍是禁用的，值也保留。[`EntityId`](/zh/docs/reference/entityid) 字段原来指向组内实体的，改为指向它在 `into` 里对应的实体，其余的一律变成 [`EntityId.Null`](/zh/docs/reference/entityid#null)；父实体不在组内的 [`ChildOf`](/zh/docs/reference/childof) 不会被设置。返回加载的实体数。O(实体数 × 组件数)。遍历进行中不能调用。

`markWritten` 为 false 时，加载的组件不算写入：存档里的每个组件加载后都没有变更 tick，覆盖了之前写过的值（预制体的默认值）的也一样，所以 `[Changed<T>]` 系统和 `Since` 过滤条件不会因为这次加载访问该实体（从存储恢复的 Actor 内容和存储一致，“保存变化的部分”在代码写入之前不会保存它的任何东西）。存档里没有的组件保留各自的 tick。

**异常**

- `ArgumentException`：`into` 没有按存档里的每个实体各给出一个本 World 的存活实体，或者同一个实体出现了不止一次。
- `InvalidDataException`：字节不是存档，或者把同一个唯一键给了多个实体。
- `InvalidOperationException`：加载的某个唯一键（[`IUniqueIndexed`](/zh/docs/reference/iuniqueindexed)）被另一个实体持有，而不是它要加载到的那个实体（加载前对照 World 检查）：什么都不写。

**复杂度**（[API 表](/zh/docs/api)）：O(实体数 × 组件数)

### `LoadKeeping` [#loadkeeping]

让分组 `TGroup` 里每个启用的系统更新一次（同步执行，零分配）。没有系统的分组什么都不做。

**复杂度**（[API 表](/zh/docs/api)）：

- `world.Update()`：分组内所有系统之和
- `world.Update<TGroup>()`：分组内所有系统之和
