An [`IIndexed`](/zh/docs/reference/iindexed) component whose key names one entity: a player's account id, a session token, the occupant of a grid cell. A write that would give a second entity a key another entity has throws `InvalidOperationException` before it changes anything (Set, CreateEntity / CreateEntities, GetOrAdd, Instantiate, Clone, SetAll, Enable / EnableAll, LoadEntities / LoadEntitiesInto, MoveEntities), and a [`World.Load`](/zh/docs/reference/world#load) of a save holding a key twice throws `InvalidDataException`; the world is then as it was. Writing an entity's own key again is fine; to move a key from one entity to another, change the first one before the second. A null key (the default of a reference-type key) is no key: any number of entities may have it, and no lookup finds them. [`EntityId`](/zh/docs/reference/entityid) keys (relations) cannot be unique.

The index of a unique component is eager: each world creates it with the first table holding the component, so every write is checked from the first one (an [`IIndexed`](/zh/docs/reference/iindexed) index is built by its first lookup). Look entities up with `world.Index<T, TKey>().Get(key)` / `TryGet` (the generated `world.XIndex`); `Find`, `Count` and the ordered walks work as for any index.
