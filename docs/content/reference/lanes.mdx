Stream compaction for batch methods, a GPU's ballot and compaction on a CPU: a vector compare decides a lane mask (`Vector256.LessThan(hp, limit).ExtractMostSignificantBits()`: CUDA's `__ballot_sync`; its `__popc` is `PopCount`), and [`Lanes.Compact`](/en/docs/reference/lanes#compact) writes the selected elements side by side: the ids of the rows a batch method picked (`entities.Ids`), their values, their indexes. With AVX-512 a lane of 4 or 8 bytes moves 16 or 8 at a time (`VPCOMPRESSD` / `VPCOMPRESSQ`); otherwise, and for other sizes, one at a time without a branch per element.

## Methods

### `Compact` [#compact]

```csharp
public static int Compact<T>(ReadOnlySpan<T> source, ulong mask, Span<T> destination) where T : unmanaged;
```

Write the elements of `source` whose bit is set in `mask` (bit `i` selects `source[i]`, so at most 64 elements) to the start of `destination`, in order, and return how many: `PopCount(mask)`. Only selected elements are read and only that many are written. O(64 / lanes per vector) with AVX-512 for elements of 4 or 8 bytes, else O(selected); allocation-free.

**Parameters**

- `source`: The elements to choose from: a run of a batch method's span or of its `EntitySpan.Ids`.
- `mask`: The selected elements; no bit at or past `source.Length` may be set.
- `destination`: Where the selected elements go; at least `PopCount(mask)` long.

**Returns** The number of elements written.

**Exceptions**

- `ArgumentException`: A bit of `mask` selects no element of `source`, or `destination` is too short.
