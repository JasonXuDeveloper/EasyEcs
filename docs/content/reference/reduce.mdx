A reduction of a `[ForEach]` pass into singleton `T` (OpenMP's `reduction`, MPI's `Allreduce`), taken by `ref`: `static void Count(in Health h, ref Reduce<Census> census) =>
census.Value.Alive++;`. Each chunk of a parallel pass (or the whole pass on one thread) accumulates into its own copy, which starts at [`IReduction.Identity`](/en/docs/reference/ireduction#identity): no lock and no atomic per row. When the pass ends, the copies are combined in chunk order, which is row order, and the result replaces the world's `T` (added when missing).

Integer results are exact and do not depend on the threads. A floating-point result depends on where chunks begin, since each chunk's sum is rounded on its own. Chunks of a pass that reduces begin where the row count alone says (16 chunks of 1,024 to 16,384 rows, or [`ForEachAttribute.ChunkRows`](/en/docs/reference/foreachattribute#chunkrows) when set), so the result is the same on every run and for any thread count, but not bit for bit the result of the same method with `Parallel = false` (one partial result).

A plain struct passed by `ref`, not a wrapper holding a reference: the pass keeps each run's partial result in a local, and the JIT keeps a local passed by `ref` to an inlined method in registers, while a local whose address a ref field holds stays in memory, a load and a store per row (a float sum then runs several times slower).

The system writes `T` (once per pass); [`Reduce.Value`](/en/docs/reference/reduce#value) holds this chunk's partial result, not the total.

#### Type parameters

- `T`: The singleton holding the result, which combines with itself.
