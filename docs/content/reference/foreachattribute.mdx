```csharp
public sealed class ForEachAttribute : Attribute
```

Runs a method of an [`EcsSystem`](/en/docs/reference/ecssystem) (or a static method of any other type, through a generated entry point) for every entity matching its component parameters (and the [`WithAttribute`](/en/docs/reference/withattribute) / [`WithoutAttribute`](/en/docs/reference/withoutattribute) / [`WithAnyAttribute`](/en/docs/reference/withanyattribute) filters), each update, after [`EcsSystem.OnUpdate`](/en/docs/reference/ecssystem#onupdate), in declaration order.

Parameters: 1..9 components (`ref` to write, `in` to read, [`Mut`](/en/docs/reference/mut) to write some rows; or `Span<T>` / `ReadOnlySpan<T>` for a batch method that receives runs of rows), singletons (`ref` / `in`), and optionally [`Entity`](/en/docs/reference/entity) and [`World`](/en/docs/reference/world). Static and instance methods are supported.

```csharp
public class MovementSystem : EcsSystem
{
    [ForEach, Without<Frozen>]
    static void Move(ref Position p, in Velocity v) { p.X += v.X; p.Y += v.Y; }
}
```

EasyEcs.Generator compiles it to a struct job ([`IForEach`](/en/docs/reference/iforeach), [`IForEachEntity`](/en/docs/reference/iforeachentity) or [`IForEachBatch`](/en/docs/reference/iforeachbatch)): no delegate, no allocation, inlined.

## Properties

### `ChunkRows` [#chunkrows]

```csharp
public int ChunkRows { get; init; }
```

With [`ForEachAttribute.Parallel`](/en/docs/reference/foreachattribute#parallel): the rows a thread takes at a time, rounded up to a multiple of 64 (OpenMP's `schedule(dynamic, n)`). By default a chunk holds about a quarter of each thread's share of the rows, and at least 1,024 (4,096 when the method writes a tracked component), so a pass over a few hundred heavy rows (a chunk of terrain each, a path search each) runs on one thread; set the rows one thread should take at a time when one row costs microseconds. Smaller chunks cost a claim each, and chunks that share a 4,096-row block of change ticks share its summary (atomically). Default 0: chosen from the row count. Not without [`ForEachAttribute.Parallel`](/en/docs/reference/foreachattribute#parallel) and not below 0 (EECS054).

### `FloatMode` [#floatmode]

```csharp
public FloatMode FloatMode { get; init; }
```

What a vector loop may change in floating-point results. [`FloatMode.Exact`](/en/docs/reference/floatmode#exact) keeps every result the method's bit for bit, so a float sum into a [`Reduce`](/en/docs/reference/reduce) stays one row at a time (EECS055 says so): the lanes of a vector loop each add their own rows, in another order. [`FloatMode.Fast`](/en/docs/reference/floatmode#fast) accepts that order: the sum of the same rows, rounded differently (not bit for bit the method's, and not the same across vector widths). Integer sums and the Min / Max of any lane type are exact either way. Default [`FloatMode.Exact`](/en/docs/reference/floatmode#exact).

### `Parallel` [#parallel]

```csharp
public bool Parallel { get; init; }
```

Run chunks of the matching rows on several threads (`World.ForEachParallel`). The method must make no structural change, run per entity and write no singleton (EECS010); it pays off for heavy per-row work over tens of thousands of rows. Default false.

### `Simd` [#simd]

```csharp
public SimdMode Simd { get; init; }
```

Whether the generator turns the method into a `System.Numerics.Vector<T>` loop over its runs of rows (several rows per instruction, the results of the method bit for bit). [`SimdMode.Auto`](/en/docs/reference/simdmode#auto) vectorizes a method that qualifies and reports why one that looks eligible does not (EECS055, a message); [`SimdMode.Require`](/en/docs/reference/simdmode#require) makes a method that does not qualify an error (EECS056); [`SimdMode.Off`](/en/docs/reference/simdmode#off) keeps the method one row at a time. Default [`SimdMode.Auto`](/en/docs/reference/simdmode#auto).

### `Slices` [#slices]

```csharp
public int Slices { get; init; }
```

Spread the method's rows over N runs of its system: each run visits one slice, about 1 / N of the rows of every matching table (slice [`EcsSystem.RunCount`](/en/docs/reference/ecssystem#runcount) mod N, [`QueryFilter.Slice`](/en/docs/reference/queryfilter#slice)), so every row is visited once per N runs and a system over many entities costs about 1 / N per update instead of a spike on one. With [`EcsSystem.UpdateInterval`](/en/docs/reference/ecssystem#updateinterval) M, a row is visited once per N \* M updates. Rows that move between runs (swap-removes, structural changes, tables that grow or shrink) may be skipped or visited twice in one cycle. Works per entity, in batches and with [`ForEachAttribute.Parallel`](/en/docs/reference/foreachattribute#parallel) (the slice is cut into chunks). Not with `[Changed<T>]` / `[Removed<T>]` (EECS035): the rows of the other slices would lose the changes made since the system last ran. Default 1: every row on every run.
