对每个匹配组件参数（以及 [`WithAttribute`](/zh/docs/reference/withattribute) / [`WithoutAttribute`](/zh/docs/reference/withoutattribute) / `[WithAny<T1, T2>]` 过滤条件）的实体，执行 [[EcsSystem]](/zh/docs/reference/ecssystemattribute) 的一个静态方法（或者通过生成的入口点，执行任何其他类型的静态方法）。每次更新执行一次，在它的 `OnUpdate` 方法之后，按声明顺序。

参数：1 到 9 个组件（`ref` 表示写，`in` 表示读，[`Mut`](/zh/docs/reference/mut) 表示只写其中一部分行；按段接收行的批处理方法用 `Span<T>` / `ReadOnlySpan<T>`）、单例（`ref` / `in`），还可以加上 [`Entity`](/zh/docs/reference/entity) 和 [`World`](/zh/docs/reference/world)。

```csharp
[EcsSystem]
ref struct Movement
{
    [ForEach, Without<Frozen>]
    static void Move(ref Position p, in Velocity v) { p.X += v.X; p.Y += v.Y; }
}
```

EasyEcs.Generator 把它编译成结构体 job（[`IForEach`](/zh/docs/reference/iforeach)、[`IForEachEntity`](/zh/docs/reference/iforeachentity) 或 [`IForEachBatch`](/zh/docs/reference/iforeachbatch)）：没有委托，不分配内存，可以内联。

### `ChunkSize` [#chunksize]

```csharp
public int ChunkSize { get; init; }
```

与 [`ForEachAttribute.Parallel`](/zh/docs/reference/foreachattribute#parallel) 一起用：一个线程每次取的行数，向上取整到 64 的倍数（相当于 OpenMP 的 `schedule(dynamic, n)`）。默认由运行时按每次遍历测得的行开销决定：每个线程大约四块；行很重时每块约 25 µs（几百行、每行一块地形或一次寻路，也能分到所有线程上）；遍历很短时块更少。第一次遍历之前，以及按块合并结果的方法（[`Reduce`](/zh/docs/reference/reduce)、[`Emit`](/zh/docs/reference/emit)：固定 16 块，结果因此不随耗时变化），按行数决定。只在要覆盖这个选择时才设置。块越小，领块的次数越多；共用一个 4,096 行变更 tick 区段的块会（以原子操作）共用它的摘要。默认 0：由运行时决定。不能脱离 [`ForEachAttribute.Parallel`](/zh/docs/reference/foreachattribute#parallel) 单独使用，也不能小于 0（EECS054）。

### `FloatMode` [#floatmode]

```csharp
public FloatMode FloatMode { get; init; }
```

向量循环可以改变哪些浮点结果。[`FloatMode.Exact`](/zh/docs/reference/floatmode#exact) 让每个结果都与方法本身逐位相同，所以写进 [`Reduce`](/zh/docs/reference/reduce) 的浮点求和保持一次一行（EECS055 会说明）：向量循环的每个通道各加各的行，相加顺序不同。[`FloatMode.Fast`](/zh/docs/reference/floatmode#fast) 接受这种顺序：同样那些行的和，只是舍入不同（与方法本身不逐位相同，不同向量宽度之间也不相同），并接受 `Sin`、`Cos`、`Exp`、`Log`、`Log2` 和 `Hypot` 的向量近似（与标量函数相差 1 到 2 ulp 以内）。整数求和以及任何通道类型的 Min / Max 两种模式下都精确。默认 [`FloatMode.Exact`](/zh/docs/reference/floatmode#exact)：每台机器上结果都相同（每个通道都是一次 IEEE 运算）。

### `FusionMode` [#fusionmode]

```csharp
public FusionMode FusionMode { get; init; }
```

方法是否和系统里与它相邻声明的 [ForEach] 方法共用一次遍历（遍历融合：每行只载入缓存一次，几个方法按声明顺序在这一行上运行）。[`FusionMode.Auto`](/zh/docs/reference/fusionmode#auto)：一次遍历和分开遍历结果相同时（过滤条件和设置相同、没有结构变更、不读别的实体，也不读另一个方法写的单例），融合相邻的方法，差一点就能融合时报告原因（EECS093，一条消息）；[`FusionMode.Require`](/zh/docs/reference/fusionmode#require)：方法没有和前一个方法共用遍历就报错（EECS094）；[`FusionMode.Off`](/zh/docs/reference/fusionmode#off)：方法单独遍历。默认 [`FusionMode.Auto`](/zh/docs/reference/fusionmode#auto)。

### `Parallel` [#parallel]

```csharp
public bool Parallel { get; init; }
```

把匹配的行分块，放到多个线程上执行（`World.ForEachParallel`）。方法不能做结构变更，必须逐实体执行，也不能写单例（EECS010）；每行工作量大、行数上万时才划算。默认 false。

### `SimdMode` [#simdmode]

```csharp
public SimdMode SimdMode { get; init; }
```

生成器是否把方法写成按一段连续的行跑的 `System.Numerics.Vector<T>` 循环（一条指令算几行，结果与方法本身逐位相同）。[`SimdMode.Auto`](/zh/docs/reference/simdmode#auto) 给符合条件的方法生成向量循环，看起来适合却不符合的方法报告原因（EECS055，一条消息）；[`SimdMode.Require`](/zh/docs/reference/simdmode#require) 让不符合条件的方法编译失败（EECS056）；[`SimdMode.Off`](/zh/docs/reference/simdmode#off) 让方法保持一次一行。默认 [`SimdMode.Auto`](/zh/docs/reference/simdmode#auto)。

### `Slices` [#slices]

```csharp
public int Slices { get; init; }
```

把方法的行分摊到系统的 N 次运行上：每次运行访问一片，约为每个匹配表行数的 1 / N（第 [`SystemHandle.RunCount`](/zh/docs/reference/systemhandle#runcount) mod N 片，见 [`QueryFilter.Slice`](/zh/docs/reference/queryfilter#slice)），所以每 N 次运行每行访问一次，处理大量实体的系统每次更新只花约 1 / N，而不是集中在某一次更新上出现尖峰。配合 [[UpdateInterval(M)]](/zh/docs/reference/updateintervalattribute)，每行每 N \* M 次更新访问一次。两次运行之间移动了的行（交换删除、结构变更、表扩容或缩小）在一轮里可能被跳过，也可能被访问两次。逐实体、批处理和 [`ForEachAttribute.Parallel`](/zh/docs/reference/foreachattribute#parallel) 都能用（这一片再切成块）。不能和 `[Changed<T>]` / `[Removed<T>]` 一起用（EECS035）：其他片的行会丢掉系统上次运行之后的变更。默认 1：每次运行访问每一行。
