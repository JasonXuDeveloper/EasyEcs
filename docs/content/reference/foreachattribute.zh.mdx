```csharp
public sealed class ForEachAttribute : Attribute
```

Runs a static method of an [[EcsSystem]](/zh/docs/reference/ecssystemattribute) (or of any other type, through a generated entry point) for every entity matching its component parameters (and the [`WithAttribute`](/zh/docs/reference/withattribute) / [`WithoutAttribute`](/zh/docs/reference/withoutattribute) / `[WithAny<T1, T2>]` filters), each update, after its `OnUpdate` method, in declaration order.

Parameters: 1..9 components (`ref` to write, `in` to read, [`Mut`](/zh/docs/reference/mut) to write some rows; or `Span<T>` / `ReadOnlySpan<T>` for a batch method that receives runs of rows), singletons (`ref` / `in`), and optionally [`Entity`](/zh/docs/reference/entity) and [`World`](/zh/docs/reference/world).

```csharp
[EcsSystem]
ref struct Movement
{
    [ForEach, Without<Frozen>]
    static void Move(ref Position p, in Velocity v) { p.X += v.X; p.Y += v.Y; }
}
```

EasyEcs.Generator compiles it to a struct job ([`IForEach`](/zh/docs/reference/iforeach), [`IForEachEntity`](/zh/docs/reference/iforeachentity) or [`IForEachBatch`](/zh/docs/reference/iforeachbatch)): no delegate, no allocation, inlined.

### `ChunkRows` [#chunkrows]

```csharp
public int ChunkRows { get; init; }
```

与 [`ForEachAttribute.Parallel`](/zh/docs/reference/foreachattribute#parallel) 一起用：一个线程每次取的行数，向上取整到 64 的倍数（相当于 OpenMP 的 `schedule(dynamic, n)`）。默认由运行时按每次遍历测得的行开销决定：每个线程大约四块；行很重时每块约 25 µs（几百行、每行一块地形或一次寻路，也能分到所有线程上）；遍历很短时块更少。第一次遍历之前，以及按块合并结果的方法（[`Reduce`](/zh/docs/reference/reduce)、[`Emit`](/zh/docs/reference/emit)：固定 16 块，结果因此不随耗时变化），按行数决定。只在要覆盖这个选择时才设置。块越小，领块的次数越多；共用一个 4,096 行变更 tick 区块的块会（以原子操作）共用它的摘要。默认 0：由运行时决定。不能脱离 [`ForEachAttribute.Parallel`](/zh/docs/reference/foreachattribute#parallel) 单独使用，也不能小于 0（EECS054）。

### `FloatMode` [#floatmode]

```csharp
public FloatMode FloatMode { get; init; }
```

向量循环可以改变哪些浮点结果。[`FloatMode.Exact`](/zh/docs/reference/floatmode#exact) 让每个结果都与方法本身逐位相同，所以写进 [`Reduce`](/zh/docs/reference/reduce) 的浮点求和保持一次一行（EECS055 会说明）：向量循环的每个通道各加各的行，相加顺序不同。[`FloatMode.Fast`](/zh/docs/reference/floatmode#fast) 接受这种顺序：同样那些行的和，只是舍入不同（与方法本身不逐位相同，不同向量宽度之间也不相同），并接受 `Sin`、`Cos`、`Exp`、`Log`、`Log2` 和 `Hypot` 的向量近似（与标量函数相差 1 到 2 ulp 以内）。整数求和以及任何通道类型的 Min / Max 两种模式下都精确。默认 [`FloatMode.Exact`](/zh/docs/reference/floatmode#exact)：每台机器上结果都相同（每个通道都是一次 IEEE 运算）。

### `FusionMode` [#fusionmode]

```csharp
public FusionMode FusionMode { get; init; }
```

Whether the method shares one walk with the [ForEach] methods declared next to it in its system (pass fusion: each row loaded into cache once, the methods run on it in declaration order). [`FusionMode.Auto`](/zh/docs/reference/fusionmode#auto) fuses consecutive methods when one walk gives the results of separate passes (the same filter and settings, no structural change, no read of other entities or of a singleton another method writes) and reports a near miss (EECS093, a message); [`FusionMode.Require`](/zh/docs/reference/fusionmode#require) makes a method that does not share the walk of the method before it an error (EECS094); [`FusionMode.Off`](/zh/docs/reference/fusionmode#off) gives the method a walk of its own. Default [`FusionMode.Auto`](/zh/docs/reference/fusionmode#auto).

### `Parallel` [#parallel]

```csharp
public bool Parallel { get; init; }
```

把匹配的行分块，放到多个线程上执行（`World.ForEachParallel`）。方法不能做结构变更，必须逐实体执行，也不能写单例（EECS010）；每行工作量大、行数上万时才划算。默认 false。

### `SimdMode` [#simdmode]

```csharp
public SimdMode SimdMode { get; init; }
```

生成器是否把方法写成按一段连续的行跑的 `System.Numerics.Vector<T>` 循环（一条指令算几行，结果与方法本身逐位相同）。[`SimdMode.Auto`](/zh/docs/reference/simdmode#auto) 给符合条件的方法生成向量循环，看起来适合却不符合的方法报告原因（EECS055，一条消息）；[`SimdMode.Require`](/zh/docs/reference/simdmode#require) 让不符合条件的方法编译失败（EECS056）；[`SimdMode.Off`](/zh/docs/reference/simdmode#off) 让方法保持一次一行。默认 [`SimdMode.Auto`](/zh/docs/reference/simdmode#auto)。

### `Slices` [#slices]

```csharp
public int Slices { get; init; }
```

把方法的行分摊到系统的 N 次运行上：每次运行访问一片，约为每个匹配表行数的 1 / N（第 [`SystemHandle.RunCount`](/zh/docs/reference/systemhandle#runcount) mod N 片，见 [`QueryFilter.Slice`](/zh/docs/reference/queryfilter#slice)），所以每 N 次运行每行访问一次，处理大量实体的系统每次更新只花约 1 / N，而不是集中在某一次更新上出现尖峰。配合 [[UpdateInterval(M)]](/zh/docs/reference/updateintervalattribute)，每行每 N \* M 次更新访问一次。两次运行之间移动了的行（交换删除、结构变更、表扩容或缩小）在一轮里可能被跳过，也可能被访问两次。逐实体、批处理和 [`ForEachAttribute.Parallel`](/zh/docs/reference/foreachattribute#parallel) 都能用（这一片再切成块）。不能和 `[Changed<T>]` / `[Removed<T>]` 一起用（EECS035）：其他片的行会丢掉系统上次运行之后的变更。默认 1：每次运行访问每一行。
