A view of one entity's components: a `ref struct` whose instance fields are `ref` (written), `ref readonly` (read) or [`Mut`](/en/docs/reference/mut) (written, stamped only where written) fields of components, public or internal, with the business methods that use them: `[View] public ref struct Fighter { public ref Health Health; public ref readonly Armor Armor; public void TakeDamage(int n) => Health.Value -= Math.Max(0, n - Armor.Value); }`. A `[ForEach]` or `[ForEntity]` method takes it by value (`static void Hit(Fighter fighter, in Damage damage)`): the method visits the entities that have every component of the view, its fields read and write as its own `ref` / `in` parameters would (the schedule, the change ticks of tracked components and the vector loop alike), and the generated job builds the view over the row at no cost. The generator also writes `entity.AsFighter()` and `entity.TryGetFighter(out fighter)`. A view holds refs into the entity's row, so a structural change of that entity (or any change that moves rows) ends its use.
