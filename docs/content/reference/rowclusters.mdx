The clusters of one ordered table (an order inferred for a pair method, or [[OrderBy]](/en/docs/reference/orderbyattribute)): its rows in key order, cut into clusters of [`RowClusters.Size`](/en/docs/reference/rowclusters#size) rows, each with an axis-aligned box over the declared point of its rows, widened by the margin. What a search over space reads: a box far from the query skips its rows at once, a near one is read row by row (or a cluster per vector) from the table's columns ([`RowClusters.Read`](/en/docs/reference/rowclusters#read)). From [`World.Clusters`](/en/docs/reference/world#clusters) (every table ordered by a component) or [`EntitySpan.Clusters`](/en/docs/reference/entityspan#clusters) (the table of a batch method's run of rows, whose row 0 is [`EntitySpan.FirstRow`](/en/docs/reference/entityspan#firstrow)).

The boxes are drawn by the sort and hold until the next one as long as no row moved farther than the margin: rows [0, [`RowClusters.SortedRows`](/en/docs/reference/rowclusters#sortedrows)) are in clusters; rows [[`RowClusters.SortedRows`](/en/docs/reference/rowclusters#sortedrows), [`RowClusters.RowCount`](/en/docs/reference/rowclusters#rowcount)) joined the table since and are in none (a search reads them one by one, or waits for the next sort). A row that moved into a cluster's row since the sort widened that cluster's box. Inside a pass a row destroyed or moved away by the pass is a tombstone: its id's index is negative ([`RowClusters.Ids`](/en/docs/reference/rowclusters#ids)). A row of a cluster may lack the component since the sort ([`RowClusters.Has`](/en/docs/reference/rowclusters#has)). Valid until the next structural change of the world (a ref struct over the table's arrays).

### `Pairs` [#pairs]

```csharp
public int Pairs(RowClusters other, float cutoff, Span<ClusterPair> destination);
public int Pairs(float cutoff, Span<ClusterPair> destination);
```

The pairs of this table's clusters whose boxes come within `cutoff` of each other on every axis: the candidates of a search for the rows within `cutoff` of each other, which a kernel then reads [`RowClusters.Size`](/en/docs/reference/rowclusters#size) × [`RowClusters.Size`](/en/docs/reference/rowclusters#size) rows per pair (every other pair of rows is farther apart). Each cluster is paired with itself (a cluster whose rows all lack the component with none), and each other pair is written once, smaller cluster first. Written to `destination` as far as it holds; returns how many there are, so a caller whose buffer was short grows it and calls again. A sweep over the clusters sorted by their low side on axis 0: O(clusters × log clusters + candidates). The sort's buffers come from the shared array pools: allocation-free in steady state, and safe on several threads at once (it changes nothing).

**Parameters**

- `cutoff`: The distance, on each axis, beyond which two rows never interact: 0 or more.
- `destination`: Where the pairs go.

**Returns** The number of pairs, which may exceed the length of `destination`.

**Exceptions**

- `ArgumentOutOfRangeException`: `cutoff` is negative, infinite or NaN.
- `InvalidOperationException`: The boxes cover no axis.
