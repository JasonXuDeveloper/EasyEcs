```csharp
public struct Reduce<T> where T : struct, ISingletonComponent, IReduction<T>
```

把一次 `[ForEach]` 遍历归约到单例 `T`（OpenMP 的 `reduction`，MPI 的 `Allreduce`），按 `ref` 传入：`static void Count(in Health h, ref Reduce<Census> census) => census.Value.Alive++;`。并行遍历的每个块（单线程时是整次遍历）累加到自己的副本里，副本从 [`IReduction.Identity`](/zh/docs/reference/ireduction#identity) 开始：每行不加锁，也没有原子操作。遍历结束时，副本按块的顺序（也就是行的顺序）合并，结果替换 World 里的 `T`（没有就先添加）；`T` 声明了 [[Accumulate]](/zh/docs/reference/accumulateattribute) 时，结果合并进它：每次遍历都往上加的累计值。

整数结果是精确的，和线程无关。浮点结果取决于块从哪里开始，因为每个块的和各自舍入。做归约的遍历只按行数决定块从哪里开始（16 个块，每块 1,024 到 16,384 行；设置了 [`ForEachAttribute.ChunkSize`](/zh/docs/reference/foreachattribute#chunksize) 时按它），所以每次运行、任何线程数下结果都一样，但和同一个方法 `Parallel = false` 的结果（只有一个部分结果）不一定逐位相同。

它是按 `ref` 传入的普通结构体，而不是持有引用的包装：遍历把每段连续行的部分结果放在局部变量里，JIT 会把按 `ref` 传给内联方法的局部变量留在寄存器里，而地址被 ref 字段持有的局部变量只能留在内存里，每行一次读一次写（浮点求和因此慢好几倍）。

系统写 `T`（每次遍历一次）；[`Reduce.Value`](/zh/docs/reference/reduce#value) 是这个块的部分结果，不是总数。
