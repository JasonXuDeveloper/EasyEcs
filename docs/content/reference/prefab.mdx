A recipe for entities: a set of component values that belongs to no world, so no query ever sees it. [`World.Instantiate`](/en/docs/reference/world#instantiate) creates an entity with a copy of every value, in any world. Build it once (from code or configuration) and keep it; one prefab may serve worlds on several threads as long as nobody changes it meanwhile.

A prefab may have members ([`Prefab.AddMember`](/en/docs/reference/prefab#addmember)): a boss with its minions and its mount. Instantiating any of them creates the whole group, and an [`EntityId`](/en/docs/reference/entityid) field that names a member ([`Prefab.Id`](/en/docs/reference/prefab#id), for example `new ChildOf(boss.Id)`) names that member's new entity, any other is [`EntityId.Null`](/en/docs/reference/entityid#null): ids in a prefab name members only (an id of a world's entity may equal a member's). An [`Entity`](/en/docs/reference/entity) field is copied as it is: set relations to a world's entities after instantiating.

A prefab with a copy of every value of `basePrefab` (and of its members), to change on its own: a variant of a configured NPC. Later changes of either prefab do not reach the other (a copy, no inheritance). O(components).

### `SetAbsent` [#setabsent]

```csharp
public Prefab SetAbsent<T>() where T : struct, IComponent;
```

Give the recipe a column for `T` without the component: instances lack it, but their table has room for it, so adding it later (a tag set and cleared per tick, a state some instances enter) flips a presence bit instead of moving the row to another table, and every instance stays in one table. A value the recipe had is dropped. Returns this prefab. O(1).

**Complexity** ([API table](/en/docs/api)): O(1)
