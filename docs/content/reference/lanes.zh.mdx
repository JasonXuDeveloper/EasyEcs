批处理方法的流压缩，在 CPU 上做 GPU 的 ballot 和压缩：一次向量比较得出通道掩码（`Vector256.LessThan(hp, limit).ExtractMostSignificantBits()`：CUDA 的 `__ballot_sync`；它的 `__popc` 是 `PopCount`），[`Lanes.Compact`](/zh/docs/reference/lanes#compact) 把选中的元素紧挨着写出：批处理方法选中的行的 id（`entities.Ids`）、它们的值、它们的下标。有 AVX-512 时，4 字节或 8 字节的通道一次移动 16 个或 8 个（`VPCOMPRESSD` / `VPCOMPRESSQ`）；否则，以及其他大小的元素，一次一个，每个元素没有分支。

## 方法 [#methods]

### `Compact` [#compact]

```csharp
public static int Compact<T>(ReadOnlySpan<T> source, ulong mask, Span<T> destination) where T : unmanaged;
```

把 `source` 中在 `mask` 里置位的元素（第 `i` 位选中 `source[i]`，所以最多 64 个）按顺序写到 `destination` 开头，返回写了几个：`PopCount(mask)`。只读选中的元素，只写这么多个。有 AVX-512 时 4 字节或 8 字节的元素为 O(64 / 每个向量的通道数)，否则 O(选中数)；不分配。

**参数**

- `source`：从中挑选的元素：批处理方法某个 span 或它的 `EntitySpan.Ids` 的一段。
- `mask`：选中的元素；`source.Length` 及之后的位不能置位。
- `destination`：选中元素写入的位置；长度至少 `PopCount(mask)`。

**返回值**：写入的元素个数。

**异常**

- `ArgumentException`：`mask` 的某一位没有对应 `source` 的元素，或 `destination` 太短。

**复杂度**（[API 表](/zh/docs/api)）：O(1)：最多 64 个元素；有 AVX-512 时，8 字节或 4 字节的元素为 8 步或 4 步向量操作；否则每个选中元素一步，选中超过 12 个时每个元素一步，直到最后一个选中的元素
