```csharp
public readonly struct QueryFilter
```

查询的附加条件：必须存在但不读取的组件（[`QueryFilter.With`](/zh/docs/reference/queryfilter#with)），或者必须不存在的组件（[`QueryFilter.Without`](/zh/docs/reference/queryfilter#without)）。建一次并保存起来（比如放进 static readonly 字段）：

```csharp
static readonly QueryFilter Alive = QueryFilter.Create().Without<Dead>();
```

## 方法 [#methods]

### `Changed` [#changed]

```csharp
public QueryFilter Changed<T>(ulong since) where T : struct, IComponent, ITracked;
```

要求有 `T`，并且只选 `T` 在变更 tick `since` 或之后写过的行：`since` 是之前读到的 [`World.ChangeTick`](/zh/docs/reference/world#changetick)（`[Changed<T>]` 方法自己就会选出系统上次运行以来写过的行）。一个过滤条件只有一个 tick：它的 `Changed` 和 `Removed` 必须用同一个。

**异常**

- `ArgumentException`：前面的 `Changed` 或 `Removed` 用了另一个 tick。

**复杂度**（[API 表](/zh/docs/api)）：O(1)；遍历跳过 `since` 之前写过的表、4,096 行的块和 64 行的字

只选 `T1, T2` 中至少一个在变更 tick `since` 或之后写过的行：即 `Changed<T1>(since)` OR ... OR `Changed<T2>(since)`（行要有它所对应的那个组件；其他组件可以没有）。一个过滤条件的所有 `ChangedAny` 调用合成一个集合；这个集合、`Changed` 和 `Removed` 过滤条件、`RemovedAny` 的集合 以及其他过滤条件按 AND 组合。tick 之后没有任何一列写过的表整张跳过，没有任何一列写过的行字和行块也跳过。一个过滤条件只有一个 tick（用 [`QueryFilter.Since`](/zh/docs/reference/queryfilter#since) 移动）：每个客户端各留一个，用各自的 tick 运行。

**异常**

**复杂度**（[API 表](/zh/docs/api)）：构建 O(n)；遍历时跳过集合里的列自 `since` 以来都没被写过的表，以及没有任何列写过的块和位字

### `Create` [#create]

```csharp
public static QueryFilter Create();
```

不加限制的过滤条件：实体只要拥有查询的组件就匹配。链式调用从它开始（`Create().Without<Dead>()`）。O(1)。

**复杂度**（[API 表](/zh/docs/api)）：O(1)

### `InGroup` [#ingroup]

```csharp
public QueryFilter InGroup<T>(int group) where T : struct, IComponent, IGroup;
```

要求有 `T`，且分组是 `group`：只遍历这一组的表（[`World.GroupBy`](/zh/docs/reference/world#groupby)；World 没有按 `T` 分组时，所有表都属于第 0 组）。一个过滤条件只能指定一个分组：再指定另一个分组会抛出 `ArgumentException`。

**复杂度**（[API 表](/zh/docs/api)）：O(1)；遍历只走这个分组的表

### `Removed` [#removed]

```csharp
public QueryFilter Removed<T>(ulong since) where T : struct, IComponent, ITracked;
```

只选在变更 tick `since` 或之后失去 `T`、而且没有再拿回来的实体（`[Removed<T>]` 方法自己就会选出系统上次运行以来的移除）。移除组件后实体的行还在，所以一次移除和别的行一样，也是一行：存在位清零，变更 tick 记着移除的时间。已经销毁的实体没有行，不会访问到。一个过滤条件只有一个 tick：它的 `Changed` 和 `Removed` 必须用同一个。

**异常**

- `ArgumentException`：前面的 `Changed` 或 `Removed` 用了另一个 tick。

**复杂度**（[API 表](/zh/docs/api)）：同 `Changed`

### `Since` [#since]

```csharp
public QueryFilter Since(ulong since);
```

返回同一个过滤条件，只是把它的 [`QueryFilter.Changed`](/zh/docs/reference/queryfilter#changed) 和 [`QueryFilter.Removed`](/zh/docs/reference/queryfilter#removed) 过滤条件（以及 `ChangedAny` 和 `RemovedAny`）挪到 tick `since`，不用重建：适合存在字段里、每次更新后再用一次的过滤条件，或者每个客户端用各自确认过的 tick 各用一次。

**复杂度**（[API 表](/zh/docs/api)）：O(1)

### `Slice` [#slice]

```csharp
public QueryFilter Slice(int index, int of);
```

只访问每个匹配表的 `of` 片行中的第 `index` 片：index 从 0 依次到 `of` - 1 的这些遍历把每行访问一次，每次约为 1 / `of` 的行。`[ForEach(Slices = N)]` 方法传入系统这次运行对应的那一片（[`SystemHandle.RunCount`](/zh/docs/reference/systemhandle#runcount) mod N）。O(1)。

表按 64 行的倍数切分（它的存在位字），按遍历开始时的行数切，所以少于 64 行的表只有一块；匹配中的第 i 张表从第 (`index` + i) mod `of` 片开始切，所以很多张小表也会分散到各片上。两次遍历之间移动了的行（交换删除用表的最后一行填空洞、结构变更把实体移到另一张表、表扩容或缩小跨过切分点）在 `of` 次遍历的一轮里可能被跳过，也可能被访问两次；下一轮会再看到它们。

`ForEach`、`ForEachEntity`、`ForEachBatch` 以及它们的 `Parallel` 形式支持分片；需要所有匹配行的调用（`Query`、`Read`、`Count`、`Any`、`DestroyAll`、`entity.Run`、`SetAll` 和其他批量调用）遇到分片的过滤条件会抛 `ArgumentException`。分 1 片就是整张表。

**异常**

- `ArgumentOutOfRangeException`：`of` 小于 1，或者 `index` 不在 [0, `of`) 内。

**复杂度**（[API 表](/zh/docs/api)）：O(1)；一次遍历约访问 S / N 行，按 64 行位字切分
