public struct EntityRandom : ISingletonComponent, IEquatable<EntityRandom>

Deterministic random numbers for `[ForEach]` methods, parallel ones included (cuRAND's Philox, a counter-based generator): each number is a pure function of a seed, an entity, a tick and a stream, with no state to advance, so it is the same on every run, for any thread count and any order the rows run in. A singleton holding the seed and the tick: `static void Wander(ref Velocity v, Entity entity, in EntityRandom random) => v.X = random.Range(entity.Id, 0,
-1f, 1f);`, where the system that advances the simulation's clock advances [`EntityRandom.Tick`](/en/docs/reference/entityrandom#tick) too. The static members take the four inputs explicitly (a seed of your own, the tick of your clock).

The `stream` tells apart the draws of one entity in one tick: give each call site of a method its own (0, 1, 2, ...). The same four inputs give the same number, so two call sites with one stream draw the same number.

The bits are four rounds of SplitMix64's finalizer, one per input: a bijection of 64 bits per round, so two inputs that differ in one bit differ in about half the output bits. It is a hash, not a cryptographic generator.

#### Parameters

- `Seed`: The world's seed: a different seed, a different sequence for every entity.
- `Tick`: The step of the simulation the numbers are drawn for: advance it once per step.
