```csharp
public sealed class ValueIndex<T, TKey> where T : struct, IComponent, IIndexed<TKey> where TKey : IEquatable<TKey>
```

The value index of component `T` in one world ([`World.Index`](/zh/docs/reference/world#index)). It is kept current as values are written: `Set` and `CreateEntity` re-index the entity at once (O(1)), and entities leave it as soon as they are destroyed or lose the component, so a lookup does no catching up. The first lookup (and the first after [`World.Restore`](/zh/docs/reference/world#restore)) indexes every row once; the index of a unique component ([`IUniqueIndexed`](/zh/docs/reference/iuniqueindexed)) is current from the world's first table holding it instead, and refuses a write that would give a key to a second entity. Lookups allocate nothing once every key has been seen; the index belongs to the world's owner thread, like component values (a system that looks up from an `OnUpdate` hook or a `[ForEach]` method taking the `World` runs alone).
