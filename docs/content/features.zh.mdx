## 模拟 [#simulate]

每个 tick 的核心：数据放在表里，逻辑放在系统里，再加上驱动它们的循环。

```csharp
public record struct Position(float X, float Y) : IComponent;
public record struct Velocity(float X, float Y) : IComponent;
public record struct Health(int Value) : IComponent, ITracked;
public record struct Armor(int Value) : IComponent;
public struct Dead : IComponent;
public record struct Clock(float Dt) : ISingletonComponent;

public class MovementSystem : EcsSystem
{
    [ForEach, Without<Dead>]
    static void Move(ref Position p, in Velocity v, in Clock clock)
    {
        p.X += v.X * clock.Dt;
        p.Y += v.Y * clock.Dt;
    }
}
```

### World 与实体 [#worlds-and-entities]

`World` 拥有实体、组件、单例和系统，World 之间什么都不共享。`Entity` 是一个 16 字节的句柄（World、下标、版本号）：id 会回收复用，
每次访问都校验版本号，所以指向已销毁实体的句柄会抛异常，不会碰到复用这个 id 的新实体。

- **适合：** 每个独立的模拟一个 World（一张地图、一个场景、一局对战、一个测试）。代码里存 `Entity` 句柄，组件里存 `EntityId`。
- **开销：** 每个实体 id 一条 16 字节的记录。带组件创建时一次放进最终的表；销毁时用表的最后一行填洞。
  `WorldOptions.InitialEntityCapacity`、`EnsureEntityCapacity(n)` 和 `Reserve<T1, …, Tn>(n)`（连表一起）按已知峰值预分配，长期运行的服务器运行时不会再扩容。
- **指南：** [实体与组件](/zh/docs/guide/entities-and-components)

### 组件与标签 [#components-and-tags]

组件是结构体（`IComponent`），存放在原型（archetype）表里：每种组件组合一张表，每种组件一列，每个实体一行。非托管列固定在内存里，
并从 64 字节边界开始。空结构体就是标签。移除组件只清一个存在位、保留这一行，再加回来同样便宜。

- **适合：** 每个实体的数据，按系统会一起读的内容拆分；来来去去的状态用标签。
- **别用于：** 大多数实体每个 tick 都在变的值，不要做成标签，用字段。
- **开销：** 一次遍历只加载它读的列。获得一个表里没有对应列的组件，这一行拷贝一次；之后再开关只是翻一个位。
- **指南：** [实体与组件](/zh/docs/guide/entities-and-components)

### 生成成员 [#generated-members]

源生成器给每个组件生成具名的 C# 14 扩展成员：`e.Position`、`HasPosition`、`SetPosition(x, y)`、`RemovePosition()`，
标签有 `IsDead`，单例有 `world.Clock`，被索引的组件有 `world.TeamIndex`，`Prefab` 上也有同样的写入方法。被追踪和被索引的组件
生成只读属性，所以读永远不算写。

- **适合：** 所有写明具体组件的代码。泛型 API（`Get<T>()`、`Set(…)`）留给泛型代码。
- **开销：** 没有。每个成员都是对泛型 API 的内联调用，生成器也知道哪些是结构变更。
- **指南：** [实体与组件](/zh/docs/guide/entities-and-components)、[速查表](/zh/docs/cheat-sheet#generated-members)

### 生成的部分 [#generated-parts]

组件或单例原本要手写实现的东西，用特性声明，生成器把它写进 `partial` 类型：成员（或结构体本身）上的 `[IndexKey]` / `[UniqueKey]`
写出 `IIndexed<TKey>` / `IUniqueIndexed<TKey>` 和它们的 `Key`，`[Group]` 写出 `IGroup`，单例字段上的 `[Sum]`、`[Product]`、`[Min]`、
`[Max]`、`[All]`、`[Any]` 写出归约的 `Identity` 和 `Combine`。每个 World 共用的设置也声明在类型上：`[GroupBy]` 拆表，
`[WhenTargetDestroyed(policy)]` 设置链接的目标销毁策略，`[NotSaved]` 让运行时状态不进任何存档。

```csharp
public partial record struct Faction([IndexKey] int Id) : IComponent;
public partial struct Census : ISingletonComponent { [Sum] public int Alive; [Max] public int Oldest; }
```

- **适合：** 所有的键、分组和逐字段的总数：一个特性代替一个接口及其成员。
- **别用于：** 由多个成员算出的键、不是逐字段的归约：手写接口。
- **开销：** 运行时没有；生成的成员就是你本来要写的那些。设置类特性从 World 第一张包含该类型的表起生效。
- **指南：** [生成的部分](/zh/docs/guide/entities-and-components#declared-parts)、
  [EECS062-069](/zh/docs/guide/analyzer#eecs062)

### 系统与 [ForEach] [#systems-and-foreach]

系统继承 `EcsSystem`，只做一件事。`[ForEach]` 方法就是它的整个循环，参数可以是组件（`ref` 写、`in` 读）、单例、`Entity` 和 `World`。
生成器把每个方法编译成结构体 job，JIT 把它内联到行循环里。`OnCreate`、`OnUpdate` 和 `OnDestroy` 负责初始化和每次更新的额外工作。

- **适合：** 一个 tick 里所有逐实体的逻辑。
- **开销：** 把 `Velocity` 加到 `Position` 的 `[ForEach]` 系统，每个实体 <BenchValue k="forEach.perEntity" />；同样的循环手写在两个普通数组上是
  <BenchValue k="rawArray.perEntity" />。每个系统每次更新：三次虚调用，加每个方法一次查询缓存查找。
- **指南：** [系统](/zh/docs/guide/systems)、[ECS 设计原则](/zh/docs/ecs-principles)

### 泛型系统 [#generic-systems]

系统类可以是泛型的：每个闭合类型（`CountOf<Position>`、`CountOf<Health>`）都是一个独立的系统，有自己生成的 job 和读写集合，
各自添加、排序、调度。闭合的泛型系统也可以当基类。

- **适合：** 同一条规则作用于几种组件类型（计数、衰减、按资源种类清理）。
- **别用于：** 泛型的 `[ForEach]` 方法：没人能给它提供类型实参（[EECS004](/zh/docs/guide/analyzer#eecs004)）；把类做成泛型。
- **开销：** 除了闭合出来的系统本身没有额外开销；靠反射构造的类型在第一次用到时才闭合代码。
- **指南：** [系统](/zh/docs/guide/systems#generic-systems)

### 过滤条件 [#filters]

`[With<T>]` 要求有某个不作为参数传入的组件，`[Without<T>]` 排除一个组件，`[WithAny<T>]` 要求几个里至少有一个，
`[Changed<T>]` 和 `[Removed<T>]` 按变更 tick 选择。临时代码里有同样的 `QueryFilter`。系统分组上可以写 `[With<T>]`、`[Without<T>]`、
`[WithAny<T>]`，对分组里的所有系统生效；也可以让分组自己或它实现的接口实现 `ISystemGroupWith<T>` / `ISystemGroupWithout<T>`。
这样一个泛型接口就能给每种 actor 类型各配一个带过滤的分组，特性做不到这一点，因为特性里不能写类型参数。

- **适合：** 状态（`[Without<Dead>]`）、角色（`[With<Player>]`）、多选一（`[WithAny<Frozen>, WithAny<Stunned>]`）。
- **开销：** 匹配结果按查询形状缓存；不可能匹配的表只跳过一次，部分行缺组件的表按位字一次检测 64 行。
- **指南：** [查询与过滤](/zh/docs/guide/queries)、[分组过滤](/zh/docs/guide/systems#group-filters)

### 可选组件 [#optional-components]

`Maybe<T>` 参数不管实体有没有 `T` 都会访问：`HasValue` 说明有没有，`Value` 是 `ref`。可选部分不大时，一个方法就能代替
`[With<T>]` 和 `[Without<T>]` 两个版本。`ReadOnlyMaybe<T>` 是只读版本：从不打 tick，调度时算读，也是带索引的组件唯一能用的可选参数。

- **适合：** 只有部分实体才有的加成（伤害计算时的护甲、回血时的增益）。
- **别用于：** 最热的循环：用 `[With<T>]` / `[Without<T>]` 拆成两个方法，每行都不用检测。
- **开销：** 不做结构变更的方法每行检测一个存在位；做结构变更的方法每个实体查找一次。
- **指南：** [系统](/zh/docs/guide/systems#maybe)、[`ReadOnlyMaybe<T>`](/zh/docs/guide/systems#read-only-maybe)

### 生成器写出的向量循环（SIMD） [#vector-loops]

组件有 1 到 4 个同样大小数值（`float`、`int` 等；`Position { X, Y, Z }` 也行）的逐行 `[ForEach]` 方法，会以生成器根据方法体写出的
向量循环运行（CPU 支持 AVX-512 时用 `Vector512`，之后用 `Vector<T>`），和 Burst 编译 job 的做法一样：`if` 和 `?:` 变成掩码，单例和常量复制到每条通道，多个字段拆成每个字段一个向量，
结果和逐行方法逐位相同。

- **适合：** 对大量行做算术：衰减、积分、截断、计数。
- **别用于：** 不用管：它是自动的。不符合条件的方法（两种大小的通道、每条路径上都有函数调用）照旧逐行运行，
  [EECS055](/zh/docs/guide/analyzer#eecs055) 会说明原因；`SimdMode = SimdMode.Require` 让它成为构建错误（[EECS056](/zh/docs/guide/analyzer#eecs056)），
  `SimdMode.Off` 不再提示。并行方法、`Maybe<T>` 参数、`byte` 和 `short` 通道、`Vector2` / `Vector3` 字段、整体赋值（`new T(...)`、`with`）
  和条件分支里的调用也能得到循环；`FloatMode.Fast` 让 `Sin`、`Exp`、`Log` 等改用向量近似。`SystemInfo.Loops` 列出每个方法得到的循环。
- **开销：** 运行时只有循环本身，循环在编译时写好；`Reduce<T>` 每条通道一个累加器。
- **指南：** [系统](/zh/docs/guide/systems#vector-loops)、[FloatMode](/zh/docs/guide/systems#float-mode)、
  [高性能写法](/zh/docs/guide/high-performance)

### 批量方法 [#batch-methods]

参数是 `Span<T>` / `ReadOnlySpan<T>` 的 `[ForEach]` 方法，一次接收一整段连续的匹配行，每段调用一次，方便用 `Vector<T>` 做向量化。
`world.ForEachBatch` 在临时 job 里做同样的事。

- **适合：** 对大量行做算术（移动、衰减、求和）。
- **别用于：** 需要结构变更的逻辑：批量方法执行期间 World 的结构是冻结的。
- **开销：** 每段行调用一次，而不是每个实体一次。
- **指南：** [系统](/zh/docs/guide/systems)

### 单例 [#singletons]

每个 World 一份的结构体（`ISingletonComponent`）：时钟、配置、计数器、空间网格。`[ForEach]` 方法以 `ref` 或 `in` 参数接收；
系统之外的代码用稳定句柄 `SingletonRef<T>`。

- **适合：** 所有 World 级状态。系统自身不存状态。
- **别用静态字段代替：** 静态字段由所有 World 共享。
- **开销：** 作为参数时每次遍历查找一次。
- **指南：** [单例](/zh/docs/guide/singletons)

### 排序、分组与间隔 [#system-groups-and-intervals]

系统按注册顺序执行，可以用 `[UpdateBefore<T>]` / `[UpdateAfter<T>]` 调整。`[UpdateInGroup<G>]` 把系统放进一个分组，只在
`world.Update<G>()` 时执行。`[UpdateInterval(N, Phase = P)]` 让系统每 N 次更新执行一次，并分散到不同相位（次数是 `world.UpdateCount<G>()`）；`Enabled` 关掉它。
分组的过滤条件（`[Without<Frozen>]`，或分组自己、它实现的接口上的 `ISystemGroupWith<T>` / `ISystemGroupWithout<T>`）作用于分组里所有系统的 `[ForEach]` 方法。

- **适合：** 不同的节奏：输入每次唤醒都处理，模拟按固定 tick 跑，存盘每隔几秒一次；每种 actor 一个分组，用一个泛型接口统一声明。
- **开销：** 除了系统本身没有额外开销；空分组的更新什么都不做。排序成环会编译失败（[EECS019](/zh/docs/guide/analyzer#eecs019)）。
- **指南：** [系统](/zh/docs/guide/systems)

### 分片 [#slices]

`[ForEach(Slices = N)]` 把一个方法要处理的行分摊到系统的 N 次运行里：每次只访问一片，约占每张匹配表的 1/N，按 64 行的位字切分，
所以每 N 次运行每行恰好访问一次。`system.RunCount` 表示这是第几次运行（这次的分片是 `RunCount % N`）；结构体 job 用
`QueryFilter.Slice(index, of)` 做同样的事。

- **适合：** 晚一点也无妨、但一个 tick 做完太贵的工作：重新给 AI 目标打分、扫描空闲会话、给大量实体做数值衰减。
- **别用于：** `[Changed<T>]` / `[Removed<T>]` 方法，它们必须看到每一次变更（[EECS035](/zh/docs/guide/analyzer#eecs035)）；
  每个 tick 必须处理每一行的逻辑。两次运行之间搬动过的行，在一轮里可能被跳过或访问两次。
- **开销：** 每次运行处理约 1/N 的行，外加遍历表的开销；配合 `[UpdateInterval(M)]`，每行每 N × M 次更新访问一次。
  `Query`、`Count` 和批量调用不接受分片过的过滤条件。
- **指南：** [系统](/zh/docs/guide/systems)

### 立即生效的结构变更 [#immediate-structural-changes]

创建、销毁、添加、移除都立即生效，在遍历同一批表的过程中也一样。一次遍历里每个实体最多访问一次：还没轮到就离开的实体直接跳过，
中途加入的实体留到下一次遍历；方法体搬动了自己的实体，`[ForEach]` 方法的 `ref` 参数依然有效。

- **适合：** 任何时候。在做出决定的地方直接写变更，同一次更新里后面的代码和系统都能看到。
- **和命令缓冲相比：** 把变更推迟到缓冲里的库，会让系统看到一个马上就要变的状态，效果的先后还取决于缓冲何时回放。
  EasyEcs 没有需要回放的缓冲。
- **开销：** 可能做结构变更的遍历，每个实体之后检查一个计数器；不可能做结构变更的方法连这一步都省了。
- **指南：** [结构变更](/zh/docs/guide/structural-changes)、[ref 与 await](/zh/docs/guide/refs-and-await)

### 遍历后销毁的事件 [#consume]

`[ForEach, Consume]` 在遍历结束时正好销毁这一遍访问过的行：处理事件或命令实体的方法每个只处理一次，方法体里不用写 `entity.Destroy()`。

- **适合：** 伤害事件、客户端命令、请求：只活一遍的实体。
- **别用于：** 比读它的系统活得更久的实体；分片的方法（[EECS085](/zh/docs/guide/analyzer#eecs085)）。
- **开销：** 没有结构变更的遍历之后，每张表一次 `DestroyAll`，而不是每行一次销毁（这时遍历抛异常就什么都不销毁）；所在的系统独自运行。
  手写的销毁由 [EECS084](/zh/docs/guide/analyzer#eecs084) 报告。
- **指南：** [系统](/zh/docs/guide/systems#consume)

### 临时查询 [#ad-hoc-queries]

在任何代码里遍历：`foreach (var item in world.Query<T…>(filter))`、结构体 job（`world.ForEach`、`ForEachEntity`）、
`world.Count` 和 `world.Any`。系统之外的静态 `[ForEach]` 方法会生成一个入口（`Reports.CountAlive(world, ref alive)`），
带着调用方传入的值，当作结构体 job 执行。静态 `[ForEntity]` 方法在单个实体上运行，
拿到的 `ref` 和遍历时一样：它的入口（`Requests.TakeHit(unit, damage)`）在实体已销毁、缺组件或不满足过滤条件时返回 `false`；
`entity.Run<Health, TJob>(ref job, filter)` 用同样的方式运行手写的 job。job 的 `static int WriteMask` 指明哪些组件算作写入（默认全部）；
实现 `INoStructuralChanges` 的 job 省掉结构变更的簿记。

- **适合：** 工具、测试、两次更新之间的请求处理、一次性的遍历；发给单个实体的请求或消息用 `[ForEntity]`。
- **别用于：** 每个 tick 都要跑的逻辑：系统有排序、有调度、有耗时统计。
- **开销：** 零分配。`Count` 只是把表的行数加起来；`Any` 找到第一个就停；结构体 job 是最快的临时遍历。
  `[ForEntity]` 的入口（`entity.Run`）是 O(1)，过滤条件每多一个组件多 O(1)。
- **指南：** [查询与过滤](/zh/docs/guide/queries)、[`[ForEntity]`](/zh/docs/guide/queries#run-on-one-entity)

## 响应变化 [#react]

服务器很多时间花在“上个 tick 以来变了什么”上：同步、存盘、重建索引。EasyEcs 把变化记录成数据，系统只访问那些行。

```csharp
public record struct Replica(int Health) : IComponent;

public class ReplicationSystem : EcsSystem
{
    [ForEach, Changed<Health>]                       // 只访问本系统上次执行后被写过的行
    static void Send(in Health hp, ref Replica replica) => replica = new Replica(hp.Value);
}
```

### 变更追踪 [#change-tracking]

标了 `ITracked` 的组件，每行记录最后一次写入时的变更 tick（任何给出 `ref` 的访问都算写入）。`[Changed<T>]` 方法只访问本系统上次执行后
被写过的行，`[ChangedAny<A, B>]` 访问几个组件里至少有一个被写过的行。查询里用 `QueryFilter.Changed<T>(since)` 和
`ChangedAny<A, B>(since)`：一个过滤条件存一份，每个客户端带着自己确认过的 tick 跑一遍（`filter.Since(ack)`），各自拿到自己上次确认以来的变化。

- **适合：** 向客户端同步、保存脏数据、为移动过的单位更新空间结构；`ChangedAny` 适合“任何一部分变了就整体下发”的快照（血量、法力、护甲）。
- **别用于：** 大多数行每个 tick 真的都在变的组件（移动中单位的位置），没有可跳过的。每个 tick 都重算、但值很少变的组件不一样：
  只在值变了时写入（[见下](#write-only-when-changed)），照样追踪。
- **开销：** 每行 8 字节，每次写入一次存储；不追踪的组件没有任何开销。10 万实体里同步 10 个变化的实体耗时 <BenchValue k="changed.10" />，
  扫描全部行是 <BenchValue k="changed.10.scan" />。自 tick 以来没有任何列被写过的表整张跳过，`ChangedAny` 也一样。
- **指南：** [变更追踪](/zh/docs/guide/change-tracking)

### 值变了才算写入 [#write-only-when-changed]

被追踪组件的 `ref` 参数会给方法访问到的每一行打 tick，不管写没写。`Mut<T>` 参数只给方法真正写了的行打 tick：`Value` 只读，
`Write()` 给出 `ref` 并打 tick，`SetIfChanged(value)` 只在值不同时存入并打 tick。遍历之外，`entity.SetIfChanged(value)` 和生成的
`SetHealthIfChanged(…)` 也是这样。

- **适合：** 每个 tick 都重算、偶尔才变的值：单位的目标、所在的格子、推导出来的属性。`[Changed<T>]` 的读取方只会访问值真变了的行。
- **别用于：** 大多数行反正都会写的值：普通 `ref` 更便宜。
- **开销：** `Value` 就是一次普通读取；每次写入打一次 tick（方法会做结构变更或并行运行时，再加一次实体查找）；`SetIfChanged` 先比较值（`IEquatable<T>`，record struct 自带；
  否则按非托管结构体的字节比较）。调度器把 `Mut<T>` 参数算作对 `T` 的写入。
- **指南：** [变更追踪](/zh/docs/guide/change-tracking)

### 移除检测 [#removal-detection]

`[Removed<T>]` 方法访问本系统上次执行后失去了被追踪 `T` 的实体，每次移除访问一次，还能读写它们的其他组件：移除时行被保留，并打上 tick。
`[RemovedAny<A, B>]` 和 `QueryFilter.RemovedAny<A, B>(since)` 选出失去了几个组件之一的实体。

- **适合：** 告诉客户端什么没了（火灭了、护盾碎了），释放组件代表的东西（预留的格子）。
- **别用于：** 已销毁的实体，它们没有行：由[销毁日志](#destroy-log)报告。
- **开销：** 除了组件本来就有的 tick 列，不占额外存储。10 万实体里找出 10 次移除耗时 <BenchValue k="removed.10" />。
- **指南：** [变更追踪](/zh/docs/guide/change-tracking#removal-detection)

### 销毁日志 [#destroy-log]

设置 `WorldOptions.DestroyLogCapacity = n` 后，World 记下最近销毁的 n 个实体，以及各自被销毁时的变更 tick。
`world.DestroyedSince(since, into, out count)` 列出某个读取方的 tick 以来销毁的实体，所以每个客户端都能按自己确认过的 tick 知道该删哪些实体。
读取方比日志还旧（早于 `DestroyLogOldestTick`）时返回 false：这个客户端需要重新下发全量状态。

- **适合：** 把实体的消失同步给很多客户端，而它们确认到的 tick 各不相同。
- **别用于：** 只有一个读取方、而且必须在实体消失前处理它（释放座位、关闭连接）：那是[清理组件](#cleanup-components)的事。
- **开销：** 每条记录 16 字节，一次性分配；每次销毁一次存储；关闭时（默认）没有开销。`DestroyedSince` 是 O(报告的记录数)，不分配内存。
- **指南：** [变更追踪](/zh/docs/guide/change-tracking)

### 清理组件 [#cleanup-components]

实现 `ICleanupComponent` 的组件让实体在 `Destroy` 之后继续存活：`Destroy` 改为让实体退休（其他组件被移除，加上 `Retired` 标签），
实体一直保留，直到某个系统释放资源、移除最后一个清理组件。

- **适合：** World 之外、必须恰好释放一次的资源：一个连接、一个预留的座位、另一个服务里的槽位。
- **别用于：** 纯数据：已销毁实体的组件不需要释放。
- **开销：** 没有清理组件的表，每次销毁多检查一个标志。
- **指南：** [清理与禁用](/zh/docs/guide/cleanup-and-disable)

### 禁用与启用 [#disable-and-enable]

`entity.Disable<T>()` 让组件对查询、`Has` 和 `Get` 不可见，同时保留它的值；`Enable<T>()` 再把它还回来。期间实体带着 `Disabled<T>` 标签，
所以被暂停的实体一个查询就能找到。

- **适合：** 暂停：眩晕期间冻结冷却，玩家接管单位时关掉 AI。
- **别用于：** 以后不再需要的值：直接移除组件。
- **开销：** O(1)；一张表里第一次禁用时，这一行搬到带标签列的表，只搬一次。
- **指南：** [清理与禁用](/zh/docs/guide/cleanup-and-disable)

## 查找 [#find]

按值查找，不用手工维护一个同步的字典。

```csharp
public partial record struct Team([IndexKey] int Id) : IComponent;
[GroupBy] public partial record struct Zone([Group] int Id) : IComponent;   // 每个 World 都按它分组
public partial record struct Account([UniqueKey] int Id) : IComponent;
```

```csharp
using var world = new World();
world.CreateEntity(new Team(1), new Zone(3), new Position(0, 0), new Account(7));

int red = world.TeamIndex.Count(1);                             // 一次哈希查找
int inZone = world.Count<Position>(QueryFilter.Create().InZone(3));   // 只遍历 3 号场景的行
Entity owner = world.AccountIndex.Get(7);                       // 唯一键对应的那一个实体
```

### 值索引 [#value-indexes]

键标了 `[IndexKey]` 的组件（生成器实现 `IIndexed<TKey>`）可以按 `Key` 查找：`world.Index<T, TKey>()`（或 `world.TeamIndex`）的 `Find`、`TryFind` 和 `Count`。
每次 `Set`、创建和销毁都会更新索引；经 `ref` 写入时索引看不到，所以编译期直接报错（[EECS015](/zh/docs/guide/analyzer#eecs015)）。

- **适合：** 按名字找玩家、找公会里的单位、找某个网格格子里的实体。
- **别用于：** 大多数行每个 tick 都在变、又很少查找的值：每次变化都要重新挂链。
- **开销：** 每个被索引的实体一个节点，只有用到索引的 World 才付出。`Count` 是一次哈希查找，`Find` 每个匹配一步。
- **指南：** [索引与关系](/zh/docs/guide/indexes-and-relations)

### 唯一键 [#unique-keys]

键标了 `[UniqueKey]` 的组件（`IUniqueIndexed<TKey>`），一个键只对应一个实体：`index.Get(key)` 返回它（没有就抛异常），`TryGet(key, out e)` 试着取。
任何会让第二个实体拿到别人已有的键的写入（`Set`、创建、`Instantiate`、`Clone`、`SetAll`、`Enable`、读档和搬移），都会在改动任何东西之前抛出
`InvalidOperationException`。引用类型键为 null 时视为没有键。

- **适合：** 账号 id、玩家名、会话令牌、格子的占用者：绝不能对应两个实体的键。
- **别用于：** `EntityId` 键（[EECS036](/zh/docs/guide/analyzer#eecs036)）；几个实体共用的键（用普通的 `[IndexKey]`）。
- **开销：** 第一张含该组件的表出现时索引就建好了，所以每次写入都会检查：每个变了的键一次哈希查找，批量调用和读档多遍历一遍行。
  `Get` 和 `TryGet` 是一次哈希查找，只读这个键自己的记录：唯一键直接存它的实体，每个键没有数组。能映射到有界槽位的键
  （`IDirectIndexed<TKey>`：网格格子、小 id）改为读一个数组元素（[直接映射的键](/zh/docs/guide/indexes-and-relations#direct-index)）。
- **指南：** [索引与关系](/zh/docs/guide/indexes-and-relations)

### 有序区间 [#ordered-ranges]

键可比较的值索引还能按键的顺序遍历：`Range(min, max)`、`RangeDescending`、`Ascending()` 和 `Descending()`。

- **适合：** 排行榜、按分数匹配、某个等级区间的玩家。
- **开销：** 键出现和消失时维护有序的键列表：每次 O(log 键数)，再加一次块移动。
- **指南：** [索引与关系](/zh/docs/guide/indexes-and-relations)

### 按值分表 [#table-groups]

类型上标 `[GroupBy]`（每个 World）或调用 `world.GroupBy<T>()`（一个 World）后，`IGroup` 组件的值（它的 `[Group]` 成员）会把表拆开：同一个场景、地图或对局的实体共用一批表，`QueryFilter.InGroup<T>(group)`
只遍历它们的行，在内存里是连续的。设置新值会把实体搬到新分组的表里。

- **适合：** 一个 World 里有很多场景或对局，各自单独更新、单独查询。
- **别用于：** 经常变化的值（每次变化一次行拷贝），或者每组只有寥寥几个实体。
- **开销：** `GroupBy` 时一次 O(实体数)；每次换组一次行拷贝。
- **指南：** [分组](/zh/docs/guide/groups)

## 组织 [#structure]

实体之间的链接、实体内部的列表，以及用来刷出实体的配方。

```csharp
public partial record struct OwnedBy([IndexKey] EntityId Owner) : IComponent;
public record struct Loot(int Item);
```

```csharp
var archer = world.CreateEntity(new Health(10));
world.CreateEntity(new OwnedBy(archer), new Position(0, 0));        // 箭指向它的主人
int arrows = world.OwnedByIndex.Count(archer);

var turret = world.CreateEntity(new ChildOf(archer));               // 随父实体一起销毁
archer.Set(new DynamicBuffer<Loot>());
archer.WriteLoot().Add(new Loot(7));                                // 一次被追踪的写入

var goblin = new Prefab().SetPosition(0, 0).SetHealth(30);
var wave = new Entity[100];
world.Instantiate(goblin, wave);
var guard = world.Instantiate(goblin, new ChildOf(archer));          // 自带父实体，只拷贝一次行
```

### 关系 [#relations]

以 `EntityId` 为键的索引组件，把每个实体链接到一个目标（箭指向弓箭手），索引能列出所有指向某个目标的实体。`IRelation` 元素把一个实体
链接到多个目标（英雄同时在几个队伍里），用 `Link` / `Unlink` 维护，用 `world.Relations<T>()` 反查。
`WhenTargetDestroyed(TargetPolicy…)` 决定目标销毁时链接怎么处理：保留、移除，或者连带销毁。

- **适合：** 归属关系、队伍成员、增益作用的单位、有自己状态的物品。
- **别用于：** 只有主人自己读的一袋普通值：[动态缓冲](#dynamic-buffers)只是一个组件，不用每个元素一个实体。
- **开销：** 反查 O(1) 起步，每条链接 O(1)；一条 `IRelation` 链接占 20 字节，再加目标列表里的 8 字节，可回收复用。
- **指南：** [索引与关系](/zh/docs/guide/indexes-and-relations)

### 层级 [#hierarchy]

内置的 `ChildOf(EntityId Parent)` 组件把子实体链接到父实体。`world.Children(parent)` 列出子实体，
`world.Descendants(root)` 深度优先走完整棵子树（每个实体排在它的子实体之前，不含根），`.AddTo(ids, includeRoot: true)`
把它收进列表，供迁移或存档使用，`SetChildOf(other)` 换父实体，
销毁父实体会连带销毁所有后代。

- **适合：** 一艘船和它的炮塔、一个玩家和挂在身上的物品、一个小队和它的成员。
- **别用于：** 变换传播：没有内置的世界坐标变换，需要的话自己写系统。
- **开销：** 第一次调用为所有 `ChildOf` 建一次索引之后，`Children` O(1) 起步、每个子实体 O(1)；`Descendants` 每个实体 O(1)，
  预热后不分配内存；级联销毁每条链接 O(1)。
- **指南：** [层级](/zh/docs/guide/hierarchy)

### 动态缓冲 [#dynamic-buffers]

`DynamicBuffer<T>` 是每个实体一个的列表，以被追踪组件的形式存放。它的写操作（`Add`、`RemoveAt`、`Clear`、`AsSpan`）都要以 `ref`
拿缓冲，所以 `[Changed<DynamicBuffer<T>>]` 能找出列表变了的实体，经 `in` 写入则编译不过。快照会拷贝其中的元素。

- **适合：** 属于某个实体、变了就要发送或保存的列表：背包、路径、最近的命中记录。
- **别用于：** 有自己状态的元素（每个元素一个实体，加一条关系），或者数量固定的一小组值（非托管组件里的 `[InlineArray]`）。
- **开销：** 每个实体一个对象加一个数组，第一次写入时创建；容量之内的写入不分配内存。销毁的缓冲把列表交给池，同类型的下一个缓冲
  从池里取，不论在哪个线程：`MaxPooledLength` 决定最长保留多长的列表，`FillPool(n)` 在启动时把池填满。`SetCount(n)` 返回 span，原地写整个缓冲。
- **指南：** [动态缓冲](/zh/docs/guide/dynamic-buffers)、[缓冲池](/zh/docs/guide/dynamic-buffers#pool)、[ECS 设计原则第 8 条](/zh/docs/ecs-principles#8-choose-how-to-hold-a-collection)

### 预制体与克隆 [#prefabs-and-cloning]

`Prefab` 是一份不属于任何 World 的组件值配方，所以没有查询能看到它，也没有系统需要过滤它。`world.Instantiate(prefab)` 创建一个实体，
`Instantiate(prefab, span)` 创建一整波；`new Prefab(base)` 生成变体，`AddMember()` 组成一组（首领带着小怪和坐骑）。
`Instantiate(prefab, new ChildOf(boss), new Position(x, y))` 在同一次调用里给实例最多九个自己的组件：覆盖预制体里的值，或者新加上去。
`entity.Clone()` 复制一个活着的实体。`SetAbsent<T>()` 给配方留一列 `T` 但不带这个组件，实例之后进入的状态（`SetEnraged()`）只翻一个存在位，
不用搬行。

- **适合：** 反复刷出的实体种类：NPC 类型、投射物、掉落物，写在代码里或启动时从配置加载；带组件的形式适合父实体、位置或主人每个实例都不同的刷怪。
- **别用于：** 每个值都不一样的实体：直接带值创建。
- **开销：** 每个实例一次行拷贝，带组件也一样（拷贝之后不再搬行）；一整波只过一次结构闸门，表最多扩容一次。
- **指南：** [预制体](/zh/docs/guide/prefabs)

## 持久化 [#persist]

World 就是数据，所以能拷贝、能写出去、能搬走、能重新加载。

```csharp
var before = world.Capture();                       // 内存里
world.Update();
world.Restore(before);                              // 回滚；之前的句柄重新有效

var bytes = new System.Buffers.ArrayBufferWriter<byte>();
world.Save(bytes);                                  // 写成字节：文件、数据库、另一个进程
using var restarted = new World();
restarted.Load(bytes.WrittenSpan);
```

### 快照 [#snapshots]

`world.Capture()` 把实体、组件和单例拷进一个 `WorldSnapshot`；`world.Restore(snapshot)` 把它们放回去，可以恢复任意多次。
`Capture(into)` 复用已有快照的数组。

- **适合：** 撤销一回合、客户端预测的回滚、回放、测试之间重置 World。
- **别用于：** 跨重启的持久化（用[存档](#saves)）；组件里的托管引用是共享的，不会深拷贝。
- **开销：** 两个方向都是 O(实体数 × 组件数)；拍进复用的快照不分配内存。
- **指南：** [快照](/zh/docs/guide/snapshots)

### 存档 [#saves]

`world.Save(writer)` 把整个 World 写成字节，`world.Load(bytes)` 在本进程或另一个进程的 World 里读回来：id、组件和单例都一样。
非托管组件按原始行写出；托管组件、单例和标了 `[NinoType]` 的非托管组件由 Nino 写出。类型按 Nino 类型 id 记录，所以加载时会跳过进程里已经不存在的组件，改了名的组件用 `[NinoFormerName]` 就能留住。

重启时，`SaveWithout(writer, in exclude)` 不写 `ComponentSet` 里的组件和单例（运行时状态、缓存、配置），这些类型也就不需要格式化器；
`LoadKeeping(bytes, in keep, markWritten: false)` 保留新进程已经设好的单例，比如它的配置。无论在哪里都是运行时状态的类型标上
`[NotSaved]`：任何存档都不包含它，它也不需要格式化器。

- **适合：** 跨重启持久化、落盘的回放、把一个 World 发到另一台机器。
- **别用于：** 原地修改非托管组件的内存布局：请新增一个组件类型，否则旧存档加载不了。
- **开销：** 每个非托管列一次块拷贝；缓冲足够大之后不再分配内存。
- **指南：** [存档](/zh/docs/guide/saves)

### 迁移 [#migration]

`SaveEntities` 和 `LoadEntities` 经由字节把相关的实体（一个玩家和他拥有的东西）搬到另一个 World，换上新 id，组内的链接随之改写。
`MoveEntities` 在同一线程的两个 World 之间直接搬，不经过编码。记录只保存需要持久化的部分：`SaveEntitiesWith(writer, ids, set)`
配一个 `ComponentSet`，只写出集合里的组件；`LoadEntitiesInto(bytes, entities)` 把它们放到已经存在的实体上。
加上 `markWritten: false`，恢复的值不算变更，按变更存盘的系统就不会立刻把它写回去。`SaveEntitiesWithout(writer, ids, set)` 反过来：
除了集合都写，留给加载后会重新算的数据。

- **适合：** 玩家换场景或换服，对局结束把幸存者交给大厅（用 `Descendants` 收集整组）；实体先于存储数据出现的 actor 用记录。
- **开销：** O(给出的实体数 × 组件数)；`MoveEntities` 直接拷贝行。
- **指南：** [迁移与卸载](/zh/docs/guide/migration-and-unload)、[记录](/zh/docs/guide/migration-and-unload#records)

### 卸载插件类型 [#unloading]

`world.RemoveTypes(assembly)` 或 `RemoveTypes(context)` 从 World 里移除插件的系统、单例、索引和组件，于是可回收的
`AssemblyLoadContext` 可以卸载、加载新版本，数据靠存档带过去。

- **适合：** 在线服务器热重载游戏逻辑。
- **开销：** O(持有这些组件的实体数 + 表数 + 缓存的查询数)，走冷路径，会分配内存。
- **指南：** [迁移与卸载](/zh/docs/guide/migration-and-unload)

## 扩展 [#scale]

更多的实体，更多的核，更大的刷怪波次。

### 每个线程一个 World [#threading-model]

一个 World 有一个所有者线程，就是调用 `Update` 的那个。结构变更检查一个普通的所有者标志（没有原子操作），在并行区域里发生时直接抛异常，
而不是把表写坏；分析器能看到的跨线程变更会在编译期报出（[EECS013](/zh/docs/guide/analyzer#eecs013)、[EECS014](/zh/docs/guide/analyzer#eecs014)）。

- **适合：** 每张地图或每个场景一个 World，各占一个线程，完全不需要同步。其他线程的输入通过你自己的队列交给它，由一个系统取出处理。
- **开销：** 4 个各 2.5 万实体的 World 在 4 个线程上一个 tick 耗时 <BenchValue k="tick.fourWorlds" />，一个 10 万实体的 World 是
  <BenchValue k="tick.oneWorld" />。
- **指南：** [多线程与并行](/zh/docs/guide/threading)

### 并行系统 [#parallel-systems]

打开 `WorldOptions.ParallelSystems` 后，相邻的、没有顺序约束、读写不冲突的系统同时执行。读写集合由 `ref` 和 `in` 参数生成，
结果始终和顺序执行一致。

- **适合：** 几个互相独立的重系统，加上空闲的核。
- **别用于：** 只处理几千个实体的轻系统：每个阶段都有一次线程池交接的开销。
- **开销：** 零分配；`MaxDegreeOfParallelism` 限制线程数。
- **指南：** [多线程与并行](/zh/docs/guide/threading)

### 并行 [ForEach] [#parallel-foreach]

`[ForEach(Parallel = true)]` 把一个方法要处理的行切成块，由调用线程和线程池线程同时执行。分析器拒绝可能竞争的方法
（[EECS010](/zh/docs/guide/analyzer#eecs010)）：结构变更、批量方法、以 `ref` 接收单例。`world.ForEachParallel` 和
`ForEachEntityParallel` 对结构体 job 做同样的事。

- **适合：** 几万个实体以上、每个实体计算量大的工作：转向、寻路跟随、AI 打分；配上 `ChunkRows = n`，也适合只有几百行、每行几微秒的活（地形区块、寻路）。
- **别用于：** 几千个实体的轻量行：交接的开销比活本身还大。
- **开销：** 线程做完一块就领下一块，也就是 OpenMP 的 `schedule(dynamic, n)`。默认每块 1,024 到 16,384 行，大约每个线程四块，零分配；
  写被追踪组件的方法按 4,096 行的整数倍切块（变更摘要一段的行数），所以表要更大才会被拆开。`ChunkRows = n` 指定每块的行数
  （向上取整到 64；[EECS054](/zh/docs/guide/analyzer#eecs054)）。
- **指南：** [多线程与并行](/zh/docs/guide/threading)、[`ChunkRows`](/zh/docs/guide/threading#chunk-rows)

### 对所有行求总数（归约） [#reductions]

`ref Reduce<T>` 参数把一遍 `[ForEach]` 变成求一个总数：`T` 是字段标了 `[Sum]`、`[Min]`、`[Max]` 等的单例（或手写实现 `IReduction<T>` 的 `Identity`、`Combine`），并行遍历的每一块
（单线程时是整遍）累加进自己的部分结果，这一遍结束时按行的顺序合并部分结果并替换 `T`：就是 OpenMP 的 `reduction`、MPI 的 `Allreduce`。

- **适合：** 存活的单位数、一种资源的总量、人群的范围：每遍对大量行求一个结果。
- **别用于：** 每个实体各自的结果（写进这一行的组件），以及每个 tick 只有几行会改变的总数（在改这些行的地方更新）。
- **开销：** 每行一次对本块自己的结构体的写入，没有锁也没有原子操作；每块一个 job 副本，合并一次；第一遍之后零分配。整数精确；
  `ChunkRows` 固定时，浮点结果在任何线程数下都相同。[EECS057](/zh/docs/guide/analyzer#eecs057) 拒绝对 `T` 的第二处写入；
  [EECS060](/zh/docs/guide/analyzer#eecs060) 和 [EECS061](/zh/docs/guide/analyzer#eecs061) 报告它所替代的共享计数器和 job 字段。
- **指南：** [多线程与并行](/zh/docs/guide/threading#reductions)

### 并行方法里的临时空间和查找 [#scratch-and-lookups]

另外两个参数让并行 `[ForEach]` 方法保持并行。`Scratch<T>` 是方法在当前线程上的工作内存（OpenMP 的 `threadprivate`）：每个线程只分配一次的
列表或缓冲，这个线程跑的每一行都复用它。`Lookup<T>` 读取任意实体在这一遍之前的组件 `T`（MPI 的单边 `Get`、Unity 的 `ComponentLookup`），
按 id，带索引的 `T` 还能按键。

- **适合：** 一行的候选、边界或缓冲（`Scratch<T>`）；目标的位置、首领、某个键的持有者（`Lookup<T>`）。
- **别用于：** 上限固定的小缓冲（`stackalloc`）；当前行自己的组件（直接作为参数）。
- **开销：** `Scratch<T>` 每块查一次这个线程的值，每个线程第一行之后零分配；`Lookup<T>` 每次读取一次实体查找，单线程时也比 `World` 参数快。
  系统算作读 `T`；[EECS058](/zh/docs/guide/analyzer#eecs058) 不让临时内存进入 World，[EECS059](/zh/docs/guide/analyzer#eecs059)
  不让方法查找自己会写的组件。
- **指南：** [临时空间](/zh/docs/guide/threading#scratch)、[查找](/zh/docs/guide/threading#lookups)

### 遍历产出的记录 [#emit]

`Emit<T>` 参数把记录（命中、声音、消息）追加到所在块自己的列表里，不加锁也不用原子操作；遍历结束时，这些列表按行的顺序并入单例
`Emitted<T>`（Unity 的 `NativeStream`，一种并行追加）。之后的系统处理这些记录并清空它们。

- **适合：** 并行遍历给其他实体或网络产出的东西：要结算的伤害、要发送的事件。
- **别用于：** 每行一个的结果（行自己的组件）或一个总数（[归约](#reductions)）。
- **开销：** 每条记录追加一次到块的池化列表，遍历结束时每个列表拷贝一次；稳定运行时零分配。手工填充的列表由
  [EECS089](/zh/docs/guide/analyzer#eecs089) 报告，读自己记录的遍历由 [EECS070](/zh/docs/guide/analyzer#eecs070) 报告。
- **指南：** [多线程与并行](/zh/docs/guide/threading#emit)

### 确定性随机数 [#entity-random]

`EntityRandom` 是保存种子和 tick 的单例；每个数都是（种子、实体、tick、流）的纯函数，所以并行遍历不管多少线程、行按什么顺序跑，
抽到的数都一样，用同一个种子回放也会重复出来。

- **适合：** 游荡、刷怪判定、掉落、暴击、AI 选择：回放或测试必须重现的随机性。
- **别用于：** 机密（`RandomNumberGenerator`），以及遍历之外没人需要重现的随机性（`Random.Shared`）。
- **开销：** 每个数四轮整数混合，不写任何状态，所以方法仍是只读的，可以并行。`[ForEach]` 方法里的 `System.Random` 由
  [EECS071](/zh/docs/guide/analyzer#eecs071) 报告，同一个流抽两次由 [EECS088](/zh/docs/guide/analyzer#eecs088) 报告。
- **指南：** [多线程与并行](/zh/docs/guide/threading#entity-random)

### 其他数据上的并行循环 [#for-parallel]

`world.ForParallel` 在并行 `[ForEach]` 方法用的执行器上，对不是表中行的数据运行结构体 job：`IForRange` job 遍历一段下标，
`IForSpan<T>` job 遍历 `DynamicBuffer<T>` 的元素（`Emitted<T>` 的记录），每块是一个可写的 span（Kokkos 的 `RangePolicy`）。

- **适合：** 列表或数组上的重活：处理遍历产出的记录、填充网格。
- **别用于：** 实体的行（用并行 `[ForEach]`），以及几千个元素的轻活。
- **开销：** 和并行 `[ForEach]` 一样的分块和辅助线程，每种 job 第一次调用之后零分配；每块一份 job 拷贝
  （调用之后读 job 字段由 [EECS061](/zh/docs/guide/analyzer#eecs061) 报告）。
- **指南：** [多线程与并行](/zh/docs/guide/threading#for-parallel)

### 网格瓦片 [#grid-tiles]

把网格切成瓦片，每个瓦片一个实体，格子存在 `DynamicBuffer<TCell>` 里：`Tile<TCell, TTile>` 参数把瓦片连同邻居的边交给 `[ForEach]` 方法
（模板计算的光环，MPI 的 ghost 格子）。生成器查找邻居、声明读取、让方法保持并行；安静的瓦片会休眠，旁边的边变了再醒来。

- **适合：** 热量、流体、元胞自动机、影响力场、体素光照：格子的下一个值由周围的格子算出。
- **别用于：** 地图上稀疏的物体（用格子的[索引](#value-indexes)），以及一个缓冲就装得下的小网格。
- **开销：** 每个瓦片把自己和光环拷贝一次到线程的纹理里；模板计算改变不了的行直接跳过。误用由
  [EECS059](/zh/docs/guide/analyzer#eecs059)、[EECS072](/zh/docs/guide/analyzer#eecs072) 和 [EECS073](/zh/docs/guide/analyzer#eecs073) 报告。
- **指南：** [网格瓦片](/zh/docs/guide/grids)

### 批量操作 [#bulk-operations]

`world.CreateEntities(span, a, b)` 刷出一波取值相同的实体，`Instantiate(prefab, span)` 按预制体刷一波，`DestroyAll<T>(filter)`
销毁所有匹配的实体。`SetAll`、`RemoveAll`、`DisableAll` 和 `EnableAll` 对所有匹配的实体改同一个组件，每次处理整个 64 行位字。

- **适合：** 一波怪物、清空一个场景、回合重置、给所有人解除一个状态。
- **开销：** 每次调用只过一次结构闸门，表最多扩容一次。
- **指南：** [批量操作](/zh/docs/guide/bulk)

## 构建与运维 [#operate]

让代码库在增长中保持正确、让运行中的服务器可观测的那部分功能。

### 分析器与代码修复 [#analyzer]

包里在生成器旁边附带了分析器（EECS002 到 EECS089）和代码修复。不合法的 `[ForEach]` 方法、类组件、有状态的系统、引用系统的系统、
经 `in` 的写入、可能竞争的并行方法、跨线程的结构变更、经 `ref` 写入的被索引组件、成环的排序，都会编译失败；还有几条警告标出能跑但有代价的写法。

- **适合：** 一直开着；默认就是开的，它让系统保持解耦。
- **指南：** [分析器规则](/zh/docs/guide/analyzer)

### 系统耗时统计 [#per-system-timing]

打开 `WorldOptions.MeasureSystems` 后，系统的每次执行都会被统计：`system.Stats` 里有 `Runs`、`LastTime`、`TotalTime` 和 `AverageTime`，
这次执行分配的字节数（`LastAllocated`、`TotalAllocated`，包括它的并行 `[ForEach]` 方法在辅助线程上的分配），以及它的 `[ForEach]`
方法访问的实体数（`LastEntities`、`TotalEntities`）。

- **适合：** 在线服务器上的诊断接口、指标导出或日志，看哪个系统越来越慢、哪个在分配内存、耗时是不是跟着实体数涨。
- **开销：** 打开时每次执行读两次时间戳、两次分配计数，每个 `[ForEach]` 遍历再数一次匹配数；关闭时没有开销。
- **指南：** [调试与诊断](/zh/docs/guide/diagnostics#timing)、[系统](/zh/docs/guide/systems#measuring-systems)

### 调度 [#schedule]

`world.DescribeSchedule()` 描述 World 怎样运行它的系统：每个分组有哪些阶段，每个系统读写什么，某个系统为什么要等前一个阶段，
以及哪些冲突的系统之间只靠注册顺序分先后。`ToString()` 输出文本，`ToMermaid()` 输出流程图。

- **适合：** 启动时打一行日志；排查两个系统为什么没有并行；找出需要用 `[UpdateBefore<T>]` / `[UpdateAfter<T>]` 写明顺序的系统对。
- **开销：** 冷调用，会为描述分配内存；任何线程都能调用。
- **指南：** [调试与诊断](/zh/docs/guide/diagnostics)

### 异常处理 [#errors]

默认情况下，系统抛出的异常会传出 `Update()`。设置 `WorldOptions.SystemErrors = SystemErrorPolicy.Disable` 后，出错的系统会停用，
异常保存在 `system.Error` 里，更新继续执行；把 `Enabled` 设回 `true` 就会重试。

- **适合：** 在线服务器用 `Disable`，故障变成健康检查能读到的数据；测试里用 `Throw`。
- **开销：** 系统不抛异常就没有开销。
- **指南：** [调试与诊断](/zh/docs/guide/diagnostics#errors)、[系统](/zh/docs/guide/systems#errors)

### 运行时自省 [#introspection]

`world.DescribeTables()` 列出所有表及其列、行数、容量和字节数；`entity.Describe()` 列出一个实体的组件值。调试器里能直接看到实体的组件。

- **适合：** 管理后台、内存报告、调试。
- **开销：** 生成描述时分配内存（冷路径），不碰热路径。
- **指南：** [调试与诊断](/zh/docs/guide/diagnostics)

### 归还内存 [#trim-excess]

表满了就翻倍，之后容量一直保留，所以峰值占的内存不会自己回来。`world.TrimExcess()` 把它还回去：删掉空表，把其他表缩到行数向上取整的 2 的幂
（至少 64），并释放存档、读档和迁移用的缓冲。句柄、查询、系统、索引和快照照常可用。

- **适合：** 峰值过后的空闲时刻：一波怪清完、一局对战结束、`world.EntityCount` 远低于峰值时的维护任务。
- **别用于：** 每个 tick 调用：它删掉的东西，之后的结构变更又要重新分配。
- **开销：** O(表数 × (缓存的查询数 + 快照数) + 被缩小的表的行数 × 列数)；会分配内存（冷路径）。实体记录的长度不变。
- **指南：** [调试与诊断](/zh/docs/guide/diagnostics)

### Native AOT [#native-aot]

系统、job 和过滤条件都在编译期生成，热路径上没有反射。库本身开着裁剪和 AOT 分析器构建，所以 `<PublishAot>true</PublishAot>`
之外，EasyEcs 不需要任何额外配置。

- **适合：** 体积小、启动快的服务器容器。

### 托管与测试 [#hosting-and-testing]

World 跑在 ASP.NET Core 应用或 Worker Service 里，由一个托管服务独占：它创建 World、驱动 tick、从 channel 接收请求、停机时存盘。
测试一个系统就给它一个自己的 World：准备实体和单例，调用 `world.Update()`，断言数据。

- **适合：** 每个真实的服务器、每个系统。
- **开销：** EasyEcs 这边没有：不需要托管包或测试包，这个模式就是你自己的几个类。
- **指南：** [托管](/zh/docs/guide/hosting)、[测试系统](/zh/docs/guide/testing)

### 模板与示例程序 [#templates]

`dotnet new easyecs` 创建一个按固定 tick 运行的控制台服务器：`Components/`、每个系统一个文件的 `Systems/`（其中有一个
用预制体刷怪的系统），`Program.cs` 只负责托管 World（加 `--tests` 多一个 NUnit 项目，每个系统一个测试文件）；
`dotnet new easyecs-system` 添加一个系统。[示例](/zh/docs/samples)按学习顺序收录完整程序；指南里
[变更追踪](/zh/docs/guide/change-tracking#full-example)等功能页的“怎么用”部分最后都有一个完整例子。

- **指南：** [快速开始](/zh/docs/getting-started)、[项目结构](/zh/docs/guide/project-structure)、[示例](/zh/docs/samples)
