The smallest complete EasyEcs program, and the place to start: two entities that move, a tag that marks one of them
as a player, a clock that counts the ticks, and three systems with one job each. Every code block on this page is
included from [`samples/HelloWorld`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/HelloWorld),
which CI builds and runs, comparing its output with the one shown below.

## Run it [#run-it]

```bash
dotnet run --project samples/HelloWorld
```

## The data [#data]

Components are plain data: fields and no logic. `Position` and `Velocity` are on both entities; `Player`, a
component with no fields, is a [tag](/en/docs/guide/entities-and-components#tags) that systems filter on; `Clock` is
a [singleton](/en/docs/guide/singletons), one value per world.

<include lang="csharp" meta='title="Components.cs"'>../../../samples/HelloWorld/Components.cs</include>

## The systems [#systems]

[Systems](/en/docs/guide/systems) have one job each and no state of their own. A `[ForEach]` method runs once per
entity that has its component parameters, `ref` for what it writes and `in` for what it reads. `MoveSystem` moves
every entity with a position and a velocity, `ReportSystem` prints the players only (`[With<Player>]` is a
[filter](/en/docs/guide/queries#filters)), and `ClockSystem` advances the clock once per update in `[OnUpdate]`, not
once per entity.

<include lang="csharp" meta='title="Systems.cs"'>../../../samples/HelloWorld/Systems.cs</include>

## The program [#program]

Create the world, add the singleton and the systems, create two entities, run three updates. `world.Update()` runs
every system once, in the order they were added.

<include lang="csharp" meta='title="Program.cs"'>../../../samples/HelloWorld/Program.cs</include>

## Output [#output]

```text
tick 0: player at (1, 2)
tick 1: player at (2, 4)
tick 2: player at (3, 6)
2 entities after 3 ticks
```

`ReportSystem` runs before `ClockSystem`, so the first update prints tick 0. The second entity moves too, but it has
no `Player` tag, so it is never printed.
