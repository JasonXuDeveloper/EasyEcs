在 Godot 4 .NET 项目里用 EasyEcs：场景的根节点持有一个 World，每个物理 tick 更新一次，用一个 multimesh 画出所有实体。一千个点
在场地里移动，碰到边缘就反弹。本页所有代码都直接引用自
[`samples/Godot`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/Godot)，CI 用 Godot 4.7.2 无窗口构建并运行
它，把输出和下面给出的对比。建议先读 [HelloWorld](/zh/docs/samples/hello-world) 示例。

## 运行 [#run-it]

用 Godot 4 编辑器（.NET 版）打开这个目录，点运行；或者不开窗口直接跑：

```bash
dotnet build samples/Godot
godot --headless --path samples/Godot -- --ticks 120
```

## 项目 [#project]

就是普通的 Godot 4 .NET 项目：[`project.godot`](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/samples/Godot/project.godot)
和场景 [`Main.tscn`](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/samples/Godot/Main.tscn)，根节点是 `Main`。
真正要改的只有目标框架这一行：Godot 把 C# 项目的程序集加载进项目指定的 .NET 运行时。旧版编辑器建的项目写的是 `net8.0`，
改成 `net10.0` 并装好 .NET 10 SDK 即可（[Unity 和 Godot](/zh/docs/faq#unity-godot)）。别的都不用配：包里的生成器和分析器在
`dotnet build` 和编辑器的构建里一样运行。

## 节点 [#node]

节点是宿主，系统才是游戏。`Main` 只在 Godot 和 World 之间搬数据：在 `_Ready` 里创建 World 和实体，在 `_PhysicsProcess`
（Godot 的固定 tick）里调用 `world.Update()`，在 `_ExitTree` 里释放自己创建的东西（[托管 World](/zh/docs/guide/hosting#owner)）。
每次更新后，它把所有位置拷进一个 float 缓冲，交给 `RenderingServer.MultimeshSetBuffer`：所有实体一次绘制，不用每个实体一个节点。`--ticks` 参数和 CI 检查的报告在
[`Support.cs`](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/samples/Godot/Support.cs) 里：这是周边代码，不是本课重点。

## 输出 [#output]

```text
120 ticks, 1000 entities, 1000 inside the arena
updates after the first allocated 0 B
```

第一次更新会建好查询缓存；之后每个 tick 都不分配内存，在 Godot 里和在服务端一样。CI 在 Linux 上跑这个示例；Godot 导出到其他平台
（Android、iOS）时用的是 Godot 自带的运行时，这里没有测试。
