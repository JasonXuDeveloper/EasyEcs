一个小型游戏服务器：客户端在另一个线程，模拟按固定 30 Hz 跑 tick，只同步变化的数据。十六个假客户端在三秒的游戏时间里加入、移动、开火、离开。
本页的代码块全部引自 [`samples/GameLoop`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/GameLoop)，
CI 会构建并运行它。建议先读 [HelloWorld](/zh/docs/samples/hello-world)。

## 运行 [#run-it]

```bash
dotnet run --project samples/GameLoop                   # 3 秒（90 个 tick）
dotnet run --project samples/GameLoop -- --ticks 30     # 1 秒
```

## 数据 [#data]

请求是输入，每种一个组件；然后是模拟状态、单例和两个[系统分组](/zh/docs/guide/systems#system-groups)。`Client` 是
[值索引](/zh/docs/guide/indexes-and-relations#value-indexes)（`IIndexed<int>`），`world.ClientIndex` 按客户端 id 找玩家；`Position`
是 `ITracked`，同步才能只访问动过的实体；单例 `Prefabs` 存着玩家和子弹的[预制体](/zh/docs/guide/prefabs)。

<include lang="csharp" meta='title="Components.cs"'>../../../samples/GameLoop/Components.cs</include>

## 输入 [#input]

输入就是数据：网络线程把消息投进邮箱，`ReceiveInputSystem` 把每条消息变成一个请求实体
（[来自其他线程的输入](/zh/docs/guide/threading#input-from-other-threads)）。它在 `InputGroup` 里，所以宿主每次唤醒都跑它，不只在 tick 上。
邮箱是宿主给它的 `readonly` 字段：它是系统连到网络的通道，不是 World 状态。

<include lang="csharp" meta='title="Systems/Input.cs"'>../../../samples/GameLoop/Systems/Input.cs</include>

## 请求 [#requests]

每种请求一个系统。各自用 `world.ClientIndex.TryFind` 找到玩家并处理；`[Consume]` 在遍历结束时销毁这次遍历到的请求，所以一个请求只活一个 tick。加入和开火用每个实例各自的值
实例化 `prefabs.Player` 和 `prefabs.Bullet`，每个只拷贝一行。

<include lang="csharp" meta='title="Systems/Requests.cs"'>../../../samples/GameLoop/Systems/Requests.cs</include>

## 模拟 [#simulation]

按一个固定步长移动，子弹到期消失，时钟前进。`MovementSystem` 通过 [`Mut<Position>`](/zh/docs/guide/change-tracking#set-if-changed)
写入：`SetIfChanged` 只给真正变了的位置打 tick，站着不动的玩家不会被同步。

<include lang="csharp" meta='title="Systems/Simulation.cs"'>../../../samples/GameLoop/Systems/Simulation.cs</include>

## 同步 [#replication]

[变更追踪](/zh/docs/guide/change-tracking)：`[Changed<Position>]` 跳过系统上次运行以来没动的实体；动了的每个往发件箱写 16 字节，
由宿主发出并清空。

<include lang="csharp" meta='title="Systems/Replication.cs"'>../../../samples/GameLoop/Systems/Replication.cs</include>

## 程序 [#program]

先设单例，再按分组加系统，然后是主循环：每次唤醒处理输入，到点跑一个模拟 tick，每三个 tick 同步一次。`--ticks N` 决定跑多久，Ctrl+C 干净退出，
[`WorldOptions.MeasureSystems`](/zh/docs/guide/diagnostics#timing) 给出报告里每个系统的运行次数和耗时。邮箱、假客户端、
固定 tick 计时器、网络和报告都在 [`Host/`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/GameLoop/Host)：
是必要的管道代码，不是本课重点。

## 输出 [#output]

用 `-c Release -- --ticks 30` 运行。假客户端用固定种子，除时序带来的差异外，每次的计数都相同；耗时随机器而变。
所有检查通过时进程返回 0，否则返回 1。

```text
t=1s players=16 bullets=59 entities=75
30 ticks in 1.0 s
  220 messages (0 refused)
  34 joins, 18 leaves
  59 bullets fired
  378 position updates replicated (5.9 KB)
  LeaveSystem             30 runs,      4.7 us last run
  JoinSystem              30 runs,      2.2 us last run
  MoveSystem              30 runs,      6.9 us last run
  FireSystem              30 runs,     71.0 us last run
  MovementSystem          30 runs,      4.7 us last run
  LifetimeSystem          30 runs,      4.7 us last run
  ClockSystem             30 runs,      0.8 us last run
  ReceiveInputSystem     252 runs,      0.4 us last run
  ReplicationSystem       10 runs,     15.1 us last run
  ok   players have the prefab's components and their client id
  ok   bullets have the prefab's components and their lifetime
  ok   no client has two players
  ok   the mailbox refused no message
stopped
```

`ReceiveInputSystem` 跑的次数远多于 tick：等下一个 tick 时，循环每次醒来都会清空邮箱；`ReplicationSystem` 则每三个 tick 跑一次。
