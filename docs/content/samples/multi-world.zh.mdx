服务器常把游戏拆成互不共享的区（地图、房间、对局），每个区一个 World，各占一个线程。这里每个区都是同一个小游戏，
2 万个单位；有几个处理器就开几个区，同时更新。本页每段代码都直接引用自
[`samples/MultiWorld`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/MultiWorld)，CI 会构建并运行它。

## 你会学到 [#what-you-learn]

- **World 归一个线程所有**：哪个线程建的 World，就由它更新、由它释放；不加锁，也不共享
  （[每个线程一个 World](/zh/docs/guide/threading#recommended-one-world-per-thread)）。
- **单例按 World 隔离**：每个区的 `Tally` 只统计自己 World 里的死亡数（[单例](/zh/docs/guide/singletons)）。
- **一次创建大量实体**：`world.CreateEntities(units, …)` 一次调用填满一个句柄数组
  （[结构变更](/zh/docs/guide/structural-changes)）。
- **一个系统只做一件事**：移动、扣血、复活，各是一个 `[ForEach]` 方法（[系统](/zh/docs/guide/systems)）。

## 运行 [#run-it]

```bash
dotnet run -c Release --project samples/MultiWorld                    # 每个区更新 1000 次
dotnet run -c Release --project samples/MultiWorld -- --updates 200
```

## 输出 [#output]

4 核机器上的一次运行。死亡数每次都一样；耗时和吞吐量取决于机器。

```text
zone  0: 20,000 units,  51,430 deaths,  169.3 ms
zone  1: 20,000 units,  51,428 deaths,  188.4 ms
zone  2: 20,000 units,  51,429 deaths,  165.6 ms
zone  3: 20,000 units,  51,426 deaths,  150.6 ms
4 worlds on 4 threads, 80,000 units, 1000 updates each
253 ms, 316.2 M entity-updates/s
```

各区只有初始方向不同，所以死亡数差几个；整次运行的耗时接近单个区的耗时，因为各区是并排跑的。这只是演示，不是测量：
CI 运行它但不比对输出，性能数字以 BenchmarkDotNet 套件为准（`MultiWorldBenchmark`，见[性能指南](/zh/docs/performance)）。
