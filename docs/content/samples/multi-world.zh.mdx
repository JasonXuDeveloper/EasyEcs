服务器常把地图拆成多个区，每个区一个 World，各占一个线程：每个核都在跑，互不共享，不用锁。但地图有边界，站在边界旁的单位
仍要看得到边界另一侧的单位。这里四个区沿一条长带并排，共 8,000 个单位。两次更新之间，各区交换边界上的行：离边界在视野以内的
单位，作为只读的**幽灵行**复制进相邻的区；走过边界的单位，迁到它现在所在的区。最后程序把同一张地图当作一个 World 再跑一遍，
检查各区数出的目击次数和它相同。本页每段代码都直接引用自
[`samples/MultiWorld`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/MultiWorld)，CI 会构建并运行它。

<Callout type="info" title="幽灵行与光环">
  这个做法来自把网格分给多个进程的 MPI 程序：每个进程保存一份邻居边缘格子的副本（**幽灵格子**，即**光环**），在两步之间通过
  **光环交换**刷新。幽灵行就是实体版的幽灵格子：邻居的一行的副本，在这里只读，只有它的所有者写它。
</Callout>

## 运行 [#run-it]

```bash
dotnet run -c Release --project samples/MultiWorld                    # 更新 200 次
dotnet run -c Release --project samples/MultiWorld -- --updates 50
```

## 数据 [#data]

单位是一个 `Position` 加一个 `Velocity`。幽灵只有一个 `Position` 和 `Ghost` 标签：它带着邻居要读的数据，没有 `Velocity`，
所以移动单位的系统永远不会写它。区的 `Tally` [单例](/zh/docs/guide/singletons)只统计自己 World 里的目击次数。

## 系统 [#systems]

`SightSystem` 为区里每个单位数出视野以内的单位。它是一个邻居对方法：`[Neighbor]` 参数让生成器按距离判断写出邻居搜索，
邻居是所有带 `Position` 的实体，所以幽灵和区里自己的单位一样被看到。`[Without<Ghost>]` 让幽灵不去看：幽灵看到的，由拥有它的区去数。
`MoveSystem` 和 `BounceSystem` 只读写有 `Velocity` 的单位。每个[系统](/zh/docs/guide/systems)只做一件事，不知道区的存在，
所以同样三个系统用在每个区，也用在整张地图的那个 World。

## 地图和一个区 [#zone]

`Map` 说明各区的位置和每个单位的起点。`Zone.Create` 用三个系统建一个区的 World，视野系统排在最前，读的是上次交换留下的数据；
`Zone.Run` 更新它，每次更新后在交换处等待。两次交换之间只有它的线程碰这个 World
（[每个线程一个 World](/zh/docs/guide/threading#recommended-one-world-per-thread)）。

## 边界 [#border]

`Border.Exchange` 在所有区都等待时运行，所以运行它的那一个线程可以碰每个 World；它是宿主代码，因为系统属于一个 World，
而边界属于两个。它先丢掉上次的幽灵（`DestroyAll<Ghost>`），再用 [`MoveEntities`](/zh/docs/guide/migration-and-unload#move-entities)
把越过边界的单位迁到它所在的区（所有组件一起走），最后把离边界在视野以内的单位作为幽灵复制进相邻的区。每次交换的幽灵都是新实体：
可以记住幽灵的位置，不要记住它的 id。

<include lang="csharp" meta='title="Border.cs"'>../../../samples/MultiWorld/Border.cs</include>

## 程序 [#program]

每个区一个线程。`Barrier`（屏障）在每次更新后拦住它们，由最后到达的线程运行交换，再放它们继续。主线程等它们结束，
打印每个区，然后把地图当作一个 World 跑一遍。

## 输出 [#output]

每次运行、每台机器都一样：各区和一个 World 数出的目击次数相同，不同时进程以 1 退出。

```text
zone 0: 1,803 units,  79 ghosts,   357 arrivals,  3,377,596 sightings
zone 1: 1,999 units, 158 ghosts,   915 arrivals,  3,795,928 sightings
zone 2: 1,998 units, 161 ghosts,   914 arrivals,  3,806,712 sightings
zone 3: 2,200 units,  81 ghosts,   558 arrivals,  4,163,422 sightings
4 zones on 4 threads: 15,143,658 sightings in 200 updates
one world:            15,143,658 sightings
the zones saw what one world sees
```

中间两个区有两条边界，幽灵大约是两端的两倍。没有幽灵，各区会漏掉跨边界的目击，最后一行就会说出来。这只是演示，不是测量：
并排的多个 World 有多快，以 BenchmarkDotNet 套件为准（`MultiWorldBenchmark`，见[性能指南](/zh/docs/performance)）。
