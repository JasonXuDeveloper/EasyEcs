游戏逻辑放在插件里的服务器：宿主把插件加载进可回收的 `AssemblyLoadContext`，运行它，把它的类型移出 World，卸载，
再重新加载；这期间宿主自己的实体和系统一直在跑，插件的组件值在重载后也还在。本页每段代码都直接引用自
[`samples/HotReload`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/HotReload)，CI 会构建并运行它，
并把输出和下面的结果比对。

## 你会学到 [#what-you-learn]

- **逻辑放进可回收插件**：插件的系统、组件和单例都在一个程序集里，宿主把它加载进可回收的 `AssemblyLoadContext`。
- **干净地卸载**：`world.RemoveTypes(assembly)` 把插件的系统、组件和单例移出 World，World 里不再有东西引用插件，
  它的上下文就能被回收（[卸载插件的类型](/zh/docs/guide/migration-and-unload#remove-types)）。
- **保住数据**：卸载前存档、重载后读档，插件的组件值就带过来了。存档按类型全名的哈希记录类型，与加载它的程序集无关
  （[热重载](/zh/docs/guide/migration-and-unload#hot-reload)、[存档](/zh/docs/guide/saves)）。
- **批量变更**：`World.SetAll` 一次调用给整张表的单位加上组件（[批量操作](/zh/docs/guide/bulk)）。

## 运行 [#run-it]

```bash
dotnet run --project samples/HotReload/HotReload.Host
```

插件项目随宿主一起构建，并复制到宿主的 `plugins/` 目录。

## 输出 [#output]

所有检查通过时进程返回 0，否则返回 1。

```text
plugin loaded, 3 updates: 300 points, 3 systems
  ok   the plugin's context was collected: nothing in the world roots it
  ok   its systems left, the host's stayed
  ok   the host's entities and components stayed
plugin reloaded, 2 more updates: 500 points, 3 systems
  ok   the scores carried over the reload (3 + 2 updates of 100 units)
all checks passed
```

重载后的 500 分，是 100 个单位先得 3 次分、再得 2 次分：分数从存档里回来了；第一个上下文已被回收，而宿主的 100 个
单位和它的 `MoveSystem` 一直留在 World 里。
