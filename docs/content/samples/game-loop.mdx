A small game server: clients on another thread, a fixed 30 Hz simulation tick, and replication of only what changed.
Sixteen fake clients join, move, fire and leave for three seconds of game time. Every code block on this page is included
from [`samples/GameLoop`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/GameLoop), which CI builds
and runs. Read [HelloWorld](/en/docs/samples/hello-world) first.

## Run it [#run-it]

```bash
dotnet run --project samples/GameLoop                   # 3 seconds (90 ticks)
dotnet run --project samples/GameLoop -- --ticks 30     # 1 second
```

## The data [#data]

Requests are the input, one component per kind; then the simulation state, the singletons and the two
[system groups](/en/docs/guide/systems#system-groups). `Client` is a
[value index](/en/docs/guide/indexes-and-relations#value-indexes) (`IIndexed<int>`), so `world.ClientIndex` finds a
player by client id; `Position` is `ITracked`, so replication can visit only what moved; the `Prefabs` singleton
holds the [prefabs](/en/docs/guide/prefabs) of a player and a bullet.

<include lang="csharp" meta='title="Components.cs"'>../../../samples/GameLoop/Components.cs</include>

## Input [#input]

Input is data: the network thread posts messages to a mailbox, and `ReceiveInputSystem` turns each one into a
request entity ([input from other threads](/en/docs/guide/threading#input-from-other-threads)). The system is in
`InputGroup`, so the host runs it on every wake-up, not only on ticks. The mailbox is a `readonly` field the host
gives it: the system's connection to the network, not world state.

<include lang="csharp" meta='title="Systems/Input.cs"'>../../../samples/GameLoop/Systems/Input.cs</include>

## Requests [#requests]

One system per kind of request. Each finds the player with `world.ClientIndex.TryFind`, acts, and destroys the
request: a request lives for one tick. Joins and shots instantiate `prefabs.Player` and `prefabs.Bullet` with the
values that differ per instance, one row copy each.

<include lang="csharp" meta='title="Systems/Requests.cs"'>../../../samples/GameLoop/Systems/Requests.cs</include>

## The simulation [#simulation]

Movement over one fixed step, bullets that expire, and the clock. `MovementSystem` writes through
[`Mut<Position>`](/en/docs/guide/change-tracking#set-if-changed): `SetIfChanged` stamps only a position that changed,
so a player standing still is not replicated.

<include lang="csharp" meta='title="Systems/Simulation.cs"'>../../../samples/GameLoop/Systems/Simulation.cs</include>

## Replication [#replication]

[Change tracking](/en/docs/guide/change-tracking): `[Changed<Position>]` skips the entities that did not move since
the system last ran; each one that did writes 16 bytes into the outbox, which the host sends and clears.

<include lang="csharp" meta='title="Systems/Replication.cs"'>../../../samples/GameLoop/Systems/Replication.cs</include>

## The program [#program]

The singletons first, then the systems by group, then the loop: input on every wake-up, a simulation tick when one is
due, replication every third tick. `--ticks N` sets the length of the run, Ctrl+C stops it cleanly, and
[`WorldOptions.MeasureSystems`](/en/docs/guide/diagnostics#timing) gives the per-system run counts and times of the
report. The mailbox, the fake clients, the fixed-tick timer, the network and the report
are in [`Host/`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/GameLoop/Host): plumbing, not the
lesson.

## Output [#output]

With `-c Release -- --ticks 30`. The fake clients use a fixed seed, so the counts are the same from run to run up to
timing; the times vary with the machine. The process exits with 0 when every check passes and with 1 otherwise.

```text
t=1s players=16 bullets=59 entities=75
30 ticks in 1.0 s
  220 messages (0 refused)
  34 joins, 18 leaves
  59 bullets fired
  378 position updates replicated (5.9 KB)
  LeaveSystem             30 runs,      4.7 us last run
  JoinSystem              30 runs,      2.2 us last run
  MoveSystem              30 runs,      6.9 us last run
  FireSystem              30 runs,     71.0 us last run
  MovementSystem          30 runs,      4.7 us last run
  LifetimeSystem          30 runs,      4.7 us last run
  ClockSystem             30 runs,      0.8 us last run
  ReceiveInputSystem     252 runs,      0.4 us last run
  ReplicationSystem       10 runs,     15.1 us last run
  ok   players have the prefab's components and their client id
  ok   bullets have the prefab's components and their lifetime
  ok   no client has two players
  ok   the mailbox refused no message
stopped
```

`ReceiveInputSystem` runs far more often than the tick: the loop drains the mailbox every time it wakes up while it
waits for the next tick, and `ReplicationSystem` runs once every three ticks.
