在 ECS World 上实现 Actor：实体按键接收消息，每类 Actor 有自己的系统，第一次用到时从存储加载，只在变化后保存。商店卖完就关门，
银行按时付利息。本页所有代码都直接引用自
[`samples/Actors`](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/Actors)，CI 会构建并运行它，把输出和下面
给出的对比。建议先读 [GameLoop](/zh/docs/samples/game-loop) 和 [SaveLoad](/zh/docs/samples/save-load) 两个示例。

## 运行 [#run-it]

```bash
dotnet run --project samples/Actors
```

## 数据 [#data]

一类 Actor 就是一个类型，靠一个接口同时承担三件事：`Shop` 和 `Bank` 实现 `IActor<TSelf>`，于是同时是 Actor 的键组件
（[值索引](/zh/docs/guide/indexes-and-relations#value-indexes)）、这一类的[系统分组](/zh/docs/guide/systems#system-groups)，
以及这个分组的[过滤条件](/zh/docs/guide/systems#group-filters)（`ISystemGroupWith<In<Shop>>`）：特性写不出类型参数，接口替每一类
声明一次过滤条件。键用显式接口实现（`Shop IIndexed<Shop>.Key => this;`）：record struct 上
如果有公开的 `Key => this` 属性，`ToString()` 会无限打印 `Key`。`Stock` 和 `Balance` 要持久化，都是 `ITracked`（[变更追踪](/zh/docs/guide/change-tracking)）；`Sales` 和 `Closed` 只在内存里。

## 消息 [#messages]

一条消息就是一个实体上的任务：`Buy` 和 `Deposit` 是任务，`Mailman` 在索引里按键找到 Actor，用
[`entity.Run(ref job, filter)`](/zh/docs/guide/queries#run-on-one-entity) 在它身上跑任务：一次查找拿到任务要的全部组件，用
`static readonly` 过滤条件拒绝已关门的商店。卖掉最后一件的 `Buy` 会在任务中途加上 `Closed`：这是一次结构变更，任务里的 ref
仍然指向商店的值。`Mailman` 先读库存再跑 `Buy`：任务一运行，它的 `WriteMask`
就会给 `Stock` 打 tick，被拒绝的订单如果也跑了任务，下一次保存就会把没变的商店再存一遍。

## 每类 Actor 的系统 [#systems]

每个系统属于它那一类的分组，所以 `world.Update<Shop>()` 只在商店上跑商店的系统。`InterestSystem` 通过
[`Mut<Balance>`](/zh/docs/guide/change-tracking#set-if-changed) 写入：`SetIfChanged` 只给真正增长了的余额打 tick。

## 保存变过的 [#saving]

保存分组只有一个系统，覆盖所有种类的 Actor。它的 `[Changed<T>]` 方法选出它上次运行后被写过的行，所以每次运行列出的是上次保存后
被写过的 Actor，它自己的运行就是标记。保存记录会改写表，遍历期间不允许（[EECS041](/zh/docs/guide/analyzer#eecs041)），所以
系统把 Actor 记进 `Unsaved` 单例，由宿主在 `world.Update<Saving>()` 之后保存。

## 激活 [#activation]

`Activate` 返回已激活的 Actor；没有就用这一类的预制体创建一个，再用 `LoadEntitiesInto(..., markWritten: false)` 把它的
[记录](/zh/docs/guide/migration-and-unload#records)（持久化组件的 `ComponentSet`）加载上去，加载不算变更。新 Actor 没有记录，默认值就是它的初始状态，
下一次保存会写下它们。

## 输出 [#output]

```text
activated: shop 1 has 2, shop 2 (new) has 5, bank 7 has 1000
saved after activation: 1
buy 1 at shop 1: sold, 1 left, closed: False
buy 1 at shop 1: sold, 0 left, closed: True
buy 1 at shop 1: refused, 0 left, closed: True
deposit 50 at bank 7: True
deposit 50 at bank 8: False
after the updates: shop 1 has 3 (sold 2), bank 7 has 1060
saved after the messages: 2
restarted: shop 1 has 3 (sold 0), bank 7 has 1060
```

激活后只保存了新商店：用 `markWritten: false` 加载的两条记录不算变更。第三笔订单在任务运行前就被拒绝（商店在第二笔后卖完并关门），
银行 8 从未激活。发完消息后保存了商店 1 和银行 7；商店 2 激活后已经保存过，之后没人写它，所以不再保存。重启后商店保留了存下的库存，但销量归零：`Sales` 只在内存里。
