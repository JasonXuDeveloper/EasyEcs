[Friflo.Engine.ECS](https://github.com/friflo/Friflo.Engine.ECS) is the closest peer of EasyEcs: both are archetype
ECS libraries that allocate nothing per server tick, both have tags, indexed components, relations and a hierarchy,
and on the headline tick they are close. The differences are in the model. Friflo
iterates chunks of a cached query and records structural changes in a command buffer; EasyEcs generates struct jobs
from `[ForEach]` methods, applies changes immediately, keeps removed components' rows with presence bits, and tracks
changes and removals as data instead of events.

In the <FeatureCount library="Friflo" k="total" /> head-to-head benchmarks both libraries take part in, EasyEcs is faster in
<FeatureCount library="Friflo" k="ahead" />, within the measurement error in <FeatureCount library="Friflo" k="even" /> and slower in <FeatureCount library="Friflo" k="slower" />.
On the same server tick of 100,000 entities, Friflo takes <BenchValue k="peers.friflo.ratio" /> the time of EasyEcs
(<BenchValue k="peers.friflo10k.ratio" /> at 10,000), and neither allocates per tick. Friflo also runs in Unity and on
older .NET (netstandard2.1, net6.0-8.0); EasyEcs needs .NET 10.

## At a glance [#at-a-glance]

| | EasyEcs | Friflo.Engine.ECS |
| --- | --- | --- |
| Storage | archetype tables, presence bits per column | archetypes |
| Changes during a query | applied at once | `StructuralChangeException`; recorded in a `CommandBuffer` |
| Removing a component or a tag | flips a bit, the entity keeps its row | moves the entity to another archetype |
| Systems | `EcsSystem` with generated `[ForEach]` jobs | `SystemRoot`, `SystemGroup`, `QuerySystem` |
| Change tracking | `[Changed<T>]`: rows written since the last run | none (component events) |
| Removal tracking | `[Removed<T>]` | `OnComponentRemoved` events |
| Saves | binary `Save` / `Load`, in-memory snapshots | JSON (`EntitySerializer`) |
| Compile-time checks | analyzer EECS002-EECS056 with code fixes | none |
| Runtimes | net10.0 | netstandard2.1, net6.0-8.0; Unity |

## Concepts side by side [#concepts]

| Concept | Friflo.Engine.ECS | EasyEcs |
| --- | --- | --- |
| World | `new EntityStore()` | `new World()` |
| Component | `struct X : IComponent` | `struct X : IComponent` (namespace `EasyEcs`) |
| Tag | `struct Dead : ITag`, `AddTag<Dead>()` | `struct Dead : IComponent` (empty), `entity.SetDead()` |
| Singleton | `UniqueEntity` | `ISingletonComponent`, `world.AddSingleton<T>()` |
| Create | `store.CreateEntity(a, b)` | `world.CreateEntity(a, b)` |
| Reserve before creating | `store.EnsureCapacity(n)`, `archetype.EnsureCapacity(n)` | `world.Reserve<A, B>(n)` |
| Create many | `archetype.CreateEntity()` per entity, `CreateEntityBatch` | `world.CreateEntities(span, a, b)` |
| Read, write | `entity.GetComponent<T>()` (ref) | `entity.Hp` (ref, generated), `entity.Get<T>()` in generic code |
| Add, remove | `entity.AddComponent(c)`, `RemoveComponent<T>()` | `entity.SetHp(…)`, `entity.RemoveHp()` |
| Destroy | `entity.DeleteEntity()` | `entity.Destroy()`, `world.DestroyAll<T>(filter)` |
| Query | `store.Query<A, B>().WithoutAnyTags(Tags.Get<Dead>())` | `[ForEach, Without<Dead>]`; `QueryFilter.Create().Without<Dead>()` |
| Iterate | `foreach (var (as, bs, entities) in query.Chunks)` + `Span` loops | a `[ForEach]` method, or a batch method taking `Span<T>` |
| Entity per row | `query.ForEachEntity((ref A a, Entity e) => ...)` | an `Entity` parameter of a `[ForEach]` method |
| Command buffer | `store.GetCommandBuffer()`, `Playback()` | none: changes apply at once |
| Bulk change | `EntityBatch`, `query.Entities.ApplyBatch(batch)` | `world.SetAll(value, filter)`, `RemoveAll<T>(filter)` |
| Prefab | an entity of the store, `store.CloneEntity(e)` | `Prefab`, `world.Instantiate(prefab, span)` |
| Disable | `entity.Enabled = false` | a tag and `[Without<T>]`, or `entity.Disable<T>()` |
| Indexed component | `IIndexedComponent<TKey>`, `store.ComponentIndex<T, TKey>()[key]`, `ValueInRange` | `IIndexed<TKey>`, `world.Index<T, TKey>().Find(key)`, ordered `Range` |
| Link to an entity | `ILinkComponent`, `GetIncomingLinks<T>()` | an `EntityId` key (`IIndexed<EntityId>`), `index.Find(target)` |
| Many links | `ILinkRelation`, `AddRelation`, `GetRelations<T>()` | `IRelation`, `entity.Link`, `world.Relations<T>()` |
| Hierarchy | `AddChild`, `ChildEntities` | `ChildOf(parent)`, `world.Children(parent)`, cascading destroy |
| Removal callback | `store.OnComponentRemoved += ...` | `[Removed<T>]` (no callback) |
| Parallel query | `store.JobRunner = new ParallelJobRunner(n)`, `QueryJob.RunParallel()` | `[ForEach(Parallel = true)]` |
| Save | `EntitySerializer.WriteStore` / `ReadIntoStore` (JSON) | `world.Save(writer)` / `world.Load(bytes)` (binary) |

## The same task in both [#same-task]

The death check of the headline tick: units whose health ran out get a `Dead` tag and are counted. Friflo cannot add
the tag while its query iterates, so the port records it and plays the buffer back after the system
(`FrifloSimulation.cs`).

<Tabs items={['EasyEcs', 'Friflo.Engine.ECS']}>
<Tab value="EasyEcs">

```csharp title="DeathSystem.cs"
public struct Hp : IComponent { public int Value, Max; }
public struct Npc : IComponent { public int TemplateId; }
public struct Deaths : ISingletonComponent { public int Count, NpcKills; }

public class DeathSystem : EcsSystem
{
    [ForEach, Without<Dead>]
    static void CheckDeath(Entity entity, in Hp hp, ref Deaths deaths)
    {
        if (hp.Value > 0) return;
        entity.SetDead();                       // applied now
        deaths.Count++;
        if (entity.HasNpc) deaths.NpcKills++;
    }
}
```

```csharp
world.AddSingleton<Deaths>();
world.AddSystem<DeathSystem>();
world.Update();
```

</Tab>
<Tab value="Friflo.Engine.ECS">

```csharp title="FrifloDeath.cs" doccheck=skip
var alive = store.Query<Hp>().WithoutAnyTags(Tags.Get<Dead>());
var buffer = store.GetCommandBuffer();
buffer.ReuseBuffer = true;

foreach (var (hps, entities) in alive.Chunks)
{
    var hp = hps.Span;
    for (int i = 0; i < hp.Length; i++)
    {
        if (hp[i].Value > 0) continue;
        buffer.AddTag<Dead>(entities.Ids[i]);         // recorded
        counters.Deaths++;
        if (entities.EntityAt(i).HasComponent<Npc>()) counters.NpcKills++;
    }
}

buffer.Playback();                                    // applied here
```

</Tab>
</Tabs>

The counters live in a singleton that the generated job resolves once per pass. Because the `Dead` tag is applied at
once, a later system in the same update already skips the corpse.

## What Friflo does better [#what-friflo-does-better]

- **Removal callbacks at small counts.** Friflo's `OnComponentRemoved` reports 10 removals in
  <BenchValue k="removed.friflo.10" /> against <BenchValue k="removed.10" /> for `[Removed<T>]`: the callback collects
  the ids as removals happen. At 1,000 removals they are even.
- **Relations.** On the friend-list benchmark Friflo is slightly ahead (<BenchValue k="relation.friflo" /> against
  <BenchValue k="relation.easyecs" />), within the error: both keep a list of links per entity and an index by
  target.
- **The parallel query.** Friflo's `ParallelJobRunner` (<BenchValue k="parallelQuery.friflo" />) is ahead of a
  parallel `[ForEach]` (<BenchValue k="parallelQuery.easyecs" />) in this run, whose parallel rows carry a large
  error. Friflo keeps worker threads of its own; EasyEcs wakes thread-pool helpers only while they pay
  ([D22](/en/docs/decisions)).
- **Reach and tooling.** Unity, netstandard2.1 and net6.0-8.0, events, a thread-safe `CommandBufferSynced` and JSON
  serialization.

## When to choose Friflo [#when-to-choose-friflo]

Choose Friflo when you need Unity or a runtime older than .NET 10, want events or JSON, or prefer explicit chunk
loops and a command buffer. Choose EasyEcs for a .NET 10 server or Godot game where you want changes applied where they are
decided, systems written as one method each and checked at compile time, change tracking without dirty tags, and
binary saves and snapshots built in. Porting a Friflo codebase:
[Migrate from Friflo.Engine.ECS](/en/docs/migrate-from-friflo).
