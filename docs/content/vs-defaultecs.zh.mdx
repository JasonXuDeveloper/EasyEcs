[DefaultEcs](https://github.com/Doraku/DefaultEcs) 给每种组件类型一个池，并在组件增减时实时维护响应式的实体集合；系统
遍历集合里的实体，再从池里取组件。EasyEcs 把组件相同的实体放进同一张原型表，为每个 `[ForEach]` 方法生成一个 struct
job，顺着表的列往下走。两者都内置了变更追踪、移除追踪、值索引、并行系统和存档；区别在存储方式、系统的写法和一个
tick 的开销。

两个库都参与的 <FeatureCount library="DefaultEcs" k="total" /> 项正面对比里，EasyEcs 在 <FeatureCount library="DefaultEcs" k="ahead" /> 项更快，<FeatureCount library="DefaultEcs" k="even" /> 项差距在测量误差之内，
<FeatureCount library="DefaultEcs" k="slower" /> 项更慢。
在 10 万实体的同一个服务器 tick 上，DefaultEcs 的耗时是 EasyEcs 的 <BenchValue k="peers.defaultecs.ratio" />，每个 tick
分配 <BenchValue k="peers.defaultecs.alloc" />，EasyEcs 分配 <BenchValue k="peers.easyecs.alloc" />。DefaultEcs 支持
netstandard1.1-2.1 和 Unity，EasyEcs 只支持 .NET 10。

## 一览 [#at-a-glance]

| | EasyEcs | DefaultEcs |
| --- | --- | --- |
| 存储 | 原型表，每列有存在位 | 每种组件一个池，加实体集合 |
| 系统 | `EcsSystem`，`[ForEach]` 生成 job | `AEntitySetSystem<T>` / `AComponentSystem<T, TComponent>`，配 `[With]` / `[Without]` 特性 |
| 遍历途中的变更 | 当场生效 | 当场作用于集合；`useBuffer` 先复制一份集合，或者用 `EntityCommandRecorder` |
| 变更追踪 | 每次 `ref` 写入，`[Changed<T>]` | 每次写入后调 `NotifyChanged<T>()`，`WhenChanged<T>()` 集合 |
| 移除追踪 | `[Removed<T>]` | `WhenRemoved<T>()` 集合，手动 Complete |
| 每个服务器 tick 的分配 | 无 | 有 |
| 运行时 | net10.0 | netstandard1.1-2.1；Unity |

## 概念对照 [#concepts]

| 概念 | DefaultEcs | EasyEcs |
| --- | --- | --- |
| World | `new World(capacity)` | `new World(new WorldOptions { InitialEntityCapacity = n })` |
| 组件 | 任意 struct | 实现 `IComponent` 的 struct |
| 带组件创建 | `var e = world.CreateEntity(); e.Set(a); e.Set(b);` | `world.CreateEntity(a, b)`（一次放进最终的表） |
| 批量创建 | 同样逐个创建 | `world.CreateEntities(span, a, b)`，或者循环前先 `world.Reserve<A, B>(n)` |
| 读、写 | `e.Get<T>()`（ref）、`world.GetComponents<T>()[e]` | `entity.Hp`（`ref`；被追踪的组件是 `ref readonly`）；`[ForEach]` 参数 |
| 标签 | `e.Set<Dead>()` | `entity.SetDead()` |
| 销毁 | `e.Dispose()` | `entity.Destroy()` |
| 单例 | `world.Set<T>(value)`、`world.Get<T>()` | `ISingletonComponent`、`world.SetClock(…)`、`world.Clock`、`ref T` 参数 |
| 遍历集合的系统 | `[With(typeof(A)), Without(typeof(B))] class S : AEntitySetSystem<TState>` | `class S : EcsSystem`，内含 `[ForEach, Without<B>] static void M(ref A a)` |
| 遍历单个组件的系统 | `AComponentSystem<TState, A>` | 参数为 `ref A` 的 `[ForEach]` 方法 |
| 系统序列 | `new SequentialSystem<T>(systems)` | 按顺序 `world.AddSystem<S>()`，或用 `[UpdateBefore<T>]` / `[UpdateAfter<T>]` |
| 并行系统 | `new ParallelSystem<T>(runner, systems)` | `WorldOptions.ParallelSystems`（冲突由生成的访问集判断） |
| 并行遍历集合 | 配 `DefaultParallelRunner` 的 `AEntitySetSystem` | `[ForEach(Parallel = true)]` |
| 实体集合 | `world.GetEntities().With<A>().Without<B>().AsSet()` | `QueryFilter`、`world.Query<A>(filter)`、`world.Count<A>(filter)` |
| 上次之后变过的 | `.WhenChanged<T>()` + `NotifyChanged<T>()` + `Complete()` | `ITracked` + `[Changed<T>]` |
| 上次之后被移除的 | `.WhenRemoved<T>()` + `Complete()` | `ITracked` + `[Removed<T>]` |
| 按值索引 | `AsMultiMap<T>()`、`AsMap<T>()` | `IIndexed<TKey>`、`world.Index<T, TKey>()` |
| 延迟变更 | `EntityCommandRecorder`、`Record(e).Set<T>()`、`Execute()` | 不需要 |
| 禁用 | `e.Disable()`、`e.Disable<T>()` | 标签加 `[Without<T>]`，或 `entity.DisableHp()` |
| 复制到 World | `e.CopyTo(world)` | `entity.Clone()`、`world.MoveEntities(...)`、`Prefab` |
| 存档 | `BinarySerializer`、`TextSerializer` | `world.Save(writer)` / `world.Load(bytes)` |
| 消息 | `world.Subscribe<T>`、`world.Publish<T>` | 数据：后面的系统去读的单例或组件 |

## 同一个任务的两种写法 [#same-task]

取主 tick 里的状态系统：着火的单位掉血，几个 tick 后火灭。DefaultEcs 的移植版在遍历时移除组件，所以系统传了
`useBuffer: true`，更新前先把集合复制一份（`DefaultEcsSimulation.cs`）。

<Tabs items={['EasyEcs', 'DefaultEcs']}>
<Tab value="EasyEcs">

```csharp title="StatusSystem.cs"
public struct Hp : IComponent { public int Value, Max; }
public struct Fire : IComponent { public int Ticks, DamagePerTick; }

public class StatusSystem : EcsSystem
{
    [ForEach]
    static void Burn(Entity entity, ref Fire fire, ref Hp hp)
    {
        hp.Value -= fire.DamagePerTick;
        if (--fire.Ticks <= 0) entity.RemoveFire();      // 只翻一个位，行不动
    }
}
```

```csharp
world.AddSystem<StatusSystem>();
world.Update();
```

</Tab>
<Tab value="DefaultEcs">

```csharp title="DefaultEcsStatus.cs" doccheck=skip
[With(typeof(Fire), typeof(Hp))]
public sealed class BurnSystem(World world) : AEntitySetSystem<Counters>(world, true)   // useBuffer: true
{
    protected override void Update(Counters c, ReadOnlySpan<Entity> entities)
    {
        var fires = World.GetComponents<Fire>();
        var hps = World.GetComponents<Hp>();
        foreach (ref readonly var e in entities)
        {
            ref var fire = ref fires[e];
            hps[e].Value -= fire.DamagePerTick;
            if (--fire.Ticks <= 0) e.Remove<Fire>();
        }
    }
}

var systems = new SequentialSystem<Counters>(new BurnSystem(world) /* , ... */);
systems.Update(counters);
```

</Tab>
</Tabs>

## DefaultEcs 做得更好的地方 [#what-defaultecs-does-better]

- **覆盖面。** 支持 netstandard1.1 到 2.1 和 Unity；EasyEcs 需要 .NET 10。
- **共享组件。** `SetSameAs` 让多个实体共用一个组件值；EasyEcs 没有共享组件（[D14](/zh/docs/decisions)）：把共享数据放进
  单例，组件里存一个 id。
- **消息。** 内置发布 / 订阅；EasyEcs 把消息建模成数据。
- **文本序列化器**，和二进制的并存。
- **稀疏存储** 适合实体频繁改变组件组合、却很少整体遍历的 World：加组件从不复制其他组件。

## 什么时候选 DefaultEcs [#when-to-choose-defaultecs]

需要老运行时或 Unity，想让系统之间用响应式集合或消息沟通，而且 World 小到每 tick 的分配和池查找都无所谓，就选
DefaultEcs。.NET 10 服务器或 Godot 游戏、每个 tick 要遍历大量实体、不想每次写入都调 `NotifyChanged` 也能追踪变更、每个 tick 不能
有分配，就选 EasyEcs。要移植 DefaultEcs 项目：[从 DefaultEcs 迁移](/zh/docs/migrate-from-defaultecs)。
