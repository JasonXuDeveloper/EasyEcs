这里按顺序列出计划要做的事。一项发布之后就离开本页，此后由[更新日志](/zh/docs/changelog)和各篇指南介绍它。
放弃的功能在这里留一行，理由写在[设计决策](/zh/docs/decisions)里。每项性能改动都要用 BenchmarkDotNet 测改前改后，
时间和分配都是净收益才发布。

## 计划 [#planned]

### 让生成器替用户少写代码 [#less-code-through-the-generator]

生成器已经会写 `entity.Health`、`HasHealth`、`SetHealth(…)`、`SetHealthIfChanged(…)`、`IsDead`、单例组件成员、`world.XIndex`、缓冲成员、
命名的查询元素、预制体的缓冲写方法，以及 job 和访问集。每次发布前都会重新过一遍 API、[战斗服示例](/zh/docs/example)和各篇指南：
用户写了两遍的代码都是生成成员的候选，没人用的生成成员就删掉。候选能在真实代码里省下代码、又不给每次调用加开销才会加入；
只是换个写法的会被否决（[D26](/zh/docs/decisions#d26-generated-members-and-a-suggestion-to-use-them)）。

### 工具链与运行时 [#toolchain-and-runtime]

最低要求是 .NET 10 SDK（C# 14、Roslyn 5.0），生成器基于它构建。只有测得出收益，EasyEcs 才会用更新的运行时特性
（[D21](/zh/docs/decisions#d21-net-10-features-only-where-they-measure)）。

### 评估 Unity 支持 [#unity]

Unity 用 Mono 和 IL2CPP 运行 C#，EasyEcs 依赖的 .NET 10 特性它们一样都没有（[D15](/zh/docs/decisions#d15-net-10-only)）。
Unity 正在迁移到 CoreCLR；等 Unity 有版本能运行 .NET 10 代码，就评估支持它需要什么：生成器和分析器能否在 Unity 的编译流程里运行，
player 构建（IL2CPP 及其预先编译的限制），编辑器的域重载与 EasyEcs 启动时注册的类型如何相处，以及在 player 里测一遍主基准。
Godot 不需要这些：面向 `net10.0` 的 Godot 4 .NET 项目现在就能运行 EasyEcs（[常见问题](/zh/docs/faq#unity-godot)）。

### 给网格邻居推送光环 [#push-halo]

按区块划分的网格模拟（[体素服务器](/zh/docs/samples/voxel-server#water)里的水）每一步都要把每个流动区块的邻居的边载入它的瓦片（`Tile<TCell, TTile>.Pad`）。计划中的设计反过来：
区块的边变了时推进邻居的光环，这样一步只读自己的组件，邻居都静止的区块也没有东西要拷（[D73](/zh/docs/decisions#d73-survey-items-not-added)）。

### 向量循环：留待以后的形式 [#vector-loops-left]

`[ForEach]` 方法在单线程和并行时都能得到向量循环，支持窄通道、结构体值、`Maybe<T>` 掩码、冷分支和宽行
（[D90](/zh/docs/decisions#d90-vector-loops-reach)）。留待以后：并行方法里的掩码字（一个块传的是整段行）、并行方法里和窄通道上的
`Maybe<T>`、窄通道和宽行的掩码字（它们改为逐行运行方法），以及 `Atan2`、`Asin`、`Pow` 这类在 .NET 10 里没有向量形式的函数。
用得上它的方法测出更快时才发布。

## 已放弃 [#dropped]

- `Added<T>`：`[Changed<T>]` 也会选出新添加的行；要区分新出现和被写过，用一个由响应系统移除的标签
  （[D4](/zh/docs/decisions#d4-no-addedt-filter)）。
- 并行 job 的命令缓冲：并行 job 只写数据，排在它后面的系统做结构变更
  （[D3](/zh/docs/decisions#d3-no-command-buffer-for-parallel-jobs)）。
- 给查询调用点用拦截器：调用参数照样求值，在调用处构建的过滤条件怎么都会被构建
  （[D18](/zh/docs/decisions#d18-no-interceptors-for-query-calls-filters-carry-no-references)）。
  `AddEmbeddedAttributeDefinition`：生成器不生成特性类型（特性都在 EasyEcs.Core 里）。
- 可赋值的标签属性（`entity.IsDead = true`）：C# 14 不允许在 `foreach` 变量、索引器结果或 `in` 参数的字段上给结构体的扩展属性赋值，
  而 ECS 代码恰恰在这些地方持有实体（[D19](/zh/docs/decisions#d19-no-settable-tag-properties)）。
- 扁平的 `[InlineArray]` 备忘、存档类型表用 `FrozenDictionary`、`OverloadResolutionPriority`、`field`：测过或权衡过，没有净收益
  （[D21](/zh/docs/decisions#d21-net-10-features-only-where-they-measure)）。
- 多类型的 `Disable` / `Enable` 和批量调用
  （[D26](/zh/docs/decisions#d26-generated-members-and-a-suggestion-to-use-them)）。
- 生成 `world.AddSystems()`：系统按注册顺序运行，这份列表就是 tick 的顺序，应当在构建 World 的地方读到（[D56](/zh/docs/decisions#d56-not-added)）。
- 读单例时发现缺失就自动添加（`world.X`、`GetSingleton<T>()`、`[ForEach]` 参数）：缺单例说明忘了初始化，而默认值很少是对的
  （步长为零的时钟），所以所有读取都抛异常；确实要默认值的地方用 `GetOrAddX()`
  （[D27](/zh/docs/decisions#d27-reading-a-missing-singleton-throws-everywhere)）。
- 由特性生成缓存过滤条件、按组件生成计数成员（`world.CountPlayer()`）、命名的 `TryGetXRef`：省不下代码，API 面却更大（[D56](/zh/docs/decisions#d56-not-added)）。
- span 方法上的 `[ForEach(Parallel = true)]`、`entity.LastWriteTick<T>()`、公开读写集、多个 World 共享并行预算
  （[D36](/zh/docs/decisions#d36-not-added)）。
- 运行条件（`[RunIf]`）：什么时候跑哪个分组，系统分组和宿主已经能决定；每个系统一个谓词，是调度器看不见的代码
  （[D51](/zh/docs/decisions#d51-not-added)）。
- `UpdatePeriod` 和系统时间：时间归宿主的固定步长循环管，`[UpdateInterval]` 数的是更新次数，结果可复现
  （[D51](/zh/docs/decisions#d51-not-added)）。
- `[Requires<B>]`：每种实体一个预制体，一次拷贝就带齐整套组件，没有隐式的结构变更（[D51](/zh/docs/decisions#d51-not-added)）。
- 外部键到实体的映射表：`IUniqueIndexed<TKey>` 就是这张表，每次写入都会维护（[D51](/zh/docs/decisions#d51-not-added)）。
- 内置 `Meter`：数据都在 `SystemStats` 里，发布出去是文档里给出的宿主写法，EasyEcs 不必依赖指标库
  （[D51](/zh/docs/decisions#d51-not-added)）。
- World 校验和：对 `world.Save` 的输出做哈希，用户代码里就能做，不必给所有人定死一种算法（[D51](/zh/docs/decisions#d51-not-added)）。
- 唯一索引旁边的区块网格、只在变化时才写 `InChunk`、按位字拷贝存在位、只拷贝变化过的边的光环：测过，没有净收益，或者被 `IDirectIndexed<TKey>`
  和推送光环的设计取代（[D73](/zh/docs/decisions#d73-survey-items-not-added)）。
- 网格瓦片的生成式逐格内核：字节运算会提升成 `int`，模板又按行归约；瓦片负责加载光环，规则留在方法里（[D77](/zh/docs/decisions#d77-tiles)）。
- 网格模板一次加载走多步（时间分块）、沿 y 的滑动窗口、缓存瓦片的邻居：测过，在装得进缓存的网格上更慢，或不值得为它加每实体状态
  （[D77](/zh/docs/decisions#d77-tiles)）。
- 部分快照 API：用一个系统把需要的值拷进单例里的环形缓冲（延迟补偿的写法），只拷需要的东西
  （[D51](/zh/docs/decisions#d51-not-added)）。
- 按依赖驱动的系统调度（系统在与它冲突的系统结束后就开始，而不是等阶段屏障）：测过的世界的依赖图路径与阶段路径相同
  （[D76](/zh/docs/decisions#d76-stages-not-a-dependency-graph)）。
- 为累计总数（跨更新增长的分数）建议归约，以及为手写的 `Scratch<T>` 单设规则：前者不是同一段代码，EECS028 已经指出 `Scratch<T>`
  （[D97](/zh/docs/decisions#d97-hand-written-parameters)）。
- 每个实体一份随机数生成器状态，以及 Philox 或 threefry：每次抽取都要写一次，存档更大，也比四轮终结混合慢
  （[D79](/zh/docs/decisions#d79-entity-random)）。
- 按键（直方图）归约：在这种 API 面向的规模上没有一个候选方案明显胜出；几千个桶以内用 `[InlineArray]` 桶的 `Reduce<T>` 就够
  （[D81](/zh/docs/decisions#d81-keyed-reductions)）。
- 把 `[ForEntity]` 入口写成 `Entity` 的扩展成员：所有模块的所有请求都会堆进同一个类型的成员列表（[D82](/zh/docs/decisions#d82-for-entity)）。
- 用可重写的属性或在运行时设置系统的节奏：特性是调度能读到的常量；要变的节奏就放进一个分组，由宿主决定何时更新
  （[D83](/zh/docs/decisions#d83-update-interval-attribute)）。
- 宽行的完整转置、gather 和跨步加载，`[Lane]` / `[Hot]` 字段标记，`[Layout(Soa)]` 存储，以及展开的向量循环：测下来更慢或不更快，
  或者方法本身已经说明了用哪些字段（[D90](/zh/docs/decisions#d90-vector-loops-reach)）。
- 通过 `WorldOptions` 做 World 设置，以及用反射读声明特性：每个 World 一项设置仍然会忘，反射让每个 World 启动时都付出代价
  （[D101](/zh/docs/decisions#d101-declaration-attributes)）。
