What changed from one EasyEcs release to the next, newest first, for code that uses EasyEcs. Upgrading across a
major or minor version that needs code changes? The
[migration guide](/en/docs/migration) has the steps. Each
[GitHub release](https://github.com/JasonXuDeveloper/EasyEcs/releases) also lists every pull request it contains.

## 4.7.0 [#v4-7-0]

### New [#v4-7-0-new]

- `Mut<T>`, a `[ForEach]` parameter of a component the method writes on some rows only: `Value` reads, `Write()` and
  `SetIfChanged(value)` stamp the row they write, so `[Changed<T>]` readers visit only the rows whose value changed.
  `entity.SetIfChanged(value)` and the generated `SetHealthIfChanged(…)` skip an equal value outside a pass. See
  [change tracking](/en/docs/guide/change-tracking).
- `[ChangedAny<T1..Tn>]` / `[RemovedAny<T1..Tn>]` and `QueryFilter.ChangedAny<T1..Tn>(since)` / `RemovedAny`: rows
  where at least one of 2 to 9 tracked components was written, or lost. One filter kept in a field serves every
  client with `filter.Since(ack)`. See [change tracking](/en/docs/guide/change-tracking).
- `WorldOptions.DestroyLog` and `world.DestroyedSince(since, into, out count)`: the entities destroyed since a reader's
  tick, for replicating despawns to clients that acknowledge at different ticks; false (resynchronize) when the reader
  is older than the log (`DestroyLogOldestTick`). See [change tracking](/en/docs/guide/change-tracking).
- `IUniqueIndexed<TKey>`: a key that names one entity, found with `index.Get(key)` / `TryGet(key, out e)`; every write
  that would give a second entity a taken key throws before it changes anything. See
  [indexes and relations](/en/docs/guide/indexes-and-relations).
- `index.Find(key).Count`, `world.Children(parent).Count` and, for a relation, `relations.Find(target).Count`: how many
  entities had the key (or links pointed at the target) when found, in O(1), so a buffer is sized without walking the
  matches twice. `index.KeyCount` and `relations.TargetCount` count the distinct keys (or targets) in O(1). See
  [indexes and relations](/en/docs/guide/indexes-and-relations#value-indexes).
- `world.Descendants(root).AddTo(ids, includeRoot)` appends a subtree to a `List<EntityId>`, each parent before its
  children: the group `MoveEntities` and `SaveEntities` take, without a collecting loop. See
  [hierarchy](/en/docs/guide/hierarchy#moving).
- `world.Instantiate(prefab, in c1 … in cn)` and `Instantiate(prefab, entities, in c1 … in cn)`: an instance with up
  to nine components of its own (a parent, a position, an owner) in one row copy. The keys of unique components, the
  given ones and the prefab's, are checked before any entity is created. See [prefabs](/en/docs/guide/prefabs).
- `world.TrimExcess()` gives back the memory a peak left: empty tables go, the others shrink, the buffers of saves,
  loads and migrations are released. See [debugging and diagnostics](/en/docs/guide/diagnostics).
- `[ForEach(Slices = N)]` spreads a method's rows over N runs of its system; `QueryFilter.Slice(index, count)` does it
  for a struct job, and `EcsSystem.RunCount` says which run is current. See [systems](/en/docs/guide/systems).
- `SystemStats` records the bytes each run allocated (`LastAllocated`, `TotalAllocated`) and the entities its
  `[ForEach]` methods visited (`LastEntities`, `TotalEntities`); `world.DescribeSchedule()` describes the stages, the
  waits and the pairs only registration orders, as text or a mermaid flowchart. See
  [debugging and diagnostics](/en/docs/guide/diagnostics).
- Restart saves: `world.Save(output, in exclude)` leaves the components and singletons of a `ComponentSet` out,
  `world.Load(input, in keep, markWritten)` keeps the singletons the new process set, and
  `ComponentSet.WithSingleton<T>()` / `With(Type)` name singletons. See [restart](/en/docs/guide/saves#restart).
- The analyzer: [EECS035](/en/docs/guide/analyzer#eecs035) rejects an invalid `Slices` (below 1, or with a
  `Changed` / `Removed` filter); [EECS036](/en/docs/guide/analyzer#eecs036) a unique component that cannot be indexed by
  its key (an `EntityId` key, or a second index key); [EECS031](/en/docs/guide/analyzer#eecs031) covers a loop of
  `Instantiate` calls with the same values; [EECS033](/en/docs/guide/analyzer#eecs033) suggests the generated
  `SetXIfChanged(…)`.
- `SaveEntities(output, a.Id, b.Id)` and `bag.AddRange(x, y)` take the values directly (`params` spans, built on the
  stack). The guides pass a collected list as `CollectionsMarshal.AsSpan(list)` instead of a `ToArray()` copy. See
  [migration](/en/docs/guide/migration-and-unload#save-entities).

### Performance [#v4-7-0-performance]

- Spawning with components is one row copy instead of `Instantiate` and then `Set`. See
  [decision D41](/en/docs/decisions#d41-instantiate-with-components).
- A system that recomputes a tracked value every tick no longer makes every `[Changed<T>]` reader visit every row:
  with `Mut<T>`, only the rows whose value changed are stamped. See
  [decision D46](/en/docs/decisions#d46-mut-stamps-per-write).
- `ChangedAny` skips the tables, 4,096-row blocks and 64-row words none of its components wrote. See
  [decision D49](/en/docs/decisions#d49-changedany-semantics).

### Changes that need code changes [#v4-7-0-breaking]

- `SaveEntities(output, ids, set)` throws `ArgumentException` when the set names a singleton (a group save writes
  none). See the [migration guide](/en/docs/migration#v4-7-save-entities).
- `EcsSystem` has a public `RunCount`: a member of that name in a system hides it (warning CS0108). See the
  [migration guide](/en/docs/migration#v4-7-run-count).

### Fixes [#v4-7-0-fixes]

- A parallel pass (a parallel `[ForEach]` or `ForEachParallel`, or a stage of parallel systems) could hang, its
  caller spinning forever, and run one chunk (or system) twice: a helper thread still finishing the last pass could
  claim an item of the next one when the next one had more. Sliced parallel passes, whose chunk count changes from run
  to run, hit it within seconds. A pass now closes the last one's claims before it starts. See
  [threading](/en/docs/guide/threading#parallel-foreach-methods).
- A parallel `[ForEach]` that writes a tracked component could lose change stamps: two chunks inside one 4,096-row
  block raced on the block's change summary, so a `[Changed<T>]` reader could skip rows that were written. Such passes
  now cut their chunks at multiples of 4,096 rows. See
  [decision D48](/en/docs/decisions#d48-parallel-tracked-chunks).
- After `RemoveTypes` dropped tables, a `Capture(into)` into an older snapshot, or a later `Load`, could reuse the
  copy of another table (other columns). A copy is now reused only for its own table. See
  [snapshots](/en/docs/guide/snapshots).
- `entity.GetOrAdd<T>()` of an indexed component that the entity lacked did not tell the value index, so `Find` and
  `Count` missed the entity until its next `Set`; the default value's key is now indexed. See
  [indexes and relations](/en/docs/guide/indexes-and-relations).

## 4.6.0 [#v4-6-0]

### New [#v4-6-0-new]

- `world.Load(input, markWritten: false)` loads a whole save without change ticks: no loaded row counts as written
  or removed, also for systems added after the load, so a restart that resumes a saved world does not send every
  record again. See [restart](/en/docs/guide/saves#restart).
- `world.AddSystem<T>(changesFromNow: true)` (and `AddSystem(system, changesFromNow: true)`) starts a system at the
  current tick: the first run of its `[Changed<T>]` and `[Removed<T>]` methods visits only what is written or removed
  after the call. See [ticks](/en/docs/guide/change-tracking#ticks).

### Fixes [#v4-6-0-fixes]

- Native AOT publishes without warnings: a program with tracked components (`ITrackChanges`, also the built-in
  `ChildOf`) or disabled components got an IL3054 warning (generic recursion), which fails a build that treats
  warnings as errors. See [Native AOT](/en/docs/faq#native-aot).

## 4.5.0 [#v4-5-0]

### New [#v4-5-0-new]

- `entity.Run(ref job)` runs a struct job (`IForEachEntity<T1..T9>`) on one entity: it returns false when the entity
  is stale or lacks a component, and `entity.Run(ref job, filter)` also when a `QueryFilter` (`With`, `Without`,
  `WithAny`, `Changed`, `Removed`, a group) rejects it. The job's `Writes` stamp change ticks as in a pass, its `ref`
  parameters stay valid across its own structural changes, and its writes reach the moved row even when it throws.
  See [one entity: `entity.Run`](/en/docs/guide/queries#run-on-one-entity).
- A system group can filter through interfaces: `IGroupWith<T>` / `IGroupWithout<T>` on the group, or on an interface
  it implements, act as `[With<T>]` / `[Without<T>]`. A generic interface gives each type its own group
  (`IActorGroup<TActor> : IGroupWith<Inbox<TActor>>`), which attributes cannot express. See
  [group filters](/en/docs/guide/systems#group-filters).
- `world.Descendants(root)` walks a whole subtree, depth first, allocation-free once warm: collect a group with every
  level of children before moving or saving it. See [list them](/en/docs/guide/hierarchy#children).
- `world.LoadEntitiesInto(input, entities, markWritten: false)` restores a record without counting it as a change, so
  `[Changed<T>]` savers and replicators do not send it back; that holds for a value it replaces too, such as a
  prefab's default. See
  [a record of what persists](/en/docs/guide/migration-and-unload#records).
- The EasyEcs package brings Nino's generator: a `[NinoType]` component gets its formatter with no other package
  reference, so a project can drop its `Nino.Generator` reference (a kept one must not be older than the Nino of EasyEcs). See
  [declare the components](/en/docs/guide/saves#declare).
- The analyzer treats `entity.Run` as a structural call: [EECS010](/en/docs/guide/analyzer#eecs010) rejects it in a
  parallel `[ForEach]` method, [EECS013](/en/docs/guide/analyzer#eecs013) and
  [EECS014](/en/docs/guide/analyzer#eecs014) check it like `Set`.

### Fixes [#v4-5-0-fixes]

- The analyzer treats `world.LoadEntitiesInto` as a structural call, like `LoadEntities`: it was missing from the
  members [EECS010](/en/docs/guide/analyzer#eecs010), [EECS013](/en/docs/guide/analyzer#eecs013) and
  [EECS014](/en/docs/guide/analyzer#eecs014) check, so a call in a parallel `[ForEach]` method, in a method that
  promises no structural change or on another thread compiled without an error.

## 4.4.0 [#v4-4-0]

### New [#v4-4-0-new]

- `world.SaveEntities(output, ids, set)` saves only the components of a `ComponentSet`
  (`ComponentSet.Create().With<Bank>()`, or `With(typeof(Bank))` for types learned at run time): a record of what
  persists, without the runtime components around it, which then need no Nino formatter. See
  [a record of what persists](/en/docs/guide/migration-and-unload#records).
- `world.LoadEntitiesInto(input, entities)` loads such a save onto entities that exist already: the i-th saved
  entity's components are added to or replace those of the i-th entity, each entity moving table at most once, with
  indexes, groups, change tracking and `EntityId` fields following. See
  [a record of what persists](/en/docs/guide/migration-and-unload#records).
- A component renamed or moved to another namespace keeps its saves with `[NinoFormerName("Old.Name")]`: saves
  record types by their Nino type id. See [when the code changed](/en/docs/guide/saves#versioning).
- An unmanaged `[NinoType]` component is written by its Nino formatter, so a `VersionTolerant` or `Keyed` one may gain
  members between builds and still load its old rows. See [when the code changed](/en/docs/guide/saves#versioning).
- A refused load names the cause and the fix: raw rows against a formatter, a changed size or layout, two types of the
  process sharing an id. See [why a save does not load](/en/docs/guide/troubleshooting#save-refused).

### Performance [#v4-4-0-performance]

- A `DynamicBuffer<T>` that dies (its entity destroyed, the component removed) hands its emptied list to the next
  buffer of its element type the thread creates: entities that come and go with buffers allocate nothing once warm.
  See [dynamic buffers](/en/docs/guide/dynamic-buffers#what-it-costs) and
  [decision D32](/en/docs/decisions#d32-the-lists-of-dead-buffers-are-pooled-per-thread).

### Changes that need code changes [#v4-4-0-breaking]

- Saves written by 4.3 or earlier do not load (`InvalidDataException`): write again the data that must outlive the
  upgrade. See the [migration guide](/en/docs/migration#v4-4-saves).
- EasyEcs builds on Nino 4.0.0-rc.6: reference `Nino.Generator` 4.0.0-rc.6. See the
  [migration guide](/en/docs/migration#v4-4-nino).
- An unmanaged component marked `[NinoType]` is saved by its formatter instead of as raw rows; remove the attribute
  where raw rows are meant. See the [migration guide](/en/docs/migration#v4-4-ninotype).

### Fixes [#v4-4-0-fixes]

- [EECS033](/en/docs/guide/analyzer#eecs033) no longer suggests a generated member the receiver does not have
  (`entity.Read<ChildOf>()` was told to become `entity.ChildOf`, a member of query items, which does not compile).

## 4.3.0 [#v4-3-0]

### New [#v4-3-0-new]

- Performance rules in the analyzer, for code that works but does more than it needs. Warnings, for code that costs:
  [EECS025](/en/docs/guide/analyzer#eecs025) a `ref` / `Span<T>` parameter, `Get<T>()` or `WriteX()` that only
  reads, [EECS026](/en/docs/guide/analyzer#eecs026) a `[ForEach]` parameter the method does not use,
  [EECS027](/en/docs/guide/analyzer#eecs027) a component or singleton looked up through the visited `Entity` or the
  `World` on every row, [EECS028](/en/docs/guide/analyzer#eecs028) an allocation in a `[ForEach]` method or
  `OnUpdate`, [EECS029](/en/docs/guide/analyzer#eecs029) an instance `[ForEach]` method that uses nothing of its
  system, [EECS030](/en/docs/guide/analyzer#eecs030) a structural change entity by entity over a query,
  [EECS031](/en/docs/guide/analyzer#eecs031) entities created one by one in a counted loop,
  [EECS032](/en/docs/guide/analyzer#eecs032) `Count() > 0` instead of `Any()` and counting or filtering in a loop.
  Suggestion (Info), for the same cost written shorter: [EECS033](/en/docs/guide/analyzer#eecs033) a generic call
  with a generated member of the same meaning (`entity.Get<Position>()` as `entity.Position`). Error: [EECS034](/en/docs/guide/analyzer#eecs034) a system that
  calls `World.Update()`. Why each rule is in and the ones left out:
  [decision D29](/en/docs/decisions#d29-performance-rules-only-where-the-cost-is-measured-and-the-fix-does-the-same).
- Code fixes for the new rules where the change is mechanical: `in`, `ReadOnlySpan<T>`, `Read<T>()`, `[With<T>]`,
  `static`, the bulk call (`SetAll`, `RemoveAll`, `DisableAll`, `EnableAll`, `DestroyEntities`), `CreateEntities` or
  `EnsureCapacity`, `Any` / `Count`, and the generated member. Each is offered only when the result compiles.
- Every analyzer diagnostic links its section of the [analyzer rules](/en/docs/guide/analyzer) page.

### Changes that need code changes [#v4-3-0-breaking]

- A build that treats warnings as errors fails on the new warnings (EECS025 to EECS032) until the code is changed or
  the rule is suppressed, and a system that calls `World.Update()` no longer builds (EECS034). See the
  [migration guide](/en/docs/migration#v4-2-to-v4-3).

## 4.2.0 [#v4-2-0]

### New [#v4-2-0-new]

- `world.EnsureCapacity<T1, …, Tn>(count)` pre-sizes the table of exactly those components and the entity storage,
  so the next `count` `CreateEntity` / `CreateEntities` calls with them never grow either (Friflo's
  `archetype.EnsureCapacity`, Arch's `EnsureCapacity(signature, n)`). See
  [structural changes](/en/docs/guide/structural-changes#bulk).

### Performance [#v4-2-0-performance]

- Creating many entities in a fresh world no longer sets off a full garbage collection inside the call: a
  reservation (`EnsureCapacity`, `EnsureEntityCapacity`, `CreateEntities`, `InitialEntityCapacity`) grows the table
  and the entity storage to what it needs instead of the next power of two, and large entity storage sized by one
  goes to the pinned object heap, beside the columns. See
  [decision D28](/en/docs/decisions#d28-reservations-grow-to-what-they-need-entity-storage-on-the-pinned-heap).

### Changes that need code changes [#v4-2-0-breaking]

- A `[ForEach]` method's singleton parameter throws `InvalidOperationException` when the world has no such singleton,
  like `world.X` and `GetSingleton<T>()` (it used to add the default value); `world.SingletonRef<T>()` throws the same
  way. Add the singleton where the world is built, before the first `Update()`: `world.SetClock(…)` or
  `world.AddSingleton<Clock>()`, or `world.GetOrAddClock()` where the default is right. See
  [singletons](/en/docs/guide/singletons#in-systems) and the
  [migration guide](/en/docs/migration#v4-1-to-v4-2).

### Fixes [#v4-2-0-fixes]

- A `[ForEach]` method with a parameter named `owner` no longer fails to build with CS0100 in generated code.
- `world.EnsureCapacity(prefab, count)` called while a query or `[ForEach]` pass walks the table it grows no longer
  leaves the pass writing to the old columns for the rest of the table. See
  [structural changes](/en/docs/guide/structural-changes#refs-across-a-change).

## 4.1.0 [#v4-1-0]

### New [#v4-1-0-new]

- Archetype tables: each table stores its components as columns of rows, unmanaged columns pinned and 64-byte
  aligned. Removing a component keeps the row and clears a presence bit, so states that come and go never move
  data. See [architecture](/en/docs/architecture).
- Immediate structural changes with stricter iteration: a pass visits each entity at most once, and `ref` writes of a
  `[ForEach]` method survive the body's own structural changes. See
  [structural changes](/en/docs/guide/structural-changes).
- Batch `[ForEach]` methods taking `Span<T>` / `ReadOnlySpan<T>` (whole runs of rows, with an `EntitySpan`), and
  `[ForEach(Parallel = true)]` to split one method's rows over threads without allocating. See
  [systems](/en/docs/guide/systems) and [threading](/en/docs/guide/threading).
- Static `[ForEach]` methods outside systems, generic systems and runners, filters on system groups, `Maybe<T>`
  parameters, `UpdatePhase`, and systems need no `partial`. See [systems](/en/docs/guide/systems).
- Ordering by dependency with `[UpdateBefore<T>]` / `[UpdateAfter<T>]`; errors as data with
  `SystemErrorPolicy.Disable` and `system.Error`; per-system timing with `WorldOptions.MeasureSystems` and
  `system.Stats`. See [systems](/en/docs/guide/systems).
- Change tracking (`ITrackChanges`, `[Changed<T>]`, `QueryFilter.Changed<T>(since)`) and removal detection
  (`[Removed<T>]`, `QueryFilter.Removed<T>(since)`). See [change tracking](/en/docs/guide/change-tracking).
- Generated members for every component, tag, singleton, index, buffer and query shape: `hero.Position.X += 1`,
  `hero.SetVelocity(1, 0)`, `hero.SetDead()`, `world.Battle.Tick++`, `world.ZoneIndex.Find(3)`, `item.Position`,
  `prefab.SetLoot(…)`. See [entities and components](/en/docs/guide/entities-and-components).
- Prefabs (`new Prefab()`, derived prefabs, groups with `AddMember`), `world.Instantiate`, `EnsureCapacity` and
  `entity.Clone()`. See [prefabs](/en/docs/guide/prefabs).
- `DynamicBuffer<T>`: a list per entity held as a tracked component. See
  [dynamic buffers](/en/docs/guide/dynamic-buffers).
- Value indexes (`IIndexed<TKey>`, `world.Index<T, TKey>()`), ordered walks (`Range`, `Ascending`), relations
  (`IRelation` buffers) and target policies (`WhenTargetDestroyed`). See
  [indexes and relations](/en/docs/guide/indexes-and-relations).
- Hierarchies: `ChildOf(EntityId Parent)`, children, destroy cascades. See [hierarchy](/en/docs/guide/hierarchy).
- `GroupBy<T>()` splits tables by a value, so a query for one zone walks only its tables. See
  [groups](/en/docs/guide/groups).
- `entity.Disable<T>()` / `Enable<T>()` and cleanup components (`ICleanupComponent`). See
  [cleanup and disable](/en/docs/guide/cleanup-and-disable).
- Bulk `SetAll` / `RemoveAll` / `DisableAll` / `EnableAll`, and `CreateEntities` / `DestroyEntities`. See
  [bulk changes](/en/docs/guide/bulk).
- Snapshots: `world.Capture()` / `world.Restore(snapshot)`. See [snapshots](/en/docs/guide/snapshots).
- Saves: `world.Save` / `Load` through Nino. See [saves](/en/docs/guide/saves).
- `SaveEntities` / `LoadEntities` / `MoveEntities` hand a group of entities to another world or process, and
  `world.RemoveTypes(assembly)` takes a plugin's types out of a world so its `AssemblyLoadContext` can unload. See
  [migration and unload](/en/docs/guide/migration-and-unload).
- `WithAny<T>` filters, `entity.Read<T>()` and `entity.TryGetRef<T>(out found)`. See
  [queries](/en/docs/guide/queries).
- `world.Describe()`, `entity.Describe()` and a debugger view of entities. See [API](/en/docs/api).
- Analyzer rules up to EECS024 and code fixes for them, bundled in the package. See
  [analyzer](/en/docs/guide/analyzer).
- Templates: `dotnet new install EasyEcs.Templates`. See [getting started](/en/docs/getting-started).

### Performance [#v4-1-0-performance]

- A realistic server tick of 100,000 entities runs much faster than in 4.0.1 and allocates nothing. See
  [performance](/en/docs/performance).
- Structural changes check a plain owner flag instead of a compare-and-swap, so creating and destroying
  entities is faster.
- Jobs that cannot change structure iterate with no per-entity bookkeeping.
- Parallel runs use the thread pool and wake helper threads only when they pay
  ([D22](/en/docs/decisions#d22-parallel-runs-use-the-thread-pool-and-wake-helpers-only-when-they-pay)).
- Change and removal summaries per block of rows
  ([D23](/en/docs/decisions#d23-change-summaries-per-block-removals-summarized-apart)), index keys as id arrays
  ([D24](/en/docs/decisions#d24-an-indexs-key-holds-its-entities-in-one-array)) and structural loops compiled for
  tables without tombstones
  ([D25](/en/docs/decisions#d25-structural-row-loops-are-compiled-for-tables-without-tombstones)).
- A `QueryFilter` holds no object reference, so building one at the call is cheaper
  ([D18](/en/docs/decisions#d18-no-interceptors-for-query-calls-filters-carry-no-references)).
- Counting rows by their set bits with `Vector512` / `Vector<T>`
  ([D21](/en/docs/decisions#d21-net-10-features-only-where-they-measure)).

### Changes that need code changes [#v4-1-0-breaking]

Every step is in the
[migration guide](/en/docs/migration#v4-0-to-v4-1).

- `WorldOptions.Parallel` is `WorldOptions.ParallelSystems`: write `new WorldOptions { ParallelSystems = true }`.
- `Entity.Id` is an `EntityId` and `Entity.Version` is gone: read `entity.Id.Index` and `entity.Id.Version`, and
  store `EntityId`s in components (EECS017 warns about `Entity` fields).
- `EcsSystem.Priority` is gone: order systems with `[UpdateBefore<T>]` / `[UpdateAfter<T>]`.
- The `World.SystemError` event is gone: use `new WorldOptions { SystemErrors = SystemErrorPolicy.Disable }` and read
  `system.Error`.
- `world.DestroyEntity(entity)` is gone: call `entity.Destroy()`.
- `entity.Add<T>()` is gone: write `Set(new T(…))` or the generated `SetX(…)` to add or replace, `GetOrAdd<T>()` to add
  a default only when missing.
- `world.CompactArchetypes()` and `world.GetFragmentationStats()` are gone: tables stay dense on their own.
- `IForEach` jobs receive only the components: take the entity through `IForEachEntity`.
- `Query` results are ref structs: no `await` in the loop, no storing items in fields, lambdas or LINQ.
- Structural changes belong to the world's owner thread; one made inside a parallel stage or a parallel `[ForEach]`
  throws `InvalidOperationException`. See [threading](/en/docs/guide/threading).
- EECS007 (state in a system) and EECS008 (a system referencing a system) are errors; they were warnings in
  4.0. Move the state into a component or singleton, and let systems communicate through data.
- `QueryEnumerator.Count` and `IsEmpty` are gone: call `world.Count<…>(filter)` / `world.Any<…>(filter)`.
- `UpdateInterval` and `UpdatePhase` should return constants: EECS018 warns when they do not.
- Refs into a table can be invalidated by structural changes of other entities; iteration order follows table rows;
  `AddSingleton` resets an existing singleton in place; stale handles answer `Has` / `TryGet` with false. See
  [refs and await](/en/docs/guide/refs-and-await).

### Fixes [#v4-1-0-fixes]

- `Entity.GetHashCode()` is deterministic across runs, computed from the entity's index and version.
- The analyzer knows generated writers by their symbols: a component named `Settings`, read through
  `entity.Settings`, no longer hides an EECS013.

## 4.0.1 [#v4-0-1]

### New [#v4-0-1-new]

- `WorldOptions.Parallel` runs systems side by side when their generated read/write sets do not conflict, with the
  same result as running them in order. See [threading](/en/docs/guide/threading).
- A `[ForEach]` method may take no component when a `[With<T>]` names what to query:
  `[ForEach, With<Dead>] static void Remove(Entity e)`. See [systems](/en/docs/guide/systems).

## 4.0.0 [#v4-0-0]

### New [#v4-0-0-new]

- A rewrite for .NET 10 in one `EasyEcs` namespace: `World`, `Query`, and a single version-checked `Entity` handle whose
  accessors return `ref T`.
- Synchronous `EcsSystem`s with source-generated `[ForEach]` methods, system groups with `[UpdateInGroup<T>]`,
  recycled entity ids and per-world singletons.
- An analyzer that enforces the ECS principles (EECS006-EECS008). See
  [ECS principles](/en/docs/ecs-principles).

### Changes that need code changes [#v4-0-0-breaking]

Every rename is in the
[migration guide](/en/docs/migration#v3-to-v4-0).

- `Context` is `World` and `GroupOf` is `Query`.
- Systems are synchronous: no UniTask, no async callbacks.
- Events are gone: state changes are components.
