EasyEcs 的每个公开类型和调用，按用途分组，并标出各自的开销。所有类型都在 `namespace EasyEcs` 下。T1..T9 重载各自由一个模板生成
（见[架构](/zh/docs/architecture#source-generators-and-analyzer-easyecsgenerator)）。每个成员的签名、参数和 XML 文档见自动生成的
[API 参考](/zh/docs/reference)，参考页里引用的复杂度就来自本页。

记号：

- *n*：调用涉及的组件数（1 到 9）。
- *c*：实体拥有的组件数。
- *M*：匹配查询的表（原型）数。
- *S*：这些表的行数：存活实体，以及做结构变更的遍历进行期间留下的墓碑。
- *k*：索引中一个键对应的实体数；*L*：一个实体的关系数。
- “均摊”：表和实体数组偶尔会翻倍扩容。

除非另有说明，World 预热之后这些调用都不分配内存，而且只能由 World 的所有者线程调用（见[多线程与并行](/zh/docs/guide/threading)）。

## 类型 [#types]

| 类型 | 种类 | 用途 |
| --- | --- | --- |
| `World` | sealed class，`IDisposable` | 持有实体、组件、单例、索引和系统。 |
| `WorldOptions` | sealed class | `ParallelSystems`、`MaxDegreeOfParallelism`、`InitialEntityCapacity`、`MeasureSystems`、`SystemErrors`、`DestroyLogCapacity`（仅 init）。 |
| `Entity` | readonly struct | 句柄：`Id`、`World`、`IsAlive`。已销毁或 default 的句柄回答查询类调用（`IsAlive`、`Has`、`TryGet`、`TryGetRef`）时返回 false，访问和修改时抛异常，`Destroy` 则直接忽略。可隐式转换为 `EntityId`。 |
| `EntityId` | readonly struct，非托管 | `Index` 和 `Version`，8 字节：组件里用它引用实体。`EntityId.Null` 不指向任何实体。 |
| `IComponent`、`ISingletonComponent` | 标记接口 | 组件和单例结构体。空组件就是标签。 |
| `ITracked` | 标记接口 | 每行记录最后一次写入或移除时的变更 tick（[变更追踪](/zh/docs/guide/change-tracking)）。 |
| `IIndexed<TKey>` | 接口 | World 按 `Key` 建索引的组件；用 `Set` 写入（EECS015）。键是 `EntityId` 时就是指向实体的链接。 |
| `IUniqueIndexed<TKey>`、`UniqueIndexExtensions` | 接口、扩展方法 | 一个键只对应一个实体的索引组件：把别人已有的键给第二个实体的写入会抛异常；`index.Get(key)`、`TryGet`（[索引与关系](/zh/docs/guide/indexes-and-relations)）。 |
| `IDirectIndexed<TKey>` | 接口 | 键能映射到有限个槽的唯一组件（`static Slots`、`static SlotOf(key)`）：索引在哈希旁边多存一个槽数组，`Get` / `TryGet` 和写入时的唯一性检查只读一个元素（[索引与关系](/zh/docs/guide/indexes-and-relations)）。 |
| `IRelation` | 接口 | `DynamicBuffer<T>` 的元素，把所在实体链接到 `Target`（[索引与关系](/zh/docs/guide/indexes-and-relations)）。 |
| `ChildOf` | record struct | `ChildOf(EntityId Parent)`：层级；销毁父实体时子实体一起销毁（[层级](/zh/docs/guide/hierarchy)）。 |
| `IGroup` | 接口 | 用 `Group` 的值拆分表的组件（`world.GroupBy<T>()`，[分组](/zh/docs/guide/groups)）。 |
| `ICleanupComponent`、`Retired` | 标记接口、标签 | 对持有清理组件的实体调用 `Destroy` 会让它退休：实体带着清理组件和 `Retired` 标签继续存活，直到最后一个清理组件被移除（[清理与禁用](/zh/docs/guide/cleanup-and-disable)）。 |
| `Disabled<T>` | 标签 | `T` 被禁用期间存在：值保留，组件对查询隐藏。 |
| `Prefab` | sealed class | 不属于任何 World 的组件值配方（[预制体](/zh/docs/guide/prefabs)）。 |
| `DynamicBuffer<T>` | struct，`IComponent, ITracked` | 每个实体一个列表；通过 `ref` 上的 `DynamicBufferExtensions` 写入（[动态缓冲](/zh/docs/guide/dynamic-buffers)）。 |
| `ValueIndex<T, TKey>` | sealed class | `world.Index<T, TKey>()`：`Find`、`TryFind`、`Count`；键可比较时还有有序遍历（`OrderedIndexExtensions`）。 |
| `RelationIndex<T>` | sealed class | `world.Relations<T>()`：链接到某个目标的实体。 |
| `TargetPolicy`、`TargetPolicyExtensions` | 枚举、扩展方法 | 目标被销毁时链接怎么处理：`Keep`、`Remove`、`Destroy`。 |
| `[EcsSystem]` | 特性 | 标在只有静态成员的 `ref struct` 上：一个系统。钩子是标了 `[OnCreate]`、`[OnUpdate]`、`[OnDestroy]` 的静态方法，参数取 `World`、`SystemHandle`、两者或都不取（[系统](/zh/docs/guide/systems)）。 |
| `SystemHandle` | readonly struct | 加入 World 的一个系统：`Enabled`、`Error`、`Stats`、`LastRunTick`、`RunCount`、`Name`、`Type`、`World`、`IsAlive`；系统移除后句柄失效（成员抛异常）。 |
| `ForEachAttribute` 及其过滤特性 | 特性 | `[ForEach]`（`Parallel = true`、`ChunkRows = n`、`Slices = N`、`SimdMode = SimdMode.Auto` / `Require` / `Off`、`FloatMode = FloatMode.Exact` / `Fast`）、`[With<T>]`、`[Without<T>]`、`[WithAny<T>]`、`[Changed<T>]`、`[Removed<T>]`、`[ChangedAny<T1..Tn>]`、`[RemovedAny<T1..Tn>]`；`[Consume]`（遍历结束后销毁访问过的行）；`[ForEntity]`（通过生成的入口在单个实体上运行的静态方法）。 |
| `Maybe<T>` | ref struct | `[ForEach]` 方法的可选组件参数：`HasValue`、`Value`。 |
| `ReadOnlyMaybe<T>` | ref struct | 只读版本：`Value` 是 `ref readonly`，从不打 tick，带索引的组件也能用；`Maybe<T>` 可以转换成它。 |
| `[View]` | 特性 | 标在由 `ref`（写）、`ref readonly`（读）和 `Mut<T>`（在部分行上写）组件字段加业务方法组成的 `ref struct` 上：一个实体的若干组件，`[ForEach]` 和 `[ForEntity]` 方法可以把它当参数，实体用 `entity.AsX()` / `TryGetX(out X)` 拿到它。 |
| `[Prefab]` | 特性 | 标在每个组件一个字段、字段初始化器即默认值的 partial struct 上：生成器写出 `X.Prefab`，一个由这些默认值构成的 `static readonly Prefab`，用于 `world.Instantiate(X.Prefab)`。 |
| `Mut<T>` | ref struct | `[ForEach]` 方法的组件参数，只有方法真正写了的行才算写入：`Value`、`Write()`、`SetIfChanged(value)`（[变更追踪](/zh/docs/guide/change-tracking)）。 |
| `Reduce<T>`、`IReduction<T>` | 结构体、接口 | `[ForEach]` 参数（按 `ref` 传入），把一次遍历归约到单例 `T`，`T` 实现 `IReduction<T>`（`Identity`、`Combine`）：`Value`、`Combine(value)`。 |
| `[Sum]`、`[Product]`、`[Min]`、`[Max]`、`[All]`、`[Any]` | 特性 | 标在 partial struct 的每个实例字段上（标在 struct 上：给没有自己特性的字段）：生成器写出它的 `IReduction<T>`（`Identity` 和逐字段的 `Combine`）。 |
| `[Accumulate]` | 特性 | 标在可归约的单例上：一个累计值，每次遍历的结果合并进 World 里的值，而不是替换它。 |
| `[LookupKey]`、`[UniqueKey]`、`[Group]` | 特性 | 标在 partial 组件的成员上（`[LookupKey]` 标在类型上：键是整个值）：生成器显式实现 `IIndexed<TKey>.Key`（`IUniqueIndexed<TKey>`）或 `IGroup.Group`。 |
| `[GroupBy]`、`[WhenTargetDestroyed(policy)]`、`[NotSaved]` | 特性 | 每个 World 从第一张含这个类型的表开始应用的设置：分组、目标被销毁时链接的策略；`[NotSaved]`：任何存档都不写这个类型，读档保留 World 自己的单例。 |
| `[OrderBy(box...)]`、`IOrderKey<TKey>` | 特性、接口 | 写在 partial 组件的成员上：每个 World 让含这个组件的表按这个键排序（`Interval`、`Margin`），覆盖成对方法初始化时请求的顺序；生成器写出显式的 `OrderKey` 和 `BoxPoint`。 |
| `[Neighbor]` | 特性 | 写在 `[ForEach]` 方法的参数上：成对中另一个实体的组件（按 `in` 取）或它的 `Entity`；方法对第一个判断给出的截断距离以内的每一对运行一次（成对方法）。 |
| `RowBlocks`、`BlockPair` | ref struct、record struct | 一张有序表的行，每 `Size` 行一簇（8 行，ARM64 上 4 行），每簇一个包围盒（`world.Blocks<T>()`、`entities.Blocks`）：`Count`、`SortedRows`、`Start`、`End`、`Min(axis)`、`Max(axis)`、`Read<T>()`、`Ids`、`Has(row)`、`Pairs(reach, into)`。 |
| `IRowOrder<T>`、`RowKeys` | 接口、静态类 | 给生成代码用：顺序怎样读一行（`Key`、`Point`，静态成员），一个点按格子大小算出的 Morton 码（`RowKeys.Morton`）。 |
| `Scratch<T>` | ref struct | `[ForEach]` 参数：方法在当前线程上的工作内存，在行、遍历和 World 之间保留：`Value`。 |
| `Emit<T>`、`Emitted<T>` | ref struct、结构体 | `[ForEach]` 参数（按值传入），追加记录（`Add`、`AddRange`），遍历结束时按块的顺序并入单例 `Emitted<T>`（`Items`，一个 `DynamicBuffer<T>`）。 |
| `[ForEachRecord]`、`IForEachRecord<T>` | 特性、接口 | 标在第一个参数是 `in T` 的静态方法上：生成器按顺序对 `Emitted<T>` 的每条记录运行它，然后清空（`Emitted<T>.Consume` 运行它的 job）。 |
| `EntityRandom` | record struct | 单例（`Seed`、`Tick`）加纯静态函数：按（种子、实体、tick、流）确定的随机数：`Bits`、`Float`、`Range`、`Chance`。 |
| `IForRange`、`IForSpan<T>` | 接口 | `world.ForParallel` 的 job：`Execute(start, end)` 处理一段下标，`Execute(start, span)` 处理一个列表的元素。 |
| `Lookup<T>`、`LookupExtensions` | ref struct、静态类 | `[ForEach]` 参数，读取任意实体的组件 `T`，调度为对 `T` 的读：`this[id]`、`Read(id)`、`Has(id)`；带索引的 `T` 还可按键查找：`TryFind(key, out entity)`、`Find(key)`、`Count(key)`。 |
| `Lanes` | 静态类 | 批处理方法的流压缩：`Compact(source, mask, destination)` 把掩码选中的元素紧挨着写出；`Rows(mask, first, destination)` 写出选中的行号。 |
| `Tile<TCell, TTile>`、`ITile<TKey>`、`ITileShape`、`TileFaces`、`TileNeighborhood`、`TileBoundary`、`TileIds` | ref struct、接口、枚举 | `[ForEach]` 参数：实体的 `DynamicBuffer<TCell>`，连同它在 `TTile` 网格中邻居的（`TTile` 是带索引的组件，带静态的形状、光环、邻域和边界，以及每个邻居的键），被调度为两者的读：`Pad(from, to, border, mask)`、`Beside(face)`、`Beside(dx, dy, dz)`、`Cells`、`ChangedEdges(next, out changed)`、`Facing(edges)`。 |
| `PaddedTile<TCell, TTile>`、`TileRows<TTile>`、`TileRow<TTile>`、`TileCursor<TCell, TTile>`、`TileStencil` | ref struct、结构体、枚举 | 模板采样的层，外面带一圈 `Halo` 个格子的 halo：`Rows(reads)` 遍历活跃行，`At(row)` 在一行周围采样（`Load128`、`Load256`、`LoadVector`、`this[dx, dy, dz]`），`this[x, y, z]`。 |
| `ISystemGroup`、`ISystemGroupWith<T>`、`ISystemGroupWithout<T>`、`[UpdateInGroup<T>]`、`[UpdateBefore<T>]`、`[UpdateAfter<T>]`、`[UpdateInterval(n, Phase = p)]` | 接口、特性 | 系统分组（可通过接口加过滤条件）、排序与节奏。 |
| `SystemErrorPolicy` | 枚举 | `Throw`（默认）或 `Disable`：系统抛异常时怎么办。 |
| `SystemStats`、`SystemList` | readonly struct | 系统的运行次数、耗时、分配字节数和访问的实体数；`world.Systems`，零分配。 |
| `ScheduleInfo`、`GroupInfo`、`StageInfo`、`SystemInfo`、`StageWait`、`SystemPair` | sealed record | `world.DescribeSchedule()` 的返回值：阶段、读写集、等待关系、只靠注册顺序的系统对，以及每个 `[ForEach]` 方法得到的循环（`SystemInfo.Loops`）；`ToString()`、`ToMermaid()`。 |
| `SystemAccess` | struct | 系统读写了哪些数据；只由生成的代码填写。 |
| `QueryFilter` | readonly struct | `With`、`Without`、`WithAny`、`Changed`、`Removed`、`ChangedAny`、`RemovedAny`、`InGroup`、`Since`、`Slice`；不持有对象引用。 |
| `QueryEnumerator<T1..Tn>`、`QueryItem<T1..Tn>` | ref struct | `Query` 的结果：`item.Entity` 和指向行内数据的 ref（`item.Position`）。 |
| `IForEach<…>`、`IForEachEntity<…>`、`IForEachBatch<…>`、`IForEachMasked<…>`、`INoStructuralChanges` | 接口 | 临时遍历用的结构体 job（`IForEachMasked`：批处理 job，还接收一个 64 行的字，通过的行记成位，向量循环就编译成它）；`EntitySpan` 是批处理一段行对应的实体。 |
| `SingletonRef<T>` | readonly struct | 稳定的单例句柄；`.Value` 是 `ref T`。 |
| `WorldSnapshot` | sealed class | World 的内存副本（`world.Capture()`）。 |
| `ComponentSet` | readonly struct | 组件和单例类型的集合，建一次：`SaveEntitiesWith` 写哪些组件，`SaveWithout` 不写哪些，`LoadKeeping` 保留哪些单例。 |
| `TableInfo`、`ColumnInfo`、`ComponentValue` | record struct | `world.DescribeTables()` 和 `entity.Describe()` 的返回值。 |

## 实体 [#entities]

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `new World(options)` | O(`InitialEntityCapacity`) | `options` 可为 null（默认值）；分配实体数组和空表 |
| `world.CreateEntity()` | 均摊 O(1) | 复用回收的 id |
| `world.CreateEntity(in T1 … in Tn)` | 均摊 O(n) | 直接放进最终的表 |
| `world.CreateEntities(Span<Entity> entities, in T1 … in Tn)` | 均摊 O(count × n) | 整波只过一次闸门，表最多扩容一次；写回句柄 |
| `entity.Destroy()` | O(c) | 表的最后一行补上空位（遍历期间变成墓碑）；回收 id；失效句柄直接忽略；从索引里摘掉；级联销毁 `ChildOf` 子实体并执行目标策略；开了 `WorldOptions.DestroyLogCapacity` 时多写一条 16 字节的记录 |
| `world.DestroyAll<T1..Tn>(filter)` | O(M + S) | 一次过闸门销毁所有匹配并返回数量；遍历期间也安全 |
| `world.CollectIds<T1..Tn>(into, filter)` | O(M)，再加 `into` 写满前读过的行 | 按查询顺序把匹配实体的 id 写进 span，写满为止，返回写了几个：一批有上限的工作，交给 `DestroyEntities`、`SaveEntities` 或结构变更；所有行都匹配的表一次拷贝，`into` 放得下一整个 64 行的字时一次 `Lanes.Compact`；不分配 |
| `world.DestroyEntities(ids)` | O(ids × c) | 一次过闸门、一次级联销毁一组 id 并返回数量；失效的和重复的 id 会跳过；遍历期间也安全 |
| `entity.IsAlive` / `world.IsAlive(id)` | O(1) | |
| `world.TryGetEntity(id, out e)` / `GetEntity(id)` | O(1) | 这个版本的实体不存活时返回 false（或抛异常） |
| `world.EntityCount` | O(1) | |
| `world.Entities` | O(容量) | 按 id 顺序列出存活实体，用于诊断 |
| `world.EnsureEntityCapacity(capacity)` | O(容量) | 预先分配实体数组；已经够大时什么都不做 |
| `world.Reserve<T1..Tn>(count)` | O(n)，外加一次扩容 | 为正好有 `T1..Tn` 的表和实体数组预留空间，接下来 `count` 次带这些组件的创建都不再扩容；也预留它们带索引组件的键、带清理组件时退休所进的表，以及空闲 id 列表（[预留](/zh/docs/guide/prefabs#reserve)） |

## 组件 [#components]

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `entity.Get<T>()` | O(1) | `ref T`：一次版本检查、一次查列、一次存在位测试、一次读取；缺失或不存活时抛异常；对被追踪组件算一次写入 |
| `entity.Read<T>()` | O(1) | `ref readonly T`；从不算写入 |
| `entity.TryGetRef<T>(out bool found)` | O(1) | `ref T`，缺失时是空 ref；找到时对被追踪组件算一次写入 |
| `entity.Has<T>()` / `TryGet<T>(out T)` | O(1) | 缺失或不存活时返回 false；`TryGet` 返回副本（不算写入） |
| `entity.Has<T1..Tn>()` | O(n) | 全部都有才为 true，只查一次记录 |
| `entity.Set(in T1 … in Tn)` | O(n)，需要搬行时均摊 O(c) | 添加或覆盖，最多一次行复制，返回实体；表里已有这一列的组件只置存在位；键变了就重新索引（O(1)）；唯一键已被别的实体占用时，改动任何东西之前就抛异常 |
| `entity.SetIfChanged(in T value)` | O(1) 加一次比较（O(`T` 的大小)）；值不同时同 `Set` | 实体已经是这个值时返回 false，不写、不打 tick、不重建索引；缺失时添加 `T`；按 `IEquatable<T>` 比较，没有就按非托管 `T` 的字节比较 |
| `entity.GetOrAdd<T>()` | O(1)；缺失时，表里有 `T` 的列为 O(1)，否则均摊 O(c) | `ref T`；只在缺失时添加默认值；对被追踪组件算一次写入；新加的被索引 `T` 按默认值的键进索引（唯一键则占用这个键） |
| `entity.GetOrAdd<T>(in T value)` / 生成的 `GetOrAddX(…)` | 同 `GetOrAdd<T>()` | `ref T`；只在缺失时添加 `value`（和 `Set` 一样进索引、进分组、占用唯一键）；已有 `T` 的实体保留自己的值 |
| `entity.Remove<T1..Tn>()` | O(n) | 清存在位，行留在原处；缺失的组件忽略；被追踪组件的移除会打 tick（`[Removed<T>]`）；返回实体 |
| `entity.Disable<T>()` / `Enable<T>()` | O(1)；一张表第一次禁用时搬一次行 | 值保留，但查询、`Has` 和 `Get` 都当它不存在；禁用算移除，启用算写入；无事可做时返回 false |
| `entity.IsDisabled<T>()` | O(1) | |
| 生成的成员：`entity.X`、`HasX`、`TryGetX`、`GetOrAddX()`、`SetX(…)`、`SetXIfChanged(…)`、`RemoveX()`、`WriteX()`、`DisableX()`、`EnableX()`、`IsXDisabled`；标签 `IsX`、`SetX()`；`world.XIndex` | 同对应的泛型调用 | 每个组件的 C# 14 扩展成员（[生成的成员](/zh/docs/guide/entities-and-components)）；`entity.X` 等于 `Get`，被追踪或被索引的组件则等于 `Read`，写入改用 `WriteX()` 或 `SetX(…)`；可比较的被追踪、被索引或分组组件还有 `SetXIfChanged(…)`；EasyEcs 自带的 `ChildOf` 也有这些成员（没有 `DisableChildOf` / `EnableChildOf`：它不能被禁用），`Retired` 有 `entity.IsRetired` |

## 预制体与克隆 [#prefabs-and-cloning]

副本的每个 `DynamicBuffer<T>` 都是自己独立的列表，会立刻进入索引，它拥有的每个被追踪组件都算一次写入；源上没有的组件在副本上也没有，不算移除。

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `new Prefab()` | O(1) | 空配方；只分配一次私有存储 |
| `new Prefab(basePrefab)` | O(c) | 变体：复制所有值（和成员），之后各改各的 |
| `prefab.Set(in T1 … in Tn)` | O(n)，新增组件时均摊 O(c) | 添加或替换值；返回预制体 |
| `prefab.Remove<T1..Tn>()` | O(n) | 缺失的忽略；返回预制体 |
| `prefab.Has<T>()` / `Read<T>()` | O(1) | 预制体没有 `T` 时 `Read` 抛异常 |
| `prefab.SetBuffer<T>(params ReadOnlySpan<T>)` | O(n) | 由这些元素组成的 `DynamicBuffer<T>`；每个实例都有自己的列表 |
| `prefab.SetAbsent<T>()` | O(1) | 有 `T` 的列但没有这个组件：实例没有它，之后加上它只在所在的表里翻转存在位，不搬行 |
| `prefab.AddMember()` | O(1) | 预制体组的一个成员：实例化任何一个都会创建全部；指向成员的 `EntityId` 字段在每个实例上改写 |
| 生成的成员：`prefab.X`、`HasX`、`SetX(…)`、`RemoveX()`；标签 `IsX`、`SetX()`；缓冲 `SetLoot(items…)` | 同对应的泛型调用 | 写方法返回预制体；属性只读；不算任何 World 的结构变更 |
| `[Prefab]` 结构体生成的 `X.Prefab` | 类型首次使用时 O(c)，只一次 | 由字段初始化器的值（没有初始化器的字段取 `default`）构成的预制体，所有 World 共用：实例化它，或者修改它的变体（`new Prefab(X.Prefab)`） |
| `world.Instantiate(prefab)` | O(c) | 一次行复制；目标表每个预制体表只找一次并缓存；遍历期间也安全（新实体不会被这次遍历访问）；预制体组为 O(成员数 × c) |
| `world.Instantiate(prefab, Span<Entity> entities)` | O(count × c) | 整波只过一次闸门，表最多扩容一次 |
| `world.Instantiate(prefab, in T1 … in Tn)` | 均摊 O(c + n) | 预制体的值加上给定的值（覆盖预制体里的，或者新加；给定的组件若在预制体里被禁用则启用），一次行复制直接进最终的表，不经过中间表；给定的 `ChildOf` 会挂上层级，唯一键先检查；预制体组为 O(成员数 × c) 再加一次搬行，组件给传入的那个预制体对应的实体 |
| `world.Instantiate(prefab, Span<Entity> entities, in T1 … in Tn)` | O(count × (c + n)) | 每个实例都是同样的值；只过一次闸门，表最多扩容一次，每个给定的列一次填满 |
| `world.Reserve(prefab, count)` | O(c)，外加一次扩容 | 为接下来 `count` 个实例要进的表预留空间，生成波次在 tick 中不再扩容；也预留实例的索引键、退休表和空闲 id（不含缓冲列表：用 `ReserveBuffers`） |
| `world.ReserveBuffers(prefab, count)` | O(c + 行数)，外加一次性 O(lists) 次分配 | 给预制体带的每个 `DynamicBuffer<T>` 补池（`FillPool`），直到每个实例、每个带它的成员都有一个列表；整个进程生效，多个预制体之间不累加 |
| `entity.Clone()` | O(c) | 同一 World、同一张表里的新实体，复制全部组件；实体不存活或已退休（因清理组件而保留）时抛异常 |

## 动态缓冲 [#dynamic-buffers]

`new DynamicBuffer<T>()` 在第一次写入之前不持有列表。读可以通过任何引用（`in`、`Read<T>()`）；写必须通过 `ref`，并算作被追踪的写入。

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `bag.Count`、`bag.Capacity`、`bag[i]`、`AsReadOnlySpan()`、`GetEnumerator()` | O(1) | 只读；下标越界抛异常 |
| `bag.Add(item)` / `AddRange(items)` | 均摊 O(1) / O(items) | `items`：span、多个值（`params`）或 `CollectionsMarshal.AsSpan(list)`；只在缓冲区扩容时分配 |
| `bag.Insert(i, item)` / `RemoveAt(i)` | O(count) | 保持顺序 |
| `bag.RemoveAtSwapBack(i)` | O(1) | 最后一个元素移到 `i` |
| `bag.Clear()` | O(1)，元素含引用时 O(count) | 保留容量 |
| `bag.EnsureCapacity(n)` / `AsSpan()` | 扩容时 O(count) / O(1) | `AsSpan()` 可写 |
| `bag.SetCount(n)` | O(增加或去掉的元素数) | 返回要写的 span（`AsSpan()`）；增加的元素为 `default`；只有缓冲扩容时分配 |
| `bag.TrimExcess()` | O(count) | 重新分配到 count 大小；空缓冲把列表还给池，不再持有列表 |
| `DynamicBuffer<T>.MaxPooledLength` | O(1) | 销毁的 `T` 缓冲还给[缓冲池](/zh/docs/guide/dynamic-buffers#pool)的列表最长多少个元素（默认 4 KB 能放下的个数）；按元素类型、整个进程生效，启动时设置 |
| `DynamicBuffer<T>.FillPool(lists)` | 一次性 O(lists) 次分配；池里够了就是 O(1) | 往池里放 `MaxPooledLength` 个元素的空列表，直到有 `lists` 个；按元素类型、整个进程生效，在设好 `MaxPooledLength` 之后调用 |

快照、存档或克隆一列缓冲时会复制元素：O(元素数)，每个实体一个新列表。

## 查询 [#queries]

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `[ForEach]` 方法 / `world.ForEach<T1..Tn, TJob>(ref job, filter)` | O(M + S) | 最快：结构体 job，没有委托 |
| `world.ForEach(values…, static (ref P p, …) => …)` / `ForEachParallel(…)` | O(M + S) | lambda 遍历：生成器把每处调用编译成同参数、同方法体的 `[ForEach]` 方法会得到的 job（包括向量循环）；lambda 前最多 4 个值，成为 job 的字段（变更过滤的 tick 放在最前面）；0 B；调用没被编译时抛异常（EECS095） |
| `world.ForEachEntity<T1..Tn, TJob>(ref job, filter)` | O(M + S) | job 还会拿到 `Entity` |
| `entity.Run<T1..Tn, TJob>(ref job)` / `Run(ref job, filter)` | O(n)，过滤条件每个组件再加 O(1) | 单个实体；实体失效、缺组件或被过滤掉时返回 false；job 做结构变更后 ref 仍然有效 |
| `entity.Run<T1..Tn, TJob>(ref job, in filter, since)` | O(n)，再加 O(过滤条件提到的组件数) | 同 `Run(ref job, filter)`，只是用 `since` 作过滤条件的 tick：和 `filter.Since(since)` 的检查一样，但不拷贝过滤条件（一个 `static readonly` 过滤条件，`[ForEntity, Changed<T>]` 的入口就这样传） |
| `[ForEntity]` 方法：生成的 `Owner.Method(entity, values…)` | 同 `entity.Run` | 用生成的 job 调 `entity.Run`（`ref` 参数构成 `WriteMask`，过滤特性构成一个 `static readonly` 过滤条件）；返回 false 的情况同 `Run`；带 `[Changed<T>]` 的方法第二个参数是 `since`；接收单例或 `World` 的方法，对不属于任何 World 的实体返回 false |
| `[ForEach]` / `[ForEntity]` 方法或 lambda 遍历的 `[View]` 参数 | 同把这些组件直接当参数 | job 在行上构造视图（每个字段一个 ref，不拷贝）；`ref` 字段算系统的写（被追踪的组件每个访问过的行都打 tick），`Mut<T>` 字段算只在写过的行上打 tick 的写（没有向量循环），`ref readonly` 字段算读；调用视图成员的方法，和把同样代码写在参数上一样能得到向量循环（成员被内联）；接收视图的 lambda 遍历保留标量循环；同一组件被访问两次报 EECS099 |
| `[View]` 生成的 `entity.AsX()` / `TryGetX(out X)` | O(字段数) | 每个字段一个 ref（`ref` 用 `Get`，`ref readonly` 和 `Mut<T>` 用 `Read`，`Mut<T>` 的写入会打 tick）；缺组件或实体不存活时 `AsX` 抛异常，`TryGetX` 返回 false；不是结构变更 |
| `[ForEach, Consume]` | 遍历本身，之后 O(M + S)：一次 `DestroyAll`（整张表一起释放）或每行一次销毁 | 遍历结束时销毁访问过的行：方法不做结构变更时按它的过滤条件做一次 `DestroyAll`，否则在方法处理完每一行后销毁那一行；遍历期间才开始匹配的行保留；批量销毁的遍历抛异常时什么也不销毁；所在的系统独自运行；不能和 `Slices` 一起用（EECS085） |
| `[ForEach]` 成对方法（`[Neighbor]` 参数） | 每次遍历 O(N + M) 画出窗口的包围盒，有窗口离开包围盒时 O(W log W + 窗口对数)，之后 O(截断距离内的对数) 次调用，方法符合条件时每次调用处理一个向量的行；N、M = 行数和邻居数，W = 每 `Vector<float>.Count` 行一个的窗口数 | 行和邻居的距离通过方法的截断判断（每行一个或统一一个）的每一对都运行，包括行自己的实体；每个通道按查询顺序遇到邻居的表、按行的顺序遇到它们的行，所以向量循环和逐对运行的方法逐位相同；第一次遍历让被比较组件的表排序（判断用到的轴上的 Morton 码）；单线程，所在的系统独自运行；预热后不分配 |
| `world.ForEachBatch<T1..Tn, TJob>(ref job, filter)` | O(M + S / 64 + 段数) | 连续行的 span；不能做结构变更 |
| 带向量循环的 `[ForEach]` 方法（生成的，[向量循环](/zh/docs/guide/systems#vector-loops)） | O(M + S / L + 段数)，L = 每个向量的行数（先 `Vector512`，再 `Vector<T>`；按通道大小和 CPU，2 到 64） | 行、结果（`FloatMode.Fast` 之外）、变更 tick 和读写都和逐行运行的方法相同；每段先广播一次统一值，不足 L 行的尾部由方法自己跑；单线程时按 `ForEachMasked` 运行（只有部分行通过的字，每 L 行一个带掩码的向量），并行时按 `ForEachBatchParallel` 跑每块里连续的行；2 到 4 个字段的组件每个向量多一次解交错加载和一次交错存储（没有 AVX2 或 AVX-512 时每行都由方法跑）；`Reduce<T>` 每条通道每个字段一个累加器，每段合并一次；零分配 |
| `world.ForEachMasked<T1..Tn, TJob>(ref job, filter)` | O(M + S / 64 + 段数 + 部分通过的字数) | 同 `ForEachBatch`，但只有部分行通过的 64 行字整个交给 job，通过的行记成位（`IForEachMasked`），不再按每一段通过的行各调一次；全部通过的字并进连续段 |
| `world.ForEachParallel<T1..Tn, TJob>(ref job, filter, chunkRows)` / `ForEachEntityParallel` / `ForEachBatchParallel`（一块中连续行的 span） | O(M + S)，分摊到最多 `MaxDegreeOfParallelism` 个线程 | `INoStructuralChanges` job；每块 1,024 到 `World.MaxChunkRows` 行（job 写被追踪组件时为 4,096 的整数倍），或 `chunkRows` 向上取整到 64（`[ForEach(ChunkRows = n)]`；这时遍历前打开 O(B) 个区段，B 为 4,096 行的区段数，每写 64 行一次原子 OR），每块一个 job 副本（job 做归约 `Reduce<T>` 时保留这些副本，按块的顺序合并，O(块数)）；只在划算时唤醒助手线程 |
| `world.ForParallel<TJob>(count, ref job, chunkRows)` / `ForParallel<T, TJob>(ref buffer, ref job, chunkRows)` | O(count)，分摊到最多 `MaxDegreeOfParallelism` 个线程 | 和 `ForEachParallel` 同一个运行器、同样的块（没有表：没有变更 tick，每块 1,024 到 `World.MaxChunkRows`，或 `chunkRows` 向上取整到 64）；每块一个 job 副本，不合并回来；结构被冻结（结构变更抛异常）；每种 job 类型第一次调用之后 0 B |
| `foreach (var item in world.Query<T1..Tn>(filter))` | O(M + S) | 指向行内的 ref：被追踪组件的每个被访问行都算写入；循环里不能 `await` |
| `foreach (var item in world.Read<T1..Tn>(filter))` | O(M + S) | 指向行内的 `ref readonly`：不打 tick；其余同 `Query` |
| `world.Count<T1..Tn>(filter)` | O(M)，需要测位的表再加 S / 64 | 累加表计数，或数存在位（和 tick），AVX-512 下每步 8 个字 |
| `world.Any<T1..Tn>(filter)` | 最坏 O(M + S / 64) | 找到第一个就停 |
| `QueryFilter.Create().With<T>().Without<U>().WithAny<V>()` | O(1) | 只建一次，放在 `static readonly` 字段里；多个 `WithAny` 组成一个“至少有一个”的集合 |
| `filter.Changed<T>(since)` / `[Changed<T>]` | O(1)；遍历跳过 `since` 之前写过的表、4,096 行的区段和 64 行的字 | 被追踪的 `T` 在 `since` 及之后被写过的行（[变更追踪](/zh/docs/guide/change-tracking)）；一个过滤条件只有一个 tick |
| `filter.Removed<T>(since)` / `[Removed<T>]` | 同 `Changed` | 在 `since` 及之后失去被追踪的 `T`、且现在仍没有它的实体；已销毁的实体不报告（由销毁日志报告） |
| `filter.ChangedAny<T1..Tn>(since)` / `[ChangedAny<T1..Tn>]` | 构建 O(n)；遍历时跳过集合里的列自 `since` 以来都没被写过的表，以及没有任何列写过的块和位字 | 2 到 9 个被追踪组件里至少有一个在 `since` 及之后被写过的行；一个过滤条件的所有 `ChangedAny` 调用合成一个集合，和其他条件按 AND 组合；每个过滤条件一个 tick |
| `filter.RemovedAny<T1..Tn>(since)` / `[RemovedAny<T1..Tn>]` | 同 `ChangedAny` | 在 `since` 及之后至少失去其中一个、且现在仍没有它的实体 |
| `filter.Slice(index, of)` / `[ForEach(Slices = N)]` | O(1)；一次遍历约访问 S / N 行，按 64 行位字切分 | 只用于 `ForEach` 系列调用（`Query`、`Read`、`Count`、`Any`、`DestroyAll`、`entity.Run(ref job, filter)` 和批量调用会抛 `ArgumentException`）；分帧方法访问第 `RunCount % N` 片；不能和 `[Changed<T>]` / `[Removed<T>]` 一起用（EECS035） |
| `filter.InGroup<T>(group)` | O(1)；遍历只走这个分组的表 | [分组](/zh/docs/guide/groups) |
| `filter.Since(since)` | O(1) | 把 `Changed`、`Removed`、`ChangedAny` 和 `RemovedAny` 的 tick 换掉，不用重建过滤条件：一个过滤条件，带着每个客户端的 tick 跑 |

一种查询形状第一次使用时建缓存项，O(所有表)，在共享闸门内完成。之后的查找要么命中备忘，要么一次哈希探测。新建一张表
（第一个拥有新组件组合的实体）的开销是 O(表数 + 已缓存的查询形状数)，因为它要加入所有匹配的缓存查询。两者都是冷路径。

`Mut<T>`：只在部分行上写的组件，作为 `[ForEach]` 参数：

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `mut.Value` | O(1) | `ref readonly T`；不打 tick |
| `mut.Write()` | O(1)：一次打 tick（方法会做结构变更或并行运行时，再加一次实体查找） | `ref T`，这一行记为写入（被追踪的 `T`）；每次写入调用一次 |
| `mut.SetIfChanged(in T value)` | O(`T` 的大小)，值不同时再加一次 `Write()` | 存入了就返回 true；按 `IEquatable<T>` 比较，没有就按非托管 `T` 的字节比较；没实现 `IEquatable<T>` 的托管 `T` 抛 `NotSupportedException` |

`Lanes`，用于以向量比较选行的批处理方法：

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `Lanes.Compact<T>(source, mask, destination)` | O(1)：最多 64 个元素；8 字节或 4 字节的元素，AVX-512 为 8 步或 4 步向量操作，没有选中元素的步跳过；没有 AVX-512 时，选中不超过 12 个就每个选中元素一步，否则 AVX2 为 16 步或 8 步，128 位向量（ARM64 的 NEON、SSSE3）对 4 字节元素为 16 步，其余情况每个元素一步，直到最后一个选中的元素 | 对 `mask` 的每个置位 `i`，按顺序把 `source[i]` 写到 `destination` 开头，返回 `PopCount(mask)`；不读 `source` 之外的内存，只写这么多个元素；某一位落在 `source.Length` 或之后、或 `destination` 短于 `PopCount(mask)` 时抛出 `ArgumentException`；不分配 |
| `Lanes.RowNumbers(mask, first, destination)` | O(1)：对 0 到 63 这些数做 `Compact`，再按向量加上 `first` | 对 `mask` 的每个置位 `i`，按顺序写出 `first + i`，返回 `PopCount(mask)`：把条件通过的一个字的行变成行列表；`destination` 太短时抛出 `ArgumentException`；不分配 |

`Tile<TCell, TTile>`，网格分块上模板计算的 `[ForEach]` 参数，以及它加载的带边层：

| API | 复杂度 | 说明 |
| --- | --- | --- |
| 遍历中的每个实体 | O(邻居数) 次哈希探测：`Faces` 为 4 或 6，`FacesAndEdges` 为 8 或 18，`All` 为 8 或 26 | 生成的 job 按键找一次邻居，方法接收的同一网格的所有分块共用；网格的索引在遍历之前建好 |
| `tile.Pad(from, to, border, mask)` / `tile.Pad()` | O(层数 × (Width + 2r) × (Depth + 2r))，r 为 `Halo`；每行一到两次向量拷贝 | 把这些层拷进线程的纹理，外面一圈 r 个格子，上下各多 r 层（没有邻居处按形状的 `Boundary`：`border`、钳制或镜像）；传 `mask` 时每层记一个活跃行的字；线程有了纹理之后不分配；形状无效（EECS072）、层超出 `0..Height - 1` 或缓冲比形状短时抛出异常 |
| `tile.Beside(face)` / `tile.Beside(dx, dy, dz)` / `tile.Cells` | O(1) | 邻居的 id（没有、或不在邻域内时为默认值）/ 实体的格子 |
| `tile.ChangedEdges(next, out changed)` | O(格子数)，逐行按字节比较 | 这一步和格子是否不同，以及边缘（深 r 个格子）变了的面 |
| `tile.Facing(edges)` | 每个邻居 O(1) | 把这些边缘读进光环的邻居，隔着面、棱和角 |
| `padded.Rows(reads)` | 每层、每访问一行 O(1)：一次尾零计数 | 模板（`TileStencil`，最远 r）读到不为零格子的行，逐层；加载时没传 `mask` 则抛出异常 |
| `padded.At(row)` | O(1) | 这一行的第一个格子；检查行在范围内 |
| `cursor.Load128<TLane>(dx, dy, dz)` / `Load256` / `LoadVector` / `cursor[dx, dy, dz]` | O(1)：一次非对齐加载 | 偏移在这一行的 r 个格子、行、层之内；每条轴一次无符号比较，常量时被消掉 |
| `padded[x, y, z]` | O(1) | 纹理的任意格子，有检查 |

## 索引 [#indexes]

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `world.Index<T, TKey>()` | O(1)；第一次调用时创建 | 每个 World、每个被索引组件一个；换另一种键类型会抛异常 |
| `index.Count(key)` / `TryFind(key, out Entity)` | O(1) | 一次哈希探测（键是实体时是一次数组访问）；第一次查找时把每行索引一遍 |
| `index.KeyCount` | O(1) | 有实体持有的不同键的个数（有多少个公会有成员），随实体加入和离开各个键维护 |
| `index.Find(key)` | O(1)，然后每个实体 O(1) | 用于 `foreach` 的 `ref struct`；循环中可以销毁实体，不能修改 `T` |
| `index.Find(key).Count` / `world.Children(parent).Count` | O(1) | 查找时拥有这个键的实体数（不用遍历两次就能确定缓冲区大小）；循环中销毁的实体会被循环跳过，但仍计入 |
| `index.Ascending()` / `Descending()` | 第一次遍历 O(键数 log 键数)，之后每个实体 O(1) | 键可比较时的有序遍历（排行榜、计时器）；第一次遍历之后索引保持键有序：每出现或消失一个键 O(log 键数) 加一次块移动 |
| `index.Range(min, max)` / `RangeDescending(min, max)` | 第一次遍历 O(键数 log 键数)，之后 O(log 键数) 定位 `min`，每个实体 O(1) | 闭区间 |
| `index.WhenTargetDestroyed(policy)` | O(1)；之后每个被销毁的实体 O(1) | `EntityId` 键：目标被销毁时，指向它的组件 `Keep`（默认）、`Remove` 或 `Destroy` |
| `index.Get(key)` / `TryGet(key, out Entity)` | O(1)：一次哈希查找；直接索引组件的键在自己的槽里时，读一次数组 | 唯一组件（`IUniqueIndexed<TKey>`）：这个键对应的那个实体；没有时 `Get` 抛 `InvalidOperationException` |

唯一组件的索引在第一张含它的表出现时就建好，所以每次写入都在改动之前检查：`Set` 和 `CreateEntity` 每个变了的键多一次哈希查找；
`SetAll` 和 `EnableAll` 对匹配的行多遍历一遍；`Clone`、`Instantiate`、`LoadEntities`、`LoadEntitiesInto` 和 `MoveEntities` 为
O(行数 × 唯一列数)；`Load` 为 O(行数)。键已被占用时抛 `InvalidOperationException`（存档里同一个键出现两次则是 `InvalidDataException`），
World 保持原样。

| `relations.Find(target).Count` | O(1) | 查找时指向 `target` 的链接数；循环中去掉的链接会被循环跳过，但仍计入 |

## 有序表 [#ordered-tables]

按某个组件排序的表让行保持键的顺序（成对方法的距离判断用位置的 Morton 码，或 `[OrderBy]` 声明的键），按节奏重新排序，
每 `Size` 行一簇（8 行，ARM64 上 4 行），每簇一个包围盒。N = 表的行数，C = 列数，K = 键里会变的字节数，B = 簇数。

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `world.OrderRows<T, TOrder>(axes, cell, interval, margin)` | O(表数)，只做一次 | 给生成的初始化代码用：现在和以后含 `T` 的表都按 `TOrder` 的键排序，下一次更新第一次排序，之后每 `interval` 次更新一次；一个组件以第一次请求为准，`[OrderBy]` 覆盖它；遍历中调用抛出异常 |
| 排序（按节奏的更新、`world.SortRows<T>()`） | 行要移动时 O(N × (K + C))，已经有序时 O(N) | 对 (键, 行) 做 LSD 基数排序，所有行相同的字节跳过；在结构闸门内对每一列、存在位、变更 tick 和槽位做一次置换（引用和句柄缓存的行失效，和任何结构变更一样）；没有 `T` 的行排在最后；重新画包围盒；稳定状态 0 B（池化缓冲）；`SortRows` 在遍历中调用抛出异常 |
| 没有任何顺序的表 | 0 | 不排序，没有包围盒，行移动处只多一次 null 判断 |
| `world.Blocks<T>()` | O(1)，遍历 O(表数) | 每张按 `T` 排序的表的 `RowBlocks`；组件没有顺序时一个也没有 |
| `blocks.Min(axis)` / `Max(axis)` / `Start(b)` / `End(b)` / `Read<T>()` / `Ids` / `Has(row)` | O(1) | 每簇包围盒的边、一簇的行（`[b * Size, min((b + 1) * Size, SortedRows))`）、表的只读列；`SortedRows` 之后的行是排序后加入的，不在任何簇里；移进某簇的行会扩大那簇的包围盒 |
| `blocks.Pairs(reach, into)` / `Pairs(other, reach, into)` | O(B log B + 对数) | 每个轴上包围盒相距不超过 `reach` 的簇对（每簇和自己一对，其余每对一次），写到 `into` 写满为止；返回总数；稳定状态 0 B |
| `entities.Blocks`、`entities.FirstRow` | O(1) | 批处理方法所在表的簇，以及这段行开始的行号 |

## 快照、存档与迁移 [#saves]

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `world.Capture()` / `Capture(into)` | O(实体数 × 组件数 + 表数 + 单例数) | 按值复制；`Capture(into)` 复用之前快照的数组，够大之后不再分配；遍历进行时不可用 |
| `world.Restore(snapshot)` | O(实体数 × 组件数 + 表数 + 单例数) | 快照里的句柄重新有效，之后创建的句柄失效；每个恢复的行都算写入（或移除） |
| `world.Save(output)` | O(实体数 × 组件数) | 把 World 写成字节：非托管行原样写出，托管值走 Nino；缓冲够大之后不再分配；输出是 `NinoArrayBufferWriter` 时原地写入，其他 writer 多复制一次 |
| `world.SaveWithout(output, in ComponentSet exclude)` | O(实体数 × 组件数) | 不写 `exclude` 里的组件和单例（`Disabled<T>` 跟着 `T` 一起不写），这些类型不需要格式化器；缓冲够大之后不再分配 |
| `world.Load(input, markWritten)` | O(实体数 × 组件数) | 实体保留原 id；组件布局变了会抛 `InvalidDataException`，World 保持原样；`markWritten: false`：加载的行算作从未写过 |
| `world.LoadKeeping(input, in ComponentSet keep, markWritten)` | O(实体数 × 组件数) | `keep` 里的单例保持 World 现在的样子（跳过存档里的值）；`keep` 里有组件时抛 `ArgumentException`；`markWritten` 只作用于加载的行 |
| `world.SaveEntities(output, ids)` | O(给定实体数 × 组件数) | 相关的实体（一个玩家和它拥有的东西），交给另一个 World 或进程 |
| `world.SaveEntitiesWith(output, ids, set)` | O(给定实体数 × 组件数) | 只写 `ComponentSet` 里的组件（建一次：`ComponentSet.Create().With<T>()`，每个类型 O(1)）；集合里有单例时抛 `ArgumentException` |
| `world.SaveEntitiesWithout(output, ids, set)` | O(给定实体数 × 组件数) | 写集合以外的所有组件（加载后会重新算出的数据）；集合里有单例时抛 `ArgumentException` |
| `ComponentSet.Create().With<T>()` / `WithSingleton<T>()` / `With(type)` | 每次 O(1)；`With(type)` 一次查找（冷路径） | `With(type)` 接受组件或单例类型；`Contains<T>()` / `ContainsSingleton<T>()` 为 O(1) |
| `world.LoadEntities(input, entities)` | O(实体数 × 组件数) | 新 id；指向组内实体的 `EntityId` 字段会改写，其他的变成 `EntityId.Null` |
| `world.LoadEntitiesInto(input, targets, markWritten)` | O(实体数 × 组件数) | 读到已经存在的实体上：每个实体最多换一次表，存档里没有的组件保持不变；`markWritten: false`：加载的组件算作从未写过 |
| `world.MoveEntities(target, ids, moved)` | O(实体数 × 组件数) | 搬到本线程的另一个 World，不经过编码；原实体被销毁（持有清理组件的则退休，清理组件留在原实体上）；退休的实体被跳过 |
| 这些调用的 `ids` / `entities` | 传参 O(1) | span：数组、`[a.Id, b.Id]` 或 `SaveEntities(output, a.Id, b.Id)`（在栈上构造），列表写成 `CollectionsMarshal.AsSpan(list)`：不复制、不分配 |

细节见[快照](/zh/docs/guide/snapshots)、[存档](/zh/docs/guide/saves)、[迁移与卸载](/zh/docs/guide/migration-and-unload)。

## 系统、单例与维护 [#systems-singletons-maintenance]

| API | 复杂度 | 说明 |
| --- | --- | --- |
| `world.AddSystem<T>(changesFromNow)` | O(s²)，s 为所在分组的系统数 | 返回 `SystemHandle`；调用 `[OnCreate]` 方法；重建顺序和阶段（冷路径）；World 已有这个系统、排序出现环时抛异常，没有任何程序集为该类型生成代码时抛 `NotSupportedException`；`changesFromNow: true`：第一次运行只看调用之后的写入 |
| `world.RemoveSystem<T>()` | O(s²) | 调用 `[OnDestroy]` 方法；返回是否移除了系统；它的句柄随之失效 |
| `world.HasSystem<T>()` / `System<T>()` / `TryGetSystem<T>(out system)` | O(1) | 不存在时 `System<T>` 抛异常，`TryGetSystem` 返回 false 和默认句柄 |
| `system.Enabled` / `Error` / `LastRunTick` / `RunCount` / `Stats` / `Name` / `Type` / `World` | O(1) | World 里这个系统的记录；句柄失效后抛 `InvalidOperationException` |
| `system.IsAlive` | O(1) | 系统移除或 World 释放后为 false |
| `world.Update()` / `world.Update<TGroup>()` | 分组内所有系统之和 | 同步、零分配；`Dispose` 之后调用抛 `ObjectDisposedException` |
| `world.ChangeTick` | O(1) | 每个系统阶段加一，每次更新结束再加一 |
| `world.AddSingleton<T>()` / `GetSingleton<T>()` / `GetOrAddSingleton<T>()` | O(1) | `ref T`；`AddSingleton` 在单例已存在时抛异常；`GetSingleton` 在缺失时抛异常 |
| `world.GetOrAddSingleton<T>(in T value)` / 生成的 `GetOrAddX(…)` | O(1) | `ref T`；只在缺失时添加 `value`；已有 `T` 的 World 保留自己的值 |
| `world.SingletonRef<T>()` | O(1) | 稳定句柄；单例没添加时抛异常；`.Value` 一次读取 |
| `world.TryGetSingleton<T>(out T)` / `HasSingleton<T>()` / `RemoveSingleton<T>()` | O(1) | 单例不存在时 `RemoveSingleton` 返回 false |
| 生成的成员：单例 `X` 的 `world.X`、`HasX`、`GetOrAddX()`、`SetX(…)`、`RemoveX()` | 同对应的泛型调用 | |
| `world.Systems` | 遍历 O(系统数)，`Count` 为 O(分组数) | 按执行顺序列出所有分组的系统，零分配 |
| `world.DefaultUpdateCount` | O(1) | 默认分组已更新的次数 |
| `world.UpdateCount<TGroup>()` | O(1) | 到目前为止 `Update<TGroup>()` 的调用次数，正在跑的这次也算（第一次之前为 0）：`[UpdateInterval]` 数的就是它 |
| `world.RemoveTypes(assembly)` / `RemoveTypes(context)` | O(拥有这些组件的实体数 + 表数 + 已缓存查询数) | 把插件的系统、单例、索引和组件移出 World，它的 `AssemblyLoadContext` 才能卸载；会分配（冷路径） |
| `world.DescribeTables()` | O(表数 + 列数) | 每张表的列、行数、容量和字节数；会分配（冷路径） |
| `world.DescribeSchedule()` | O(分组数 × 系统数³) | 每个分组的阶段、每个系统的读写集、等待关系和只靠注册顺序的系统对；会分配（冷路径）；任何线程都能调用 |
| `schedule.ToString()` / `ToMermaid()` | O(系统数 + 等待数 + 系统对数) | 缩进文本形式，或 mermaid 流程图；会分配 |
| `world.TrimExcess()` | O(表数 × (缓存的查询数 + 快照数) + 被缩小的表的行数 × 列数) | 删掉空表（快照持有行的表除外），把其他表缩到行数向上取整的 2 的幂（至少 64），释放存档、读档和迁移用的缓冲；会分配（冷路径）；只在所有者线程、不在遍历中调用；删掉的表和边按需重建 |
| `world.DestroyedSince(since, Span<EntityId> into, out int count)` | O(count) | 在 `since` 及之后销毁的实体，从旧到新；`since` 早于 `DestroyLogOldestTick` 时返回 false（什么都不写）：需要重新同步；`WorldOptions.DestroyLogCapacity` 为 0 时抛异常；零分配；所有者线程或并行阶段的线程 |
| `world.DestroyLogOldestTick` | O(1) | `DestroyedSince` 能回答的最早 tick；日志关闭时为 `ulong.MaxValue` |
| `entity.Describe()` | O(c) | 实体组件的装箱副本，禁用的会标出；会分配（冷路径） |
| `world.Dispose()` | O(系统数 + 实体数 + 表数) | 按逆序调用每个系统的 `[OnDestroy]` 方法，然后释放存储；所有系统句柄失效 |

`WorldOptions.SystemErrors`：`SystemErrorPolicy.Throw`（默认：异常从 `Update()` 抛出，`[OnDestroy]` 的异常从 `Dispose` 抛出）或
`Disable`（关掉出错的系统，把异常留在 `system.Error` 里，直到重新启用；出错的那次运行照样推进 `LastRunTick`）。
`WorldOptions.MeasureSystems` 把每次运行记到 `system.Stats`（`Runs`、`LastTime`、`TotalTime`、`AverageTime`、`LastAllocated`、`TotalAllocated`、
`LastEntities`、`TotalEntities`，读取都是 O(1)），代价是每次运行（以及并行 `[ForEach]` 的每个辅助块）多读两次时间戳和两次分配计数，
每个 `[ForEach]` 遍历再数一次匹配数。`WorldOptions.DestroyLogCapacity`（默认 0，关闭）为 `DestroyedSince` 预先分配这么多条 16 字节的记录：
`new World` 时一次 O(容量)。

值与句柄，全部 O(1)：`entity.Id` / `World`，`id.Index` / `Version`，`==` / `Equals` / `GetHashCode`（id 和版本）/ `ToString`；
`snapshot.EntityCount`；`system.LastRunTick`、`RunCount`、`Enabled`、`Error`、`Stats`、`World`。
