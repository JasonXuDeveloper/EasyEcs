这里从新到旧列出 EasyEcs 各版本之间的变化，只写影响使用者代码的部分。跨版本升级需要改代码时，步骤见
[迁移指南](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/MIGRATION_GUIDE.md)（英文）。每个
[GitHub Release](https://github.com/JasonXuDeveloper/EasyEcs/releases) 也会列出它包含的全部 pull request。

## 4.3.0 [#v4-3-0]

### 新功能 [#v4-3-0-new]

- 分析器新增性能规则，针对能跑、但做了多余工作的代码。警告：[EECS025](/zh/docs/guide/analyzer#eecs025) 只读的 `ref` /
  `Span<T>` 参数、`Get<T>()` 或 `WriteX()`；[EECS026](/zh/docs/guide/analyzer#eecs026) 方法没用到的 `[ForEach]` 参数；
  [EECS027](/zh/docs/guide/analyzer#eecs027) 每一行都通过被访问的 `Entity` 或 `World` 查组件或单例；
  [EECS028](/zh/docs/guide/analyzer#eecs028) `[ForEach]` 方法或 `OnUpdate` 里的内存分配；
  [EECS029](/zh/docs/guide/analyzer#eecs029) 没用到系统任何成员的实例 `[ForEach]` 方法；
  [EECS030](/zh/docs/guide/analyzer#eecs030) 遍历查询逐个实体做结构变化。建议（信息级别）：
  [EECS031](/zh/docs/guide/analyzer#eecs031) 在计数循环里逐个创建实体；[EECS032](/zh/docs/guide/analyzer#eecs032) 用
  `Count() > 0` 代替 `Any()`，以及在循环里计数或过滤；[EECS033](/zh/docs/guide/analyzer#eecs033) 有同等含义生成成员的泛型调用
  （`entity.Get<Position>()` 写成 `entity.Position`）。错误：[EECS034](/zh/docs/guide/analyzer#eecs034) 系统调用
  `World.Update()`。每条规则为什么加、哪些没加：见[决策 D29](/zh/docs/decisions#d29-performance-rules-only-where-the-cost-is-measured-and-the-fix-does-the-same)。
- 新规则在改法机械时附带代码修复：`in`、`ReadOnlySpan<T>`、`Read<T>()`、`[With<T>]`、`static`、批量调用（`SetAll`、`RemoveAll`、
  `DisableAll`、`EnableAll`、`DestroyEntities`）、`CreateEntities` 或 `EnsureCapacity`、`Any` / `Count`，以及生成的成员。
  只有改完能编译时才提供。
- 每条分析器诊断都链接到[分析器规则](/zh/docs/guide/analyzer)页面上对应的小节。

### 需要修改代码的变更 [#v4-3-0-breaking]

- 把警告当错误的构建会因新警告（EECS025 到 EECS030）失败，直到改了代码或压掉规则；调用 `World.Update()` 的系统不再能编译
  （EECS034）。见[迁移指南](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/MIGRATION_GUIDE.md#v42--v43)（英文）。

## 4.2.0 [#v4-2-0]

### 新功能 [#v4-2-0-new]

- `world.EnsureCapacity<T1, …, Tn>(count)` 为正好有这些组件的表和实体存储预留空间，接下来 `count` 次带这些组件的
  `CreateEntity` / `CreateEntities` 都不会再扩容（相当于 Friflo 的 `archetype.EnsureCapacity`、Arch 的
  `EnsureCapacity(signature, n)`）。见[结构变更](/zh/docs/guide/structural-changes#bulk)。

### 性能 [#v4-2-0-performance]

- 在新建的 World 里一次创建大量实体，调用过程中不会再触发完整的垃圾回收：预留（`EnsureCapacity`、`EnsureEntityCapacity`、
  `CreateEntities`、`InitialEntityCapacity`）把表和实体存储扩到正好需要的大小，不再扩到下一个 2 的幂；按预留大小分配的大块实体存储放进
  固定对象堆，和列放在一起。见[决策 D28](/zh/docs/decisions#d28-reservations-grow-to-what-they-need-entity-storage-on-the-pinned-heap)。

### 需要修改代码的变更 [#v4-2-0-breaking]

- World 里没有对应的单例时，`[ForEach]` 方法的单例参数会抛 `InvalidOperationException`，和 `world.X`、`GetSingleton<T>()`
  一样（以前会添加默认值）；`world.SingletonRef<T>()` 也一样会抛。在建 World 的地方、第一次 `Update()` 之前添加单例：
  `world.SetClock(…)` 或 `world.AddSingleton<Clock>()`，默认值合适的地方用 `world.GetOrAddClock()`。见
  [单例](/zh/docs/guide/singletons#in-systems)和[迁移指南](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/MIGRATION_GUIDE.md#v41--v42)（英文）。

### 修复 [#v4-2-0-fixes]

- `[ForEach]` 方法的参数名叫 `owner` 时，生成的代码不再报 CS0100 编译失败。
- 查询或 `[ForEach]` 遍历一张表时调用 `world.EnsureCapacity(prefab, count)` 扩容这张表，遍历剩下的行不会再写进旧的列。见
  [结构变更](/zh/docs/guide/structural-changes#refs-across-a-change)。

## 4.1.0 [#v4-1-0]

### 新功能 [#v4-1-0-new]

- 原型表：每张表把组件存成按行排列的列，非托管列固定在内存中并按 64 字节对齐。移除组件不搬行，只清一个存在位，
  来来去去的状态不会移动数据。见[架构](/zh/docs/architecture)。
- 结构变更立即生效，遍历规则更严格：一次遍历最多访问每个实体一次，`[ForEach]` 方法通过 `ref` 写入的值在方法体自己做结构变更之后仍然有效。
  见[结构变更](/zh/docs/guide/structural-changes)。
- 接收 `Span<T>` / `ReadOnlySpan<T>` 的批量 `[ForEach]` 方法（整段连续行，附带 `EntitySpan`），以及把一个方法的行分给多个线程、
  不产生分配的 `[ForEach(Parallel = true)]`。见[系统](/zh/docs/guide/systems)和[线程模型](/zh/docs/guide/threading)。
- 系统之外的静态 `[ForEach]` 方法、泛型系统和 runner、系统分组上的过滤器、`Maybe<T>` 参数、`UpdatePhase`，系统也不再需要 `partial`。
  见[系统](/zh/docs/guide/systems)。
- 用 `[UpdateBefore<T>]` / `[UpdateAfter<T>]` 按依赖排序；用 `SystemErrorPolicy.Disable` 和 `system.Error` 把错误当作数据；
  用 `WorldOptions.MeasureSystems` 和 `system.Stats` 统计每个系统的耗时。见[系统](/zh/docs/guide/systems)。
- 变更追踪（`ITrackChanges`、`[Changed<T>]`、`QueryFilter.Changed<T>(since)`）和移除检测（`[Removed<T>]`、
  `QueryFilter.Removed<T>(since)`）。见[变更追踪](/zh/docs/guide/change-tracking)。
- 为每个组件、标签、单例组件、索引、缓冲和查询形状生成成员：`hero.Position.X += 1`、`hero.SetVelocity(1, 0)`、
  `hero.SetDead()`、`world.Battle.Tick++`、`world.ZoneIndex.Find(3)`、`item.Position`、`prefab.SetLoot(…)`。
  见[实体与组件](/zh/docs/guide/entities-and-components)。
- 预制体（`new Prefab()`、派生预制体、用 `AddMember` 组成的组）、`world.Instantiate`、`EnsureCapacity` 和 `entity.Clone()`。
  见[预制体](/zh/docs/guide/prefabs)。
- `DynamicBuffer<T>`：每个实体一个列表，作为被追踪的组件持有。见[动态缓冲](/zh/docs/guide/dynamic-buffers)。
- 值索引（`IIndexed<TKey>`、`world.Index<T, TKey>()`）、有序遍历（`Range`、`Ascending`）、关系（`IRelation` 缓冲）和目标策略
  （`WhenTargetDestroyed`）。见[索引与关系](/zh/docs/guide/indexes-and-relations)。
- 层级：`ChildOf(EntityId Parent)`、子实体、级联销毁。见[层级](/zh/docs/guide/hierarchy)。
- `GroupBy<T>()` 按值拆分表，查询一个区域只遍历它自己的表。见[分组](/zh/docs/guide/groups)。
- `entity.Disable<T>()` / `Enable<T>()` 和清理组件（`ICleanupComponent`）。见[清理与禁用](/zh/docs/guide/cleanup-and-disable)。
- 批量 `SetAll` / `RemoveAll` / `DisableAll` / `EnableAll`，以及 `CreateEntities` / `DestroyEntities`。见[批量变更](/zh/docs/guide/bulk)。
- 快照：`world.Capture()` / `world.Restore(snapshot)`。见[快照](/zh/docs/guide/snapshots)。
- 存档：基于 Nino 的 `world.Save` / `Load`。见[存档](/zh/docs/guide/saves)。
- `SaveEntities` / `LoadEntities` / `MoveEntities` 把一组实体交给另一个 World 或进程；`world.RemoveTypes(assembly)` 把插件的类型移出
  World，让它的 `AssemblyLoadContext` 可以卸载。见[迁移与卸载](/zh/docs/guide/migration-and-unload)。
- `WithAny<T>` 过滤、`entity.Read<T>()` 和 `entity.TryGetRef<T>(out found)`。见[查询](/zh/docs/guide/queries)。
- `world.Describe()`、`entity.Describe()` 和调试器里的实体视图。见 [API](/zh/docs/api)。
- 分析器规则扩展到 EECS024，并随包附带对应的代码修复。见[分析器](/zh/docs/guide/analyzer)。
- 项目模板：`dotnet new install EasyEcs.Templates`。见[快速开始](/zh/docs/getting-started)。

### 性能 [#v4-1-0-performance]

- 10 万实体的真实服务器 tick 比 4.0.1 快得多，而且零分配。见[性能](/zh/docs/performance)。
- 结构变更检查一个普通的所有者线程标志，不再用比较并交换，创建和销毁实体更快。
- 不会做结构变更的 job 遍历时没有逐实体的簿记开销。
- 并行运行用线程池，只在划算时唤醒助手线程
  （[D22](/zh/docs/decisions#d22-parallel-runs-use-the-thread-pool-and-wake-helpers-only-when-they-pay)）。
- 按行块维护变更和移除摘要（[D23](/zh/docs/decisions#d23-change-summaries-per-block-removals-summarized-apart)），索引的键存成 id 数组
  （[D24](/zh/docs/decisions#d24-an-indexs-key-holds-its-entities-in-one-array)），为没有墓碑的表单独编译结构性循环
  （[D25](/zh/docs/decisions#d25-structural-row-loops-are-compiled-for-tables-without-tombstones)）。
- `QueryFilter` 不持有对象引用，在调用处构建更便宜
  （[D18](/zh/docs/decisions#d18-no-interceptors-for-query-calls-filters-carry-no-references)）。
- 用 `Vector512` / `Vector<T>` 按置位数统计行（[D21](/zh/docs/decisions#d21-net-10-features-only-where-they-measure)）。

### 需要修改代码的变更 [#v4-1-0-breaking]

完整步骤见[迁移指南](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/MIGRATION_GUIDE.md#v40--v41)（英文）。

- `WorldOptions.Parallel` 改名为 `WorldOptions.ParallelSystems`：写成 `new WorldOptions { ParallelSystems = true }`。
- `Entity.Id` 是 `EntityId`，`Entity.Version` 已删除：读 `entity.Id.Index` 和 `entity.Id.Version`；组件里存 `EntityId`
  （组件里有 `Entity` 字段时 EECS017 会警告）。
- `EcsSystem.Priority` 已删除：用 `[UpdateBefore<T>]` / `[UpdateAfter<T>]` 排序。
- `World.SystemError` 事件已删除：用 `new WorldOptions { SystemErrors = SystemErrorPolicy.Disable }`，再读 `system.Error`。
- `world.DestroyEntity(entity)` 已删除：调用 `entity.Destroy()`。
- `entity.Add<T>()` 已删除：添加或替换写 `Set(new T(…))` 或生成的 `SetX(…)`，只在缺少时添加默认值用 `GetOrAdd<T>()`。
- `world.CompactArchetypes()` 和 `world.GetFragmentationStats()` 已删除：表自己保持紧凑。
- `IForEach` job 只接收组件：需要实体时改用 `IForEachEntity`。
- `Query` 的结果是 ref struct：循环里不能 `await`，元素不能存进字段、lambda 或 LINQ。
- 结构变更属于 World 的所有者线程；在并行阶段或并行 `[ForEach]` 里做结构变更会抛 `InvalidOperationException`。
  见[线程模型](/zh/docs/guide/threading)。
- 所有分析器规则都是错误：EECS007（系统里有状态）和 EECS008（系统引用系统）在 4.0 里是警告。把状态移进组件或单例，系统之间通过数据
  通信。
- `QueryEnumerator.Count` 和 `IsEmpty` 删除了：改用 `world.Count<…>(filter)` / `world.Any<…>(filter)`。
- `UpdateInterval` 和 `UpdatePhase` 应当返回常量，否则 EECS018 会警告。
- 指向表的 ref 可能因为其他实体的结构变更而失效；遍历顺序按表的行；`AddSingleton` 原地重置已有的单例组件；失效的句柄
  `Has` / `TryGet` 返回 false。见[ref 与 await](/zh/docs/guide/refs-and-await)。

### 修复 [#v4-1-0-fixes]

- `Entity.GetHashCode()` 每次运行结果相同，由实体的下标和版本算出。
- 分析器按符号识别生成的写方法：名为 `Settings` 的组件通过 `entity.Settings` 读取时，不会再掩盖 EECS013。

## 4.0.1 [#v4-0-1]

### 新功能 [#v4-0-1-new]

- 系统生成的读写集不冲突时，`WorldOptions.Parallel` 让它们并排运行，结果与按顺序运行相同。见[线程模型](/zh/docs/guide/threading)。
- `[With<T>]` 已经写明要查询什么时，`[ForEach]` 方法可以不接收任何组件：`[ForEach, With<Dead>] static void Remove(Entity e)`。
  见[系统](/zh/docs/guide/systems)。

## 4.0.0 [#v4-0-0]

### 新功能 [#v4-0-0-new]

- 面向 .NET 10 重写，统一在 `EasyEcs` 命名空间下：`World`、`Query`，以及一个带版本校验、访问器返回 `ref T` 的 `Entity` 句柄。
- 同步的 `EcsSystem` 和源生成的 `[ForEach]` 方法、`[UpdateInGroup<T>]` 系统分组、实体 id 复用、每个 World 自己的单例组件。
- 强制执行 ECS 原则的分析器（EECS006-EECS008）。见 [ECS 设计原则](/zh/docs/ecs-principles)。

### 需要修改代码的变更 [#v4-0-0-breaking]

所有改名见[迁移指南](https://github.com/JasonXuDeveloper/EasyEcs/blob/master/MIGRATION_GUIDE.md#v3x--v40)（英文）。

- `Context` 改为 `World`，`GroupOf` 改为 `Query`。
- 系统是同步的：没有 UniTask，也没有异步回调。
- 事件已删除：状态变化就是组件。
