EasyEcs is newer than most models' training data, and its rules (stateless systems, state changes as data, `in` and
`ref` parameters, the owner thread) are what an assistant gets wrong first. A coding agent working in your project
gets them from the EasyEcs skill; a chat assistant gets the docs themselves, as `llms.txt` or a Markdown copy of any
page.

## The EasyEcs skill [#agent-skill]

The skill holds the rules that matter when writing EasyEcs code: components and systems, method and group filters,
structural changes, `entity.Run` for a request on one entity, threads and refs, performance, persistence (snapshots,
saves, records with `LoadEntitiesInto`), what EasyEcs does not do (including the actor pattern it leaves to you),
project layout and debugging, and an example. They are drawn from the [ECS principles](/en/docs/ecs-principles), the
[analyzer rules](/en/docs/guide/analyzer), the [performance guide](/en/docs/performance),
[project structure](/en/docs/guide/project-structure) and [diagnostics](/en/docs/guide/diagnostics).

An agent reads only the skill's description until a task writes, reviews or migrates EasyEcs code; then it loads the
rules. Other conversations pay nothing for them. Claude Code, Cursor, Codex, GitHub Copilot, Gemini CLI and the other
agents that read [Agent Skills](https://agentskills.io) all load it.

<Tabs items={['skills CLI', 'By hand']}>
<Tab value="skills CLI">

```bash
npx skills add JasonXuDeveloper/EasyEcs
```

The [skills CLI](https://github.com/vercel-labs/skills) asks which agents to install it for: `-a claude-code` picks
one, `-g` installs it for your user instead of the project. The repository publishes one skill, `easyecs`.
`npx skills update` brings it up to date after a release.

</Tab>
<Tab value="By hand">

A skill is a folder with a `SKILL.md`. Download it into the folder your agent reads skills from
(`.claude/skills` for Claude Code, `.agents/skills` for Codex, Cursor and others):

```bash
curl -fsSL --create-dirs -o .claude/skills/easyecs/SKILL.md \
  https://raw.githubusercontent.com/JasonXuDeveloper/EasyEcs/master/skills/easyecs/SKILL.md
```

Download it again after a release.

</Tab>
</Tabs>

The analyzer still checks every build, so a rule the agent misses becomes a compile error or a warning, not a bug.

## The docs as text [#docs-as-text]

| File | What it holds |
| --- | --- |
| [`/llms.txt`](https://ecs.xgamedev.net/llms.txt) | A summary of EasyEcs, its key facts and a link to the Markdown copy of every English page ([llmstxt.org](https://llmstxt.org) format) |
| [`/llms-full.txt`](https://ecs.xgamedev.net/llms-full.txt) | The full text of every English page in one file |
| [`/llms.zh.txt`](https://ecs.xgamedev.net/llms.zh.txt), [`/llms-full.zh.txt`](https://ecs.xgamedev.net/llms-full.zh.txt) | The same for the Chinese pages (also at `/zh/llms.txt` and `/zh/llms-full.txt`) |

Give an assistant `llms.txt` when it can follow links, `llms-full.txt` when it cannot. The full file includes the
code of the [battle server example](/en/docs/example), so a model sees every feature used together.

## Markdown copies of every page [#markdown-copies]

Add `.md` to a page's URL for its Markdown: `https://ecs.xgamedev.net/en/docs/guide/queries.md`. The docs home is
`/en/docs.md`. A request for the page itself with `Accept: text/markdown` gets the same Markdown, so tools that ask for
Markdown first need no special URL:

```bash
curl -H "Accept: text/markdown" https://ecs.xgamedev.net/en/docs/guide/systems
```

The menu at the top of each page copies its Markdown or opens it in ChatGPT, Claude, T3 Chat or Scira with the page
attached.

## Other tools [#other-tools]

Services that index GitHub repositories and documentation for assistants, such as [Context7](https://context7.com)
and [DeepWiki](https://deepwiki.com), can be pointed at the
[EasyEcs repository](https://github.com/JasonXuDeveloper/EasyEcs) from their own sites. They are run by others: check
what they return against these docs, which are the source.
