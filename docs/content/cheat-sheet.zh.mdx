EasyEcs 日常用到的全部 API，用表格加短代码排在一页里，每节都链接到详细讲解的指南页面。所有类型都在同一个命名空间：
`using EasyEcs;`。

本页的示例共用下面这些声明：

```csharp
public record struct Position(float X, float Y) : IComponent;
public record struct Velocity(float X, float Y) : IComponent;
public record struct Health(int Value) : IComponent, ITracked;          // 被追踪：写入会被记录
public record struct Mana(int Value) : IComponent, ITracked;
public record struct Team(int Id) : IComponent, IIndexed<int> { public int Key => Id; }
public record struct Account(int Id) : IComponent, IUniqueIndexed<int> { public int Key => Id; }   // 一个键一个实体
public record struct Zone(int Id) : IComponent, IGroup { public int Group => Id; }
public record struct OwnedBy(EntityId Owner) : IComponent, IIndexed<EntityId> { public EntityId Key => Owner; }
public record struct MemberOf(EntityId Target) : IRelation;                   // 每个实体可以有多条
public record struct Loot(int Item);                                          // DynamicBuffer 的元素
public record struct Seat(int Number) : ICleanupComponent;                    // 销毁后再释放
public struct Dead : IComponent;                                              // 标签
public record struct Session(int Connection) : IComponent;                   // 运行时状态，不进存档
public record struct Clock(long Tick) : ISingletonComponent;                  // 每个 World 一份
public record struct Config(int MaxPlayers) : ISingletonComponent;
```

## 声明数据 [#declare-data]

| 声明 | 含义 | 指南 |
| --- | --- | --- |
| `struct X : IComponent` | 每个实体一份的数据，每种类型一列 | [实体与组件](/zh/docs/guide/entities-and-components) |
| 没有字段的 `struct X : IComponent` | 标签：用于过滤的“是或否”状态 | [实体与组件](/zh/docs/guide/entities-and-components) |
| `struct X : ISingletonComponent` | 每个 World 一份 | [单例](/zh/docs/guide/singletons) |
| `: ITracked` | 每行记录最后一次写入和移除的 tick | [变更追踪](/zh/docs/guide/change-tracking) |
| `: IIndexed<TKey>` 加 `Key` | 通过 `world.Index<T, TKey>()` 按值查找 | [索引与关系](/zh/docs/guide/indexes-and-relations) |
| `: IUniqueIndexed<TKey>` 加 `Key` | 一个键只对应一个实体：`index.Get(key)`；会让第二个实体拿到这个键的写入直接抛异常 | [索引与关系](/zh/docs/guide/indexes-and-relations) |
| `: IIndexed<EntityId>` | 指向一个实体的链接，可以从目标反查 | [索引与关系](/zh/docs/guide/indexes-and-relations) |
| `: IRelation` 加 `Target` | 每个实体多条链接，存放在缓冲里 | [索引与关系](/zh/docs/guide/indexes-and-relations) |
| `: IGroup` 加 `Group` | 调用 `world.GroupBy<T>()` 后按值拆表 | [分组](/zh/docs/guide/groups) |
| `: ICleanupComponent` | `Destroy` 之后仍保留：其他组件被移除，实体带上 `Retired` 标签，直到系统移除最后一个清理组件 | [清理与禁用](/zh/docs/guide/cleanup-and-disable) |
| `Disabled<T>` | `T` 被禁用期间实体带着的标签：查询它就能找到被暂停的实体 | [清理与禁用](/zh/docs/guide/cleanup-and-disable) |
| `DynamicBuffer<T>` | 每个实体一个列表，每次写入都被追踪 | [动态缓冲](/zh/docs/guide/dynamic-buffers) |
| `ChildOf(EntityId Parent)` | 内置的层级链接 | [层级](/zh/docs/guide/hierarchy) |
| `struct G : ISystemGroup` | 有自己节奏的一组系统 | [系统](/zh/docs/guide/systems) |
| 分组（或它实现的接口）上的 `: ISystemGroupWith<T>` / `ISystemGroupWithout<T>` | 分组里的系统只访问有 / 没有 `T` 的实体；一个泛型接口就能给每种 actor 类型各配一个带过滤的分组 | [系统](/zh/docs/guide/systems#group-filters) |
| `class S<T> : EcsSystem` | 泛型系统：每个闭合类型（`S<Position>`）都是一个独立的系统 | [系统](/zh/docs/guide/systems#generic-systems) |

组件必须是结构体（[EECS006](/zh/docs/guide/analyzer#eecs006)）。指向实体的链接存 `EntityId`，不要存 `Entity`
（[EECS017](/zh/docs/guide/analyzer#eecs017)）。

## World [#world]

| 调用 | 作用 |
| --- | --- |
| `new World(options)` | 一个独立的 World；`Dispose()` 会调用每个系统的 `OnDestroy` |
| `world.Update()` | 把默认分组的系统执行一遍 |
| `world.Update<TGroup>()` | 执行一个系统分组 |
| `world.AddSystem<T>()` / `AddSystem(instance)` | 添加系统（调用 `OnCreate`） |
| `world.RemoveSystem<T>()` / `TryGetSystem<T>(out s)` / `Systems` | 移除、查找、列出系统 |
| `world.EntityCount` / `Entities` | 存活实体数，以及零分配的遍历 |
| `world.ChangeTick` | 当前的变更 tick |
| `world.DefaultUpdateCount` | 默认分组已完成的 `Update()` 次数 |
| `world.Reserve<T1, …, Tn>(n)` / `Reserve(prefab, n)` / `EnsureEntityCapacity(n)` | 在已知峰值或一波刷怪之前预分配 |
| `world.TryGetEntity(id, out e)` / `GetEntity(id)` / `IsAlive(id)` | 从 `EntityId` 换回经过校验的句柄 |
| `world.DescribeTables()` | 表、列、行数和字节数，供工具使用 |
| `world.DescribeSchedule()` | 每个分组的阶段、每个系统读写什么、为什么要等、哪些系统对只靠注册顺序；`ToString()` / `ToMermaid()` |
| `world.TrimExcess()` | 峰值过后、空闲时删掉空表并缩小其他表 |
| `world.DestroyedSince(since, into, out count)` / `DestroyLogOldestTick` | 开了 `WorldOptions.DestroyLogCapacity` 时，某个 tick 以来销毁的实体；返回 `false` 表示读取方比日志还旧 |

```csharp
Console.WriteLine(world.DescribeSchedule());        // 阶段、等待关系、只靠注册顺序的系统对
world.TrimExcess();                                 // 一波怪清完之后：内存还回去，什么都不会坏
```

## 实体 [#entities]

```csharp
using var world = new World();
Entity unit = world.CreateEntity(new Position(0, 0), new Velocity(1, 0), new Health(100));
```

下表是泛型调用，也就是[生成的成员](#generated-members)底下调用的 API；写明组件的代码用生成的成员（`unit.Velocity`、
`SetHealth(50)`、`RemoveDead()`），见表后的例子。

| 调用 | 作用 | 结构变更 |
| --- | --- | --- |
| `world.CreateEntity(a, b, …)` | 带最多 9 个组件创建，直接放进最终的表 | 是 |
| `entity.Set(a, b, …)` | 一次搬迁里添加或覆盖最多 9 个组件；返回实体 | 是 |
| `entity.SetIfChanged(value)` | 实体已经是这个值就不写，否则 `Set`；写了返回 `true`（相同的值不打 tick、不重建索引） | 新加时是 |
| `entity.Remove<A, B>()` | 移除已有的组件；返回实体 | 是 |
| `entity.GetOrAdd<T>()` | `ref T`，没有时先以默认值添加 | 添加时是 |
| `entity.Get<T>()` | 用于写入的 `ref T`（对变更追踪算一次写入） | 否 |
| `entity.Read<T>()` | `ref readonly T`（永远不算写入） | 否 |
| `entity.TryGet<T>(out T copy)` | 有就拿一份拷贝 | 否 |
| `entity.TryGetRef<T>(out bool found)` | `ref T`，没有时是空引用 | 否 |
| `entity.Has<T>()` / `Has<A, B>()` | 有没有这个，或这几个全有 | 否 |
| `entity.Disable<T>()` / `Enable<T>()` / `IsDisabled<T>()` | 隐藏一个组件，保留它的值 | 是 |
| `entity.Clone()` | 在同一个 World 里复制这个实体；已退休、只为清理组件留着的实体会抛异常 | 是 |
| `entity.Run<T1..T9, TJob>(ref job)` / `Run(ref job, filter)` | 在这个实体上跑一个 `IForEachEntity` job，拿到的 `ref` 和遍历时一样；实体已销毁、缺组件或不满足过滤条件时返回 `false` | job 做了结构变更时是 |
| `entity.Destroy()` | 销毁；id 换一个版本号后回收复用 | 是 |
| `entity.IsAlive` / `Id` / `World` | 句柄状态；每次访问都校验版本号 | 否 |
| `entity.Describe()` | 实体的组件值，给调试器和日志用 | 否 |
| `EntityId` / `EntityId.Null` / `id.IsNull` / `id.Index` / `id.Version` | 存进组件的 8 字节 id；`Null` 就是默认值 | 否 |

```csharp
unit.Velocity.X = 2;                                // 通过 ref 原地写入
float x = unit.Position.X;                          // 读（被追踪的组件是 ref readonly）
unit.Set(new Health(50), new Dead());               // 一次设置两个：写法更简洁，性能相同
unit.RemoveDead();                                  // 只翻一个存在位，行保留
if (unit.TryGetHealth(out var hp)) { /* hp 是拷贝 */ }
```

```csharp
public struct TakeHit : IForEachEntity<Health>
{
    public int Damage;
    public static int WriteMask => 1;                  // 第 0 位：Health 算作写入

    public void Execute(Entity target, ref Health hp) => hp.Value -= Damage;
}
```

```csharp
var hit = new TakeHit { Damage = 30 };
bool applied = unit.Run<Health, TakeHit>(ref hit);   // 在请求对应的实体上处理它
```

`ref` 在下一次结构变更之前有效，跨 `await` 一律无效（[ref 与 await](/zh/docs/guide/refs-and-await)）。

## 生成成员 [#generated-members]

源生成器为每个组件、标签和单例生成具名成员（C# 14 扩展成员），每个都是对上面泛型 API 的内联调用。

| 声明 | 生成 |
| --- | --- |
| 组件 `Position` | `e.Position`（`ref`）、`HasPosition`、`TryGetPosition(out p)`、`GetOrAddPosition()`、`SetPosition(x, y)`、`RemovePosition()`、`DisablePosition()`、`EnablePosition()`、`IsPositionDisabled` |
| 被追踪或被索引的 `Health` | `e.Health` 是 `ref readonly`；用 `SetHealth(…)` 写，或者用 `WriteHealth()`（`ref`，仅被追踪的组件）；`SetHealthIfChanged(…)` 只写不同的值 |
| 标签 `Dead` | `e.IsDead`、`SetDead()`、`RemoveDead()` |
| 被索引的 `Team` | `world.TeamIndex`（即 `world.Index<Team, int>()`） |
| 唯一键 `Account` | `world.AccountIndex.Get(id)` / `TryGet(id, out e)` |
| 分组组件 `Zone` | `filter.InZone(id)`（即 `InGroup<Zone>(id)`） |
| 缓冲元素 `Loot` | `e.Loot`（`ref readonly DynamicBuffer<Loot>`）、`HasLoot`、`WriteLoot()`、`GetOrAddLoot()`、`RemoveLoot()` |
| 关系 `MemberOf` | `e.LinkMemberOf(target)`、`UnlinkMemberOf(target)`、`LinksMemberOf(target)`、`world.MemberOfIndex` |
| 单例 `Clock` | `world.Clock`（`ref`）、`HasClock`、`GetOrAddClock()`、`SetClock(…)`、`RemoveClock()` |
| `Prefab` 上 | `SetPosition(…)`、`RemovePosition()` 返回预制体本身；`prefab.Position`（只读）、`HasPosition`、`IsDead` |
| `world.Query<Position, Velocity>()` 的元素 | `item.Position`、`item.Velocity` |

```csharp
unit.SetPosition(3, 4).SetDead();                   // setter 返回实体，可以链式调用
unit.Position.X += 1;                               // 不追踪的组件：ref
unit.SetHealth(80);                                 // 被追踪的组件：用 Set 写，会打上 tick
bool rewritten = unit.SetHealthIfChanged(80);       // false：值已经是 80，不打 tick
bool dead = unit.IsDead;
```

指南：[实体与组件](/zh/docs/guide/entities-and-components)。

## 系统与 [ForEach] [#systems]

```csharp title="MovementSystem.cs"
public class MovementSystem : EcsSystem
{
    [ForEach, Without<Dead>]                         // 每个有 Position 和 Velocity、没有 Dead 的实体执行一次
    static void Move(ref Position p, in Velocity v) => p = new Position(p.X + v.X, p.Y + v.Y);
}
```

### [ForEach] 参数 [#foreach-parameters]

| 参数 | 含义 | 说明 |
| --- | --- | --- |
| `ref T` | 方法要写的组件 | 1 到 9 个组件；对变更追踪算写入 |
| `in T` | 方法只读的组件 | 不算写入（经 `in` 写入由 [EECS011](/zh/docs/guide/analyzer#eecs011) 拦下） |
| `Span<T>` / `ReadOnlySpan<T>` | 一段连续的 `T` 行（批量方法） | 不能和逐实体参数混用（[EECS009](/zh/docs/guide/analyzer#eecs009)） |
| `ref S` / `in S` | 单例 | 每次遍历解析一次；没添加时抛异常 |
| `Entity` | 当前实体 | 做结构变更时用 |
| `World` | 当前 World | 在静态方法里创建实体时用 |
| `EntitySpan` | 批量方法这一段行对应的实体 | 仅批量方法 |
| `Maybe<T>` | 实体可能没有的组件 | `HasValue`、`Value` |
| `Mut<T>` | 方法只在部分行上写的组件 | `Value` 只读；`Write()` 和改了值的 `SetIfChanged(value)` 才给这一行打 tick；对调度器来说算写入 |
| 其他任意类型（系统之外） | 调用方传给入口方法的值 | `ref int count`、`in Settings s` |

### 特性 [#attributes]

| 特性 | 用在 | 作用 |
| --- | --- | --- |
| `[ForEach]` / `[ForEach(Parallel = true)]` | 方法 | 方法就是循环；`Parallel` 把行分给多个线程（[EECS010](/zh/docs/guide/analyzer#eecs010)） |
| `[ForEach(Slices = N)]` | 方法 | 每次运行只访问一片，约 1/N 的行：每 N 次运行每行一次（不能和 `Changed` / `Removed` 一起用：[EECS035](/zh/docs/guide/analyzer#eecs035)） |
| `[With<T>]` | 方法、系统分组 | 要求有 `T`，但不作为参数传入 |
| `[Without<T>]` | 方法、系统分组 | 排除有 `T` 的实体 |
| `[WithAny<A>, WithAny<B>]` | 方法、系统分组 | 至少有其中一个 |
| `[Changed<T>]` | 方法 | 系统上次执行后、被追踪的 `T` 被写过的行 |
| `[Removed<T>]` | 方法 | 系统上次执行后失去了被追踪 `T` 的实体 |
| `[ChangedAny<A, B>]` / `[RemovedAny<A, B>]` | 方法 | 2 到 9 个被追踪组件里至少有一个被写过、或被移除的行 |
| `[UpdateBefore<S>]` / `[UpdateAfter<S>]` | 系统 | 排序（成环由 [EECS019](/zh/docs/guide/analyzer#eecs019) 拒绝） |
| `[UpdateInGroup<G>]` | 系统 | 只在 `world.Update<G>()` 时执行 |

```csharp
public class DecaySystem : EcsSystem
{
    [ForEach(Slices = 4)]                            // 每次运行四分之一的行，每 4 次运行每行一次
    static void Decay(ref Velocity v) => v = new Velocity(v.X * 0.9f, v.Y * 0.9f);
}
```

`[Changed<T>]` 和 `[Removed<T>]` 只能写在方法上。系统分组上可以写 `[With<T>]`、`[Without<T>]`、`[WithAny<T>]`
（写在其他结构体上由 [EECS023](/zh/docs/guide/analyzer#eecs023) 报错），也可以实现 `ISystemGroupWith<T>` / `ISystemGroupWithout<T>`。
泛型分组接口只能用后者，因为特性里不能写类型参数：

```csharp
public struct In<TActor> : IComponent;              // 某一种 actor 的标签
public interface IActorGroup<TActor> : ISystemGroupWith<In<TActor>> where TActor : struct;
public struct Shop : IActorGroup<Shop>;             // [UpdateInGroup<Shop>] 的系统只看到带 In<Shop> 的实体
```

### 系统成员 [#system-members]

| 成员 | 作用 |
| --- | --- |
| `OnCreate()` / `OnUpdate()` / `OnDestroy()` | 生命周期；`OnUpdate` 在 `[ForEach]` 方法之前执行 |
| `World` | 系统所属的 World |
| `UpdateInterval` / `UpdatePhase` | 每 N 次更新执行一次，落在第 0 到 N-1 个相位 |
| `Enabled` | 跳过这个系统；设回 `true` 会清掉 `Error` |
| `Error` | 在 `SystemErrorPolicy.Disable` 下让它停用的那个异常 |
| `LastRunTick` | 上次执行时的变更 tick |
| `RunCount` | 本次之前已经运行的次数（分片方法访问第 `RunCount % N` 片） |
| `Stats` | 打开 `MeasureSystems` 后的 `Runs`、`LastTime`、`TotalTime`、`AverageTime`、`LastAllocated` / `TotalAllocated`（字节）、`LastEntities` / `TotalEntities`（遍历开始时匹配的实体数） |

系统不保存状态（[EECS007](/zh/docs/guide/analyzer#eecs007)），也从不引用别的系统
（[EECS008](/zh/docs/guide/analyzer#eecs008)）。指南：[系统](/zh/docs/guide/systems)。

## 查询与过滤 [#queries]

```csharp
// 字段：每个过滤条件只构建一次。
private static readonly QueryFilter Alive = QueryFilter.Create().Without<Dead>();
```

```csharp
foreach (var item in world.Query<Position, Velocity>(Alive))
    item.Position.X += item.Velocity.X;             // 元素给出 ref；item.Entity 是句柄

int movers = world.Count<Position, Velocity>(Alive);
bool anyDead = world.Any<Dead>();
```

| 调用 | 作用 |
| --- | --- |
| `world.Query<T1..T9>(filter)` | 用 `foreach` 遍历：组件的 `ref` 和 `Entity` |
| `world.Read<T1..T9>(filter)` | 同上，`ref readonly`：不打 tick（存盘、发包） |
| `world.Count<T1..T9>(filter)` / `Any<…>(filter)` | 计数，或者找到第一个就停 |
| `world.ForEach<T1..T9, TJob>(ref job, filter)` | 结构体 job `IForEach<T…>`：`Execute(ref T1 …)` |
| `world.ForEachEntity<…>(ref job, filter)` | `IForEachEntity<T…>`：`Execute(Entity e, ref T1 …)` |
| `world.ForEachBatch<…>(ref job, filter)` | `IForEachBatch<T…>`：以 span 接收一段段行 |
| `world.ForEachParallel` / `ForEachEntityParallel` | 结构体 job 分块在多个线程上执行 |
| `Runner.Method(world, …)` | 系统之外的静态 `[ForEach]` 方法生成的入口 |
| job 上的 `static int WriteMask => mask` | job 写哪些组件（第 k 个组件对应第 k - 1 位），这些组件打上变更 tick；默认 `-1`，全部 |
| job 上的 `: INoStructuralChanges` | job 保证不做结构变更：省掉逐实体的簿记，执行期间结构冻结 |

| `QueryFilter` | 选出 |
| --- | --- |
| `.With<T>()` / `.Without<T>()` / `.WithAny<T>()` | 按有无组件，和特性相同 |
| `.Changed<T>(since)` / `.Removed<T>(since)` | 在 tick `since` 及之后被写过、或失去了 `T` |
| `.ChangedAny<A, B>(since)` / `.RemovedAny<A, B>(since)` | `since` 及之后至少有一个被写过、或被移除 |
| `.Since(tick)` | 同一个过滤条件换一个 tick：一个过滤条件，带着每个客户端的 tick 跑 |
| `.Slice(index, of)` | 每张表 `of` 片里的第 `index` 片，只用于 `ForEach` 系列调用 |
| `.InGroup<T>(group)` | 分组组件的某一组 |

指南：[查询与过滤](/zh/docs/guide/queries)。

## 变更追踪 [#change-tracking]

| 算写入 | 不算写入 |
| --- | --- |
| `ref` 参数、`Span<T>`、`Query` 元素 | `in` 参数、`ReadOnlySpan<T>`、`world.Read<…>` 元素 |
| `Mut<T>.Write()`、写入新值的 `SetIfChanged(value)` | `Mut<T>.Value`、值相同的 `SetIfChanged(value)` |
| `Get<T>()`、找到时的 `TryGetRef<T>`、`GetOrAdd<T>()`、`Set(…)`、`WriteX()` | `Read<T>()`、`TryGet<T>(out copy)`、`Has<T>()`、被追踪组件的 `e.X` |
| 创建、实例化、克隆、`Enable<T>()`、`Restore`、`Load`、`LoadEntitiesInto` | 移除或 `Disable<T>()`（那是一次移除，供 `[Removed<T>]` 使用） |
| `entity.Run`：job `WriteMask` 里的组件 | `Load(…, markWritten: false)`、`LoadEntitiesInto(…, markWritten: false)` |

```csharp
ulong mark = world.ChangeTick;
world.Update();
int changed = world.Count<Health>(QueryFilter.Create().Changed<Health>(mark));
```

```csharp
public class ClampSystem : EcsSystem
{
    [ForEach]                                        // 只给真正写了的行打 tick
    static void Clamp(Mut<Health> hp)
    {
        if (hp.Value.Value > 100) hp.Write() = new Health(100);
    }
}
```

```csharp
// 一个过滤条件存在字段里，带着每个客户端确认过的 tick 跑。
private static readonly QueryFilter Dirty = QueryFilter.Create().ChangedAny<Health, Mana>(0);
```

```csharp
ulong ack = world.ChangeTick;                       // 某个客户端确认过的 tick
world.Update();
int toSend = world.Count<Health>(Dirty.Since(ack));

using var replicated = new World(new WorldOptions { DestroyLogCapacity = 4096 });
ulong seen = replicated.ChangeTick;
replicated.Update();
var gone = new EntityId[4096];
if (!replicated.DestroyedSince(seen, gone, out int goneCount)) { /* 比日志还旧：全量下发 */ }
```

## 索引、关系、层级、分组 [#indexes]

| 调用 | 作用 |
| --- | --- |
| `world.Index<T, TKey>()`（`world.TIndex`） | `T` 的值索引 |
| `index.Find(key)` / `TryFind(key, out e)` / `Count(key)` | 所有匹配、唯一一个、数量 |
| `index.Find(key).Count` / `relations.Find(target).Count` | 循环会走过多少个，O(1)，用来确定缓冲区大小 |
| `index.KeyCount` / `relations.TargetCount` | 有多少个不同的键 / 目标被持有，O(1)（被占用的格子、有成员的公会） |
| `index.Get(key)` / `TryGet(key, out e)` | 唯一键（`IUniqueIndexed<TKey>`）对应的那个实体；没有时 `Get` 抛异常 |
| `index.Range(min, max)` / `RangeDescending` / `Ascending()` / `Descending()` | 键可比较时的有序遍历 |
| `index.WhenTargetDestroyed(TargetPolicy.Keep / Remove / Destroy)` | 目标销毁时 `EntityId` 链接怎么处理 |
| `entity.Link(r)` / `Unlink<T>(target)` / `Links<T>(target)` | 多对多链接 |
| `world.Relations<T>()` 再 `Find(target)` / `Count(target)` | 谁链接到了某个目标 |
| `world.Children(parent)` | `ChildOf` 指向这个父实体的所有实体；销毁父实体会连带销毁它们（`ChildOf` 一开始就是 `TargetPolicy.Destroy`） |
| `world.Descendants(root)` | 整棵子树，深度优先，每个实体排在它的子实体之前，不含根；`ChildOf` 成环时抛 `InvalidOperationException` |
| `world.Descendants(root).AddTo(ids, includeRoot: true)` | 把根和整棵子树追加到 `List<EntityId>`：`MoveEntities` / `SaveEntities` 要的那组实体 |
| `world.GroupBy<T>()` | 按 `IGroup` 的值拆表 |

```csharp
var teams = world.TeamIndex;
var moving = new List<Entity>();
foreach (var member in teams.Find(1)) moving.Add(member);  // 先收集：别在 Find 循环里改 Team
foreach (var member in moving) member.SetTeam(2);           // 被索引的组件用 Set 写
var ship = world.CreateEntity();
world.CreateEntity(new ChildOf(ship));
foreach (var child in world.Children(ship)) { }
foreach (var part in world.Descendants(ship)) { }  // 子实体、孙实体……
var account = world.CreateEntity(new Account(42));
Entity holder = world.AccountIndex.Get(42);        // 就是它；再来一个 Account(42) 会抛异常
```

被索引和分组的组件只能用 `Set` 写，不能经 `ref` 写（[EECS015](/zh/docs/guide/analyzer#eecs015)），也不能在 `foreach` 遍历它们的索引时写（[EECS042](/zh/docs/guide/analyzer#eecs042)）。指南：
[索引与关系](/zh/docs/guide/indexes-and-relations)、[层级](/zh/docs/guide/hierarchy)、[分组](/zh/docs/guide/groups)。

## 预制体与批量操作 [#prefabs-and-bulk]

| 调用 | 作用 |
| --- | --- |
| `new Prefab().SetX(…)…` / `new Prefab(basePrefab)` | 不属于任何 World 的配方，或者某个配方的变体 |
| `prefab.AddMember()` / `prefab.Id` | 一起实例化的一组实体；`Id` 在链接里代表某个成员 |
| `prefab.SetBuffer(items)` | 每个实例各拿一份拷贝的 `DynamicBuffer<T>` |
| `world.Instantiate(prefab)` / `Instantiate(prefab, span)` | 一个实体，或者一次遍历刷出一整波 |
| `world.Instantiate(prefab, a, b, …)` / `Instantiate(prefab, span, a, b, …)` | 同上，外加最多 9 个自己的组件，覆盖或补充预制体里的值：只拷贝一次行 |
| `world.CreateEntities(span, a, b, …)` | 一波取值相同的实体 |
| `world.DestroyAll<T…>(filter)` | 销毁所有匹配的实体，返回数量 |
| `world.DestroyEntities(ids)` | 一次销毁一组 id，返回数量 |
| `world.SetAll(value, filter)` / `RemoveAll<T>(filter)` | 给所有匹配的实体设置或移除一个组件；过滤条件里没写 `Retired` 时，`SetAll` 跳过带 `Retired` 标签的实体 |
| `world.DisableAll<T>(filter)` / `EnableAll<T>(filter)` | 给所有匹配的实体禁用或启用一个组件 |

```csharp
var goblin = new Prefab().SetPosition(0, 0).SetHealth(30);
var wave = new Entity[100];
world.Instantiate(goblin, wave);
var scout = world.Instantiate(goblin, new Velocity(2, 0));   // 预制体的值，再加上自己的
world.SetAll(new Velocity(0, 0), QueryFilter.Create().With<Health>());
world.DestroyAll<Dead>();
```

指南：[预制体](/zh/docs/guide/prefabs)、[批量操作](/zh/docs/guide/bulk)。

## 动态缓冲 [#dynamic-buffers]

读用 `e.Loot`（`ref readonly`，有 `Count`、`Capacity`、索引器和 `foreach`）；写要从 `e.WriteLoot()`（或 `GetOrAddLoot()`）
以 `ref` 拿到缓冲，所以每次写入都算进变更追踪。

| 在 `ref DynamicBuffer<T>` 上调用 | 作用 |
| --- | --- |
| `Add(item)` / `AddRange(items)` / `Insert(index, item)` | 追加、追加一个 span、插入 |
| `RemoveAt(index)` / `RemoveAtSwapBack(index)` | 保持顺序移除，或者把最后一个元素挪过来（O(1)） |
| `Clear()` | 清空，保留容量 |
| `EnsureCapacity(n)` / `TrimExcess()` | 已知数量时先扩容一次，或者把内存还回去 |
| `AsSpan()` | 元素的 `Span<T>`，用来原地写 |
| `DynamicBuffer<T>.PoolCapacity = n`（静态） | 死掉的 `T` 缓冲最多把多长的列表还给池，启动时设一次 |

```csharp
unit.Set(new DynamicBuffer<Loot>());
ref var loot = ref unit.WriteLoot();
loot.EnsureCapacity(8);
loot.Add(new Loot(7));
loot.RemoveAtSwapBack(0);
```

指南：[动态缓冲](/zh/docs/guide/dynamic-buffers)。

## 快照、存档、迁移 [#persistence]

| 调用 | 作用 |
| --- | --- |
| `world.Capture()` / `Capture(into)` | 内存里的一份拷贝；`into` 复用已有快照的数组 |
| `world.Restore(snapshot)` | 回到拷贝时的状态，那时的句柄重新有效 |
| `world.Save(writer)` / `Load(bytes)` | 把整个 World 写成字节（托管组件需要 `[NinoType]`）；非托管组件的内存布局在存档之后变了，`Load` 抛 `InvalidDataException` |
| `world.SaveWithout(writer, exclude)` / `LoadKeeping(bytes, keep, markWritten: false)` | 重启：存档不写一个集合里的组件和单例，读档保留另一个集合里新进程已经设好的单例 |
| `world.SaveEntities(writer, ids)` / `LoadEntities(bytes, handles)` | 把一组实体搬到另一个 World 或进程 |
| `ComponentSet.Create().With<T>()….WithSingleton<S>()` | 组件（整个 World 的存档还可以有单例），在 `static readonly` 字段里构建一次 |
| `world.SaveEntitiesWith(writer, ids, set)` | 一条记录：只写集合里的组件 |
| `world.LoadEntitiesInto(bytes, entities, markWritten: false)` | 把记录放到已有的实体上；`markWritten: false` 让它不算变更 |
| `world.MoveEntities(target, ids, moved)` | 在同一线程的两个 World 之间直接搬，不编码；跳过已退休、只为清理留着的实体，清理组件留在原处 |
| `world.RemoveTypes(assembly or context)` | 插件的上下文卸载之前，先移除它的类型 |

```csharp
var save = world.Capture();
world.Update();
world.Restore(save);

var bytes = new System.Buffers.ArrayBufferWriter<byte>();
world.Save(bytes);
using var copy = new World();
copy.Load(bytes.WrittenSpan);
```

```csharp
// 重启：运行时状态和配置不进存档，新进程带自己的。
private static readonly ComponentSet Runtime = ComponentSet.Create().WithSingleton<Config>().With<Session>();
private static readonly ComponentSet NewConfig = ComponentSet.Create().WithSingleton<Config>();
```

```csharp
var restart = new System.Buffers.ArrayBufferWriter<byte>();
world.SaveWithout(restart, Runtime);                       // 旧进程关闭时
using var next = new World();
next.SetConfig(64);                                 // 新版本的配置
next.LoadKeeping(restart.WrittenSpan, NewConfig, markWritten: false);   // Config 保持刚设的值
```

指南：[快照](/zh/docs/guide/snapshots)、[存档](/zh/docs/guide/saves)、[迁移与卸载](/zh/docs/guide/migration-and-unload#records)。

| `WorldOptions` | 默认值 | 作用 |

| `InitialEntityCapacity` | 1024 | 预先分配的实体记录数 |

using var server = new World(new WorldOptions { ParallelSystems = true, SystemErrors = SystemErrorPolicy.Disable });
