A world often holds many zones, maps or matches, and most work touches one of them: move the units of zone 3, send
match 12 its state. `GroupBy<T>()` splits the world's tables by the value of an `IGroup` component, so entities of one
group share tables of their own. `QueryFilter.InGroup<T>(group)` then walks only that group's rows, contiguous in
memory, at the speed of a plain query over a smaller world.

<Callout type="info" title="Not system groups">
  These are groups of entities. Groups of *systems* that run at their own cadence (`ISystemGroup`,
  `[UpdateInGroup<T>]`, `World.Update<T>()`) are another feature: see [Systems](/en/docs/guide/systems).
</Callout>

## When to use it [#when-to-use-it]

<Callout type="idea" title="Use it for">
  A few to a few hundred partitions, each holding many entities and walked whole: zones or maps of one server, matches
  or rooms, teams in a big battle. Entities that change partition now and then (a player walking to the next zone).
</Callout>

<Callout type="warn" title="Skip it for">
  Keys with few entities each (a guild id, an owner): each group costs tables of its own, so use a
  [value index](/en/docs/guide/indexes-and-relations#value-indexes). Values that change every tick: each change moves
  the row. A world per partition when the partitions never interact: [one world per thread](/en/docs/guide/threading#recommended-one-world-per-thread)
  needs no filter at all.
</Callout>

## How to use it [#how-to-use-it]

<Steps>
<Step>

### Mark the component [#mark-the-component]

`IGroup.Group` is the partition the entity belongs to.

```csharp
public record struct Zone(int Id) : IComponent, IGroup
{
    public int Group => Id;
}
```

</Step>
<Step>

### Group the world at setup [#group-by]

`GroupBy<T>()` moves the existing entities to their groups' tables and keeps every later write in place: entities
created with a `Zone` go straight to their group's table.

```csharp
world.GroupBy<Zone>();                                         // once, before the world fills
for (int i = 0; i < 9; i++) world.CreateEntity(new Zone(i % 3), new Health(10 * i));
```

</Step>
<Step>

### Walk one group [#in-group]

`InGroup<T>(group)`, generated as `InZone(group)` for `Zone`, requires `T` with that group: only the group's
tables are walked. Keep filters in `static readonly` fields; a filter holds one group.

```csharp
public struct SumHealth : IForEach<Health>
{
    public int Total;
    public void Execute(ref Health health) => Total += health.Value;
}

public static class Zones
{
    public static readonly QueryFilter One = QueryFilter.Create().InZone(1);
}
```

```csharp
int inOne = world.Count<Health>(Zones.One);                   // 3
var sum = new SumHealth();
world.ForEach<Health, SumHealth>(ref sum, Zones.One);          // a struct job over zone 1 only
foreach (var item in world.Query<Health>(Zones.One)) { /* the same rows, as a query */ }
```

</Step>
<Step>

### Move an entity to another group [#move]

Write the new value with `Set` (or the generated `SetX`): the entity moves to its group's table at once, one row copy.

```csharp
var walker = world.CreateEntity(new Zone(1), new Health(50));
walker.SetZone(2);                                             // now walked by InGroup<Zone>(2)
```

</Step>
</Steps>

A grouped component is written only with `Set`: a write through a `ref` would change the value without moving the row,
so the analyzer rejects it as it does for indexed components ([EECS015](/en/docs/guide/analyzer#eecs015)).
`Set` is allowed while a query walks the group.

### Groups in systems [#in-systems]

`[ForEach]` filters are attributes and cannot name a group value. A system that works on one group at a time runs a
struct job from `OnUpdate`, with the group it reads from a singleton:

```csharp
public record struct ActiveZone(int Id) : ISingletonComponent;

public struct Regenerate : IForEach<Health>
{
    public void Execute(ref Health health) => health.Value += 1;
}

public class RegenerateActiveZone : EcsSystem
{
    protected override void OnUpdate()
    {
        var filter = QueryFilter.Create().InZone(World.ActiveZone.Id);
        var job = new Regenerate();
        World.ForEach<Health, Regenerate>(ref job, filter);
    }
}
```

An `OnUpdate` override runs alone in its stage. Building the filter per update is cheap: a `QueryFilter` holds no
object reference.

### What follows a grouping [#what-follows]

| Operation | Lands in |
| --- | --- |
| `CreateEntity`, `CreateEntities` | the group of the value, directly (no move) |
| `Set`, `SetAll` of the grouped component | the new value's group (one row copy if it changed) |
| `Instantiate(prefab)`, `Clone()`, `LoadEntities`, `MoveEntities` | the group of the copied value |
| `Restore(snapshot)` | the groups the snapshot had |
| `Load(bytes)` | the groups of this world's `GroupBy` calls (a save holds no groupings) |

In a world that never called `GroupBy<T>()`, every table holds group 0: `InGroup<T>(0)` matches every entity with `T`.

## Full example [#full-example]

Nine units in three zones. A system heals only the units of the active zone, a struct job sums the health of one
zone, and three units walk from zone 2 into zone 1. Put the files in a console project that references EasyEcs
(`dotnet add package EasyEcs`) and run it with `dotnet run`.

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;

// IGroup: the world keeps the entities of each zone in tables of their own.
public record struct Zone(int Id) : IComponent, IGroup
{
    public int Group => Id;
}

public record struct Health(int Value) : IComponent;

// The zone players are in: the only one that is simulated.
public record struct ActiveZone(int Id) : ISingletonComponent;
```

</Accordion>
<Accordion title="Jobs.cs">

```csharp title="Jobs.cs" doccheck=example
using EasyEcs;

// Struct jobs: a pass over the rows a filter selects, with no delegate.
public struct Regenerate : IForEach<Health>
{
    public void Execute(ref Health health)
    {
        health.Value += 1;
    }
}

public struct SumHealth : IForEach<Health>
{
    public int Total;

    public void Execute(ref Health health)
    {
        Total += health.Value;
    }
}
```

</Accordion>
<Accordion title="Systems.cs">

```csharp title="Systems.cs" doccheck=example
using EasyEcs;

// Heals the units of the active zone only. [ForEach] attributes cannot name a group value,
// so the system runs a struct job with an InGroup filter from OnUpdate.
public class RegenerateActiveZone : EcsSystem
{
    protected override void OnUpdate()
    {
        int zone = World.ActiveZone.Id;
        var inZone = QueryFilter.Create().InZone(zone);
        var job = new Regenerate();
        World.ForEach<Health, Regenerate>(ref job, inZone);
    }
}
```

</Accordion>
<Accordion title="Zones.cs">

```csharp title="Zones.cs" doccheck=example
using EasyEcs;

public static class Zones
{
    // Filters are values: build them once and keep them in fields. A filter holds one group.
    public static readonly QueryFilter One = QueryFilter.Create().InZone(1);
    public static readonly QueryFilter Two = QueryFilter.Create().InZone(2);

    // The units and total health of one zone. Walks the tables of that zone only.
    public static string Describe(World world, QueryFilter zone)
    {
        var sum = new SumHealth();
        world.ForEach<Health, SumHealth>(ref sum, zone);
        return $"{world.Count<Health>(zone)} units, {sum.Total} hp";
    }
}
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;

using var world = new World();

// Group the world before it fills: every entity then lands in its zone's tables directly.
world.GroupBy<Zone>();
world.SetActiveZone(Id: 1);
world.AddSystem<RegenerateActiveZone>();

for (int i = 0; i < 9; i++)
{
    world.CreateEntity(new Zone(i % 3), new Health(10 * i));
}

world.Update();
Console.WriteLine($"zone 1: {Zones.Describe(world, Zones.One)}");

// A new value moves the entity to the tables of its new zone. Set is allowed while a query walks.
foreach (var item in world.Query<Health>(Zones.Two))
{
    item.Entity.SetZone(1);
}

Console.WriteLine($"zone 1: {Zones.Describe(world, Zones.One)}");
Console.WriteLine($"zone 2: {Zones.Describe(world, Zones.Two)}");
```

</Accordion>
</Accordions>

It prints:

```text
zone 1: 3 units, 123 hp
zone 1: 6 units, 273 hp
zone 2: 0 units, 0 hp
```

Only the three units of zone 1 were healed (120 + 3). The three from zone 2 arrive with their 150 health; zone 2
is empty after they leave.

## How to use it fast [#how-to-use-it-fast]

- **Group at setup.** `GroupBy<T>()` on a full world moves every entity once; on an empty one it costs nothing.
- **Hoist the filters.** One `static readonly` filter per hot group, or a filter per update as above.
- **Group by what you walk, index by what you look up.** A group wins when you walk all of a big group; an index wins
  when a key holds a handful of entities.

## What it costs [#what-it-costs]

- **Memory:** a table per group for each combination of components, with its columns' spare capacity. Thousands of
  tiny groups fragment the world: that is a job for an index.
- **Changing group:** one row copy (like adding a component the table has no column for).
- **Walking a group:** the group's own rows only; no per-row test of the value.
- **Worlds that never call `GroupBy`** pay nothing: the check is folded away for components that are not `IGroup`.

## Pitfalls [#pitfalls]

| Mistake | What happens | Caught by |
| --- | --- | --- |
| Writing the grouped component through a `ref` | The row stays in its old group | [EECS015](/en/docs/guide/analyzer#eecs015) |
| A group per player, guild or owner | A table per key: memory and fragmentation | Use a [value index](/en/docs/guide/indexes-and-relations#value-indexes) |
| A value that changes every tick | A row copy per change | Keep it a plain component |
| Two `InGroup` calls in one filter | A filter holds one group: the last one counts | Code review |
| `GroupBy` during a pass | Throws: it moves rows | Call it at setup |
