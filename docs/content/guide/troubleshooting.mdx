Most mistakes never reach run time: the [analyzer](/en/docs/guide/analyzer) rejects them while you type. This page is
for the rest: the exceptions EasyEcs throws, quoted as they appear, and the problems that throw nothing. Search the
page for the first words of your message.

The problems that throw nothing: [a system that never runs](#system-does-not-run),
[systems that do not run in parallel](#not-parallel), [a missing generated member](#member-missing),

## Why does a structural change throw "started while another one was running"? [#structural-change-running]

```text
InvalidOperationException: A structural change started while another one was running on this world: structural
changes are made by the world's owner thread, one at a time
```

Two structural changes (create, destroy, `Set`, `Remove`, a singleton or system added) overlapped on one world. Either
a second thread changed the world while its owner did, or code running inside a change (a callback of your own around
EasyEcs calls) started another. EasyEcs checks a plain flag, so it catches many such races, not all of them.

**Fix:** change a world from one thread at a time. Other threads hand their changes over as data, through a queue a
system drains on the owner's thread ([input from other threads](/en/docs/guide/threading#input-from-other-threads),
[hosting](/en/docs/guide/hosting#requests)), or each thread gets its own world.

## Why does a structural change throw "while the world's structure is frozen"? [#structure-frozen]

```text
InvalidOperationException: A structural change was made while the world's structure is frozen (systems or a parallel
[ForEach] running on several threads, or a batch job holding spans into the tables)
```

The change was made while other code held the tables still: inside a parallel stage of systems
(`ParallelSystems`), a `[ForEach(Parallel = true)]` method, a batch method or `ForEachBatch` job (spans point into
the columns), or a job marked `INoStructuralChanges`. The analyzer reports the changes it sees there
([EECS010](/en/docs/guide/analyzer#eecs010), [EECS013](/en/docs/guide/analyzer#eecs013)); this one came through a
helper or a handle it could not follow.

**Fix:** record the change as data (a tag, a component, a request entity) and make it in a system or `[ForEach]`
method that runs alone: one that takes `Entity` or `World`, or an `OnUpdate`.

## Why is my entity "not alive"? [#entity-not-alive]

```text
InvalidOperationException: Entity is not alive (destroyed, or a default handle)
```

`Get`, `GetOrAdd`, `Set`, `Remove` or `Destroy` was called on a handle whose entity was destroyed (its id may already
belong to another entity: the version tells them apart), or on `default(Entity)`. Questions answer false instead of
throwing: `IsAlive`, `Has<T>()` and `TryGet<T>()`.

**Fix:** check `entity.IsAlive` where an entity may have died since you took its handle, and keep `EntityId`s in
components, resolving them with `world.TryGetEntity(id, out var entity)`
([entities and components](/en/docs/guide/entities-and-components)).

## Why does `Get<T>()` say the entity has no component? [#no-component]

```text
InvalidOperationException: Entity has no Mana component
```

`Get<T>()` (and the generated `entity.Mana`) needs the component; a component that was removed or
[disabled](/en/docs/guide/cleanup-and-disable) counts as absent. **Fix:** `TryGet<T>(out var value)` or the generated
`TryGetMana(out …)` where it is optional, `GetOrAdd<T>()` to add a default, or in a `[ForEach]` method a
[`Maybe<T>` parameter](/en/docs/guide/systems#maybe) or a second method split by `[With<T>]` / `[Without<T>]`.

## Why is a singleton "not added to this world"? [#singleton-not-added]

```text
InvalidOperationException: Singleton Clock was not added to this world: set it before the systems that read it run
(world.SetClock(...) or world.AddSingleton<Clock>()), or use GetOrAddClock() where a default is meant
```

Code read a singleton nobody added: `world.GetSingleton<T>()`, the generated `world.Clock`, `world.SingletonRef<T>()`,
or a `[ForEach]` method that takes `Clock` as a parameter. A parameter is resolved when its system runs, so the first
`Update()` throws, even when no entity matches. The world does not invent the singleton, because its default is
rarely right: a clock with no step would leave every entity standing still, with no error to point at the missing
setup ([singletons](/en/docs/guide/singletons#in-systems)).

**Fix:** add it where the world is built, before the first `Update()` (`world.SetClock(…)`,
`world.AddSingleton<Clock>()`), or use `GetOrAddSingleton<T>()` / `GetOrAddClock()` where a default value is right.

## Why does `Maybe<T>.Value` throw? [#maybe-empty]

```text
InvalidOperationException: The entity has no Mana (check HasValue)
```

The entity the method visits has no `T`. **Fix:** test `HasValue` before reading `Value`
([`Maybe<T>`](/en/docs/guide/systems#maybe)).

## Why does `AddSystem` say the system "already belongs to a world"? [#system-in-a-world]

```text
InvalidOperationException: ReceiveSpawns already belongs to a world
```

A system instance lives in one world. **Fix:** create one instance per world (`world.AddSystem<T>()` creates a new
one each time). Note that the same system type can be added twice to one world, and then runs twice per update.

## Why does `AddSystem` report a cycle? [#ordering-cycle]

```text
InvalidOperationException: [UpdateBefore] / [UpdateAfter] form a cycle among A, B
```

The orderings of the named systems cannot all hold. The analyzer reports the cycles it sees in one compilation
([EECS019](/en/docs/guide/analyzer#eecs019)); this one spans assemblies. **Fix:** remove one of the orderings.

## Why can a component not be disabled? [#cannot-disable]

```text
InvalidOperationException: ChildOf cannot be disabled: remove it instead
```

`Disable<T>()` keeps a value hidden from queries. A [cleanup component](/en/docs/guide/cleanup-and-disable) and
`ChildOf` cannot be hidden that way: the world must keep seeing them to finish a destroy and keep a hierarchy. **Fix:**
remove the component, or disable another component that systems filter on.

## Why must `Capture`, `Restore` or `RemoveTypes` wait for a pass? [#during-a-pass]

```text
InvalidOperationException: Snapshots cannot be captured or restored while a query iterates
InvalidOperationException: Types cannot be removed during a pass
```

They rewrite or drop whole tables, which a `foreach` over a query or a running system is walking. **Fix:** call them
between updates, outside any query loop ([snapshots](/en/docs/guide/snapshots),
[unloading](/en/docs/guide/migration-and-unload#remove-types)). `Restore` also refuses a snapshot of another world
(`ArgumentException`) and one taken before `RemoveTypes` dropped some of its tables.

## Why does a save not load? [#save-refused]

```text
InvalidDataException: Not an EasyEcs save (or one of another format version)
InvalidDataException: The size of Stock changed (8 bytes saved, 12 now): its saves cannot be loaded
InvalidDataException: The fields of Stock changed since the save: its saves cannot be loaded (add a new component type instead)
InvalidDataException: A damaged save: …
```

A load checks every component against the code that reads it, and a refused load leaves the world as it was.

- **Not an EasyEcs save:** the bytes are something else, cut short, or written by another save format version.
- **Size or fields changed:** an unmanaged component's fields were added, removed, renamed or retyped since the save,
  or a managed (`[NinoType]`) component's data no longer reads to its last byte. Keep the old type and add a new one,
  then convert in a system ([when the code changed](/en/docs/guide/saves#versioning)).
- **A damaged save:** a count or an id is out of range, or a buffer is longer than its bytes: the bytes are corrupt.

## Why does my system never run? [#system-does-not-run]

Check, in this order:

1. **It was added** to this world: `world.Systems` lists every system.
2. **It is enabled:** `Enabled` is true, and `Error` is null. Under `SystemErrorPolicy.Disable` an exception switched
   it off; setting `Enabled = true` clears the error and retries.
3. **Its group is updated:** a system with `[UpdateInGroup<G>]` runs only on `world.Update<G>()`, never on
   `world.Update()`.
4. **Its interval is due:** with `UpdateInterval => N`, it runs on every N-th update of its group, first on the N-th,
   shifted by `UpdatePhase`.
5. **Its filters match:** count what the method needs with `world.Count<T…>(filter)`. A `[Without<T>]` on the system's
   group applies to every method of the group, and a disabled component counts as absent.
6. **There was something to see:** a `[Changed<T>]` method visits only rows written since its system last ran, and a
   `[Removed<T>]` method only entities that lost `T` since then
   ([change tracking](/en/docs/guide/change-tracking#ticks)).

`WorldOptions.MeasureSystems` counts every run in `system.Stats.Runs`, which tells "never ran" from "ran and did
nothing".

## Why do my systems not run in parallel? [#not-parallel]

With `ParallelSystems`, a system shares a stage only when its access is known and does not conflict. A system runs
alone when it takes an `Entity` or `World` parameter, has an instance `[ForEach]` method, overrides `OnUpdate`, or has
no `[ForEach]` method. Two systems conflict when one writes what the other reads or writes, and a `ref` parameter
counts as a write even when the body only reads it: use `in`
([parallel systems](/en/docs/guide/threading#parallel-systems)). An ordering (`[UpdateAfter<T>]`) also puts the later
system in a later stage.

## Why is a generated member missing? [#member-missing]

The generator writes `entity.Health`, `SetHealth(…)`, `world.Clock` and the others as C# 14 extension members. It
writes nothing when:

- The project compiles with a language version below C# 14 (`<LangVersion>` set lower than the .NET 10 default).
- The type is generic, or nested in a type the generated code cannot see.
- The receiver already has a member of that name: a component named `Id` gets no `entity.Id` (the handle has one),
  and a member you wrote yourself wins.
- The component is indexed (`IIndexed<TKey>`): it has no `GetOrAddX()`, and `entity.X` is read-only; write it with
  `SetX(…)`.

The generic API always works: `Get<T>()`, `Read<T>()`, `Set(…)`, `Has<T>()`, `Remove<T>()`, `GetSingleton<T>()`
([generated members](/en/docs/guide/entities-and-components)).

## Why did a value I wrote through a `ref` disappear? [#ref-lost]

A `ref` from `entity.Get<T>()` or a query item is valid until the next structural change of
the world, which can move rows, and never across an `await`. A write through an older `ref` lands in memory the entity
no longer uses. Read again through the handle after the change ([refs and await](/en/docs/guide/refs-and-await)).

A tracked or indexed component is read-only through `entity.X` and `Read<T>()`: writes go through `Set(…)`, or the
generated `WriteX()` for a tracked one, so that the change is stamped
([change tracking](/en/docs/guide/change-tracking#write-as-usual)).

## Why did a component vanish after a load? [#save-dropped-data]

A save names each type by its namespace-qualified name, and a load skips the types this process does not have. A
component renamed or moved to another namespace since the save loads as missing: its data is dropped without an
error. Keep the names of saved types stable, and while a plugin's old and new versions are both loaded, unload the old
one before loading a save ([saves](/en/docs/guide/saves#plugins)).
