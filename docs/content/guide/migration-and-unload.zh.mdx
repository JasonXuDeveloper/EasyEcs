玩家穿过传送门进入另一个区域的 World，或者被交给另一台服务器。他的实体、物品和宠物必须一起过去，彼此之间的指向也不能断。
`SaveEntities` / `LoadEntities` 通过字节传送这些实体，`MoveEntities` 直接把它拷进同一线程的另一个 World，两者都会把其中的
`EntityId` 改写成新实体的 id。长期运行的服务器还要在不重启的情况下替换游戏逻辑：`RemoveTypes` 把插件的系统和组件从 World 中移除，
它所在的可回收 `AssemblyLoadContext` 就能卸载，新版本再加载存下来的数据。

## 什么时候用 [#when-to-use-it]

<Callout type="idea" title="适合">
  - **切换区域或地图**，在同一线程的 World 之间：`MoveEntities`。
  - **把玩家交给另一台服务器**，或保存离线玩家：`SaveEntities` / `LoadEntities`。
  - **记录**实体的一部分（比如 Actor 的余额，不带它的连接），再读回到它已有的实体上：`ComponentSet` 加
    `LoadEntitiesInto`（[记录](#records)）。
  - **热重载**不能重启的服务器里的游戏逻辑：`RemoveTypes`。
</Callout>

<Callout type="warn" title="不适合">
  迁移整个 World：[`Save`](/zh/docs/guide/saves) / [`Load`](/zh/docs/guide/saves) 能保留所有 id。同一个 World 里换“区域”：[分组](/zh/docs/guide/groups)或
  一个组件值就够了。重载不在可回收上下文里的类型：默认上下文永远不会卸载。实体还不存在、要存的是它的全部组件：不带集合的
  `SaveEntities` 加 `LoadEntities` 会把它创建出来。
</Callout>

## 怎么用 [#how-to-use-it]

### 通过字节传送实体 [#save-entities]

`SaveEntities(output, ids)` 写出列出的实体和它们的组件（跳过失效的 id 和重复项；不写单例）。`LoadEntities(bytes, handles)` 在另一个
World（本进程或其他进程）里用新 id 创建它们，并按存档顺序写回句柄。`ids` 是一个 span：数组、`[a.Id, b.Id]`（在栈上构造）、直接传 id
（`SaveEntities(output, a.Id, b.Id)`），或者把收集好的列表写成 `CollectionsMarshal.AsSpan(list)`，原地读取，不用 `ToArray()` 复制。

```csharp
using Nino.Core;

public record struct Sword(int Damage) : IComponent;

// 按主人建索引：找英雄的宠物不用把所有宠物扫一遍。
public partial record struct Pet([IndexKey] EntityId Owner) : IComponent;
```

```csharp
using System.Runtime.InteropServices;

var hero = world.CreateEntity(new Health(100));
world.CreateEntity(new Sword(10), new ChildOf(hero));
world.CreateEntity(new Pet(hero), new Health(20));

// 收集这一组：英雄、挂在他身上的、指向他的
var party = new List<EntityId>();
world.Descendants(hero).AddTo(party, includeRoot: true);                // 英雄，然后是子实体、孙实体，一层层往下
foreach (var pet in world.PetIndex.Find(hero.Id)) party.Add(pet.Id);    // 走索引，不扫描所有 Pet

var bytes = new NinoArrayBufferWriter();
world.SaveEntities(bytes, CollectionsMarshal.AsSpan(party));                  // 只写这一组 // [!code highlight]

using var otherServer = new World();
var arrived = new Entity[party.Count];
int created = otherServer.LoadEntities(bytes.WrittenSpan, arrived);   // 新 id，链接已改写 // [!code highlight]
```

`Descendants` 深度优先遍历，每个实体都排在它的子实体前面，所以收集到的组里父实体总在挂在它身上的实体之前。`MoveEntities`
要的正是这个顺序：它从后往前销毁原实体，子实体就会先于父实体销毁。`Children` 只列出一层。`ChildOf` 成环时，遍历抛
`InvalidOperationException`。指向英雄的实体（宠物、随从）通过字段上的索引来找（如上），或者用[关系](/zh/docs/guide/indexes-and-relations#relations)：
逐个检查 `Pet` 的查询随整个 World 变大，而不是随这一组变大。

### 迁到同一线程的另一个 World [#move-entities]

`MoveEntities(target, ids, moved)` 在同一线程的两个 World 之间做同样的事，但不经过编码：拷贝行、改写 id，然后销毁原实体。`moved`
按顺序接收新句柄（跳过的 id 对应 `default`）。

```csharp
using System.Runtime.InteropServices;

using var nextZone = new World();
var moved = new List<Entity>();                    // 每次搬迁都复用它：容量够大之后不再分配内存。
CollectionsMarshal.SetCount(moved, party.Count);
int count = world.MoveEntities(nextZone, CollectionsMarshal.AsSpan(party), CollectionsMarshal.AsSpan(moved));   // 英雄、剑和宠物离开这个 World
```

- 原实体销毁时会连同子实体一起销毁，所以[层级](/zh/docs/guide/hierarchy#moving)要整体迁移。
- 清理组件不会移动：它们留在原实体上（原实体已退休），由本 World 的系统释放；新实体没有这些组件，所以资源只释放一次。
- 已经退休、因清理组件而保留的实体（带 `Retired` 标签）和失效的 id 一样被跳过：不复制，不计数，它在 `moved` 中的位置为 `default`。
- 两个 World 都必须属于调用线程；把 World 迁到自己身上会被拒绝（`ArgumentException`）。

### 只存需要持久化的部分 [#records]

Actor 的实体上，运行时状态和需要持久化的数据放在一起：连接、计时器、缓存，以及重启后必须还在的银行余额。`ComponentSet` 列出记录里
的组件，`SaveEntitiesWith(output, ids, set)` 只写这些（其余组件不需要 Nino 格式化器），`LoadEntitiesInto(bytes, entities)` 把它们放到
已经存在的实体上，比如 Actor 激活时就有了、记录还没从数据库取回来的那个实体。

只有实体的一部分需要撑过进程重启（其余部分由激活它的代码重建），或者实体比数据先创建出来，就用记录。集合只建一次，放在
`static readonly` 字段里，列出需要持久化的组件；存进一个复用的 `NinoArrayBufferWriter`，写出的字节放到数据该在的地方（数据库的一行、
文件、发给另一台服务器的消息）。

```csharp
public record struct Bank(long Gold) : IComponent;
public record struct Connection(int Socket) : IComponent;              // 只在运行时存在：从不存档

public static class Records
{
    public static readonly ComponentSet Persistent = ComponentSet.Create().With<Bank>();   // 只建一次
}
```

```csharp
var actor = world.CreateEntity(new Bank(500), new Connection(7));
var record = new NinoArrayBufferWriter();
world.SaveEntitiesWith(record, [actor.Id], Records.Persistent);            // 只写 Bank // [!code highlight]

// 之后，可能在另一个进程里：Actor 先激活，记录随后才到。
var activated = world.CreateEntity(new Connection(9));
world.LoadEntitiesInto(record.WrittenSpan, [activated]);               // 加上 Bank，Connection 保留 // [!code highlight]
```

```csharp
var restored = world.CreateEntity(new Connection(10));
// 替代上面那次调用：恢复同一份记录，但不算变更。
world.LoadEntitiesInto(record.WrittenSpan, [restored], markWritten: false);
```

- 存档里第 i 个实体读到传入的第 i 个实体上；数量必须一致，每个实体都必须在本 World 里存活且只出现一次，否则在改动任何东西之前抛
  `ArgumentException`。
- 不管收到几个组件，每个实体最多换一次表。记录里有的组件会被加上或覆盖原值，没有的保持不变。
- 索引、分组和变更追踪的表现和 `Set` 一样。被禁用的组件读进来仍是禁用的，值也保留。
- 加载也算写入：`[Changed<T>]` 方法会看到读进来的组件。如果记录只是恢复原本就有的数据（actor 从数据库重新加载），传
  `markWritten: false`：记录里的每个组件加载后都没有变更 tick，覆盖了默认值（比如来自预制体）的也一样，这样按变更保存或同步组件的
  系统就不会把记录原样写回去。记录里没有的组件保留各自的 tick。
- `markWritten: false` 的代价：恢复的组件在代码写它之前，所有 `[Changed<T>]` 方法和 `Since` 过滤条件都看不到。按变更同步给客户端的
  系统，遇到还没见过这个实体的客户端，要自己发送完整状态。
- 所以每类 actor 一个预制体就够了：新 actor 用预制体的默认值作为初始状态（算写入，下次保存会存下来），恢复的 actor 由记录覆盖
  默认值（不算写入）。[Actors 示例](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/Actors)就是这么做的。
- `SaveEntitiesWith` 也会写出一个集合组件都没有的实体，作为空条目，这样存档里第 i 个实体仍对应传入的第 i 个实体。
- `EntityId` 字段按下文的规则改写，指向传入的实体；父实体不在记录里的 `ChildOf` 不会被设置。
- `LoadEntitiesInto` 是结构变更：只能在所有者线程调用（[EECS014](/zh/docs/guide/analyzer#eecs014)），遍历进行中不能调用
  （抛 `InvalidOperationException`），不能放进并行方法（[EECS010](/zh/docs/guide/analyzer#eecs010)），`[ForEach]` 方法要接收
  `Entity` 或 `World` 才能调用（[EECS013](/zh/docs/guide/analyzer#eecs013)）。
- 集合在实体存档里列的是组件。它也能列单例（`WithSingleton<T>()`，或者两种类型都接受的 `With(typeof(...))`），用于整个 World 的
  [重启](/zh/docs/guide/saves#restart)：`SaveWithout(output, in exclude)` 不写这些类型，`LoadKeeping(input, in keep)` 保留这些单例。实体存档不写单例，
  所以集合里有单例时 `SaveEntitiesWith` 和 `SaveEntitiesWithout` 都抛 `ArgumentException`。
- 运行时才知道类型的框架按 `Type` 构建集合：

```csharp
public static class RuntimeRecords
{
    public static readonly ComponentSet Persistent = ComponentSet.Create().With(typeof(Bank));
}
```

#### 集合以外的一切：`SaveEntitiesWithout` [#save-entities-without]

反过来，`SaveEntitiesWithout(output, ids, set)` 写集合以外的一切：实体加载后会重新算出来的数据（高度图、缓存、流场）不写进去，存档就小。
不写的组件不需要 Nino 格式化器，`Disabled<T>` 标签跟着它的组件一起不写。

```csharp
public record struct Terrain(int Seed) : IComponent;
public record struct HeightMap(int[] Heights) : IComponent;            // 加载后由 Terrain 重新算出

public static class ChunkSaves
{
    public static readonly ComponentSet Derived = ComponentSet.Create().With<HeightMap>();   // 只建一次
}
```

```csharp
var chunk = world.CreateEntity(new Terrain(42), new HeightMap(new int[256]));
var chunkSave = new NinoArrayBufferWriter();
world.SaveEntitiesWithout(chunkSave, [chunk.Id], ChunkSaves.Derived);   // 只有 Terrain // [!code highlight]
```

`LoadEntities` 创建出来的区块只有 `Terrain`，没有 `HeightMap`；再由一个带 `[Without<HeightMap>]` 的系统把它算回来。

| 实体 | 存档用 |
| --- | --- |
| 什么都要持久化 | `SaveEntities(output, ids)` |
| 运行时状态里只有少数组件要持久化（连接、计时器、缓存旁边的银行余额） | `SaveEntitiesWith(output, ids, persistent)` |
| 大多数组件要持久化，少数加载后会重新算（高度图、流场、路径） | `SaveEntitiesWithout(output, ids, derived)` |

列出较小的那个集合：以后新加的组件默认落在对的一边，用 `Without` 时会被保存，用 `With` 时不写。

### id 怎么改写 [#entityid-rewriting]

生成器会记下组件和缓冲元素里每个 `EntityId` 字段的位置，私有字段和嵌套结构体也算在内。一组实体到达时：

| `EntityId` 字段原来指向 | 变成 |
| --- | --- |
| 一起到达的实体 | 它对应新实体的 id |
| 没有一起到达的实体（留在原地） | `EntityId.Null` |
| 留在原地的父实体（`ChildOf`） | 移除 `ChildOf`：实体在这边成为根 |

集合里的 id（组件里的 `List<EntityId>`）不会改写。索引和分组会认识新到的实体，被追踪组件算作写入。

### 到达时的唯一键 [#unique-keys]

[唯一键](/zh/docs/guide/indexes-and-relations#unique-keys)（比如账号 id）在每个 World 里只对应一个实体，新到的一组实体不能带来目标
World 已经分出去的键。`LoadEntities`、`LoadEntitiesInto` 和 `MoveEntities` 在第一行到达之前，就拿这组实体的每个唯一键和目标 World 比对：

- 键已被目标 World 的另一个实体持有：抛 `InvalidOperationException`，什么也不进来。此时 `MoveEntities` 不动源 World 里的原实体，
  玩家还在原地。
- 字节里同一个键给了两个实体（存档损坏或是手工拼的）：抛 `InvalidDataException`。
- `LoadEntitiesInto` 写到本来就持有这个键的实体上没问题：它拿到的就是自己的键。在给定的实体之间互换键会被拒绝，和把键给第二个实体一样。

玩家回到一个还留着他旧副本的 World（过期的会话、崩溃留下的残影）时，在旧副本被销毁或去掉键之前都会被拒绝：先销毁它，再加载或迁移玩家。

[销毁日志](/zh/docs/guide/change-tracking#destroy-log)会记下 `MoveEntities` 在源 World 里销毁的原实体，源 World 的读者能看到这组实体离开。

### 卸载插件的类型 [#remove-types]

`world.RemoveTypes(assembly)`（或 `RemoveTypes(context)`，针对一个 `AssemblyLoadContext` 里的所有程序集）把插件的一切从 World 中移除：
它的系统（会执行 `OnDestroy`）、单例、索引和分组设置，以及所有实体上它的组件。实体本身保留，只是没了这些组件。含有这类列的表会连同
引用它们的所有缓存一起丢弃，World 不再持有对这个程序集的任何引用。所有 World 都移除之后，可回收上下文就能卸载；卸载时，EasyEcs
会忘掉这些类型的存档 id，并在没有存活 World 用到它们时复用其组件位。

### 热重载 [#hot-reload]

存档按 id 记录类型，所以重载能保住插件的数据：存档、移除类型、卸载、加载新版本、读档。

```csharp
using System.Buffers;
using System.Reflection;
using System.Runtime.CompilerServices;
using System.Runtime.Loader;

public sealed class PluginContext() : AssemblyLoadContext("plugin", isCollectible: true);

public static class Plugins
{
    public static Assembly Reload(World world, PluginContext old, PluginContext next, string path)
    {
        var saved = new ArrayBufferWriter<byte>();
        world.Save(saved);                                      // 插件的组件也一起存，按类型 id
        world.RemoveTypes(old);                                 // 它的系统、单例和组件全部离开 // [!code highlight]
        old.Unload();                                           // 没有别的引用后就会被回收

        var plugin = next.LoadFromAssemblyPath(path);
        RuntimeHelpers.RunModuleConstructor(plugin.ManifestModule.ModuleHandle);   // 注册它的类型，供 Load 查找
        world.Load(saved.WrittenSpan);                          // 新版本的组件拿到存下来的值
        return plugin;                                          // 之后把它的系统加回 World
    }
}
```

顺序很重要：两个版本同时加载时类型 id 相同，读档会因为类型 id 有歧义而拒绝加载。宿主自己的组件（位置、id）放在一个永远不会重载的程序集里；自己也不要
持有旧版本类型的引用（系统、插件对象），否则上下文无法回收。`RemoveTypes` 之前拍的[快照](/zh/docs/guide/snapshots)，之后不能再恢复。

[HotReload 示例](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/HotReload)完整跑一遍这个流程，并校验旧上下文已被回收、
插件数据已经带过来。

重载会留下一些内存：存档和加载用的缓冲已经长到能装下整个 World，实体离开后还有空表。新版本跑起来以后，在空闲的时候（不要在 tick 里）调用
`world.TrimExcess()` 把它们还回去（见[高峰过后还回内存](/zh/docs/guide/diagnostics#trim)）。

整个进程重启也是这样走字节，只有两点不同：旧进程不写不该带回来的东西（运行时状态、它自己的配置），新进程保留它在加载之前设好的配置。
`SaveWithout(output, in exclude)` 和 `LoadKeeping(input, in keep, markWritten: false)` 正好做这两件事：见[重启](/zh/docs/guide/saves#restart)。

## 完整例子 [#full-example]

一个英雄带着剑（剑上镶着宝石）和宠物走进另一个区域：用 `Descendants` 和宠物索引收集这一组，用 `MoveEntities` 迁过去，宠物仍然
指向它的英雄。接着，一个 Actor 的银行作为记录从之前的运行里取回来，用 `markWritten: false` 读入，按 `[Changed<Bank>]` 保存的系统
在存款之前什么都找不到。把这几个文件放进一个引用了 EasyEcs 的控制台项目（`dotnet add package EasyEcs`），用 `dotnet run` 运行。

```csharp title="Party.cs" doccheck=example
using EasyEcs;

public static class Party
{
    // 英雄、挂在他身上的实体（父实体总在子实体之前），以及他的宠物。
    public static List<EntityId> Collect(World world, Entity hero)
    {
        var party = new List<EntityId>();
        world.Descendants(hero).AddTo(party, includeRoot: true);

        foreach (var pet in world.PetIndex.Find(hero.Id))
        {
            party.Add(pet.Id);
        }

        return party;
    }
}
```

```csharp title="Program.cs" doccheck=example
using System.Runtime.InteropServices;
using EasyEcs;
using Nino.Core;

// 同一进程里的两个区域。下一个区域已经有实体，所以那边的 id 不同。
using var zone = new World();
using var nextZone = new World();
nextZone.CreateEntity(new Health(50));
nextZone.CreateEntity(new Health(50));

var hero = zone.CreateEntity(new Health(100));
var sword = zone.CreateEntity(new Sword(10), new ChildOf(hero));
zone.CreateEntity(new Gem(3), new ChildOf(sword));
zone.CreateEntity(new Pet(hero.Id), new Health(20));

// 英雄走进传送门：整组迁过去，id 随之改写。
List<EntityId> party = Party.Collect(zone, hero);
var moved = new Entity[party.Count];
zone.MoveEntities(nextZone, CollectionsMarshal.AsSpan(party), moved);
for (int i = 0; i < party.Count; i++)
{
    Console.WriteLine($"{party[i]} -> {moved[i].Id}");
}

Entity pet = moved[^1];
Console.WriteLine($"pet owner: {pet.Pet.Owner}, hero: {moved[0].Id}");
Console.WriteLine($"left behind: {zone.EntityCount} entities");

// 一份记录：之前某次运行存下的 Actor 银行，不带连接。
using var earlier = new World();
var saved = earlier.CreateEntity(new Bank(500), new Connection(7));
var record = new NinoArrayBufferWriter();
earlier.SaveEntitiesWith(record, [saved.Id], Records.Persistent);

using var world = new World();
world.AddSystem<SaveChangedBanks>();

// Actor 激活时不带 Bank：由记录加上，而且不算写入。
var actor = world.CreateEntity(new Connection(9));
world.LoadEntitiesInto(record.WrittenSpan, [actor], markWritten: false);
Console.WriteLine($"update after the load ({actor.Bank.Gold} gold):");
world.Update();

actor.SetBank(Gold: 650);
Console.WriteLine("update after a deposit:");
world.Update();
```

## 怎么用得快 [#how-to-use-it-fast]

| 别这样 | 这样做 | 为什么 |
| --- | --- | --- |
| 同一进程的 World 之间用 `SaveEntities` + `LoadEntities` | `MoveEntities` | 直接拷行，不编码 |
| 每次迁移新建缓冲区 | 复用一个 `NinoArrayBufferWriter`，每次 `ResetWrittenCount()` | 足够大之后不分配 |
| 一个实体一个实体地迁移 | 整组一次迁移 | 存档的固定开销（按 id 写类型）只付一次 |
| 只有部分组件需要持久化，却用 `SaveEntities` 存整个实体 | 用 `ComponentSet` | 运行时组件不写入，也不需要格式化器 |
| 每次存档都新建 `ComponentSet` | 一个 `static readonly` 集合 | 每次 `With` 都会复制集合 |
| 把加载后会重新算的数据也存进去（高度图、缓存、流场） | `SaveEntitiesWithout`，集合里放这些派生组件 | 存档更小，也不需要它们的格式化器 |
| 重载时重建整个 World | 先 `RemoveTypes`，再 `Load` | 宿主的实体和组件原地不动 |
| 重载之后一直背着长大的缓冲 | 新版本跑起来后调一次 `TrimExcess()` | 释放存档、加载用的缓冲和空表 |

## 开销 [#what-it-costs]

- **迁移：** O(实体数 × 组件数)；改写 id 是每个 `EntityId` 字段一次查找。
- **分配：** 缓冲区足够大之后，`SaveEntities`、`LoadEntities`、`LoadEntitiesInto` 和 `MoveEntities` 都不分配。
- **`RemoveTypes`：** O(带这类组件的实体 + 表 + 缓存的查询)；它会分配，属于冷路径：在两次更新之间调用，不要放在 tick 里。
- **稳态：** 零开销。从不调用 `RemoveTypes` 的 World，不为卸载支持付出任何时间。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 谁能发现 |
| --- | --- | --- |
| 只迁移父实体，不带子实体 | 子实体随原实体一起被销毁 | 用 `Descendants` 收集整组 |
| 只用 `Children` 收集这一组 | 漏掉孙实体，它们随父实体一起销毁 | `Descendants` 会遍历每一层 |
| 组件里的 `List<T>` 存着 `EntityId` | 不会改写：仍指向旧 World 的实体 | 用字段、缓冲或关系 |
| 组件里存了 `Entity` 句柄 | 不能存档，也不会改写 | [EECS017](/zh/docs/guide/analyzer#eecs017) |
| 先加载新插件，再卸载旧插件 | 类型 id 歧义：`InvalidDataException` | 按上面的重载顺序 |
| 还留着旧插件系统的引用 | 上下文永远回收不了 | `RemoveTypes` 之后丢掉引用 |
| 在更新或遍历期间调用 `RemoveTypes` | 抛 `InvalidOperationException` | 遍历期间由 [EECS041](/zh/docs/guide/analyzer#eecs041) 报出；更新期间在运行时 |
| 恢复 `RemoveTypes` 之前拍的快照 | 抛 `InvalidOperationException` | 运行时 |
| 在其他线程迁移 | 两个 World 都只属于各自的所有者线程 | [EECS014](/zh/docs/guide/analyzer#eecs014) |
| 迁移或加载的玩家，唯一键已被目标 World 持有 | 抛 `InvalidOperationException`；什么也不进来，原实体不动 | 先销毁过期的持有者（[唯一键](#unique-keys)） |
| `SaveEntitiesWith` 或 `SaveEntitiesWithout` 的集合里有单例 | 抛 `ArgumentException`：实体存档不写单例 | 单例放进整个 World 的[重启](/zh/docs/guide/saves#restart)存档 |
| `SaveEntitiesWithout` 漏掉的组件没人重新算 | 加载出来的实体永远缺它 | 用带 `[Without<T>]` 的系统重建它，或者留在存档里 |
| 需要持久化的组件没放进记录的集合 | 不会存档：读回后实体保留自己原来的值，或者根本没有这个组件 | 在一个地方、按需要持久化的组件建集合 |
| 用 `LoadEntities` 读记录 | 在已有实体之外又建了新实体 | 对已有实体用 `LoadEntitiesInto` |
| `LoadEntitiesInto` 传入的实体数和存档不一致，或者有失效的实体 | `ArgumentException`；什么都不改 | 按存档顺序，每个存档实体对应一个存活实体 |
| 恢复的记录被当成变更 | 按 `Changed<T>` 保存或同步的系统又把它发回去 | `markWritten: false` |
| `markWritten: false` 加载后只同步 `[Changed<T>]` 的行 | 没见过这个实体的客户端永远收不到恢复的值 | 给新客户端发送完整状态 |
