A ship carries turrets, a turret carries a gun, a squad leader leads its members. `ChildOf(parent)` links an entity
to its parent: `world.Children(parent)` lists the children, and destroying the parent destroys its descendants, so a
ship that sinks takes its turrets with it without a line of cleanup code. `ChildOf` is an
[indexed `EntityId` link](/en/docs/guide/indexes-and-relations#entityid-keys) like any other, with the destroy cascade
switched on.

## When to use it [#when-to-use-it]

<Callout type="idea" title="Use it for">
  Entities that live and die with another one: turrets on a ship, items a player carries, members of a squad, the
  parts of a vehicle. Moving a player and everything it owns to another world or server.
</Callout>

<Callout type="warn" title="Skip it for">
  Links that must not kill the linked entity (a target, a follower): use your own `EntityId` key with `Keep` or `Remove`.
  An entity with several "parents" (a member of many parties): use a [relation](/en/docs/guide/indexes-and-relations#relations).
  Transform propagation is not built in: the [sample below](#transform-propagation) is a system you write.
</Callout>

## How to use it [#how-to-use-it]

<Steps>
<Step>

### Attach children [#attach]

Give the child a `ChildOf` with the parent's id (a handle converts to it).

```csharp
public record struct Name(string Value) : IComponent;
```

```csharp
var ship = world.CreateEntity(new Name("ship"));
var turret = world.CreateEntity(new Name("turret"), new ChildOf(ship));
var gun = world.CreateEntity(new Name("gun"), new ChildOf(turret));
```

</Step>
<Step>

### List them [#children]

`world.Children(parent)` returns the entities whose `ChildOf` points at the parent: O(1), then O(1) per child. The
first call indexes every `ChildOf` once.

```csharp
foreach (var child in world.Children(ship)) { /* the turret */ }
```

</Step>
<Step>

### Walk a subtree: Descendants [#descendants]

`world.Descendants(root)` walks the whole subtree below the root, depth first, each entity before its own children;
the root itself is not one of them. It costs O(1) per entity and allocates nothing once warm. Use it where a whole tree
is the unit (saving, moving or counting it); propagation that needs each parent's result goes through
[`Children` level by level](#transform-propagation).

```csharp
int parts = 0;
foreach (var part in world.Descendants(ship)) parts++;   // the turret, then its gun
```

- **Destroying during the walk** is allowed: an entity destroyed before the walk reaches it is skipped.
- **A walk inside a walk** works: the inner one allocates a stack of its own (the outer one holds the world's).
- **A `ChildOf` cycle** (an entity that is its own ancestor) throws `InvalidOperationException` when the walk reaches
  it.
- **Changing `ChildOf` during the walk** (re-parenting, detaching) is not allowed: it rewrites the child lists the
  walk is reading. Collect first, then change.

</Step>
<Step>

### Re-parent and detach [#reparent]

`ChildOf` is a value like any other: set a new one to re-parent, remove it to make the entity a root. Like your own
components it has [generated members](/en/docs/guide/entities-and-components): `entity.ChildOf` (read-only: it is
indexed), `HasChildOf`, `TryGetChildOf(out link)`, `SetChildOf(parent)`, `SetChildOfIfChanged(parent)`,
`RemoveChildOf()` and `world.ChildOfIndex`, with `SetChildOf` / `RemoveChildOf` on a prefab too. It has no
`DisableChildOf`: `ChildOf` cannot be disabled.

```csharp
gun.SetChildOf(ship);      // the gun now hangs on the ship
turret.RemoveChildOf();    // the turret is a root
```

</Step>
<Step>

### Destroy a parent [#cascade]

Destroying a parent destroys its children, and theirs, in the same call.

```csharp
ship.Destroy();                            // the gun goes with it; the detached turret stays
bool gunAlive = gun.IsAlive;               // false
```

</Step>
</Steps>

### Spawn children from a prefab [#instantiate-children]

A child made from a [prefab](/en/docs/guide/prefabs) gets its parent in the same call:
`world.Instantiate(minion, new ChildOf(boss))` writes the `ChildOf` over the copy in its final table, so the child is
linked with one row copy and no move ([Give each instance its own values](/en/docs/guide/prefabs#instantiate-with-values)).
The batch form `world.Instantiate(minion, span, new ChildOf(boss))` hangs a whole wave on one parent.

### Walk up to an ancestor [#ancestors]

`Children` and `Descendants` go down. Going up needs no index: read the entity's `ChildOf`, follow its `Parent`, and
repeat until you reach an entity with the component you look for, or a root (an entity without `ChildOf`). A gun
finds the ship it is mounted on, an item the player that carries it.

```csharp
public struct Vessel : IComponent;                 // the ancestor a part looks for

public static class Ancestors
{
    // The nearest ancestor of part that has T, or default when none has.
    public static Entity Nearest<T>(Entity part) where T : struct, IComponent
    {
        var world = part.World;
        // A chain longer than the world's entities is a ChildOf cycle: stop instead of looping forever.
        for (int steps = world.EntityCount; steps > 0; steps--)
        {
            if (!part.TryGetChildOf(out var link)) return default;                // a root: no such ancestor
            if (!world.TryGetEntity(link.Parent, out var parent)) return default; // the parent is gone (Keep)
            if (parent.Has<T>()) return parent;
            part = parent;
        }

        throw new InvalidOperationException("The ChildOf links form a cycle");
    }

    // The root above part: the first entity up the chain without a living parent (part itself for a root).
    public static Entity Root(Entity part)
    {
        var world = part.World;
        for (int steps = world.EntityCount; steps > 0; steps--)
        {
            if (!part.TryGetChildOf(out var link) || !world.TryGetEntity(link.Parent, out var parent)) return part;
            part = parent;
        }

        throw new InvalidOperationException("The ChildOf links form a cycle");
    }
}
```

```csharp
var frigate = world.CreateEntity(new Name("frigate"), new Vessel());
var deck = world.CreateEntity(new Name("deck"), new ChildOf(frigate));
var cannon = world.CreateEntity(new Name("cannon"), new ChildOf(deck));
Entity carrier = Ancestors.Nearest<Vessel>(cannon);   // the frigate, two levels up
Entity top = Ancestors.Root(cannon);                  // the frigate too: it has no parent
```

- **Cost:** one step per level, each a component read and an id lookup: O(depth), no allocation, no index. Shallow
  hierarchies (a ship and its turrets) cost a step or two.
- **In a `[ForEach]` over many entities,** that is a few lookups per row every tick. When the answer changes only when
  the entity is re-parented, keep it in a component of the child (the vessel's `EntityId`) and set it where the
  `ChildOf` is set.
- **Cycles:** `Set` does not refuse a `ChildOf` that closes a loop (an entity that becomes its own ancestor), so the
  walk bounds its steps by `world.EntityCount`, as `Descendants` does, and throws past it.
- **Links to destroyed parents** exist only under `TargetPolicy.Keep` ([below](#cascade-policy)): `TryGetEntity` says
  the parent is gone, and the walk stops there.

### Changing what a destroy does [#cascade-policy]

`ChildOf` starts with `TargetPolicy.Destroy`. Like any [target policy](/en/docs/guide/indexes-and-relations#target-policies)
it can be changed per world: `Remove` makes the children of a destroyed parent roots, `Keep` leaves their `ChildOf`
pointing at the dead id.

```csharp
world.ChildOfIndex.WhenTargetDestroyed(TargetPolicy.Remove);   // orphans become roots
```

- A child that holds a [cleanup component](/en/docs/guide/cleanup-and-disable#cleanup-components) is retired, not freed:
  it keeps its cleanup components with the `Retired` tag, and its own children go with it.
- A cycle (an entity that is its own ancestor) ends: destroying any of them destroys the loop.
- `ChildOf` cannot be disabled (`Disable<ChildOf>()` throws): a parent's destroy must find its children.

### Transform propagation [#transform-propagation]

EasyEcs has no transform component. Propagation is a system: start at the roots (`Without<ChildOf>`) and walk down
with `Children`, so each world position is computed from its parent's new one.

```csharp
public record struct LocalPosition(float X, float Y) : IComponent;
public record struct WorldPosition(float X, float Y) : IComponent;
```

```csharp title="PropagateTransforms.cs"
public class PropagateTransforms : EcsSystem
{
    // Roots: their world position is their local one; then each subtree follows its parent.
    [ForEach, Without<ChildOf>]
    static void FromRoot(Entity root, in LocalPosition local, ref WorldPosition position)
    {
        position = new WorldPosition(local.X, local.Y);
        Follow(root, position);
    }

    static void Follow(Entity parent, WorldPosition at)
    {
        foreach (var child in parent.World.Children(parent)) // [!code highlight]
        {
            ref readonly var local = ref child.LocalPosition;
            var position = new WorldPosition(at.X + local.X, at.Y + local.Y);
            child.WorldPosition = position;
            Follow(child, position);
        }
    }
}
```

```csharp
world.AddSystem<PropagateTransforms>();
var hull = world.CreateEntity(new LocalPosition(10, 0), new WorldPosition());
var mount = world.CreateEntity(new LocalPosition(0, 2), new WorldPosition(), new ChildOf(hull));
var barrel = world.CreateEntity(new LocalPosition(1, 0), new WorldPosition(), new ChildOf(mount));
world.Update();                            // barrel: WorldPosition(11, 2)
```

The method takes an `Entity`, so the system runs alone (it reads and writes other entities' components). Children are
in other tables than the roots (they have `ChildOf`), so writing them never moves the row the pass stands on. Nothing
here allocates.

### Moving a hierarchy [#moving]

`MoveEntities` and `SaveEntities` take the entities you list, not their children. Collect a hierarchy with
`world.Descendants(root).AddTo(ids, includeRoot: true)`, which appends the root and then every descendant, each parent
before its children (O(1) per entity, allocating only when the list grows; clear a reused list first), and move it
together: a child whose parent stays behind arrives without its `ChildOf` (a root there), and
`MoveEntities` destroys the originals with their children, so a child you did not list is lost. Both take a
`ReadOnlySpan<EntityId>`: pass the list's span (`CollectionsMarshal.AsSpan`) rather than a copy of it. See
[migration](/en/docs/guide/migration-and-unload#move-entities).

```csharp
using System.Runtime.InteropServices;

var player = world.CreateEntity(new Name("bob"));
world.CreateEntity(new Name("sword"), new ChildOf(player));

var group = new List<EntityId>();
world.Descendants(player).AddTo(group, includeRoot: true);   // bob, then children, grandchildren, ...
using var other = new World();
world.MoveEntities(other, CollectionsMarshal.AsSpan(group));   // bob and his sword, still linked
```

## Full example [#full-example]

A ship with a turret and a gun: world positions follow the parents, the ship's subtree is listed, then the gun is
re-parented, the turret detached, and the ship destroyed with what still hangs on it. Put the files in a console
project that references EasyEcs (`dotnet add package EasyEcs`) and run it with `dotnet run`.

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;

public record struct Name(string Value) : IComponent;

// The position relative to the parent (or to the world, for a root).
public record struct LocalPosition(float X, float Y) : IComponent;

// The position in the world, computed by PropagateTransforms.
public record struct WorldPosition(float X, float Y) : IComponent;
```

</Accordion>
<Accordion title="Systems.cs">

```csharp title="Systems.cs" doccheck=example
using EasyEcs;

// Computes every world position from the roots down,
// so each child follows its parent's new position.
public class PropagateTransforms : EcsSystem
{
    // Roots have no ChildOf: their world position is their local one.
    [ForEach, Without<ChildOf>]
    static void FromRoot(Entity root, in LocalPosition local, ref WorldPosition position)
    {
        position = new WorldPosition(local.X, local.Y);
        Follow(root, position);
    }

    static void Follow(Entity parent, WorldPosition parentPosition)
    {
        foreach (var child in parent.World.Children(parent))
        {
            LocalPosition local = child.LocalPosition;
            float x = parentPosition.X + local.X;
            float y = parentPosition.Y + local.Y;
            var position = new WorldPosition(x, y);
            child.WorldPosition = position;
            Follow(child, position);
        }
    }
}
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;

using var world = new World();
world.AddSystem<PropagateTransforms>();

// A child points at its parent with ChildOf.
Entity ship = world.CreateEntity(new Name("ship"), new LocalPosition(10, 0), new WorldPosition());
Entity turret = world.CreateEntity(
    new Name("turret"), new LocalPosition(0, 2), new WorldPosition(), new ChildOf(ship));
Entity gun = world.CreateEntity(
    new Name("gun"), new LocalPosition(1, 0), new WorldPosition(), new ChildOf(turret));

world.Update();
Console.WriteLine($"gun at {gun.WorldPosition}");

foreach (var child in world.Children(ship))
{
    Console.WriteLine($"ship > {child.Name.Value}");
}

// Descendants walks the whole subtree, depth first: each entity before its own children.
Console.Write("ship's subtree:");
foreach (var part in world.Descendants(ship))
{
    Console.Write($" {part.Name.Value}");
}

Console.WriteLine();

// Re-parent: set a new ChildOf. Detach: remove it, and the entity is a root.
gun.SetChildOf(ship);
turret.RemoveChildOf();

// ChildOf is an indexed component: its index counts the children of a parent.
var children = world.ChildOfIndex;
Console.WriteLine($"ship: {children.Count(ship)} child, turret: {children.Count(turret)} children");

// Destroying a parent destroys its children: the gun goes with the ship.
ship.Destroy();
Console.WriteLine($"turret alive: {turret.IsAlive}, gun alive: {gun.IsAlive}");
Console.WriteLine($"{world.EntityCount} entity left");
```

</Accordion>
</Accordions>

It prints:

```text
gun at WorldPosition { X = 11, Y = 2 }
ship > turret
ship's subtree: turret gun
ship: 1 child, turret: 0 children
turret alive: True, gun alive: False
1 entity left
```

The gun's world position adds its parents' offsets: 10 + 0 + 1 and 0 + 2 + 0. `Children` lists only the turret;
`Descendants` reaches the gun below it. After the turret is detached it survives the ship; the gun, re-parented to the
ship, does not.

## How to use it fast [#how-to-use-it-fast]

- **Destroy the root.** One `Destroy` follows the whole subtree inside the structural gate, with no recursion (a stack
  of targets). Destroying children one by one before their parent does the same work in more calls.
- **Keep depth shallow when you propagate.** The walk above costs one `Children` lookup per entity; flat hierarchies
  (a ship and its turrets) walk fastest.
- **`DestroyAll<T>()`** destroys a whole table at once and still applies the cascade.
- **Give a prefab's child its parent at once:** `Instantiate(prefab, new ChildOf(parent))` places it in its final
  table; `Instantiate` then `SetChildOf(...)` copies the row, then moves it.
- **Store what a walk up finds** when many entities need it every tick: an [ancestor walk](#ancestors) is O(depth)
  per call.

## What it costs [#what-it-costs]

- **Nothing until the first `ChildOf`.** A world without a table holding `ChildOf` does not look for children when it
  destroys an entity.
- **Memory:** the `ChildOf` column (8 bytes per row) and the index of an `EntityId` key (one node per child).
- **`Children`:** O(1), then O(1) per child; the first call indexes every `ChildOf`.
- **`Descendants`:** O(1) per entity of the subtree, on a stack the world keeps (0 B once warm).
- **A cascade:** O(1) per destroyed entity, plus O(1) per child it had.

## Pitfalls [#pitfalls]

| Mistake | What happens | Caught by |
| --- | --- | --- |
| Writing `ChildOf` through a `ref` | The index keeps the old parent | [EECS015](/en/docs/guide/analyzer#eecs015) |
| A parent pointer of your own as an `Entity` field | A managed column, not saved, no cascade | [EECS017](/en/docs/guide/analyzer#eecs017) |
| Moving a parent without its children | The children stay and die with the destroyed original | Collect the group with `Descendants` |
| Collecting a tree with `Children` alone | Grandchildren are left out | `Descendants` walks every level |
| A `ChildOf` cycle walked with `Descendants` | `InvalidOperationException` when the walk reaches it | At run time |
| Walking up `ChildOf` without a bound on the steps | A `ChildOf` cycle loops forever | Bound the walk by `world.EntityCount` ([ancestors](#ancestors)) |
| Re-parenting inside a `Descendants` loop | A new link grows a child list the walk reads (a detached entity is stepped past) | [EECS042](/en/docs/guide/analyzer#eecs042): collect first, then change |
| `Disable<ChildOf>()` | `InvalidOperationException` | [EECS048](/en/docs/guide/analyzer#eecs048): `Remove<ChildOf>()` |
| Expecting world positions without a system | There is no built-in transform | Write the [propagation system](#transform-propagation) |
