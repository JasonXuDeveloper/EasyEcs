一个 World 里常常有很多区域、地图或对局，而大部分工作只涉及其中一个：移动 3 号区域的单位，给 12 号对局发状态。
`GroupBy<T>()` 按 `IGroup` 组件的值拆分 World 的表，同组的实体共用自己的表。之后 `QueryFilter.InGroup<T>(group)` 只遍历
这一组的行，内存连续，速度就像在一个更小的 World 上做普通查询。

<Callout type="info" title="不是系统分组">
  这里分的是实体。按自己的节奏运行的*系统*分组（`ISystemGroup`、`[UpdateInGroup<T>]`、`World.Update<T>()`）是另一个功能，
  见[系统](/zh/docs/guide/systems)。
</Callout>

## 什么时候用 [#when-to-use-it]

<Callout type="idea" title="适合">
  几个到几百个分区，每个分区实体很多、经常整组遍历：一台服务器上的区域或地图、对局或房间、大型战斗里的阵营。
  实体偶尔换分区（玩家走进下一个区域）。
</Callout>

<Callout type="warn" title="不适合">
  每个键下实体很少（公会 id、物品主人）：每个分组都有自己的表，应该用[值索引](/zh/docs/guide/indexes-and-relations#value-indexes)。
  每个 tick 都在变的值：每次变化都要挪行。分区之间完全没有交互：[每个线程一个 World](/zh/docs/guide/threading#recommended-one-world-per-thread)
  连过滤条件都不需要。
</Callout>

## 怎么用 [#how-to-use-it]

<Steps>
<Step>

### 标记组件 [#mark-the-component]

`[Group]` 标出表示实体所属分区的成员，类型是 `int` 或以 `int` 为底层类型的枚举：生成器给组件加上 `IGroup`，并显式实现返回该成员的
`Group`。类型上的 `[GroupBy]` 让每个 World 都按它分组。

<Tabs items={['你写的', '生成器写的']}>
<Tab value="你写的">

```csharp
[GroupBy] public partial record struct Zone([Group] int Id) : IComponent;
```

</Tab>
<Tab value="生成器写的">

```csharp doccheck=skip
partial record struct Zone : IGroup
{
    readonly int IGroup.Group => Id;
}
// 另外为每个 World 注册：从第一张包含 Zone 的表起 GroupBy<Zone>()
```

</Tab>
</Tabs>

</Step>
<Step>

### 初始化时分组 [#group-by]

有了 `[GroupBy]`，每个 World 从第一张包含该组件的表起就按它分组：带着 `Zone` 创建的实体直接进入所属分组的表，测试或工具新建的 World
也不会忘了调用设置。只有部分 World 才分组的组件只标 `[Group]`，由这些 World 调用 `world.GroupBy<T>()`：它把已有实体挪到各自分组的表里，
之后的写入也都会放到正确的位置。

```csharp
for (int i = 0; i < 9; i++) world.CreateEntity(new Zone(i % 3), new Health(10 * i));   // 创建时就已分组
```

```csharp
public partial record struct Match([Group] int Id) : IComponent;   // 只在 World 要求时分组

world.GroupBy<Match>();                                        // 只调用一次，最好在 World 填满之前
```

`[GroupBy]` 标在不是 `IGroup` 组件的类型上，或 `[Group]` 标在不是 `int` 或 `int` 枚举的成员上，都会被报告
（[EECS068](/zh/docs/guide/analyzer#eecs068)、[EECS036](/zh/docs/guide/analyzer#eecs036)）。

</Step>
<Step>

### 遍历一个分组 [#in-group]

`InGroup<T>(group)`（`Zone` 生成的是 `InZone(group)`）要求实体有 `T` 且属于这个分组，只遍历该分组的表。过滤条件放进 `static readonly` 字段；一个过滤条件只能
指定一个分组。

```csharp
public struct SumHealth : IForEach<Health>
{
    public int Total;
    public static int WriteMask => 0;                             // 只读：没有哪一行算作被写过
    public void Execute(ref Health health) => Total += health.Value;
}

public static class Zones
{
    public static readonly QueryFilter One = QueryFilter.Create().InZone(1);
}
```

```csharp
int inOne = world.Count<Health>(Zones.One);                   // 3
var sum = new SumHealth();
world.ForEach<Health, SumHealth>(ref sum, Zones.One);          // 只在 1 号区域上跑结构体 job
foreach (var item in world.Query<Health>(Zones.One)) { /* 同样的行，用查询的写法 */ }
```

</Step>
<Step>

### 把实体移到另一个分组 [#move]

用 `Set`（或生成的 `SetX`）写入新值，实体立即挪到新分组的表里，代价是一次行拷贝。

```csharp
var walker = world.CreateEntity(new Zone(1), new Health(50));
walker.SetZone(2);                                             // 之后由 InGroup<Zone>(2) 遍历
```

</Step>
</Steps>

分组组件只能用 `Set` 写：通过 `ref` 写入会改了值却不挪行，所以分析器和对待索引组件一样拒绝它
（[EECS015](/zh/docs/guide/analyzer#eecs015)）。查询遍历某个分组时，可以对其中的实体调用 `Set`。

### 在系统里使用分组 [#in-systems]

`[ForEach]` 的过滤条件是特性，写不进分组的值。一次只处理一个分组的系统，在 `[OnUpdate]` 方法里跑一个结构体 job，分组号从单例里读：

```csharp
public record struct ActiveZone(int Id) : ISingletonComponent;

public struct Regenerate : IForEach<Health>
{
    public void Execute(ref Health health) => health.Value += 1;
}

[EcsSystem]
public ref struct RegenerateActiveZone
{
    [OnUpdate]
    static void OnUpdate(World world)
    {
        var filter = QueryFilter.Create().InZone(world.ActiveZone.Id);
        var job = new Regenerate();
        world.ForEach<Health, Regenerate>(ref job, filter);
    }
}
```

有 `[OnUpdate]` 方法的系统会单独占一个阶段。每次更新都新建过滤条件也很便宜：`QueryFilter` 不持有任何对象引用。

### 哪些操作会遵守分组 [#what-follows]

| 操作 | 落到 |
| --- | --- |
| `CreateEntity`、`CreateEntities` | 值所在的分组，直接放入（不挪行） |
| 对分组组件 `Set`、`SetAll` | 新值的分组（值变了才拷贝一次行） |
| `Instantiate(prefab)`、`Clone()`、`LoadEntities`、`MoveEntities` | 拷贝过来的值所在的分组 |
| `Restore(snapshot)` | 快照里原来的分组 |
| `Load(bytes)` | 按标了 `[GroupBy]` 的类型和本 World 的 `GroupBy` 调用重新分组（存档里不保存分组设置） |

在没按 `T` 分组的 World 里（没有 `[GroupBy]`，也没调用 `GroupBy<T>()`），所有表都属于 0 组：`InGroup<T>(0)` 匹配所有带 `T` 的实体。

## 完整例子 [#full-example]

九个单位分在三个区域里。一个系统只给当前活跃区域的单位回血，一个结构体 job 统计某个区域的总血量，然后三个单位从区域 2 走进
区域 1。把这几个文件放进一个引用了 EasyEcs 的控制台项目（`dotnet add package EasyEcs`），用 `dotnet run` 运行。

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;

// [GroupBy]：每个 World 都把每个区域的实体放在各自的表里。
[GroupBy] public partial record struct Zone([Group] int Id) : IComponent;

public record struct Health(int Value) : IComponent;

// 玩家所在的区域：只有它会被模拟。
public record struct ActiveZone(int Id) : ISingletonComponent;
```

</Accordion>
<Accordion title="Jobs.cs">

```csharp title="Jobs.cs" doccheck=example
using EasyEcs;

// 结构体 job：遍历过滤条件选出的行，没有委托。
public struct Regenerate : IForEach<Health>
{
    public void Execute(ref Health health)
    {
        health.Value += 1;
    }
}

public struct SumHealth : IForEach<Health>
{
    public int Total;

    // 这个 job 只读：不把任何组件算作被写过（默认值 -1 表示全部算写入）。
    public static int WriteMask => 0;

    public void Execute(ref Health health)
    {
        Total += health.Value;
    }
}
```

</Accordion>
<Accordion title="Systems.cs">

```csharp title="Systems.cs" doccheck=example
using EasyEcs;

// 只给活跃区域的单位回血。[ForEach] 的特性没法写出分组的值，
// 所以系统在它的 [OnUpdate] 方法里用带 InGroup 过滤条件的结构体 job 来跑。
[EcsSystem]
public ref struct RegenerateActiveZone
{
    [OnUpdate]
    static void OnUpdate(World world)
    {
        int zone = world.ActiveZone.Id;
        var inZone = QueryFilter.Create().InZone(zone);
        var job = new Regenerate();
        world.ForEach<Health, Regenerate>(ref job, inZone);
    }
}
```

</Accordion>
<Accordion title="Zones.cs">

```csharp title="Zones.cs" doccheck=example
using EasyEcs;

public static class Zones
{
    // 过滤条件是值：只构建一次，存在字段里。一个过滤条件只对应一个分组。
    public static readonly QueryFilter One = QueryFilter.Create().InZone(1);
    public static readonly QueryFilter Two = QueryFilter.Create().InZone(2);

    // 一个区域的单位数和总血量。只遍历这个区域的表。
    public static string Describe(World world, QueryFilter zone)
    {
        var sum = new SumHealth();
        world.ForEach<Health, SumHealth>(ref sum, zone);
        return $"{world.Count<Health>(zone)} units, {sum.Total} hp";
    }
}
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;

using var world = new World();

world.SetActiveZone(Id: 1);
world.AddSystem<RegenerateActiveZone>();

for (int i = 0; i < 9; i++)
{
    world.CreateEntity(new Zone(i % 3), new Health(10 * i));
}

world.Update();
Console.WriteLine($"zone 1: {Zones.Describe(world, Zones.One)}");

// 写入新值会把实体搬到新区域的表里。查询遍历途中也可以 Set。
foreach (var item in world.Query<Health>(Zones.Two))
{
    item.Entity.SetZone(1);
}

Console.WriteLine($"zone 1: {Zones.Describe(world, Zones.One)}");
Console.WriteLine($"zone 2: {Zones.Describe(world, Zones.Two)}");
```

</Accordion>
</Accordions>

输出：

```text
zone 1: 3 units, 123 hp
zone 1: 6 units, 273 hp
zone 2: 0 units, 0 hp
```

只有区域 1 的三个单位回了血（120 + 3）。从区域 2 过来的三个单位带着它们的 150 点血；它们走后区域 2 就空了。

## 怎么用得快 [#how-to-use-it-fast]

- **初始化时分组。** `[GroupBy]` 从第一张表起就分组；在满的 World 上调用 `GroupBy<T>()` 要把每个实体挪一次，在空 World 上没有开销。
- **把过滤条件提出来。** 每个热点分组一个 `static readonly` 过滤条件，或者像上面那样每次更新建一个。
- **要整组遍历就分组，要按键查找就建索引。** 整组遍历一个大分组时分组更快；一个键下只有几个实体时索引更快。

## 开销 [#what-it-costs]

- **内存：** 每种组件组合、每个分组各一张表，各带列的富余容量。成千上万个小分组会把 World 切得很碎，这种情况该用索引。
- **换分组：** 一次行拷贝（和添加一个表里没有列的组件一样）。
- **遍历分组：** 只碰这个分组自己的行，不用逐行比较值。
- **没有分组时：** World 没按某个 `IGroup` 组件分组，对它 `Set` 只多一次判空；不是 `IGroup` 的组件连这一步都省了
  （这个判断是常量，JIT 直接消掉）。不管分没分组，这个组件都只能用 `Set` 写。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 谁能发现 |
| --- | --- | --- |
| 通过 `ref` 写分组组件 | 行还留在旧分组 | [EECS015](/zh/docs/guide/analyzer#eecs015) |
| 每个玩家、公会或主人一个分组 | 每个键一张表：浪费内存，World 碎片化 | 改用[值索引](/zh/docs/guide/indexes-and-relations#value-indexes) |
| 值每个 tick 都变 | 每次变化一次行拷贝 | 保持普通组件 |
| 一个过滤条件里用不同的分组调用两次 `InGroup` | 抛 `ArgumentException`：一个过滤条件只有一个分组 | [EECS050](/zh/docs/guide/analyzer#eecs050)：每个分组一个过滤条件 |
| 遍历途中调用 `GroupBy` | 抛异常：它要挪行 | [EECS041](/zh/docs/guide/analyzer#eecs041)；初始化时调用 |
