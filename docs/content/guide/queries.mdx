A query selects the entities that have a set of components (1 to 9), optionally filtered: with or without other
components, one of a group, or only those written or removed since a tick. Systems use queries through `[ForEach]`
methods; code outside systems (an admin request, a test, a tool between ticks) calls them directly. Every query API
is allocation-free.

## When to use it [#when-to-use-it]

<Callout type="idea" title="Use it for">
  Iteration outside systems: request handlers between updates, tools, tests, one-off passes. Jobs on one entity
  ([`entity.Run`](#run-on-one-entity)): the handler of a request or of a message to an actor. Counts and existence
  checks (`Count`, `Any`). Bulk destroys (`DestroyEntities<T>(filter)`). The filters themselves, which `[ForEach]`
  methods take as attributes.
</Callout>

<Callout type="warn" title="Skip it for">
  Per-tick logic: write a [`[ForEach]` method](/en/docs/guide/systems#foreach-methods) in a system instead. It is
  generated, ordered with the other systems, scheduled in parallel stages and as fast as the fastest hand-written
  loop. Looking entities up by a value or by the entity they point at: use an
  [index](/en/docs/guide/indexes-and-relations), not a scan.
</Callout>

## How to use it [#how-to-use-it]

<Steps>
<Step>

### Build the filter once [#build-the-filter]

`QueryFilter` is a value built with chained calls. Keep each one in a `static readonly` field.

```csharp
public static class Filters
{
    public static readonly QueryFilter Active = QueryFilter.Create().Without<Frozen>().Without<Dead>();
    public static readonly QueryFilter Impaired = QueryFilter.Create().WithAny<Frozen>().WithAny<Stunned>();   // either
}
```

</Step>
<Step>

### Loop over the matches [#query]

`world.Query<T1..Tn>(filter)` is a `foreach` loop. Each item hands out refs into the table, named after the
components, and the entity.

```csharp
var world = new World();
world.CreateEntity(new Position(0, 0), new Velocity(1, 0));
world.CreateEntity(new Position(0, 0), new Velocity(0, 1), new Frozen());

foreach (var item in world.Query<Position, Velocity>(Filters.Active))
{
    ref var p = ref item.Position;          // a ref into the table
    p.X += item.Velocity.X;
    if (p.X > 100) item.Entity.SetDead();   // structural changes are allowed
}
```

</Step>
<Step>

### Count and test [#count-and-any]

```csharp
int moving = world.Count<Position, Velocity>(Filters.Active);
bool anyImpaired = world.Any<Position>(Filters.Impaired);   // stops at the first match
int cleared = world.DestroyEntities<Position>(QueryFilter.Create().With<Dead>());
```

</Step>
</Steps>

### Which API [#which-api]

| Need | Use |
| --- | --- |
| Per-entity logic of a system | a [`[ForEach]` method](/en/docs/guide/systems#foreach-methods) |
| Arithmetic over many rows in a system | a [batch `[ForEach]` method](/en/docs/guide/systems#batch-methods) (spans, SIMD) |
| Heavy per-entity work in a system | [`[ForEach(Parallel = true)]`](/en/docs/guide/systems#parallel-methods) |
| A component the entity may or may not have | a [`Maybe<T>` parameter](/en/docs/guide/systems#maybe), or two methods split by `With` / `Without` |
| A pass outside systems, as a method | a [`[ForEach]` runner](/en/docs/guide/systems#foreach-outside-systems): a static method with a generated entry point |
| The fastest ad-hoc loop | `world.ForEach<T1..Tn, TJob>(ref job, filter)` with a [struct job](#foreach-a-struct-job) |
| Ad-hoc loop that needs the `Entity` | `world.ForEachEntity<T1..Tn, TJob>(ref job, filter)` |
| Ad-hoc arithmetic over runs of rows | `world.ForEachBatch<T1..Tn, TJob>(ref job, filter)` |
| A job on one entity (a request, a message) | [`entity.Run<T1..Tn, TJob>(ref job, filter)`](#run-on-one-entity) |
| Ad-hoc heavy work on several threads | [`ForEachParallel` / `ForEachEntityParallel`](#on-several-threads-foreachparallel-and-foreachentityparallel) |
| A convenient loop (tools, tests, handlers) | `foreach (var item in world.Query<T1..Tn>(filter))` |
| "How many …?" / "Is there any …?" | `world.Count<T1..Tn>(filter)` / `world.Any<T1..Tn>(filter)` |
| Destroy every match | `world.DestroyEntities<T1..Tn>(filter)` |
| Only rows written or removed since a tick | `Changed<T>(tick)` / `Removed<T>(tick)`, `ChangedAny<T1..Tn>(tick)` / `RemovedAny<T1..Tn>(tick)` for any of several ([change tracking](/en/docs/guide/change-tracking)) |
| A pass that writes only the rows whose value changed | a [`Mut<T>` parameter](/en/docs/guide/change-tracking#set-if-changed) of a `[ForEach]` method |
| A share of the rows per pass, every row once per N passes | `Slice(index, count)` with a `ForEach` call, or [`[ForEach(Slices = N)]`](/en/docs/guide/systems#slices) |
| Entities by a value, or pointing at an entity | `world.Index<T, TKey>().Find(key)` ([indexes](/en/docs/guide/indexes-and-relations)) |

### Filters [#filters]

| Filter | Selects | As a `[ForEach]` attribute |
| --- | --- | --- |
| `With<T>()` | entities that also have `T` (not passed in) | `[With<T>]` |
| `Without<T>()` | entities that lack `T` | `[Without<T>]` |
| `WithAny<T>()`, repeated | entities with at least one of the `WithAny` components | `[WithAny<T>]`, repeated |
| `Changed<T>(since)` | entities whose tracked `T` was written at or after `since` | `[Changed<T>]` (since the system's last run) |
| `Removed<T>(since)` | entities that lost tracked `T` at or after `since` and still lack it | `[Removed<T>]` |
| `ChangedAny<T1..Tn>(since)` | entities where at least one of the tracked components it has was written at or after `since` | `[ChangedAny<T1, …, Tn>]` |
| `RemovedAny<T1..Tn>(since)` | entities that lost at least one of the tracked components at or after `since` and still lack it | `[RemovedAny<T1, …, Tn>]` |
| `InGroup<T>(group)` | entities whose `T` is in one [group](/en/docs/guide/groups) | none; the generated `filter.InTeam(group)` for an `IGroup` component `Team` |
| `Slice(index, count)` | slice `index` of `count` of every matching table's rows, cut at 64-row words; `ForEach`, `ForEachEntity`, `ForEachBatch` and their `Parallel` forms only | `[ForEach(Slices = N)]` ([slices](/en/docs/guide/systems#slices)) |
| `Since(tick)` | the same filter, its `Changed`, `Removed`, `ChangedAny` and `RemovedAny` parts moved to another tick | |

Every filter can be repeated and combined. The `ChangedAny` parts of a filter join one group that passes when any
of its components passes (and the `RemovedAny` parts another); the groups combine with everything else with AND. A
filter holds one tick: its `Changed`, `Removed`, `ChangedAny` and `RemovedAny` parts must name the same one (else
`ArgumentException`), and `Since(tick)` moves them together, so a filter kept in a field is reused after every update,
or [for each client](/en/docs/guide/change-tracking#per-client) with the tick it acknowledged:

```csharp
public record struct Armor(int Value) : IComponent, ITrackChanges;

public static class Replication
{
    public static readonly QueryFilter Dirty = QueryFilter.Create().Changed<Armor>(0);
}
```

```csharp
ulong mark = world.ChangeTick;
world.Update();
int dirty = world.Count<Armor>(Replication.Dirty.Since(mark));
```

`Slice(index, count)` keeps a pass to part of each table: passes with each index from 0 to `count - 1` in turn visit
every row once. Only the `ForEach` family honours it; `Query`, `Count`, `Any`, `DestroyEntities`, `entity.Run` and
the bulk calls (`SetAll`, `RemoveAll`, …) need every matching row and throw `ArgumentException` for a sliced filter.
In a system, [`[ForEach(Slices = N)]`](/en/docs/guide/systems#slices) picks the slice for you.

### `Query`: a foreach loop [#query-loop]

The enumerator and its items are ref structs holding refs into the current table, so:

- a query loop cannot contain `await`, and an item cannot be stored: keep `item.Entity` instead;
- `item.Position` (named after the component) and `item.Component1` are the same ref; named members are generated
  for each `Query<...>` shape your code calls;
- items count as a write of every tracked (`ITrackChanges`) component they hand out, whether or not the loop stores
  through them. To read tracked components without marking them (a save, a send), use a struct job with
  `Writes => 0`, a `[ForEach]` method with `in` parameters, or `entity.Read<T>()`
  ([what counts as a write](/en/docs/guide/change-tracking#what-counts-as-a-write)).

A loop may create, destroy, add and remove; the rules are in [Structural changes](/en/docs/guide/structural-changes).

### `ForEach`: a struct job [#foreach-a-struct-job]

A struct that implements `IForEach<T1..Tn>` is specialized for its type and inlined by the JIT: no delegate, no
closure, no allocation. `[ForEach]` methods compile to exactly this.

```csharp
public struct Integrate : IForEach<Position, Velocity>, INoStructuralChanges
{
    public static int Writes => 1;          // Position (component 1); Velocity is only read

    public void Execute(ref Position p, ref Velocity v)
    {
        p.X += v.X;
        p.Y += v.Y;
    }
}
```

```csharp
var integrate = new Integrate();
world.ForEach<Position, Velocity, Integrate>(ref integrate, Filters.Active);
```

The job is passed by `ref`, so fields it accumulates (a sum, a count) are visible after the call. It receives the
components only, so the pass never loads the entity rows. A job that must hold a `ref` or a `Span` can be a
`ref struct`, except for the `*Parallel` calls.

#### What a job declares: `Writes` [#what-a-job-declares-writes]

Job parameters are all `ref`, so a job says which components it actually writes with an optional
`static int Writes`: bit k - 1 for component k, default -1 (all of them). Only those count as written for
[change tracking](/en/docs/guide/change-tracking), and only those are carried over to the entity's new row when the
job changes the archetype of the entity it visits. `INoStructuralChanges` promises that `Execute` never creates,
destroys, adds or removes: the pass then skips the bookkeeping that keeps changes safe and freezes the structure, so
a change made anyway throws instead of tearing rows. Generated `[ForEach]` jobs set both from the method.

#### With the entity, or in runs of rows [#entity-and-batch-jobs]

- `IForEachEntity<T1..Tn>` with `world.ForEachEntity` also receives the `Entity`, built from the table's entity rows
  without a lookup.
- `IForEachBatch<T1..Tn>` with `world.ForEachBatch` receives runs of consecutive rows as spans,
  `Execute(EntitySpan entities, Span<T1> …)`, to vectorize with `Vector<T>` (the JIT does not vectorize loops on its
  own). `entities[i]` is built only when indexed. The spans point into the tables, so a structural change throws
  while the job runs.

```csharp
using System.Numerics;
using System.Runtime.InteropServices;

public struct KillTheWounded : IForEachEntity<Health>
{
    public static int Writes => 0;          // reads Health; the change is structural (a tag)

    public void Execute(Entity unit, ref Health hp)
    {
        if (hp.Value <= 0) unit.SetDead();
    }
}

public struct Drift : IForEachBatch<Position, Velocity>
{
    public static int Writes => 1;

    public void Execute(EntitySpan entities, Span<Position> positions, Span<Velocity> velocities)
    {
        // Two floats each: as Vector<float> spans, every lane is one coordinate
        var p = MemoryMarshal.Cast<Position, Vector<float>>(positions);
        var v = MemoryMarshal.Cast<Velocity, Vector<float>>(velocities);
        for (int i = 0; i < p.Length; i++) p[i] += v[i];
        var pf = MemoryMarshal.Cast<Position, float>(positions);
        var vf = MemoryMarshal.Cast<Velocity, float>(velocities);
        for (int i = p.Length * Vector<float>.Count; i < pf.Length; i++) pf[i] += vf[i];   // the rows left over
    }
}
```

```csharp
var kill = new KillTheWounded();
world.ForEachEntity<Health, KillTheWounded>(ref kill, QueryFilter.Create().Without<Dead>());
var drift = new Drift();
world.ForEachBatch<Position, Velocity, Drift>(ref drift, Filters.Active);
```

### One entity: `entity.Run` [#run-on-one-entity]

Code that handles one entity at a time runs a job on it with `entity.Run<T1..Tn, TJob>(ref job, filter)`: a request
or a message to an actor, a command from a client. The job is an `IForEachEntity` job, the same type a pass over the
world takes, and gets the refs a pass gives it: one table lookup for all its components instead of one per `Get`.
It returns `false`, without running the job, when the entity lacks a component, fails the filter or is not alive.

```csharp
public static class Hits
{
    // Built once: the filter is a value, kept in a field.
    public static readonly QueryFilter Alive = QueryFilter.Create().Without<Dead>();
}

public struct TakeHit : IForEachEntity<Health>
{
    public int Damage;
    public static int Writes => 1;

    public void Execute(Entity unit, ref Health hp)
    {
        if (hp.Value <= Damage) unit.SetDead();   // a structural change: hp still points at the entity's value
        hp.Value -= Damage;                       // carried over to its new row when the job returns
    }
}
```

```csharp
var hit = new TakeHit { Damage = 30 };
bool applied = unit.Run<Health, TakeHit>(ref hit, Hits.Alive);   // false: dead, no Health, or not alive
```

Without a filter, `entity.Run<T1..Tn, TJob>(ref job)` checks only that the entity is alive and has the components.
A job that only reads declares `Writes => 0`:

```csharp
public struct ReadHealth : IForEachEntity<Health>
{
    public int Value;
    public static int Writes => 0;          // reads only: nothing counts as written

    public void Execute(Entity unit, ref Health hp) => Value = hp.Value;
}
```

```csharp
var read = new ReadHealth();
if (unit.Run<Health, ReadHealth>(ref read)) Console.WriteLine(read.Value);
```

- **The refs survive the job's own structural changes**, as in `ForEachEntity`: the components in `Writes` are copied
  to the entity's new row after `Execute`, also when it throws, so what was written before the exception stays.
- **Only `Writes` count as written** for [change tracking](/en/docs/guide/change-tracking), and only when `Run`
  returns `true`. The default, `Writes => -1`, stamps every component the job takes; a job that writes nothing
  declares `Writes => 0`.
- **`false` is not "dead"**: it also means a missing component or a filter that failed. Test `entity.IsAlive` when
  the reason matters.
- **`INoStructuralChanges`** skips the bookkeeping and freezes the structure while the job runs, like a pass: a
  structural change made anyway throws `InvalidOperationException`.
- **O(1), plus O(1) per component the filter names**, unless the filter names a type past the first 256 (then it goes
  through the query cache). A filter tests the row the way a query does (`Without`, `WithAny`, `Changed<T>(tick)`,
  groups), with no lookup of the query's tables; build it once, in a `static readonly` field.
- **For the analyzer, `Run` is a structural change** (its job may make one), rejected where those are: in a
  parallel `[ForEach]` method ([EECS010](/en/docs/guide/analyzer#eecs010)), in a `[ForEach]` method that takes no
  `Entity` or `World` ([EECS013](/en/docs/guide/analyzer#eecs013)) and off the world's owner thread
  ([EECS014](/en/docs/guide/analyzer#eecs014)).

An actor is the typical user: each message handler finds the actor's entity (through a
[value index](/en/docs/guide/indexes-and-relations)) and runs one job on it. The
[Actors sample](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/Actors) is a whole program built this way.

### On several threads: `ForEachParallel` and `ForEachEntityParallel` [#on-several-threads-foreachparallel-and-foreachentityparallel]

A job that implements `INoStructuralChanges` and writes only its own row can run on several threads.
`ForEachParallel` (an `IForEach` job) and `ForEachEntityParallel` (an `IForEachEntity` job) cut the matching rows into
chunks (about four per thread, a multiple of 64 rows, between 1,024 and `World.ParallelChunkRows` = 16,384; a multiple
of 4,096 rows, at least 4,096, when the job's `Writes` include a tracked component, so that no two chunks share a
block's change-tick summary). The
calling thread and up to `WorldOptions.MaxDegreeOfParallelism - 1` thread-pool threads run them, each with its own
copy of the job, so state accumulated in its fields is not merged back. Fewer than two chunks run on the calling
thread.

```csharp
public struct Heal : IForEach<Health>, INoStructuralChanges
{
    public static int Writes => 1;

    public void Execute(ref Health health) => health.Value = Math.Min(health.Value + 10, 100);
}
```

```csharp
var heal = new Heal();
world.ForEachParallel<Health, Heal>(ref heal, Filters.Active);   // each row runs once, on one of the threads
```

The job must not read what another row's job writes (another entity, a singleton), and nothing else may change the
world during the call. [`[ForEach(Parallel = true)]`](/en/docs/guide/systems#parallel-methods) compiles a system method
to the same chunked run.

### `Count` and `Any` [#count]

`Count` sums the row counts of the matching tables, and counts presence bits only in tables where some rows lack a
queried component. `Any` stops at the first match. Neither touches a component value.

## Full example [#full-example]

Filters in a system, then a query, a count and a struct job outside it. Three units move, one of them frozen, and
a fourth has no velocity at all. Put the files in a console project that references EasyEcs
(`dotnet add package EasyEcs`) and run it with `dotnet run`.

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;

public record struct Position(float X, float Y) : IComponent;

public record struct Velocity(float X, float Y) : IComponent;

// Two states as tags. A frozen unit does not move; a frozen or burning unit is slowed.
public struct Frozen : IComponent;

public struct Burning : IComponent;
```

</Accordion>
<Accordion title="Systems.cs">

```csharp title="Systems.cs" doccheck=example
using EasyEcs;

// Halves the velocity of every unit that is frozen, burning, or both.
public class SlowSystem : EcsSystem
{
    [ForEach, WithAny<Frozen>, WithAny<Burning>]
    static void Slow(ref Velocity velocity)
    {
        velocity = new Velocity(velocity.X / 2, velocity.Y / 2);
    }
}

// Moves every unit that is not frozen.
[UpdateAfter<SlowSystem>]
public class MoveSystem : EcsSystem
{
    [ForEach, Without<Frozen>]
    static void Move(ref Position position, in Velocity velocity)
    {
        position = new Position(position.X + velocity.X, position.Y + velocity.Y);
    }
}
```

</Accordion>
<Accordion title="Queries.cs">

```csharp title="Queries.cs" doccheck=example
using EasyEcs;

// A filter is a value: build it once and keep it in a static readonly field.
public static class Filters
{
    public static readonly QueryFilter Moving = QueryFilter.Create().Without<Frozen>();
}

// A struct job: the fastest pass outside systems, with no delegate.
public struct SumX : IForEach<Position>
{
    public float Sum;

    public void Execute(ref Position position)

        Sum += position.X;
    }
}
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;

using var world = new World();
world.AddSystem<SlowSystem>();
world.AddSystem<MoveSystem>();

world.CreateEntity(new Position(0, 0), new Velocity(1, 0));
world.CreateEntity(new Position(0, 0), new Velocity(0, 1), new Frozen());
world.CreateEntity(new Position(0, 0), new Velocity(2, 2), new Burning());
world.CreateEntity(new Position(9, 9));

world.Update();

// Outside systems: loop over the matches. Each item hands out refs into the table.
foreach (var item in world.Query<Position, Velocity>(Filters.Moving))
{
    Console.WriteLine($"{item.Entity}: {item.Position}");
}

// Count and test without reading any component value.
int moving = world.Count<Position, Velocity>(Filters.Moving);
bool anyFrozen = world.Any<Frozen>();
Console.WriteLine($"moving: {moving}, any frozen: {anyFrozen}");

// Run the struct job over every position, the unit without a velocity too.

world.ForEach<Position, SumX>(ref sumX);
Console.WriteLine($"sum of X: {sumX.Sum}");
```

## How to use it fast [#how-to-use-it-fast]

| Instead of | Do | Why |
| --- | --- | --- |
| A `Query` loop every tick | A `[ForEach]` method in a system | Generated struct job, ordered and scheduled |
| `QueryFilter.Create()…` at every call | A `static readonly` filter | The cache key is built once |
| A `Query` that only reads tracked components | A job with `Writes => 0`, or `in` parameters | Items stamp what they hand out |
| `ForEachEntity` when the entity is rarely used | A batch job with `EntitySpan` | Handles built only for the rows that need one |
| A scalar loop over many rows | A batch job with `Vector<T>` | The JIT does not vectorize on its own |
| `Count(...) > 0` | `Any(...)` | Stops at the first match ([EECS032](/en/docs/guide/analyzer#eecs032)) |
| Several `Get` / `TryGetRef` and a `Has<Dead>()` per request | [`entity.Run`](#run-on-one-entity) with a `static readonly` filter | One lookup; the refs are carried across structural changes |
| Scanning for a key | A [value index](/en/docs/guide/indexes-and-relations) | O(matches) instead of O(rows) |

## What it costs [#what-it-costs]

- **The first use of a query shape** (components plus filter) visits every table once to build its cache entry.
  Tables created later join the entries they match.
- **Every later call** finds the entry through a small per-signature memo, or one hash probe past it, then walks
  O(matching tables + their rows).
- **Filtered rows** are tested 64 at a time from presence bits; words where every row passes are spanned four per
  SIMD compare, and words with no match are skipped.
- **`Count`** is O(matching tables), plus a popcount per word in tables whose rows differ.
- **No allocation**: filters are values with no object reference, enumerators and items are ref structs, jobs are
  structs.

## Pitfalls [#pitfalls]

| Mistake | What happens | Caught by |
| --- | --- | --- |
| `await` inside a `Query` loop | Does not compile: items are ref structs | The C# compiler |
| Storing a query item | Does not compile; keep `item.Entity` | The C# compiler |
| A `Query` loop that only reads tracked components | Every visited row counts as written | Use a job with `Writes => 0` or `Read<T>()` |
| `INoStructuralChanges` on a job that changes structure | `InvalidOperationException` at the change | At run time |
| Structural change in a batch job | `InvalidOperationException`: the spans point into the tables | At run time ([EECS013](/en/docs/guide/analyzer#eecs013) for `[ForEach]` methods) |
| A parallel job that writes a singleton or another entity | Races between chunks | Code review ([EECS010](/en/docs/guide/analyzer#eecs010) for `[ForEach]` methods) |
| `Changed`, `Removed`, `ChangedAny` or `RemovedAny` with different ticks in one filter | `ArgumentException` | At run time |
| A sliced filter (`Slice`) passed to `Query`, `Count`, `Any`, `DestroyEntities`, `entity.Run` or a bulk call | `ArgumentException`: the call needs every matching row | At run time |
| `Update()` called from inside a query loop of the same world | Undefined order of passes | Code review; [EECS034](/en/docs/guide/analyzer#eecs034) when called from a system |
| An `entity.Run` job without `Writes` | The default (-1) stamps every tracked component the job takes | Declare `Writes` (`0` for a job that only reads) |
| `INoStructuralChanges` on a `Run` job that changes structure | `InvalidOperationException` at the change | At run time |
| Treating `false` from `Run` as "dead" | It also means a missing component or a filter that failed | Code review: test `IsAlive` |
| `QueryFilter.Create()…` built at every `Run` or query call | The filter is rebuilt and looked up at every call | Code review: a `static readonly` field |
| `entity.Run` inside a parallel `[ForEach]` method | Its job may change structure from several threads | [EECS010](/en/docs/guide/analyzer#eecs010) |
