A query selects the entities that have a set of components (1 to 9), optionally filtered: with or without other
components, one of a group, or only those written or removed since a tick. Systems use queries through `[ForEach]`
methods; code outside systems (an admin request, a test, a tool between ticks) calls them directly. Every query API
is allocation-free.

## When to use it [#when-to-use-it]

<Callout type="idea" title="Use it for">
  Iteration outside systems: request handlers between updates, tools, tests, one-off passes. Work on one entity
  ([`[ForEntity]`](#run-on-one-entity)): the handler of a request or of a message to an actor. Counts and existence
  checks (`Count`, `Any`). Bulk destroys (`DestroyAll<T>(filter)`). The filters themselves, which `[ForEach]`
  methods take as attributes.
</Callout>

<Callout type="warn" title="Skip it for">
  Per-tick logic: write a [`[ForEach]`](/en/docs/guide/systems#foreach-methods) method in a system instead. It is
  generated, ordered with the other systems, scheduled in parallel stages and as fast as the fastest hand-written
  loop. Looking entities up by a value or by the entity they point at: use an
  [index](/en/docs/guide/indexes-and-relations), not a scan.
</Callout>

## How to use it [#how-to-use-it]

<Steps>
<Step>

### Build the filter once [#build-the-filter]

`QueryFilter` is a value built with chained calls. Keep each one in a `static readonly` field.

```csharp
public static class Filters
{
    public static readonly QueryFilter Active = QueryFilter.Create().Without<Frozen>().Without<Dead>();
    public static readonly QueryFilter Impaired = QueryFilter.Create().WithAny<Frozen, Stunned>();   // either
}
```

</Step>
<Step>

### Loop over the matches [#query]

`world.Query<T1..Tn>(filter)` is a `foreach` loop. Each item hands out refs into the table, named after the
components, and the entity.

```csharp
var world = new World();
world.CreateEntity(new Position(0, 0), new Velocity(1, 0));
world.CreateEntity(new Position(0, 0), new Velocity(0, 1), new Frozen());

foreach (var item in world.Query<Position, Velocity>(Filters.Active))
{
    ref var p = ref item.Position;          // a ref into the table
    p.X += item.Velocity.X;
    if (p.X > 100) item.Entity.SetDead();   // structural changes are allowed
}
```

</Step>
<Step>

### Count and test [#count-and-any]

```csharp
int moving = world.Count<Position, Velocity>(Filters.Active);
bool anyImpaired = world.Any<Position>(Filters.Impaired);   // stops at the first match
int cleared = world.DestroyAll<Position>(QueryFilter.Create().With<Dead>());
```

</Step>
</Steps>

### Which API [#which-api]

| Need | Use |
| --- | --- |
| Per-entity logic of a system | a [`[ForEach]`](/en/docs/guide/systems#foreach-methods) method |
| Arithmetic over many rows in a system | a batch [`[ForEach]`](/en/docs/guide/systems#batch-methods) method (spans, SIMD) |
| Heavy per-entity work in a system | [`[ForEach(Parallel = true)]`](/en/docs/guide/systems#parallel-methods) |
| A component the entity may or may not have | a [`Maybe<T>`](/en/docs/guide/systems#maybe) parameter, or two methods split by `With` / `Without` |
| A pass outside systems, as a method | a [`[ForEach]`](/en/docs/guide/systems#foreach-outside-systems) runner: a static method with a generated entry point |
| The fastest ad-hoc loop | `world.ForEach<T1..Tn, TJob>(ref job, filter)` with a [struct job](#foreach-a-struct-job) |
| Ad-hoc loop that needs the `Entity` | `world.ForEachEntity<T1..Tn, TJob>(ref job, filter)` |
| Ad-hoc arithmetic over runs of rows | `world.ForEachBatch<T1..Tn, TJob>(ref job, filter)` |
| Work on one entity (a request, a message) | a [`[ForEntity]`](#run-on-one-entity) method, or `entity.Run<T1..Tn, TJob>(ref job, filter)` |
| Ad-hoc heavy work on several threads | [`ForEachParallel`](#on-several-threads-foreachparallel-and-foreachentityparallel) / [`ForEachEntityParallel`](#on-several-threads-foreachparallel-and-foreachentityparallel) |
| A convenient loop (tools, tests, handlers) | `foreach (var item in world.Query<T1..Tn>(filter))` |
| A loop that only reads (a save, a send, a report) | [`foreach (var item in world.Read<T1..Tn>(filter))`](#read): nothing stamped |
| "How many …?" / "Is there any …?" | `world.Count<T1..Tn>(filter)` / `world.Any<T1..Tn>(filter)` |
| Destroy every match | `world.DestroyAll<T1..Tn>(filter)` |
| Up to N matches to serve, destroy or save this tick | [`world.CollectIds<T1..Tn>(span, filter)`](#collect-ids) |
| Only rows written or removed since a tick | `Changed<T>(tick)` / `Removed<T>(tick)`, `ChangedAny<T1..Tn>(tick)` / `RemovedAny<T1..Tn>(tick)` for any of several ([change tracking](/en/docs/guide/change-tracking)) |
| A pass that writes only the rows whose value changed | a [`Mut<T>`](/en/docs/guide/change-tracking#set-if-changed) parameter of a `[ForEach]` method |
| A share of the rows per pass, every row once per N passes | `Slice(index, of)` with a `ForEach` call, or [`[ForEach(Slices = N)]`](/en/docs/guide/systems#slices) |
| Entities by a value, or pointing at an entity | `world.Index<T, TKey>().Find(key)` ([indexes](/en/docs/guide/indexes-and-relations)) |

### Filters [#filters]

| Filter | Selects | As a `[ForEach]` attribute |
| --- | --- | --- |
| `With<T>()` | entities that also have `T` (not passed in) | `[With<T>]` |
| `Without<T>()` | entities that lack `T` | `[Without<T>]` |
| `WithAny<T1, T2>()` (2 to 9 types) | entities with at least one of the `WithAny` components | `[WithAny<T1, T2>]` (2 to 9 types) |
| `Changed<T>(since)` | entities whose tracked `T` was written at or after `since` | `[Changed<T>]` (since the system's last run) |
| `Removed<T>(since)` | entities that lost tracked `T` at or after `since` and still lack it | `[Removed<T>]` |
| `ChangedAny<T1..Tn>(since)` | entities where at least one of the tracked components it has was written at or after `since` | `[ChangedAny<T1, …, Tn>]` |
| `RemovedAny<T1..Tn>(since)` | entities that lost at least one of the tracked components at or after `since` and still lack it | `[RemovedAny<T1, …, Tn>]` |
| `InGroup<T>(group)` | entities whose `T` is in one [group](/en/docs/guide/groups) | none; the generated `filter.InTeam(group)` for an `IGroup` component `Team` |
| `Slice(index, of)` | slice `index` of the `of` slices of every matching table's rows, cut at 64-row words; `ForEach`, `ForEachEntity`, `ForEachBatch` and their `Parallel` forms only | `[ForEach(Slices = N)]` ([slices](/en/docs/guide/systems#slices)) |
| `Since(tick)` | the same filter, its `Changed`, `Removed`, `ChangedAny` and `RemovedAny` parts moved to another tick | |

Every filter can be repeated and combined. The `ChangedAny` parts of a filter join one set that passes when any
of its components passes (and the `RemovedAny` parts another); the sets combine with everything else with AND. A
filter holds one tick: its `Changed`, `Removed`, `ChangedAny` and `RemovedAny` parts must name the same one (else
`ArgumentException`), and `Since(tick)` moves them together, so a filter kept in a field is reused after every update,
or [for each client](/en/docs/guide/change-tracking#per-client) with the tick it acknowledged:

```csharp
public record struct Armor(int Value) : IComponent, ITracked;

public static class Replication
{
    public static readonly QueryFilter Dirty = QueryFilter.Create().Changed<Armor>(0);
}
```

```csharp
ulong mark = world.ChangeTick;
world.Update();
int dirty = world.Count<Armor>(Replication.Dirty.Since(mark));
```

`Slice(index, of)` keeps a pass to part of each table: passes with each index from 0 to `count - 1` in turn visit
every row once. Only the `ForEach` family honours it; `Query`, `Read`, `Count`, `Any`, `DestroyAll`, `entity.Run` and
the bulk calls (`SetAll`, `RemoveAll`, …) need every matching row and throw `ArgumentException` for a sliced filter.
In a system, [`[ForEach(Slices = N)]`](/en/docs/guide/systems#slices) picks the slice for you.

### `Query`: a foreach loop [#query-loop]

The enumerator and its items are ref structs holding refs into the current table, so:

- a query loop cannot contain `await`, and an item cannot be stored: keep `item.Entity` instead;
- `item.Position` (named after the component) and `item.Component1` are the same ref; named members are generated
  for each `Query<...>` shape your code calls;
- items count as a write of every tracked (`ITracked`) component they hand out, whether or not the loop stores
  through them. To read tracked components without stamping them (a save, a send), loop over
  [`Read`](#read) instead, or use a struct job with `WriteMask => 0`, a `[ForEach]` method with `in` parameters, or
  `entity.Read<T>()` ([what counts as a write](/en/docs/guide/change-tracking#what-counts-as-a-write)).

A loop may create, destroy, add and remove; the rules are in [Structural changes](/en/docs/guide/structural-changes).

### `Read`: a loop that only reads [#read]

`world.Read<T1..Tn>(filter)` walks the same rows as `Query`, but its items hand out `ref readonly` refs and stamp
nothing. A `[Changed<T>]` reader that runs after it does not see the rows as written because a report or a send read
them. The pair is the one entities have: `entity.Get<T>()` counts as a write, `entity.Read<T>()` does not.

```csharp
int total = 0;
foreach (var item in world.Read<Armor>()) total += item.Armor.Value;   // ref readonly: nothing stamped
```

The named members (`item.Armor`) are generated per `Read<...>` shape too, and the same rules hold: a ref struct, no
`await`, structural changes allowed. An item cannot be written through, so a loop that writes stays a `Query`.

### `ForEach`: a struct job [#foreach-a-struct-job]

A struct that implements `IForEach<T1..Tn>` is specialized for its type and inlined by the JIT: no delegate, no
closure, no allocation. `[ForEach]` methods compile to exactly this.

```csharp
public struct Integrate : IForEach<Position, Velocity>, INoStructuralChanges
{
    public static int WriteMask => 1;          // Position (component 1); Velocity is only read

    public void Execute(ref Position p, ref Velocity v)
    {
        p.X += v.X;
        p.Y += v.Y;
    }
}
```

```csharp
var integrate = new Integrate();
world.ForEach<Position, Velocity, Integrate>(ref integrate, Filters.Active);
```

The job is passed by `ref`, so fields it accumulates (a sum, a count) are visible after the call. It receives the
components only, so the pass never loads the entity rows. A job that must hold a `ref` or a `Span` can be a
`ref struct`, except for the `*Parallel` calls.

#### What a job declares: `WriteMask` [#what-a-job-declares-writes]

Job parameters are all `ref`, so a job says which components it actually writes with an optional
`static int WriteMask`: bit k - 1 for component k, default -1 (all of them). Only those count as written for
[change tracking](/en/docs/guide/change-tracking), and only those are carried over to the entity's new row when the
job changes the archetype of the entity it visits. `INoStructuralChanges` promises that `Execute` never creates,
destroys, adds or removes: the pass then skips the bookkeeping that keeps changes safe and freezes the structure, so
a change made anyway throws instead of tearing rows. Generated `[ForEach]` jobs set both from the method.

#### With the entity, or in runs of rows [#entity-and-batch-jobs]

- `IForEachEntity<T1..Tn>` with `world.ForEachEntity` also receives the `Entity`, built from the table's entity rows
  without a lookup.
- `IForEachBatch<T1..Tn>` with `world.ForEachBatch` receives runs of consecutive rows as spans,
  `Execute(EntitySpan entities, Span<T1> …)`, to vectorize with `Vector<T>` (the JIT does not vectorize loops on its
  own). `entities[i]` is built only when indexed. The spans point into the tables, so a structural change throws
  while the job runs.

```csharp
using System.Numerics;
using System.Runtime.InteropServices;

public struct KillTheWounded : IForEachEntity<Health>
{
    public static int WriteMask => 0;          // reads Health; the change is structural (a tag)

    public void Execute(Entity unit, ref Health hp)
    {
        if (hp.Value <= 0) unit.SetDead();
    }
}

public struct Drift : IForEachBatch<Position, Velocity>
{
    public static int WriteMask => 1;

    public void Execute(EntitySpan entities, Span<Position> positions, Span<Velocity> velocities)
    {
        // Two floats each: as Vector<float> spans, every lane is one coordinate
        var p = MemoryMarshal.Cast<Position, Vector<float>>(positions);
        var v = MemoryMarshal.Cast<Velocity, Vector<float>>(velocities);
        for (int i = 0; i < p.Length; i++) p[i] += v[i];
        var pf = MemoryMarshal.Cast<Position, float>(positions);
        var vf = MemoryMarshal.Cast<Velocity, float>(velocities);
        for (int i = p.Length * Vector<float>.Count; i < pf.Length; i++) pf[i] += vf[i];   // the rows left over
    }
}
```

```csharp
var kill = new KillTheWounded();
world.ForEachEntity<Health, KillTheWounded>(ref kill, QueryFilter.Create().Without<Dead>());
var drift = new Drift();
world.ForEachBatch<Position, Velocity, Drift>(ref drift, Filters.Active);
```

### One entity: `[ForEntity]` and `entity.Run` [#run-on-one-entity]

Code that handles one entity at a time (a request, a message to an actor, a command from a client) writes the work
as a static method marked `[ForEntity]`, like a `[ForEach]` method that runs on one entity. The generator writes the
job and an entry point next to the method, named like it, that takes the entity and the method's other values and
returns whether it ran. It gets the refs a pass gives a row: one table lookup for all its components instead of one
per `Get`. Its `ref` components are the ones stamped as written, `in` ones are read, and filter attributes
(`[Without<Dead>]`) refuse an entity the way a pass's filter skips a row; a method with `[Changed<T>]` takes the tick
to look back from as its second argument, and the entry point passes it beside the method's static filter
(`entity.Run(ref job, in filter, since)`), so no filter is copied per call. Keep the method private: the entry point
has its name.

<Tabs items={['You write', 'The generator writes']}>
<Tab value="You write">

```csharp
public static class Requests
{
    [ForEntity, Without<Dead>]
    static void TakeHit(Entity unit, ref Health hp, int damage)
    {
        if (hp.Value <= damage) unit.SetDead();   // a structural change: hp still points at the entity's value
        hp.Value -= damage;                       // carried over to its new row when the method returns
    }
}
```

</Tab>
<Tab value="The generator writes">

```csharp doccheck=skip
public static class RequestsForEntity
{
    extension(Requests)
    {
        // Runs TakeHit on unit when it is alive, has the method's components and passes its filters.
        public static bool TakeHit(Entity unit, int damage)
        {
            var job = new __ForEach.TakeHitJob0 { x2 = damage };
            return unit.Run<Health, __ForEach.TakeHitJob0>(ref job, in __ForEach.TakeHitFilter0);
        }
    }
}

file static class __ForEach
{
    internal static readonly QueryFilter TakeHitFilter0 = QueryFilter.Create().Without<Dead>();

    internal ref struct TakeHitJob0 : IForEachEntity<Health>
    {
        public int x2;
        public static int WriteMask => 1;          // the ref parameters

        public void Execute(Entity entity, ref Health c1) => TakeHit_0(null, entity, ref c1, x2);   // the method, inlined
    }
}
```

</Tab>
</Tabs>

```csharp
bool applied = Requests.TakeHit(unit, 30);   // false: dead, no Health, or not alive
```

It returns `false`, without running the method, when the entity lacks a component, fails the filter or is not alive.
A struct job written by hand and handed to `entity.Run` only is what `[ForEntity]` writes: the analyzer suggests the
method ([EECS080](/en/docs/guide/analyzer#eecs080), with a code fix that converts the job and its calls). A method
that only fits a pass (a span, an `EntitySpan`, a `Reduce<T>`, a `Scratch<T>`) or that also has `[ForEach]` is
[EECS081](/en/docs/guide/analyzer#eecs081).

The entry point is `entity.Run<T1..Tn, TJob>(ref job, filter)` with the generated job, and you can call it with a
job of your own where one has to hand values back through its fields after the run. The job is an `IForEachEntity`
job, the same type a pass over the world takes; the filter is built once, in a field:

```csharp
public static class Hits
{
    // Built once: the filter is a value, kept in a field.
    public static readonly QueryFilter Alive = QueryFilter.Create().Without<Dead>();
}
```

A job that hands a value back keeps it in a field, and one that only reads declares `WriteMask => 0`:

```csharp
public struct ReadHealth : IForEachEntity<Health>
{
    public int Value;
    public static int WriteMask => 0;          // reads only: nothing counts as written

    public void Execute(Entity unit, ref Health hp) => Value = hp.Value;
}
```

```csharp
var read = new ReadHealth();
if (unit.Run<Health, ReadHealth>(ref read, Hits.Alive)) Console.WriteLine(read.Value);
```

Without a filter, `entity.Run<T1..Tn, TJob>(ref job)` checks only that the entity is alive and has the components.
What follows holds for `[ForEntity]` methods and jobs alike:

- **The refs survive the job's own structural changes**, as in `ForEachEntity`: the components in `WriteMask` are copied
  to the entity's new row after `Execute`, also when it throws, so what was written before the exception stays.
- **Only `WriteMask` count as written** for [change tracking](/en/docs/guide/change-tracking), and only when `Run`
  returns `true`. The default, `WriteMask => -1`, stamps every component the job takes; a job that writes nothing
  declares `WriteMask => 0`.
- **`false` is not "dead"**: it also means a missing component or a filter that failed. Test `entity.IsAlive` when
  the reason matters.
- **`INoStructuralChanges`** skips the bookkeeping and freezes the structure while the job runs, like a pass: a
  structural change made anyway throws `InvalidOperationException`.
- **O(1), plus O(1) per component the filter names**, unless the filter names a type past the first 256 (then it goes
  through the query cache). A filter tests the row the way a query does (`Without`, `WithAny`, `Changed<T>(tick)`,
  groups), with no lookup of the query's tables; build it once, in a `static readonly` field.
- **For the analyzer, `Run` is a structural change** (its job may make one), rejected where those are: in a
  parallel `[ForEach]` method ([EECS010](/en/docs/guide/analyzer#eecs010)), in a `[ForEach]` method that takes no
  `Entity` or `World` ([EECS013](/en/docs/guide/analyzer#eecs013)) and off the world's owner thread
  ([EECS014](/en/docs/guide/analyzer#eecs014)).

An actor is the typical user: each message handler finds the actor's entity (through a
[value index](/en/docs/guide/indexes-and-relations)) and runs one job on it. The
[Actors sample](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/Actors) is a whole program built this way.

### On several threads: `ForEachParallel` and `ForEachEntityParallel` [#on-several-threads-foreachparallel-and-foreachentityparallel]

A job that implements `INoStructuralChanges` and writes only its own row can run on several threads.
`ForEachParallel` (an `IForEach` job) and `ForEachEntityParallel` (an `IForEachEntity` job) cut the matching rows into
chunks (by default about four per thread, a multiple of 64 rows, between 1,024 and `World.MaxChunkRows` = 16,384;
a multiple of 4,096 rows, at least 4,096, when the job's `WriteMask` includes a tracked component, so that no two
chunks share a block's change-tick summary). The calling thread and up to `WorldOptions.MaxDegreeOfParallelism - 1`
thread-pool threads claim the chunks one at a time as they finish, like OpenMP's `schedule(dynamic, n)`. Each chunk
runs on its own copy of the job, so state accumulated in its fields is not merged back. Fewer than two chunks run on
the calling thread. `ForEachBatchParallel` (an `IForEachBatch` job) cuts the same chunks and hands each the runs of
consecutive rows it holds as spans, as `ForEachBatch` does on one thread: the form a parallel
[reduction](/en/docs/guide/threading#reductions) runs in, with a run's partial result in a local.

```csharp
public struct Heal : IForEach<Health>, INoStructuralChanges
{
    public static int WriteMask => 1;

    public void Execute(ref Health health) => health.Value = Math.Min(health.Value + 10, 100);
}
```

```csharp
var heal = new Heal();
world.ForEachParallel<Health, Heal>(ref heal, Filters.Active);   // each row runs once, on one of the threads
```

The last argument, `chunkSize`, sets the rows a thread takes at a time (the `n` of `schedule(dynamic, n)`, rounded up
to 64; 0, the default, chooses from the row count): for a few hundred rows that cost microseconds each, which the
default would leave in one chunk. It is what `[ForEach(Parallel = true, ChunkSize = n)]` passes
([chunk size](/en/docs/guide/threading#chunk-rows)).

```csharp
public record struct Plan(int Cost) : IComponent;

public struct Replan : IForEach<Plan>, INoStructuralChanges
{
    public static int WriteMask => 1;

    public void Execute(ref Plan plan)
    {
        int cost = plan.Cost;
        for (int i = 0; i < 10_000; i++) cost = (cost * 31 + i) % 1_000_003;   // microseconds per row
        plan = new Plan(cost);
    }
}
```

```csharp
var replan = new Replan();
world.ForEachParallel<Plan, Replan>(ref replan, chunkSize: 64);
```

The job must not read what another row's job writes (another entity, a singleton), and nothing else may change the
world during the call. [`[ForEach(Parallel = true)]`](/en/docs/guide/systems#parallel-methods) compiles a system method
to the same chunked run.

### `Count` and `Any` [#count]

`Count` sums the row counts of the matching tables, and counts presence bits only in tables where some rows lack a
queried component. `Any` stops at the first match. Neither touches a component value.


### A bounded batch of ids: `CollectIds` [#collect-ids]

`world.CollectIds<T1..Tn>(into, filter)` writes the ids of the matching entities into a span, in the order `Query`
and `Read` visit them, until the span is full, and returns how many. It is the "take up to N this tick" of a system
that serves requests: the ids then go to `DestroyEntities`, `SaveEntities` or a loop that changes structure, which a
query loop may not do while it runs.

```csharp
[EcsSystem]
public ref struct BuryTheFallen
{
    static readonly QueryFilter Fallen = QueryFilter.Create().With<Dead>();

    static void OnUpdate(World world)
    {
        Span<EntityId> batch = stackalloc EntityId[64];
        int count = world.CollectIds<Health>(batch, Fallen);   // the first 64, in query order // [!code highlight]
        world.DestroyEntities(batch[..count]);                 // the rest wait for the next tick
    }
}
```

- **Allocation-free.** O(matching tables), plus the rows read until the span is full; a table whose rows all match
  is one copy of its ids.
- **It does not remember where it stopped.** The next call starts from the first match again, so serve what it
  returned (destroy it, tag it, save it) before the next call.
- **Filter, do not branch.** Two systems that share a request type split it with a tag (`With<Saved>` /
  `Without<Saved>`), not with a test that skips rows in the batch: `VoxelServer` serves its load requests this way
  ([a chunk's life](/en/docs/samples/voxel-server#chunks)).

## How to use it fast [#how-to-use-it-fast]

| Instead of | Do | Why |
| --- | --- | --- |
| A `Query` loop every tick | A `[ForEach]` method in a system | Generated struct job, ordered and scheduled |
| `QueryFilter.Create()…` at every call | A `static readonly` filter | The cache key is built once |
| A `Query` that only reads tracked components | [`Read<T1..Tn>`](#read), a job with `WriteMask => 0`, or `in` parameters | `Query` items stamp what they hand out |
| `ForEachEntity` when the entity is rarely used | A batch job with `EntitySpan` | Handles built only for the rows that need one |
| A scalar loop over many rows | A batch job with `Vector<T>` | The JIT does not vectorize on its own |
| `Count(...) > 0` | `Any(...)` | Stops at the first match ([EECS032](/en/docs/guide/analyzer#eecs032)) |
| Several `Get` / `TryGetRef` and a `Has<Dead>()` per request | A [`[ForEntity]`](#run-on-one-entity) method with `[Without<Dead>]` | One lookup; the refs are carried across structural changes |
| Scanning for a key | A [value index](/en/docs/guide/indexes-and-relations) | O(matches) instead of O(rows) |
| A `Read` loop that copies ids into a span and breaks when it is full | [`CollectIds`](#collect-ids) | A table whose rows all match is one copy |

## What it costs [#what-it-costs]

- **The first use of a query shape** (components plus filter) visits every table once to build its cache entry.
  Tables created later join the entries they match.
- **Every later call** finds the entry through a small per-signature memo, or one hash probe past it, then walks
  O(matching tables + their rows).
- **Filtered rows** are tested 64 at a time from presence bits; words where every row passes are spanned four per
  SIMD compare, and words with no match are skipped.
- **`Count`** is O(matching tables), plus a popcount per word in tables whose rows differ.
- **No allocation**: filters are values with no object reference, enumerators and items are ref structs, jobs are
  structs.

## Pitfalls [#pitfalls]

| Mistake | What happens | Caught by |
| --- | --- | --- |
| `await` inside a `Query` loop | Does not compile: items are ref structs | The C# compiler |
| Storing a query item | Does not compile; keep `item.Entity` | The C# compiler |
| A `Query` loop that only reads tracked components | Every visited row counts as written | Loop over [`Read<T1..Tn>`](#read) |
| `INoStructuralChanges` on a job that changes structure | `InvalidOperationException` at the change | At run time |
| Structural change in a batch job | `InvalidOperationException`: the spans point into the tables | At run time ([EECS013](/en/docs/guide/analyzer#eecs013) for `[ForEach]` methods) |
| A parallel job that writes a singleton or another entity | Races between chunks | Code review ([EECS010](/en/docs/guide/analyzer#eecs010) for `[ForEach]` methods) |
| `Changed`, `Removed`, `ChangedAny` or `RemovedAny` with different ticks in one filter | `ArgumentException` | At run time |
| A sliced filter (`Slice`) passed to `Query`, `Read`, `Count`, `Any`, `DestroyAll`, `entity.Run` or a bulk call | `ArgumentException`: the call needs every matching row | [EECS044](/en/docs/guide/analyzer#eecs044) |
| `Update()` called from inside a query loop of the same world | Every system runs while the loop walks the tables, and the update closes the loop's holes under it: rows it has not reached move behind it and are missed | [EECS051](/en/docs/guide/analyzer#eecs051); [EECS034](/en/docs/guide/analyzer#eecs034) when called from a system |
| An `entity.Run` job without `WriteMask` | The default (-1) stamps every tracked component the job takes | Declare `WriteMask` (`0` for a job that only reads) |
| `INoStructuralChanges` on a `Run` job that changes structure | `InvalidOperationException` at the change | At run time |
| Treating `false` from `Run` as "dead" | It also means a missing component or a filter that failed | Code review: test `IsAlive` |
| `QueryFilter.Create()…` built at every `Run` or query call | The filter is rebuilt and looked up at every call | Code review: a `static readonly` field |
| `entity.Run` inside a parallel `[ForEach]` method | Its job may change structure from several threads | [EECS010](/en/docs/guide/analyzer#eecs010) |
| A struct job written by hand only to be handed to `entity.Run` | Code the generator writes, kept in sync by hand | [EECS080](/en/docs/guide/analyzer#eecs080) (with a code fix): a `[ForEntity]` method |
| A `[ForEntity]` method that is an instance method, also has `[ForEach]`, or takes a span, an `EntitySpan`, a `Reduce<T>` or a `Scratch<T>` | Compile error: one entity has no pass | [EECS081](/en/docs/guide/analyzer#eecs081) |
