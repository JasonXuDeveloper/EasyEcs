A server restarts and must come back with its world: players where they stood, timers where they were, links between
entities intact. `world.Save(output)` writes the entities (ids and versions), their components and the singletons as
bytes, and `world.Load(bytes)` puts them into a world of this process or another one. Unmanaged components are their
raw rows, one block per column; managed ones, and the components marked `[NinoType]`, go through
[Nino](https://github.com/JasonXuDeveloper/Nino). Saving and
loading again into the same buffers allocates nothing.

## When to use it [#when-to-use-it]

<Callout type="idea" title="Use it for">
  Persistence across restarts, replays on disk, crash dumps, shipping a world to another process (a test harness, a
  replay viewer), keeping data through a [hot reload](/en/docs/guide/migration-and-unload#hot-reload).
</Callout>

<Callout type="warn" title="Skip it for">
  Rolling back inside one process: a [snapshot](/en/docs/guide/snapshots) is faster and needs no encoding. Moving a
  player to another server: [`SaveEntities`](/en/docs/guide/migration-and-unload#save-entities) writes just the group.
  Saving only what persists of an entity and loading it onto a live one: [a record](/en/docs/guide/migration-and-unload#records)
  is `SaveEntities` with a `ComponentSet`, loaded by `LoadEntitiesInto`.
</Callout>

## How to use it [#how-to-use-it]

<Steps>
<Step>

### Declare the components [#declare]

Unmanaged components need nothing. A managed component (one with a `string`, an array, a class) needs a Nino formatter:
mark it `[NinoType]` and make it `partial`. The EasyEcs package brings Nino with its generator, so the project
references nothing else. Mark an unmanaged component `[NinoType]` too when its shape will change between builds
([below](#versioning)).

```xml title="Game.csproj"
<PackageReference Include="EasyEcs" Version="4.*" />
```

```csharp
using Nino.Core;

public record struct Stock(int Gold, int Wood) : IComponent;          // unmanaged: saved as raw rows
public record struct Clock(long Tick) : ISingletonComponent;

[NinoType]
public partial record struct PlayerName(string Value) : IComponent;    // managed: Nino writes it
```

</Step>
<Step>

### Save [#save]

`Save` writes into any `IBufferWriter<byte>`. A `NinoArrayBufferWriter` is written directly; another writer gets a
copy from the world's own buffer.

```csharp
world.CreateEntity(new PlayerName("alice"), new Stock(10, 3));
world.SetClock(1234);

var output = new NinoArrayBufferWriter();
world.Save(output);                                                    // entities, components, singletons // [!code highlight]
File.WriteAllBytes("world.sav", output.WrittenSpan.ToArray());
```

</Step>
<Step>

### Load [#load]

`Load` replaces the world's entities, components and singletons with the save's. Entities keep their ids and
versions, so `EntityId`s stored in components still point at the same entities, and handles made before the save work
again.

```csharp
using var restarted = new World();
restarted.Load(File.ReadAllBytes("world.sav"));                       // same ids, values and clock // [!code highlight]
long tick = restarted.Clock.Tick;                                      // 1234
```

</Step>
</Steps>

### What a save holds [#what-it-holds]

| Saved | Not saved |
| --- | --- |
| Every alive entity, with its id and version | Systems, `WorldOptions` |
| Every component, unmanaged as raw rows, managed through Nino | Indexes (they rebuild on the next lookup) |
| Disabled components, with their kept values | Groupings (`Load` follows this world's `GroupBy` calls) |
| [`DynamicBuffer<T>`](/en/docs/guide/dynamic-buffers) elements | Change ticks (every loaded row counts as written) |
| Every singleton | |

Types are recorded by their Nino type id (a hash of the namespace-qualified name), and each column is a
length-prefixed slice, so a load skips the components this process has no type for. A type is found when the process
used it, or when the generator registered it: every component and singleton of a compilation that uses EasyEcs is
registered when its module loads.

### When the code changed [#versioning]

How a component may change depends on how it is written. A plain unmanaged component is its raw rows: the save records
its size and a hash of its fields (names, types, layout attributes), and only the same shape loads them. A
`[NinoType]` component, managed or unmanaged, is written by its Nino formatter, and its
[format](https://nino.xgamedev.net/en/docs/v4/evolving-data) decides what may change: `Positional` (the default) reads
only the shape it wrote, `VersionTolerant` reads rows written before members were appended, `Keyed` also takes
members inserted, removed or reordered. A load refuses what it cannot read, with an `InvalidDataException`, and leaves
the world as it was:

| Change since the save | Load |
| --- | --- |
| A component type added | Loads: the new type has no rows |
| A component type removed | Loads: its slices are skipped (its data is dropped) |
| A component type renamed or moved to another namespace | Loads with `[NinoFormerName("Old.Namespace.Name")]` on it; skipped without |
| Fields of a raw unmanaged component changed (added, removed, retyped, renamed) | `InvalidDataException` |
| Members appended to a `VersionTolerant` or `Keyed` component | Loads: the new members keep their defaults |
| A change the component's Nino format does not allow (its slice no longer reads to the last byte) | `InvalidDataException` |
| A component switched between raw rows and `[NinoType]` | `InvalidDataException` |
| Two types of the process with one id (one name, or a former name that is another's) | `InvalidDataException`: rename one |
| Bytes that are not a save, or a damaged one | `InvalidDataException` |

So a component whose shape will change is a `[NinoType]` from its first save. It stays unmanaged (a column of
values, no references), and Nino writes it value by value instead of as one block:

```csharp
[NinoType(format: NinoFormat.VersionTolerant)]
public partial record struct Rank(int Tier, int Points) : IComponent;          // the first build

// A later build renames it and appends a member: old saves load, Season is 0 in their rows.
[NinoType(format: NinoFormat.VersionTolerant), NinoFormerName("Rank")]
public partial record struct Standing(int Tier, int Points, int Season) : IComponent;
```

A raw component cannot change shape. Add a new component type instead: a build that has both loads the old save, a
system converts the old component into the new one, and a later build drops the old type.

```csharp
public record struct Crafting(int Recipe, int Progress) : IComponent;          // saved as raw rows
public record struct Workshop(int Recipe, int Progress, int Queue) : IComponent;   // the new shape

// Runs in the build that knows both types: every loaded Crafting becomes a Workshop.
// A later build deletes Crafting and this system.
public class UpgradeCrafting : EcsSystem
{
    [ForEach]
    static void Upgrade(Entity player, in Crafting old)
    {
        player.SetWorkshop(old.Recipe, old.Progress, Queue: 0);
        player.RemoveCrafting();
    }
}
```

```csharp
try
{
    restarted.Load(output.WrittenSpan);
}
catch (InvalidDataException)
{
    // a component changed since this save: the world is as it was before the call
}
```

### Components in plugins [#plugins]

The id lookup is process-wide. While a plugin's old version and its new one are both loaded, their types share ids and
a load refuses them as ambiguous. Unload the old version first (the [hot reload](/en/docs/guide/migration-and-unload#hot-reload)
order: save, `RemoveTypes`, unload, load the new version, `Load`), or keep the components you save in an assembly
that is never reloaded, such as a contracts assembly shared by the host and the plugins.

## Full example [#full-example]

Two players, one following the other, and a clock: the world is saved into a buffer and loaded into a new world, as a
restarted process would do. Put the files in a console project that references EasyEcs
([declare the components](#declare)) and run it with `dotnet run`.

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;
using Nino.Core;

// Unmanaged: saved as raw rows, one block per column.
public record struct Position(float X, float Y) : IComponent;

// An EntityId keeps its meaning: a load keeps every id and version.
public record struct Follows(EntityId Leader) : IComponent;

// Managed (a string): Nino writes it, so it is a partial [NinoType].
[NinoType]
public partial record struct PlayerName(string Value) : IComponent;

// Singletons are saved too.
public record struct Clock(long Tick) : ISingletonComponent;
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;
using Nino.Core;

using var world = new World();
world.SetClock(Tick: 1234);
var alice = world.CreateEntity(new PlayerName("alice"), new Position(3, 4));
world.CreateEntity(new PlayerName("bob"), new Position(5, 6), new Follows(alice.Id));

// Entities, components and singletons, into a buffer that can be reused for the next save.
var output = new NinoArrayBufferWriter();
world.Save(output);

// Another world, as a restarted process would make it.
using var restarted = new World();
restarted.Load(output.WrittenSpan);

Console.WriteLine($"clock: {restarted.Clock.Tick}");
foreach (var item in restarted.Query<PlayerName, Position>())
{
    Console.WriteLine($"{item.Entity.Id} {item.PlayerName.Value} at ({item.Position.X}, {item.Position.Y})");
}

foreach (var item in restarted.Query<PlayerName, Follows>())
{
    var leader = restarted.GetEntity(item.Follows.Leader);
    Console.WriteLine($"{item.PlayerName.Value} follows {leader.PlayerName.Value}");
}
```

</Accordion>
</Accordions>


It prints:

```text
clock: 1234
0v1 alice at (3, 4)
1v1 bob at (5, 6)
bob follows alice
```

The new world has the same ids, the managed names came back through Nino, the singleton clock kept its tick, and
Bob's `Follows` still names Alice without any rewriting.

## How to use it fast [#how-to-use-it-fast]

| Instead of | Do | Why |
| --- | --- | --- |
| A new buffer per save | One `NinoArrayBufferWriter`, `ResetWrittenCount()` before each save | Save allocates nothing once its buffers are large enough |
| Another `IBufferWriter<byte>` | `NinoArrayBufferWriter` | Written directly, without the copy from the world's buffer |
| A new world per load | `Load` into the same world | Its rows are reused: nothing allocated once warm |
| Managed components where values would do | Unmanaged components (ids, numbers, fixed arrays) | Raw rows are one block per column; Nino encodes value by value |
| `[NinoType]` on unmanaged components that never change | Raw rows for those, `[NinoType]` where the shape will change | A raw column is one copy |
| Your own serializer over a `Query` | `Save` / `Load` | Ids, versions, buffers, disabled values and singletons come along |

## What it costs [#what-it-costs]

- **Size:** for unmanaged components, the rows themselves (padding bytes cleared, so equal worlds save equal bytes),
  plus presence bits, ids and versions; managed and `[NinoType]` components as Nino writes them; each type's id once.
- **Time:** O(entities × components) both ways.
- **Allocation:** none on a repeated `Save` into a `NinoArrayBufferWriter`, none on a repeated `Load` into the same
  world; managed values a load reads are new objects.
- **Not while a pass iterates:** both take the structural gate.

## Pitfalls [#pitfalls]

| Mistake | What happens | Caught by |
| --- | --- | --- |
| A managed component without `[NinoType]` | `Save` throws `InvalidOperationException` (no formatter) | At run time |
| A `Nino.Generator` reference older than the Nino of EasyEcs | A package downgrade: remove the reference, the EasyEcs package brings the generator | Restore (`NU1605`) |
| An `Entity` handle in a component | A managed column Nino cannot write | [EECS017](/en/docs/guide/analyzer#eecs017) |
| Editing the fields of a saved raw component | Old saves are refused | `[NinoType(format: NinoFormat.VersionTolerant)]` from the first save, or a new component type |
| Renaming a component or moving its namespace | Old saves load without it | `[NinoFormerName]` with the old full name |
| Old and new plugin versions loaded at once | Ambiguous names: `InvalidDataException` | Unload the old version first |
| Saving or loading from another thread | Races with the owner thread | [EECS014](/en/docs/guide/analyzer#eecs014) |
