船上装着炮塔，炮塔上装着炮管，队长带着队员。`ChildOf(parent)` 把实体挂到父实体下：`world.Children(parent)` 列出子实体，
销毁父实体时后代一并销毁。船沉了，炮塔跟着没了，一行清理代码都不用写。`ChildOf` 和其他
[带索引的 `EntityId` 链接](/zh/docs/guide/indexes-and-relations#entityid-keys)没有区别，只是默认打开了级联销毁。

## 什么时候用 [#when-to-use-it]

<Callout type="idea" title="适合">
  和另一个实体同生共死的实体：船上的炮塔、玩家身上的物品、小队成员、载具的部件。把玩家和他拥有的一切迁移到另一个
  World 或另一台服务器。
</Callout>

<Callout type="warn" title="不适合">
  不该连带杀死对方的链接（攻击目标、跟随者）：用自己的 `EntityId` 键，配 `Keep` 或 `Remove`。一个实体有多个“父亲”
  （同时属于多支队伍）：用[关系](/zh/docs/guide/indexes-and-relations#relations)。变换传播不是内置功能，
  [下面的示例](#transform-propagation)是你自己写的系统。
</Callout>

## 怎么用 [#how-to-use-it]

<Steps>
<Step>

### 挂上子实体 [#attach]

给子实体加一个 `ChildOf`，参数是父实体的 id（句柄可以直接转换）。

```csharp
public record struct Name(string Value) : IComponent;
```

```csharp
var ship = world.CreateEntity(new Name("ship"));
var turret = world.CreateEntity(new Name("turret"), new ChildOf(ship));
var gun = world.CreateEntity(new Name("gun"), new ChildOf(turret));
```

</Step>
<Step>

### 列出子实体 [#children]

`world.Children(parent)` 返回 `ChildOf` 指向这个父实体的实体：O(1)，之后每个子实体 O(1)。第一次调用会把所有 `ChildOf`
索引一遍。

```csharp
foreach (var child in world.Children(ship)) { /* 炮塔 */ }
```

</Step>
<Step>

### 遍历整棵子树：Descendants [#descendants]

`world.Descendants(root)` 遍历根下面的整棵子树：深度优先，每个实体都排在它自己的子实体前面，根本身不算在内。每个实体
O(1)，热身后不分配内存。整棵树作为一个整体处理时（保存、迁移、计数）用它；需要先拿到父实体结果的传播，按
[`Children` 一层层走](#transform-propagation)。

```csharp
int parts = 0;
foreach (var part in world.Descendants(ship)) parts++;   // 先是炮塔，再是它的炮管
```

- **遍历途中可以销毁实体**：遍历还没走到就被销毁的实体会跳过。
- **遍历里可以再套一层遍历**：内层自己分配一个栈（外层占着 World 保留的那个）。
- **`ChildOf` 成环**（实体是自己的祖先）时，遍历走到环上就抛 `InvalidOperationException`。
- **遍历途中不能改 `ChildOf`**（换父实体、解除挂接）：这会改写遍历正在读的子实体列表。先收集，再修改。

</Step>
<Step>

### 换父实体、解除挂接 [#reparent]

`ChildOf` 就是一个普通的值：设一个新值就是换父实体，移除它，实体就成了根。它和你自己的组件一样有
[生成成员](/zh/docs/guide/entities-and-components)：`entity.ChildOf`（只读：它被索引）、`HasChildOf`、`TryGetChildOf(out link)`、
`SetChildOf(parent)`、`SetChildOfIfChanged(parent)`、`RemoveChildOf()` 和 `world.ChildOfIndex`，预制体上也有
`SetChildOf` / `RemoveChildOf`。没有 `DisableChildOf`：`ChildOf` 不能被禁用。

```csharp
gun.SetChildOf(ship);      // 炮管改挂到船上
turret.RemoveChildOf();    // 炮塔成了根
```

</Step>
<Step>

### 销毁父实体 [#cascade]

销毁父实体时，它的子实体、子实体的子实体都会在同一次调用里销毁。

```csharp
ship.Destroy();                            // 炮管跟着没了；已经解除挂接的炮塔还在
bool gunAlive = gun.IsAlive;               // false
```

</Step>
</Steps>

### 用预制体生成子实体 [#instantiate-children]

从[预制体](/zh/docs/guide/prefabs)生成的子实体，可以在同一次调用里拿到父实体：`world.Instantiate(minion, new ChildOf(boss))`
把 `ChildOf` 直接写进副本所在的最终表，一次行复制就挂好，不用再移动（见[每个实例带上自己的值](/zh/docs/guide/prefabs#instantiate-with-values)）。
批量形式 `world.Instantiate(minion, span, new ChildOf(boss))` 把一整波挂到同一个父实体下。

### 向上找祖先 [#ancestors]

`Children` 和 `Descendants` 往下走。往上走不需要索引：读实体的 `ChildOf`，跟着 `Parent` 走一步，重复下去，直到遇到带目标组件的实体，
或者走到根（没有 `ChildOf` 的实体）。炮找它装在哪艘船上，物品找带着它的玩家，都是这样。

```csharp
public struct Vessel : IComponent;                 // 部件要找的那个祖先

public static class Ancestors
{
    // part 最近的带 T 的祖先；没有就返回 default。
    public static Entity Nearest<T>(Entity part) where T : struct, IComponent
    {
        var world = part.World;
        // 链比 World 的实体数还长，说明 ChildOf 成了环：停下来，不要死循环。
        for (int steps = world.EntityCount; steps > 0; steps--)
        {
            if (!part.TryGetChildOf(out var link)) return default;                // 到根了：没有这样的祖先
            if (!world.TryGetEntity(link.Parent, out var parent)) return default; // 父实体已经没了（Keep）
            if (parent.Has<T>()) return parent;
            part = parent;
        }

        throw new InvalidOperationException("The ChildOf links form a cycle");
    }

    // part 之上的根：沿链往上第一个没有活着的父实体的实体（part 本身是根就返回它自己）。
    public static Entity Root(Entity part)
    {
        var world = part.World;
        for (int steps = world.EntityCount; steps > 0; steps--)
        {
            if (!part.TryGetChildOf(out var link) || !world.TryGetEntity(link.Parent, out var parent)) return part;
            part = parent;
        }

        throw new InvalidOperationException("The ChildOf links form a cycle");
    }
}
```

```csharp
var frigate = world.CreateEntity(new Name("frigate"), new Vessel());
var deck = world.CreateEntity(new Name("deck"), new ChildOf(frigate));
var cannon = world.CreateEntity(new Name("cannon"), new ChildOf(deck));
Entity carrier = Ancestors.Nearest<Vessel>(cannon);   // 护卫舰，往上两层
Entity top = Ancestors.Root(cannon);                  // 也是护卫舰：它没有父实体
```

- **开销：** 每一层一步，每步读一次组件、查一次 id：O(深度)，不分配内存，不用索引。浅层级（船和它的炮塔）一两步就到。
- **在遍历大量实体的 `[ForEach]` 里，** 这相当于每个 tick 每行多几次查找。如果结果只在换父实体时才变，就把它存进子实体的一个组件
  （船的 `EntityId`），在设置 `ChildOf` 的地方一起设置。
- **环：** `Set` 不会拒绝让链首尾相接的 `ChildOf`（实体成了自己的祖先），所以向上走要像 `Descendants` 那样用 `world.EntityCount`
  限制步数，超过就抛异常。
- **指向已销毁父实体的链接**只在 `TargetPolicy.Keep` 下存在（[见下文](#cascade-policy)）：`TryGetEntity` 会告诉你父实体没了，遍历就停在那里。

### 改变销毁的行为 [#cascade-policy]

`ChildOf` 的初始策略是 `TargetPolicy.Destroy`。和其他[目标策略](/zh/docs/guide/indexes-and-relations#target-policies)一样，
可以按 World 修改：`Remove` 让被销毁父实体的子实体变成根，`Keep` 让它们的 `ChildOf` 继续指向那个死去的 id。

```csharp
world.ChildOfIndex.WhenTargetDestroyed(TargetPolicy.Remove);   // 孤儿变成根
```

- 持有[清理组件](/zh/docs/guide/cleanup-and-disable#cleanup-components)的子实体不会被直接释放，而是“退休”：带着
  `Destroyed` 标签保留清理组件，它自己的子实体照样随它而去。
- 环（实体是自己的祖先）会正常结束：销毁其中任何一个，整个环都会被销毁。
- `ChildOf` 不能被禁用（`Disable<ChildOf>()` 会抛异常）：父实体销毁时必须找得到子实体。

### 变换传播 [#transform-propagation]

EasyEcs 没有内置变换组件。传播就是一个系统：从根（`Without<ChildOf>`）开始，用 `Children` 往下走，每个世界坐标都由父实体
刚算好的坐标得出。

```csharp
public record struct LocalPosition(float X, float Y) : IComponent;
public record struct WorldPosition(float X, float Y) : IComponent;
```

```csharp title="PropagateTransforms.cs"
public class PropagateTransforms : EcsSystem
{
    // 根：世界坐标就是本地坐标；然后每棵子树跟随它的父实体
    [ForEach, Without<ChildOf>]
    static void FromRoot(Entity root, in LocalPosition local, ref WorldPosition position)
    {
        position = new WorldPosition(local.X, local.Y);
        Follow(root, position);
    }

    static void Follow(Entity parent, WorldPosition at)
    {
        foreach (var child in parent.World.Children(parent)) // [!code highlight]
        {
            ref readonly var local = ref child.LocalPosition;
            var position = new WorldPosition(at.X + local.X, at.Y + local.Y);
            child.WorldPosition = position;
            Follow(child, position);
        }
    }
}
```

```csharp
world.AddSystem<PropagateTransforms>();
var hull = world.CreateEntity(new LocalPosition(10, 0), new WorldPosition());
var mount = world.CreateEntity(new LocalPosition(0, 2), new WorldPosition(), new ChildOf(hull));
var barrel = world.CreateEntity(new LocalPosition(1, 0), new WorldPosition(), new ChildOf(mount));
world.Update();                            // barrel：WorldPosition(11, 2)
```

方法接收了 `Entity`，所以这个系统单独运行（它要读写别的实体的组件）。子实体带着 `ChildOf`，和根不在同一张表里，写它们
不会挪动当前遍历所在的行。整个过程没有任何分配。

### 迁移层级 [#moving]

`MoveEntities` 和 `SaveEntities` 只处理你列出的实体，不会顺带它们的子实体。用 `world.Descendants(root).AddTo(ids, includeRoot: true)`
收集整棵层级：它先追加根，再追加每个后代，每个父实体都在它的子实体之前（每个实体 O(1)，只有列表扩容时才分配；复用列表时先清空），
然后一起迁移：父实体
没跟过去的子实体，到了那边会去掉 `ChildOf`（成为根）；而 `MoveEntities` 销毁原实体时会连同子实体一起销毁，没列出的子实体
就丢了。两者都接收 `ReadOnlySpan<EntityId>`：直接传列表的 span（`CollectionsMarshal.AsSpan`），不必复制一份数组。
详见[迁移](/zh/docs/guide/migration-and-unload#move-entities)。

```csharp
using System.Runtime.InteropServices;

var player = world.CreateEntity(new Name("bob"));
world.CreateEntity(new Name("sword"), new ChildOf(player));

var group = new List<EntityId>();
world.Descendants(player).AddTo(group, includeRoot: true);   // bob，然后是子实体、孙实体……
using var other = new World();
world.MoveEntities(other, CollectionsMarshal.AsSpan(group));   // bob 和他的剑，链接保持不变
```

## 完整例子 [#full-example]

一艘船，上面有炮塔，炮塔上有炮管：世界坐标跟着父实体走，再列出船的整棵子树；然后把炮管挂到别的父实体上，把炮塔摘下来，
最后销毁船和还挂在它上面的东西。把这几个文件放进一个引用了 EasyEcs 的控制台项目（`dotnet add package EasyEcs`），用 `dotnet run` 运行。

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;

public record struct Name(string Value) : IComponent;

// 相对父实体的位置（根实体就是相对世界）。
public record struct LocalPosition(float X, float Y) : IComponent;

// 世界坐标，由 PropagateTransforms 计算。
public record struct WorldPosition(float X, float Y) : IComponent;
```

</Accordion>
<Accordion title="Systems.cs">

```csharp title="Systems.cs" doccheck=example
using EasyEcs;

// 从根往下计算每个世界坐标，
// 每个子实体都跟着父实体的新位置走。
public class PropagateTransforms : EcsSystem
{
    // 根实体没有 ChildOf：世界坐标就是本地坐标。
    [ForEach, Without<ChildOf>]
    static void FromRoot(Entity root, in LocalPosition local, ref WorldPosition position)
    {
        position = new WorldPosition(local.X, local.Y);
        Follow(root, position);
    }

    static void Follow(Entity parent, WorldPosition parentPosition)
    {
        foreach (var child in parent.World.Children(parent))
        {
            LocalPosition local = child.LocalPosition;
            float x = parentPosition.X + local.X;
            float y = parentPosition.Y + local.Y;
            var position = new WorldPosition(x, y);
            child.WorldPosition = position;
            Follow(child, position);
        }
    }
}
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;

using var world = new World();
world.AddSystem<PropagateTransforms>();

// 子实体用 ChildOf 指向父实体。
Entity ship = world.CreateEntity(new Name("ship"), new LocalPosition(10, 0), new WorldPosition());
Entity turret = world.CreateEntity(
    new Name("turret"), new LocalPosition(0, 2), new WorldPosition(), new ChildOf(ship));
Entity gun = world.CreateEntity(
    new Name("gun"), new LocalPosition(1, 0), new WorldPosition(), new ChildOf(turret));

world.Update();
Console.WriteLine($"gun at {gun.WorldPosition}");

foreach (var child in world.Children(ship))
{
    Console.WriteLine($"ship > {child.Name.Value}");
}

// Descendants 深度优先走完整棵子树：每个实体都排在它自己的子实体前面。
Console.Write("ship's subtree:");
foreach (var part in world.Descendants(ship))
{
    Console.Write($" {part.Name.Value}");
}

Console.WriteLine();

// 换父实体：设一个新的 ChildOf。摘下来：移除它，实体就成了根。
gun.SetChildOf(ship);
turret.RemoveChildOf();

// ChildOf 是带索引的组件：用它的索引数一个父实体有几个子实体。
var children = world.ChildOfIndex;
Console.WriteLine($"ship: {children.Count(ship)} child, turret: {children.Count(turret)} children");

// 销毁父实体会连带销毁子实体：炮管跟着船一起没了。
ship.Destroy();
Console.WriteLine($"turret alive: {turret.IsAlive}, gun alive: {gun.IsAlive}");
Console.WriteLine($"{world.EntityCount} entity left");
```

</Accordion>
</Accordions>

输出：

```text
gun at WorldPosition { X = 11, Y = 2 }
ship > turret
ship's subtree: turret gun
ship: 1 child, turret: 0 children
turret alive: True, gun alive: False
1 entity left
```

炮管的世界坐标是它和各级父实体偏移的和：10 + 0 + 1 和 0 + 2 + 0。`Children` 只列出炮塔，`Descendants` 还能走到下面的
炮管。炮塔被摘下来以后，船销毁了它还在；炮管被挂到了船上，就跟着船一起销毁了。

## 怎么用得快 [#how-to-use-it-fast]

- **销毁根。** 一次 `Destroy` 在结构闸门内顺着整棵子树走完，不递归（用一个目标栈）。先一个个销毁子实体再销毁父实体，
  做的事一样，只是调用更多。
- **做传播时层级尽量浅。** 上面的遍历每个实体查一次 `Children`；扁平的层级（船和它的炮塔）走得最快。
- **`DestroyAll<T>()`** 一次销毁整张表，级联照样生效。
- **预制体生成的子实体直接带上父实体：** `Instantiate(prefab, new ChildOf(parent))` 一步放进最终的表；先 `Instantiate` 再
  `SetChildOf(...)` 要复制一行，再移动一次。
- **很多实体每个 tick 都要向上找时，把结果存下来：** 一次[向上找祖先](#ancestors)是 O(深度)。

## 开销 [#what-it-costs]

- **出现第一个 `ChildOf` 之前零开销。** 没有任何表包含 `ChildOf` 的 World，销毁实体时根本不去找子实体。
- **内存：** `ChildOf` 列（每行 8 字节），外加 `EntityId` 键的索引（每个子实体一个节点）。
- **`Children`：** O(1)，之后每个子实体 O(1)；第一次调用会索引所有 `ChildOf`。
- **`Descendants`：** 子树里每个实体 O(1)，用的栈由 World 保留（热身后 0 B）。
- **一次级联：** 每个被销毁的实体 O(1)，再加上它的每个子实体 O(1)。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 谁能发现 |
| --- | --- | --- |
| 通过 `ref` 写 `ChildOf` | 索引还记着旧的父实体 | [EECS015](/zh/docs/guide/analyzer#eecs015) |
| 自己用 `Entity` 字段存父指针 | 托管列，存不了盘，也没有级联 | [EECS017](/zh/docs/guide/analyzer#eecs017) |
| 只迁移父实体，不带子实体 | 子实体留在原地，随原实体一起被销毁 | 用 `Descendants` 收集整组 |
| 只用 `Children` 收集整棵树 | 漏掉孙实体 | `Descendants` 会走完每一层 |
| 用 `Descendants` 遍历成环的 `ChildOf` | 走到环上时抛 `InvalidOperationException` | 运行时 |
| 沿 `ChildOf` 向上走却不限制步数 | `ChildOf` 成环时死循环 | 用 `world.EntityCount` 限制步数（[向上找祖先](#ancestors)） |
| 在 `Descendants` 循环里换父实体 | 新的链接让遍历正在读的子实体列表增长（解除挂接的实体会被跳过） | [EECS042](/zh/docs/guide/analyzer#eecs042)：先收集，再修改 |
| `Disable<ChildOf>()` | 抛 `InvalidOperationException` | [EECS048](/zh/docs/guide/analyzer#eecs048)：改用 `Remove<ChildOf>()` |
| 没写系统却指望有世界坐标 | 没有内置变换 | 写一个[传播系统](#transform-propagation) |
