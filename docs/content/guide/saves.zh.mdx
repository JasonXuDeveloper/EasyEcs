服务器重启后必须恢复原来的 World：玩家站在原地，计时器停在原处，实体之间的链接完好无损。`world.Save(output)` 把实体（id 和版本号）、
它们的组件和单例写成字节，`world.Load(bytes)` 把它们放进本进程或另一个进程的 World。非托管组件直接写原始行，每列一个块；托管组件和标了
`[NinoType]` 的组件交给 [Nino](https://github.com/JasonXuDeveloper/Nino)。反复存档、反复读回同一块缓冲区，不产生分配。

## 什么时候用 [#when-to-use-it]

<Callout type="idea" title="适合">
  跨重启持久化、写到磁盘的回放、崩溃现场转储、把 World 交给另一个进程（测试工具、回放查看器）、在
  [热重载](/zh/docs/guide/migration-and-unload#hot-reload)时保住数据。
</Callout>

<Callout type="warn" title="不适合">
  进程内回滚：[快照](/zh/docs/guide/snapshots)更快，也不用编码。把玩家迁到另一台服务器：
  [`SaveEntities`](/zh/docs/guide/migration-and-unload#save-entities) 只写这一组实体。只存实体里需要持久化的部分、再读回到活着的实体上：
  用[记录](/zh/docs/guide/migration-and-unload#records)，即带 `ComponentSet` 的 `SaveEntities`，由 `LoadEntitiesInto` 读回。
</Callout>

## 怎么用 [#how-to-use-it]

<Steps>
<Step>

### 声明组件 [#declare]

非托管组件什么都不用做。托管组件（含 `string`、数组或类）需要 Nino 格式化器：标上 `[NinoType]`、声明为 `partial` 即可。EasyEcs 包自带 Nino
和它的生成器，项目不用再引用别的包。结构会在版本之间变化的非托管组件也标上 `[NinoType]`（见[下文](#versioning)）。

```xml title="Game.csproj"
<PackageReference Include="EasyEcs" Version="4.*" />
```

```csharp
using Nino.Core;

public record struct Stock(int Gold, int Wood) : IComponent;          // 非托管：按原始行保存
public record struct Clock(long Tick) : ISingletonComponent;

[NinoType]
public partial record struct PlayerName(string Value) : IComponent;    // 托管：由 Nino 写出
```

</Step>
<Step>

### 存档 [#save]

`Save` 可以写进任何 `IBufferWriter<byte>`。写进 `NinoArrayBufferWriter` 时直接写入，其他 writer 要从 World 自己的缓冲区拷一份。

```csharp
world.CreateEntity(new PlayerName("alice"), new Stock(10, 3));
world.SetClock(1234);

var output = new NinoArrayBufferWriter();
world.Save(output);                                                    // 实体、组件、单例 // [!code highlight]
File.WriteAllBytes("world.sav", output.WrittenSpan.ToArray());
```

</Step>
<Step>

### 读档 [#load]

`Load` 用存档里的内容替换 World 的实体、组件和单例。实体保留原来的 id 和版本号，所以组件里存的 `EntityId` 仍然指向同一个实体，
存档前拿到的句柄也重新有效。

```csharp
using var restarted = new World();
restarted.Load(File.ReadAllBytes("world.sav"));                       // 同样的 id、值和时钟 // [!code highlight]
long tick = restarted.Clock.Tick;                                      // 1234
```

</Step>
</Steps>

### 存档里有什么 [#what-it-holds]

| 会保存 | 不保存 |
| --- | --- |
| 每个存活实体，连同 id 和版本号 | 系统、`WorldOptions` |
| 每个组件：非托管的按原始行，托管的走 Nino | 索引（下次查找时重建） |
| 被禁用的组件及其保留的值 | 分组设置（`Load` 按本 World 的 `GroupBy` 调用分组） |
| [`DynamicBuffer<T>`](/zh/docs/guide/dynamic-buffers) 的元素 | 变更 tick（每个加载的行都算作被写入；`markWritten: false` 时都不算，见[重启](#restart)） |
| 每个单例 | 用 `SaveWithout(output, in exclude)` 排除的组件和单例（见[重启](#restart)） |

类型按 Nino 类型 id 记录（带命名空间的完整名字的哈希），每列是一个带长度前缀的片段，所以加载时会跳过当前进程没有的组件类型。当前进程
用过的类型、或者生成器注册过的类型都能找到：使用 EasyEcs 的程序集，其中每个组件和单例都会在模块加载时注册。

### 重启：不带运行时状态，保留新配置 [#restart]

重启是接着上一个进程的 World 往下跑：旧进程在两个 tick 之间存档，新进程读档、加上系统、继续运行。旧 World 里有三样东西不能带回来：

- **运行时状态**，换个进程就没有意义：连接、socket、句柄缓存。它们往往根本没有 Nino 格式化器，直接 `Save` 会抛异常。
- **配置**，新版本会自带：费率、上限、功能开关。存档里存的是旧值。
- **变更 tick：** 默认情况下加载的每一行都算写入，写记录或做同步的 `[Changed<T>]` 系统第一次运行就会把整个 World 再发一遍。

用一个 `ComponentSet` 列出这些类型。`SaveWithout(output, in exclude)` 存档时不写集合里的组件和单例；`LoadKeeping(input, in keep, markWritten: false)`
保留集合里的单例，维持新进程设好的样子，加载的行也不带变更 tick。

```csharp
public record struct Balance(int Gold) : IComponent, ITracked;     // 要持久化；写过的余额要记下来
public record struct Connection(Stream Socket) : IComponent;              // 只在运行时有意义，没有 Nino 格式化器
public record struct Rates(int Interest) : ISingletonComponent;           // 每个版本自己的配置
public record struct Outbox(int Records) : ISingletonComponent;           // 等着写进数据库的记录

public static class Restart
{
    // 每个进程启动时自己设置的单例：加载时原样保留。
    public static readonly ComponentSet Startup = ComponentSet.Create().WithSingleton<Rates>().WithSingleton<Outbox>();

    // 存档时不写的：上面这些单例，加上运行时组件。
    public static readonly ComponentSet Runtime = Startup.With<Connection>();
}

public class SaveBalances : EcsSystem
{
    [ForEach, Changed<Balance>]
    private static void Save(ref Outbox outbox) => outbox.Records++;   // 每个变了的余额一条记录
}
```

```csharp
using var bank = new World();                                          // 旧进程
bank.SetRates(5);
bank.SetOutbox(0);
bank.CreateEntity(new Balance(100), new Connection(Stream.Null));
var previous = new NinoArrayBufferWriter();
bank.SaveWithout(previous, in Restart.Runtime);                               // 不写 Connection、Rates、Outbox // [!code highlight]

using var resumed = new World();                                       // 新进程
resumed.SetRates(7);                                                   // 新版本的配置
resumed.SetOutbox(0);
resumed.LoadKeeping(previous.WrittenSpan, in Restart.Startup, markWritten: false);   // 两个都保留 // [!code highlight]
resumed.AddSystem<SaveBalances>();
resumed.Update();
int records = resumed.Outbox.Records;                                  // 0：读进来的余额都不算变更
int interest = resumed.Rates.Interest;                                 // 7：新的配置
```

顺着单例看一遍：`Rates` 和 `Outbox` 不在存档里，新进程在加载之前设好它们，加载时原样保留，所以 `SaveBalances` 第一次运行就能拿到 `Outbox`。
余额回来了，`Connection` 没有回来，新进程会为每个客户端重新建立连接。读进来的余额都不算写入，第一次更新什么也不记；下一笔存款照常记录。

- **不写的类型不需要格式化器。** 它们的片段根本不会写出，所以没有 `[NinoType]` 的托管组件（`Stream`、缓存对象）放在排除集合里就没问题。
  `Disabled<T>` 标签跟着它的组件走；组件全被排除的实体照样写进存档，只是不带这些组件。
- **保留只针对单例。** 被保留的单例完全维持 World 现在的样子：存储不变（加载前拿到的 `SingletonRef<T>` 照样能用），值也不变；
  存档里它的值直接跳过，不会反序列化。存档里没有的保留单例不会被删掉，World 里本来没有的也不会出现。保留集合里放组件会抛
  `ArgumentException`：加载会替换所有实体，要排除组件就在存档时排除。
- **不带保留集合时，存档里的单例会替换 World 里的**，存档里没有的单例会被删掉：用普通的 `Load` 读这份存档，新进程就没有 `Rates` 了。
- **`markWritten: false` 只作用于加载进来的行：** 没有哪一行算作写入或移除，加载之后才加上的系统也一样；之后代码再写入的内容照常能看到。
- **集合只建一次**，放在 `static readonly` 字段里：集合是值类型，每次 `With` 或 `WithSingleton` 都返回一个新集合。运行时才知道类型的框架用
  `With(typeof(...))` 添加，组件类型和单例类型都接受。
- **分组存档不接受单例。** `SaveEntitiesWith(output, ids, set)` 的集合里有单例时抛 `ArgumentException`
  （见[记录](/zh/docs/guide/migration-and-unload#records)）。

之后才加到已经有状态的 World 上的系统（不管状态是谁写的），也可以从当前 tick 开始算：`world.AddSystem<T>(changesFromNow: true)`
让它第一次运行只访问调用之后写入的行（[tick](/zh/docs/guide/change-tracking#ticks)）。托管的服务器在哪里存档、读档，见[托管](/zh/docs/guide/hosting#persistence)。

### 代码改了之后 [#versioning]

组件能怎么改，取决于它是怎么写进存档的。普通的非托管组件按原始行写：存档记下它的大小和字段哈希（字段名、类型、布局特性），只有结构
完全相同才能读回。标了 `[NinoType]` 的组件（托管或非托管）由它的 Nino 格式化器写，能改什么由它的
[格式](https://nino.xgamedev.net/zh/docs/v4/evolving-data)决定：`Positional`（默认）只认写入时的结构，`VersionTolerant` 能读追加成员
之前写的行，`Keyed` 连插入、删除、调换成员都能接受。读不了的组件会以 `InvalidDataException` 拒绝加载，World 保持调用前的样子：

| 存档之后的改动 | 加载结果 |
| --- | --- |
| 新增了组件类型 | 正常加载：新类型没有行 |
| 删除了组件类型 | 正常加载：跳过它的片段（数据丢弃） |
| 组件类型改名或换了命名空间 | 标上 `[NinoFormerName("旧命名空间.旧名字")]` 就能加载；不标则跳过 |
| 原始行组件的字段变了（增、删、改类型、改名） | `InvalidDataException` |
| `VersionTolerant` 或 `Keyed` 组件追加了成员 | 正常加载：新成员取默认值 |
| 组件的 Nino 格式不允许的改动（片段读不到最后一个字节） | `InvalidDataException` |
| 组件在原始行和 `[NinoType]` 之间切换 | `InvalidDataException` |
| 进程里两个类型 id 相同（同名，或一个的旧名是另一个的名字） | `InvalidDataException`：给其中一个改名 |
| 字节不是存档，或者已损坏 | `InvalidDataException` |

所以结构以后会变的组件，从第一次存档起就标成 `[NinoType]`。它仍是非托管的（一列值，没有引用），只是 Nino 会逐个值写，不再整块拷贝：

```csharp
[NinoType(format: NinoFormat.VersionTolerant)]
public partial record struct Rank(int Tier, int Points) : IComponent;          // 第一个版本

// 之后的版本给它改了名、追加了一个成员：旧存档照样能读，读进来的行 Season 为 0。
[NinoType(format: NinoFormat.VersionTolerant), NinoFormerName("Rank")]
public partial record struct Standing(int Tier, int Points, int Season) : IComponent;
```

原始行组件的结构改不了，只能加一个新组件类型：同时包含两者的版本加载旧存档，由一个系统把旧组件转换成新组件，之后的版本再删掉旧类型。

```csharp
public record struct Crafting(int Recipe, int Progress) : IComponent;          // 按原始行存档
public record struct Workshop(int Recipe, int Progress, int Queue) : IComponent;   // 新结构

// 在同时认识两个类型的版本里运行：加载进来的每个 Crafting 都变成 Workshop。
// 之后的版本删掉 Crafting 和这个系统。
public class UpgradeCrafting : EcsSystem
{
    [ForEach]
    static void Upgrade(Entity player, in Crafting old)
    {
        player.SetWorkshop(old.Recipe, old.Progress, Queue: 0);
        player.RemoveCrafting();
    }
}
```

```csharp
try
{
    restarted.Load(output.WrittenSpan);
}
catch (InvalidDataException)
{
    // 存档之后某个组件变了：World 还是调用前的样子
}
```

### 插件里的组件 [#plugins]

按 id 查找类型是进程级的。插件的旧版本和新版本同时加载时，它们的类型 id 相同，读档会因为类型 id 有歧义而拒绝加载。先卸载旧版本（按
[热重载](/zh/docs/guide/migration-and-unload#hot-reload)的顺序：存档、`RemoveTypes`、卸载、加载新版本、`Load`），或者把要存档的组件
放进一个永远不会重载的程序集，比如宿主和插件共用的契约程序集。

## 完整例子 [#full-example]

两个玩家（一个跟着另一个）和一个时钟：World 存进缓冲区，再读进一个新的 World，就像进程重启后那样。把这几个文件放进一个引用了
EasyEcs 的控制台项目（见[声明组件](#declare)），用 `dotnet run` 运行。

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;
using Nino.Core;

// 非托管：按原始行存，每列一块。
public record struct Position(float X, float Y) : IComponent;

// EntityId 读档后仍然有效：读档保留每个 id 和版本。
public record struct Follows(EntityId Leader) : IComponent;

// 托管（含 string）：由 Nino 写入，所以是 partial 的 [NinoType]。
[NinoType]
public partial record struct PlayerName(string Value) : IComponent;

// 单例也会存。
public record struct Clock(long Tick) : ISingletonComponent;
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;
using Nino.Core;

using var world = new World();
world.SetClock(Tick: 1234);
var alice = world.CreateEntity(new PlayerName("alice"), new Position(3, 4));
world.CreateEntity(new PlayerName("bob"), new Position(5, 6), new Follows(alice.Id));

// 实体、组件和单例，写进一个下次存档还能复用的缓冲区。
var output = new NinoArrayBufferWriter();
world.Save(output);

// 另一个 World，就像重启后的进程新建的那样。
using var restarted = new World();
restarted.Load(output.WrittenSpan);

Console.WriteLine($"clock: {restarted.Clock.Tick}");
foreach (var item in restarted.Query<PlayerName, Position>())
{
    Console.WriteLine($"{item.Entity.Id} {item.PlayerName.Value} at ({item.Position.X}, {item.Position.Y})");
}

foreach (var item in restarted.Query<PlayerName, Follows>())
{
    var leader = restarted.GetEntity(item.Follows.Leader);
    Console.WriteLine($"{item.PlayerName.Value} follows {leader.PlayerName.Value}");
}
```

</Accordion>
</Accordions>


输出：

```text
clock: 1234
0v1 alice at (3, 4)
1v1 bob at (5, 6)
bob follows alice
```

新 World 里的 id 和原来一样，托管的名字经由 Nino 读了回来，单例时钟保留了它的 tick，Bob 的 `Follows` 不用任何改写，仍然指向 Alice。

## 怎么用得快 [#how-to-use-it-fast]

| 别这样 | 这样做 | 为什么 |
| --- | --- | --- |
| 每次存档新建缓冲区 | 复用一个 `NinoArrayBufferWriter`，每次存档前 `ResetWrittenCount()` | 缓冲区足够大之后，存档不分配 |
| 用其他 `IBufferWriter<byte>` | 用 `NinoArrayBufferWriter` | 直接写入，省掉从 World 缓冲区的拷贝 |
| 每次读档新建 World | `Load` 进同一个 World | 复用已有的行：预热后不再分配 |
| 能用值的地方用了托管组件 | 非托管组件（id、数字、定长数组） | 原始行每列一个块；Nino 要逐个值编码 |
| 结构从不变化的非托管组件也标 `[NinoType]` | 这些按原始行写，结构会变的才标 `[NinoType]` | 原始行一列只拷贝一次 |
| 自己在 `Query` 上写序列化 | `Save` / `Load` | id、版本号、缓冲、禁用值和单例都一起带上 |
| 为了让 `Save` 能跑，给运行时状态写格式化器 | `SaveWithout(output, in exclude)` | 排除的类型根本不写，也不需要格式化器 |
| `Load` 之后再把新配置设一遍 | `LoadKeeping(input, in keep)` | 保留的单例在存档里直接跳过，不反序列化 |

## 开销 [#what-it-costs]

- **大小：** 非托管组件就是行本身（填充字节清零，所以相同的 World 存出相同的字节），外加存在位、id 和版本号；托管组件和 `[NinoType]` 组件按 Nino 的编码；
  每个类型的 id 只写一次。
- **时间：** 两个方向都是 O(实体数 × 组件数)。
- **分配：** 反复 `Save` 到 `NinoArrayBufferWriter` 不分配，反复 `Load` 进同一个 World 也不分配；读出的托管值是新对象。
- **遍历期间不能调用：** 两者都要进入结构闸门。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 谁能发现 |
| --- | --- | --- |
| 托管组件没有 `[NinoType]` | `Save` 抛 `InvalidOperationException`（没有格式化器） | 运行时；只在运行时有意义的类型用 `SaveWithout(output, in exclude)` 排除 |
| 设好新配置之后用普通的 `Load` | 存档里的单例把它替换掉，存档里没有的单例被删掉 | 用 `LoadKeeping(input, in keep)` 保留配置单例 |
| `Load` 的保留集合里放了组件 | 抛 `ArgumentException` | 改为存档时排除它 |
| 系统要用的单例被排除出存档，之后又没人再设 | 系统第一次运行就抛异常 | 加载前设好并保留，或者加载后再设 |
| 引用的 `Nino.Generator` 比 EasyEcs 用的 Nino 旧 | 包降级：删掉这个引用，EasyEcs 包已经带了生成器 | 还原（`NU1605`） |
| 组件里存了 `Entity` 句柄 | 托管列，Nino 写不了 | [EECS017](/zh/docs/guide/analyzer#eecs017) |
| 修改已存档的原始行组件的字段 | 旧存档被拒绝 | 从第一次存档起用 `[NinoType(format: NinoFormat.VersionTolerant)]`，或加一个新组件类型 |
| 重命名组件或换了命名空间 | 旧存档加载时丢掉它 | 用 `[NinoFormerName]` 标上旧的完整名字 |
| 新旧两个插件版本同时加载 | 名字歧义：`InvalidDataException` | 先卸载旧版本 |
| 在其他线程存档或读档 | 和所有者线程竞争 | [EECS014](/zh/docs/guide/analyzer#eecs014) |
