查询选出拥有一组组件（1 到 9 个）的实体，还可以加过滤：要求有或没有其他组件、一组组件里至少有一个、或者只要某个 tick
之后被写过或被移除的。系统通过 `[ForEach]` 方法使用查询；系统之外的代码（管理请求、测试、两个 tick 之间运行的工具）直接调用。
所有查询 API 都不分配内存。

## 什么时候用 [#when-to-use-it]

<Callout type="idea" title="适合">
  系统之外的遍历：两次更新之间的请求处理、工具、测试、一次性的遍历。单个实体上的 job（[`entity.Run`](#run-on-one-entity)）：
  请求的处理函数、发给 actor 的消息的处理函数。计数和存在性判断（`Count`、`Any`）。批量销毁
  （`DestroyAll<T>(filter)`）。以及过滤条件本身：`[ForEach]` 方法用特性的形式使用同样的过滤。
</Callout>

<Callout type="warn" title="不适合">
  每个 tick 都要跑的逻辑：写成系统里的 [`[ForEach]`](/zh/docs/guide/systems#foreach-methods) 方法。它由生成器生成，和其他系统一起排序、
  按并行阶段调度，速度和最快的手写循环一样。按值查找实体、按指向的实体查找：用[索引](/zh/docs/guide/indexes-and-relations)，不要扫描。
</Callout>

## 怎么用 [#how-to-use-it]

<Steps>
<Step>

### 过滤条件只建一次 [#build-the-filter]

`QueryFilter` 是一个用链式调用构建的值，每个都放进 `static readonly` 字段。

```csharp
public static class Filters
{
    public static readonly QueryFilter Active = QueryFilter.Create().Without<Frozen>().Without<Dead>();
    public static readonly QueryFilter Impaired = QueryFilter.Create().WithAny<Frozen>().WithAny<Stunned>();   // 任一即可
}
```

</Step>
<Step>

### 遍历匹配的实体 [#query]

`world.Query<T1..Tn>(filter)` 就是一个 `foreach` 循环。每个元素交出指向表的 ref（以组件名命名）和实体本身。

```csharp
var world = new World();
world.CreateEntity(new Position(0, 0), new Velocity(1, 0));
world.CreateEntity(new Position(0, 0), new Velocity(0, 1), new Frozen());

foreach (var item in world.Query<Position, Velocity>(Filters.Active))
{
    ref var p = ref item.Position;          // 指向表的 ref
    p.X += item.Velocity.X;
    if (p.X > 100) item.Entity.SetDead();   // 可以做结构变更
}
```

</Step>
<Step>

### 计数与判断 [#count-and-any]

```csharp
int moving = world.Count<Position, Velocity>(Filters.Active);
bool anyImpaired = world.Any<Position>(Filters.Impaired);   // 找到第一个就停
int cleared = world.DestroyAll<Position>(QueryFilter.Create().With<Dead>());
```

</Step>
</Steps>

### 选哪个 API [#which-api]

| 需求 | 用法 |
| --- | --- |
| 系统里逐个实体的逻辑 | [`[ForEach]`](/zh/docs/guide/systems#foreach-methods) 方法 |
| 系统里对大量行做算术 | 批处理 [`[ForEach]`](/zh/docs/guide/systems#batch-methods) 方法（span，SIMD） |
| 系统里每个实体都很重的计算 | [`[ForEach(Parallel = true)]`](/zh/docs/guide/systems#parallel-methods) |
| 实体可能有、也可能没有的组件 | [`Maybe<T>`](/zh/docs/guide/systems#maybe) 参数，或者用 `With` / `Without` 拆成两个方法 |
| 系统之外的遍历，写成方法 | [`[ForEach]`](/zh/docs/guide/systems#foreach-outside-systems) runner：带生成入口的静态方法 |
| 最快的临时循环 | `world.ForEach<T1..Tn, TJob>(ref job, filter)` 加[结构体 job](#foreach-a-struct-job) |
| 需要 `Entity` 的临时循环 | `world.ForEachEntity<T1..Tn, TJob>(ref job, filter)` |
| 对成段的行做临时算术 | `world.ForEachBatch<T1..Tn, TJob>(ref job, filter)` |
| 在单个实体上跑 job（一个请求、一条消息） | [`entity.Run<T1..Tn, TJob>(ref job, filter)`](#run-on-one-entity) |
| 临时的重计算，多线程 | [`ForEachParallel`](#on-several-threads-foreachparallel-and-foreachentityparallel) / [`ForEachEntityParallel`](#on-several-threads-foreachparallel-and-foreachentityparallel) |
| 写起来方便的循环（工具、测试、请求处理） | `foreach (var item in world.Query<T1..Tn>(filter))` |
| 只读的循环（存盘、发包、报表） | [`foreach (var item in world.Read<T1..Tn>(filter))`](#read)：不打 tick |
| “有多少个……？” / “有没有……？” | `world.Count<T1..Tn>(filter)` / `world.Any<T1..Tn>(filter)` |
| 销毁所有匹配的实体 | `world.DestroyAll<T1..Tn>(filter)` |
| 这个 tick 最多处理、销毁或存盘 N 个匹配的实体 | [`world.CollectIds<T1..Tn>(span, filter)`](#collect-ids) |
| 只要某个 tick 之后写过或移除的行 | `Changed<T>(tick)` / `Removed<T>(tick)`；几个组件任意一个时用 `ChangedAny<T1..Tn>(tick)` / `RemovedAny<T1..Tn>(tick)`（[变更追踪](/zh/docs/guide/change-tracking)） |
| 只写值真的变了的行 | `[ForEach]` 方法的 [`Mut<T>`](/zh/docs/guide/change-tracking#set-if-changed) 参数 |
| 每次只处理一部分行，N 次遍历把每行各过一遍 | `ForEach` 系列调用配 `Slice(index, of)`，或 [`[ForEach(Slices = N)]`](/zh/docs/guide/systems#slices) |
| 按值查找，或找指向某实体的实体 | `world.Index<T, TKey>().Find(key)`（[索引](/zh/docs/guide/indexes-and-relations)） |

### 过滤条件 [#filters]

| 过滤 | 选出 | 对应的 `[ForEach]` 特性 |
| --- | --- | --- |
| `With<T>()` | 还拥有 `T` 的实体（`T` 不作为参数传入） | `[With<T>]` |
| `Without<T>()` | 没有 `T` 的实体 | `[Without<T>]` |
| `WithAny<T>()`，可重复 | 至少拥有其中一个 `WithAny` 组件的实体 | `[WithAny<T>]`，可重复 |
| `Changed<T>(since)` | 被追踪的 `T` 在 `since` 及之后被写过的实体 | `[Changed<T>]`（从系统上次运行算起） |
| `Removed<T>(since)` | 在 `since` 及之后失去被追踪的 `T`、且至今没有补回的实体 | `[Removed<T>]` |
| `ChangedAny<T1..Tn>(since)` | 自己拥有的被追踪组件中，至少一个在 `since` 及之后被写过的实体 | `[ChangedAny<T1, …, Tn>]` |
| `RemovedAny<T1..Tn>(since)` | 在 `since` 及之后至少失去其中一个被追踪组件、且至今没有补回的实体 | `[RemovedAny<T1, …, Tn>]` |
| `InGroup<T>(group)` | `T` 属于某一个[分组](/zh/docs/guide/groups)的实体 | 无；`IGroup` 组件 `Team` 会生成 `filter.InTeam(group)` |
| `Slice(index, of)` | 每张匹配表的行切成 `of` 片，只取第 `index` 片，按 64 行的字切；只对 `ForEach`、`ForEachEntity`、`ForEachBatch` 及其 `Parallel` 版本有效 | `[ForEach(Slices = N)]`（[分片](/zh/docs/guide/systems#slices)） |
| `Since(tick)` | 同一个过滤条件，把其中的 `Changed`、`Removed`、`ChangedAny`、`RemovedAny` 换到另一个 tick | |

所有过滤都可以重复、可以组合。一个过滤条件里的 `ChangedAny` 并成一个集合，集合里任意一个组件满足就算通过（`RemovedAny`
另成一个）；这些集合再和其他条件取“与”。一个过滤条件只有一个 tick：其中的 `Changed`、`Removed`、`ChangedAny` 和
`RemovedAny` 必须用同一个（否则抛 `ArgumentException`），`Since(tick)` 会同时移动它们，所以放在字段里的过滤条件每次更新后
都能接着用，也能[给每个客户端](/zh/docs/guide/change-tracking#per-client)各用一次它确认到的 tick：

```csharp
public record struct Armor(int Value) : IComponent, ITracked;

public static class Replication
{
    public static readonly QueryFilter Dirty = QueryFilter.Create().Changed<Armor>(0);
}
```

```csharp
ulong mark = world.ChangeTick;
world.Update();
int dirty = world.Count<Armor>(Replication.Dirty.Since(mark));
```

`Slice(index, of)` 让一次遍历只处理每张表的一部分：index 从 0 到 `count - 1` 轮流跑一遍，每一行正好过一次。只有
`ForEach` 系列认它；`Query`、`Read`、`Count`、`Any`、`DestroyAll`、`entity.Run` 和批量调用（`SetAll`、`RemoveAll` 等）需要
所有匹配的行，遇到分片过滤条件会抛 `ArgumentException`。在系统里，[`[ForEach(Slices = N)]`](/zh/docs/guide/systems#slices)
会替你选好这一次的分片。

### `Query`：foreach 循环 [#query-loop]

枚举器和它的元素都是 ref struct，持有指向当前表的 ref，因此：

- 查询循环里不能 `await`，元素也不能保存下来：要保存就存 `item.Entity`；
- `item.Position`（以组件命名）和 `item.Component1` 是同一个 ref；代码里调用过的每种 `Query<...>` 形状都会生成命名成员；
- 元素交出的每个被追踪（`ITracked`）组件都算一次写入，不管循环有没有真的赋值。只读不打 tick（存盘、发包）时，改用
  [`Read`](#read) 遍历，或者用 `WriteMask => 0` 的结构体 job、带 `in` 参数的 `[ForEach]` 方法、`entity.Read<T>()`
  （见[哪些算写入](/zh/docs/guide/change-tracking#what-counts-as-a-write)）。

循环里可以创建、销毁、添加、移除，规则见[结构变更](/zh/docs/guide/structural-changes)。

### `Read`：只读的循环 [#read]

`world.Read<T1..Tn>(filter)` 遍历的行和 `Query` 一样，但元素给出的是 `ref readonly`，不打 tick。之后运行的 `[Changed<T>]`
读取方不会因为报表或发包读过这些行，就把它们当成写过。这和实体上的一对 API 一致：`entity.Get<T>()` 算写入，`entity.Read<T>()` 不算。

```csharp
int total = 0;
foreach (var item in world.Read<Armor>()) total += item.Armor.Value;   // ref readonly：不打 tick
```

每种 `Read<...>` 形状同样会生成命名成员（`item.Armor`），规则也一样：ref struct，不能 `await`，可以做结构变更。
元素不能写入，所以要写的循环仍然用 `Query`。

### `ForEach`：结构体 job [#foreach-a-struct-job]

实现 `IForEach<T1..Tn>` 的结构体会被 JIT 按类型特化并内联：没有委托，没有闭包，不分配内存。`[ForEach]` 方法编译出来的就是它。

```csharp
public struct Integrate : IForEach<Position, Velocity>, INoStructuralChanges
{
    public static int WriteMask => 1;          // Position（第 1 个组件）；Velocity 只读

    public void Execute(ref Position p, ref Velocity v)
    {
        p.X += v.X;
        p.Y += v.Y;
    }
}
```

```csharp
var integrate = new Integrate();
world.ForEach<Position, Velocity, Integrate>(ref integrate, Filters.Active);
```

job 按 `ref` 传入，它在字段里累加的东西（总和、计数）调用结束后就能读到。它只接收组件，遍历时不会加载实体行。需要持有
`ref` 或 `Span` 的 job 可以写成 `ref struct`，`*Parallel` 系列调用除外。

#### job 要声明什么：`WriteMask` [#what-a-job-declares-writes]

job 的参数全是 `ref`，所以用一个可选的 `static int WriteMask` 说明它真正写哪些组件：第 k 个组件对应第 k - 1 位，默认 -1（全部）。
只有这些组件算作[变更追踪](/zh/docs/guide/change-tracking)里的写入；job 改变了当前实体的原型时，也只有这些组件会被带到新行。
`INoStructuralChanges` 承诺 `Execute` 不创建、不销毁、不添加、不移除：遍历就会跳过保证结构变更安全的那套簿记，并冻结结构，
真做了变更会直接抛异常，而不是把行写坏。生成的 `[ForEach]` job 会根据方法自动设置这两项。

#### 带实体，或按段处理 [#entity-and-batch-jobs]

- `IForEachEntity<T1..Tn>` 配 `world.ForEachEntity`，额外拿到 `Entity`，直接从表的实体行构造，不需要查找。
- `IForEachBatch<T1..Tn>` 配 `world.ForEachBatch`，以 span 的形式拿到成段的连续行：`Execute(EntitySpan entities, Span<T1> …)`，
  方便用 `Vector<T>` 做向量化（JIT 不会自己把循环向量化）。`entities[i]` 只在取下标时才构造。span 直接指向表，所以 job 运行期间做结构变更会抛异常。

```csharp
using System.Numerics;
using System.Runtime.InteropServices;

public struct KillTheWounded : IForEachEntity<Health>
{
    public static int WriteMask => 0;          // 只读 Health；变更是结构性的（一个标签）

    public void Execute(Entity unit, ref Health hp)
    {
        if (hp.Value <= 0) unit.SetDead();
    }
}

public struct Drift : IForEachBatch<Position, Velocity>
{
    public static int WriteMask => 1;

    public void Execute(EntitySpan entities, Span<Position> positions, Span<Velocity> velocities)
    {
        // 每个组件两个 float：转成 Vector<float> 的 span 后，每条 lane 就是一个坐标
        var p = MemoryMarshal.Cast<Position, Vector<float>>(positions);
        var v = MemoryMarshal.Cast<Velocity, Vector<float>>(velocities);
        for (int i = 0; i < p.Length; i++) p[i] += v[i];
        var pf = MemoryMarshal.Cast<Position, float>(positions);
        var vf = MemoryMarshal.Cast<Velocity, float>(velocities);
        for (int i = p.Length * Vector<float>.Count; i < pf.Length; i++) pf[i] += vf[i];   // 剩下的行
    }
}
```

```csharp
var kill = new KillTheWounded();
world.ForEachEntity<Health, KillTheWounded>(ref kill, QueryFilter.Create().Without<Dead>());
var drift = new Drift();
world.ForEachBatch<Position, Velocity, Drift>(ref drift, Filters.Active);
```

### 单个实体：`[ForEntity]` 和 `entity.Run` [#run-on-one-entity]

标了 `[ForEntity]` 的静态方法在单个实体上运行：生成器写出 job，并在方法旁边写一个入口，接收实体和方法的其他值，返回方法有没有运行。
`ref` 组件算作写入并打 tick，`in` 组件只读，过滤特性（`[Without<Dead>]`）像遍历的过滤条件跳过行那样拒绝实体；带 `[Changed<T>]`
的方法，入口的第二个参数是往回看的起始 tick。方法保持 private：入口用的是它的名字。

```csharp
public static class Requests
{
    [ForEntity, Without<Dead>]
    static void TakeHit(Entity unit, ref Health hp, int damage)
    {
        if (hp.Value <= damage) unit.SetDead();   // 结构变更：hp 仍然指向这个实体的值
        hp.Value -= damage;                       // 方法返回时带到它的新行
    }
}
```

```csharp
bool applied = Requests.TakeHit(unit, 30);   // false：已死亡、没有 Health，或不存活
```

入口就是用生成的 job 调 `entity.Run`：下面说的对两者都成立。

一次只处理一个实体的代码，用 `entity.Run<T1..Tn, TJob>(ref job, filter)` 在这个实体上跑 job：一个请求、发给 actor 的一条消息、
客户端的一个命令。这个 job 是 `IForEachEntity` job，和遍历整个 World 用的是同一种类型，拿到的 ref 也和遍历时一样：所有组件只查一次表，
不用每个 `Get` 查一次。实体缺少某个组件、不满足过滤条件或已经不存活时，它返回 `false`，不执行 job。

```csharp
public static class Hits
{
    // 只建一次：过滤条件是值，放在字段里。
    public static readonly QueryFilter Alive = QueryFilter.Create().Without<Dead>();
}

public struct TakeHit : IForEachEntity<Health>
{
    public int Damage;
    public static int WriteMask => 1;

    public void Execute(Entity unit, ref Health hp)
    {
        if (hp.Value <= Damage) unit.SetDead();   // 结构变更：hp 仍然指向这个实体的值
        hp.Value -= Damage;                       // job 返回时搬到实体的新行
    }
}
```

```csharp
var hit = new TakeHit { Damage = 30 };
bool applied = unit.Run<Health, TakeHit>(ref hit, Hits.Alive);   // false：已死亡、没有 Health，或已不存活
```

不带过滤条件的 `entity.Run<T1..Tn, TJob>(ref job)` 只检查实体是否存活、是否有这些组件。只读的 job 声明 `WriteMask => 0`：

```csharp
public struct ReadHealth : IForEachEntity<Health>
{
    public int Value;
    public static int WriteMask => 0;          // 只读：不算写入任何组件

    public void Execute(Entity unit, ref Health hp) => Value = hp.Value;
}
```

```csharp
var read = new ReadHealth();
if (unit.Run<Health, ReadHealth>(ref read)) Console.WriteLine(read.Value);
```

- **job 自己做结构变更后，ref 依然有效**，和 `ForEachEntity` 一样：`Execute` 结束后，`WriteMask` 里的组件会复制到实体的新行；
  抛异常时也照样复制，异常之前写进去的值不会丢。
- **只有 `WriteMask` 里的组件算写入**，参与[变更追踪](/zh/docs/guide/change-tracking)，而且只在 `Run` 返回 `true` 时才算。
  默认的 `WriteMask => -1` 会给 job 拿到的每个组件打 tick；什么都不写的 job 声明 `WriteMask => 0`。
- **`false` 不等于“死了”**：缺组件、过滤条件不满足也返回 `false`。需要区分原因时，再查 `entity.IsAlive`。
- **`INoStructuralChanges`** 省掉这些簿记，job 运行期间冻结结构，和遍历一样：硬要做结构变更会抛 `InvalidOperationException`。
- **O(1)，过滤条件里每提到一个组件再加 O(1)**；过滤条件提到前 256 个之后的类型时例外，这时要走查询缓存。过滤条件像查询一样检查这一行
  （`Without`、`WithAny`、`Changed<T>(tick)`、分组），不用去查询缓存里找表；过滤条件建一次，放在 `static readonly` 字段里。
- **在分析器眼里，`Run` 是结构变更**（它的 job 可能改结构），结构变更不允许的地方它也不允许：并行 `[ForEach]` 方法里
  （[EECS010](/zh/docs/guide/analyzer#eecs010)）、不接收 `Entity` 或 `World` 的 `[ForEach]` 方法里
  （[EECS013](/zh/docs/guide/analyzer#eecs013)）、World 的所有者线程之外（[EECS014](/zh/docs/guide/analyzer#eecs014)）。

最典型的用法是 actor：每个消息处理函数通过[值索引](/zh/docs/guide/indexes-and-relations)找到 actor 的实体，在它身上跑一个 job。
[Actors 示例](https://github.com/JasonXuDeveloper/EasyEcs/tree/master/samples/Actors)就是这样写成的完整程序。

在 10,000 个实体上调用 1,000 次，每次换一个实体，带 1、3 或 5 个组件，有没有 `Without<Dead>` 过滤、中途有没有结构变更，

### 多线程：`ForEachParallel` 和 `ForEachEntityParallel` [#on-several-threads-foreachparallel-and-foreachentityparallel]

实现了 `INoStructuralChanges`、只写自己那一行的 job 可以在多个线程上跑。`ForEachParallel`（`IForEach` job）和
`ForEachEntityParallel`（`IForEachEntity` job）把匹配的行切成块（默认每个线程大约四块，块大小是 64 行的倍数，介于 1,024 和
`World.ParallelChunkRows` = 16,384 之间；job 的 `WriteMask` 里有被追踪组件时，块大小是 4,096 行的倍数、至少 4,096 行，这样不会
有两块共用同一个 4,096 行块的变更 tick 摘要）。调用线程加上最多 `WorldOptions.MaxDegreeOfParallelism - 1` 个线程池线程做完一块就领下一块，
和 OpenMP 的 `schedule(dynamic, n)` 一样。每块跑在 job 的一份副本上，字段里累加的状态不会合并回来。不足两块时，直接在调用线程上跑。`ForEachBatchParallel`（`IForEachBatch` job）切出同样的块，把每块里连续的行段以 span 交给 job，和单线程的 `ForEachBatch` 一样：并行[归约](/zh/docs/guide/threading#reductions)就以这种形式运行，一段行的部分结果是局部变量。

```csharp
public struct Heal : IForEach<Health>, INoStructuralChanges
{
    public static int WriteMask => 1;

    public void Execute(ref Health health) => health.Value = Math.Min(health.Value + 10, 100);
}
```

```csharp
var heal = new Heal();
world.ForEachParallel<Health, Heal>(ref heal, Filters.Active);   // 每一行只跑一次，在某一个线程上
```

最后一个参数 `chunkRows` 指定一个线程每次领多少行（`schedule(dynamic, n)` 里的 `n`，向上取整到 64；默认 0，按行数决定）：
适合只有几百行、每行几微秒的活，默认会把它们留在一块里。`[ForEach(Parallel = true, ChunkRows = n)]` 传的就是它
（[块大小](/zh/docs/guide/threading#chunk-rows)）。

```csharp
public record struct Plan(int Cost) : IComponent;

public struct Replan : IForEach<Plan>, INoStructuralChanges
{
    public static int WriteMask => 1;

    public void Execute(ref Plan plan)
    {
        int cost = plan.Cost;
        for (int i = 0; i < 10_000; i++) cost = (cost * 31 + i) % 1_000_003;   // 每行几微秒
        plan = new Plan(cost);
    }
}
```

```csharp
var replan = new Replan();
world.ForEachParallel<Plan, Replan>(ref replan, chunkRows: 64);
```

job 不能读别的行的 job 会写的东西（别的实体、单例组件），调用期间也不能有其他代码修改 World。
[`[ForEach(Parallel = true)]`](/zh/docs/guide/systems#parallel-methods) 会把系统方法编译成同样的分块执行。

### `Count` 和 `Any` [#count]

`Count` 把匹配表的行数加起来，只有在某些行缺少被查询组件的表里才去数存在位。`Any` 找到第一个匹配就停。两者都不碰组件的值。


### 有上限的一批 id：`CollectIds` [#collect-ids]

`world.CollectIds<T1..Tn>(into, filter)` 按 `Query` 和 `Read` 的遍历顺序，把匹配实体的 id 写进一个 span，写满为止，返回写了多少个。
它就是处理请求的系统里“这个 tick 最多取 N 个”：之后把这些 id 交给 `DestroyEntities`、`SaveEntities`，或者交给一个会改结构的循环，
这些都不能在查询循环进行中做。

```csharp
public class BuryTheFallen : EcsSystem
{
    static readonly QueryFilter Fallen = QueryFilter.Create().With<Dead>();

    protected override void OnUpdate()
    {
        Span<EntityId> batch = stackalloc EntityId[64];
        int count = World.CollectIds<Health>(batch, Fallen);   // 按查询顺序取前 64 个 // [!code highlight]
        World.DestroyEntities(batch[..count]);                 // 其余的等下一个 tick
    }
}
```

- **零分配。** O(匹配的表)，加上写满之前读过的行；所有行都匹配的表是一次 id 拷贝。
- **它不记得停在哪里。** 下一次调用又从第一个匹配开始，所以在下一次调用之前先处理掉它返回的（销毁、打标签、存盘）。
- **用过滤条件，不用分支。** 两个系统共用一种请求时，用标签拆开（`With<Saved>` / `Without<Saved>`），而不是在批里用判断跳过某些行：
  `VoxelServer` 就是这样处理加载请求的（[区块的一生](/zh/docs/samples/voxel-server#chunks)）。

## 完整例子 [#full-example]

系统里用过滤条件，系统外用查询、计数和 struct job。三个单位在移动，其中一个被冻住，第四个没有速度。把这几个文件放进一个
引用了 EasyEcs 的控制台项目（`dotnet add package EasyEcs`），用 `dotnet run` 运行。

<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;

public record struct Position(float X, float Y) : IComponent;

public record struct Velocity(float X, float Y) : IComponent;

// 两个状态，都是标签。冻住的单位不移动；冻住或着火的单位会减速。
public struct Frozen : IComponent;

public struct Burning : IComponent;
```

</Accordion>
<Accordion title="Systems.cs">

```csharp title="Systems.cs" doccheck=example
using EasyEcs;

// 冻住、着火或两者都有的单位，速度减半。
public class SlowSystem : EcsSystem
{
    [ForEach, WithAny<Frozen>, WithAny<Burning>]
    static void Slow(ref Velocity velocity)
    {
        velocity = new Velocity(velocity.X / 2, velocity.Y / 2);
    }
}

// 移动所有没被冻住的单位。
[UpdateAfter<SlowSystem>]
public class MoveSystem : EcsSystem
{
    [ForEach, Without<Frozen>]
    static void Move(ref Position position, in Velocity velocity)
    {
        position = new Position(position.X + velocity.X, position.Y + velocity.Y);
    }
}
```

</Accordion>
<Accordion title="Queries.cs">

```csharp title="Queries.cs" doccheck=example
using EasyEcs;

// 过滤条件是一个值：只构建一次，存在 static readonly 字段里。
public static class Filters
{
    public static readonly QueryFilter Moving = QueryFilter.Create().Without<Frozen>();
}

// struct job：系统外最快的遍历方式，没有委托。
public struct SumX : IForEach<Position>
{
    public float Sum;

    public void Execute(ref Position position)
    {
        Sum += position.X;
    }
}
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;

using var world = new World();
world.AddSystem<SlowSystem>();
world.AddSystem<MoveSystem>();

world.CreateEntity(new Position(0, 0), new Velocity(1, 0));
world.CreateEntity(new Position(0, 0), new Velocity(0, 1), new Frozen());
world.CreateEntity(new Position(0, 0), new Velocity(2, 2), new Burning());
world.CreateEntity(new Position(9, 9));

world.Update();

// 系统外：遍历匹配的实体。每个 item 给出指向表里数据的 ref。
foreach (var item in world.Query<Position, Velocity>(Filters.Moving))
{
    Console.WriteLine($"{item.Entity}: {item.Position}");
}

// 计数和判断存在，不读任何组件的值。
int moving = world.Count<Position, Velocity>(Filters.Moving);
bool anyFrozen = world.Any<Frozen>();
Console.WriteLine($"moving: {moving}, any frozen: {anyFrozen}");

// 对所有 Position 跑一遍 struct job，没有速度的单位也算在内。
var sumX = new SumX();
world.ForEach<Position, SumX>(ref sumX);
Console.WriteLine($"sum of X: {sumX.Sum}");
```

## 怎么用得快 [#how-to-use-it-fast]

| 别这样 | 这样做 | 原因 |
| --- | --- | --- |
| 每个 tick 跑一个 `Query` 循环 | 系统里的 `[ForEach]` 方法 | 生成的结构体 job，参与排序和调度 |
| 每次调用都 `QueryFilter.Create()…` | `static readonly` 过滤条件 | 缓存键只建一次 |
| 只读被追踪组件的 `Query` | [`Read<T1..Tn>`](#read)、`WriteMask => 0` 的 job，或 `in` 参数 | `Query` 的元素会给交出的行打 tick |
| 很少用到实体却用 `ForEachEntity` | 带 `EntitySpan` 的批处理 job | 只给需要的行构造句柄 |
| 对大量行写标量循环 | 用 `Vector<T>` 的批处理 job | JIT 不会自己向量化 |
| `Count(...) > 0` | `Any(...)` | 找到第一个就停（[EECS032](/zh/docs/guide/analyzer#eecs032)） |
| 每个请求几次 `Get` / `TryGetRef` 再加一次 `Has<Dead>()` | 用 `static readonly` 过滤条件调 [`entity.Run`](#run-on-one-entity) | 只查一次；ref 跨结构变更依然有效 |
| 扫描查找某个键 | [值索引](/zh/docs/guide/indexes-and-relations) | O(匹配数)，而不是 O(行数) |

## 开销 [#what-it-costs]

- **某个查询形状**（组件加过滤条件）**第一次使用时**会把所有表过一遍，建好缓存项。之后新建的表会自动加入它匹配的缓存项。
- **之后每次调用**通过一个按签名的小缓存找到缓存项，超出时做一次哈希查找，然后遍历 O(匹配表数 + 行数)。
- **带过滤的行**按存在位每次测 64 行；全部通过的字每次 SIMD 比较跨过四个，没有匹配的字直接跳过。
- **`Count`** 是 O(匹配表数)，行状态不一致的表再加上每个字一次 popcount。
- **不分配内存**：过滤条件是不含对象引用的值，枚举器和元素是 ref struct，job 是结构体。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 谁能发现 |
| --- | --- | --- |
| `Query` 循环里 `await` | 编译不过：元素是 ref struct | C# 编译器 |
| 把查询元素存下来 | 编译不过；改存 `item.Entity` | C# 编译器 |
| 只读被追踪组件的 `Query` 循环 | 访问过的每一行都算已写入 | 改用 [`Read<T1..Tn>`](#read) 遍历 |
| 会改结构的 job 却实现了 `INoStructuralChanges` | 变更处抛 `InvalidOperationException` | 运行时 |
| 批处理 job 里做结构变更 | 抛 `InvalidOperationException`：span 指向表 | 运行时（`[ForEach]` 方法由 [EECS013](/zh/docs/guide/analyzer#eecs013) 检查） |
| 并行 job 写单例组件或别的实体 | 块之间发生竞争 | 代码审查（`[ForEach]` 方法由 [EECS010](/zh/docs/guide/analyzer#eecs010) 检查） |
| 一个过滤条件里 `Changed`、`Removed`、`ChangedAny` 或 `RemovedAny` 用了不同的 tick | 抛 `ArgumentException` | 运行时 |
| 把分片过滤条件（`Slice`）传给 `Query`、`Read`、`Count`、`Any`、`DestroyAll`、`entity.Run` 或批量调用 | 抛 `ArgumentException`：这些调用需要所有匹配的行 | [EECS044](/zh/docs/guide/analyzer#eecs044) |
| 在同一个 World 的查询循环里调用 `Update()` | 循环还在走表，所有系统就跑了一遍；更新还在循环底下填掉它的空洞：还没走到的行挪到了它身后，被漏掉 | [EECS051](/zh/docs/guide/analyzer#eecs051)；在系统里调用时由 [EECS034](/zh/docs/guide/analyzer#eecs034) 检查 |
| `entity.Run` 的 job 没声明 `WriteMask` | 默认值 -1 会给 job 拿到的每个被追踪组件打 tick | 声明 `WriteMask`（只读的 job 写 `0`） |
| 会改结构的 `Run` job 却实现了 `INoStructuralChanges` | 变更处抛 `InvalidOperationException` | 运行时 |
| 把 `Run` 返回 `false` 当成“死了” | 缺组件、过滤条件不满足也返回 `false` | 代码审查：查 `IsAlive` |
| 每次调 `Run` 或查询都现建 `QueryFilter.Create()…` | 每次都重建过滤条件、重新查找 | 代码审查：放进 `static readonly` 字段 |
| 在并行 `[ForEach]` 方法里调 `entity.Run` | 它的 job 可能在多个线程上改结构 | [EECS010](/zh/docs/guide/analyzer#eecs010) |
