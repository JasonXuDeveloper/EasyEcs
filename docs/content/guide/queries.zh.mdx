查询选出拥有一组组件（1 到 9 个）的实体，还可以加过滤：要求有或没有其他组件、一组组件里至少有一个、或者只要某个 tick
之后被写过或被移除的。系统通过 `[ForEach]` 方法使用查询；系统之外的代码（管理请求、测试、两个 tick 之间运行的工具）直接调用。
所有查询 API 都不分配内存。

## 什么时候用 [#when-to-use-it]

<Callout type="idea" title="适合">
  系统之外的遍历：两次更新之间的请求处理、工具、测试、一次性的遍历。计数和存在性判断（`Count`、`Any`）。批量销毁
  （`DestroyEntities<T>(filter)`）。以及过滤器本身：`[ForEach]` 方法用特性的形式使用同样的过滤。
</Callout>

<Callout type="warn" title="不适合">
  每个 tick 都要跑的逻辑：写成系统里的 [`[ForEach]` 方法](/zh/docs/guide/systems#foreach-methods)。它由生成器生成，和其他系统一起排序、
  按并行阶段调度，速度和最快的手写循环一样。按值查找实体、按指向的实体查找：用[索引](/zh/docs/guide/indexes-and-relations)，不要扫描。
</Callout>

## 怎么用 [#how-to-use-it]

<Steps>
<Step>

### 过滤器只建一次 [#build-the-filter]

`QueryFilter` 是一个用链式调用构建的值，每个都放进 `static readonly` 字段。

```csharp
public static class Filters
{
    public static readonly QueryFilter Active = QueryFilter.Create().Without<Frozen>().Without<Dead>();
    public static readonly QueryFilter Impaired = QueryFilter.Create().WithAny<Frozen>().WithAny<Stunned>();   // 任一即可
}
```

</Step>
<Step>

### 遍历匹配的实体 [#query]

`world.Query<T1..Tn>(filter)` 就是一个 `foreach` 循环。每个元素交出指向表的 ref（以组件名命名）和实体本身。

```csharp
var world = new World();
world.CreateEntity(new Position(0, 0), new Velocity(1, 0));
world.CreateEntity(new Position(0, 0), new Velocity(0, 1), new Frozen());

foreach (var item in world.Query<Position, Velocity>(Filters.Active))
{
    ref var p = ref item.Position;          // 指向表的 ref
    p.X += item.Velocity.X;
    if (p.X > 100) item.Entity.SetDead();   // 可以做结构变更
}
```

</Step>
<Step>

### 计数与判断 [#count-and-any]

```csharp
int moving = world.Count<Position, Velocity>(Filters.Active);
bool anyImpaired = world.Any<Position>(Filters.Impaired);   // 找到第一个就停
int cleared = world.DestroyEntities<Position>(QueryFilter.Create().With<Dead>());
```

</Step>
</Steps>

### 选哪个 API [#which-api]

| 需求 | 用法 |
| --- | --- |
| 系统里逐个实体的逻辑 | [`[ForEach]` 方法](/zh/docs/guide/systems#foreach-methods) |
| 系统里对大量行做算术 | [批处理 `[ForEach]` 方法](/zh/docs/guide/systems#batch-methods)（span，SIMD） |
| 系统里每个实体都很重的计算 | [`[ForEach(Parallel = true)]`](/zh/docs/guide/systems#parallel-methods) |
| 实体可能有、也可能没有的组件 | [`Maybe<T>` 参数](/zh/docs/guide/systems#maybe)，或者用 `With` / `Without` 拆成两个方法 |
| 系统之外的遍历，写成方法 | [`[ForEach]` runner](/zh/docs/guide/systems#foreach-outside-systems)：带生成入口的静态方法 |
| 最快的临时循环 | `world.ForEach<T1..Tn, TJob>(ref job, filter)` 加[结构体 job](#foreach-a-struct-job) |
| 需要 `Entity` 的临时循环 | `world.ForEachEntity<T1..Tn, TJob>(ref job, filter)` |
| 对成段的行做临时算术 | `world.ForEachBatch<T1..Tn, TJob>(ref job, filter)` |
| 临时的重计算，多线程 | [`ForEachParallel` / `ForEachEntityParallel`](#on-several-threads-foreachparallel-and-foreachentityparallel) |
| 写起来方便的循环（工具、测试、请求处理） | `foreach (var item in world.Query<T1..Tn>(filter))` |
| "有多少个……？" / "有没有……？" | `world.Count<T1..Tn>(filter)` / `world.Any<T1..Tn>(filter)` |
| 销毁所有匹配的实体 | `world.DestroyEntities<T1..Tn>(filter)` |
| 只要某个 tick 之后写过或移除的行 | `Changed<T>(tick)` / `Removed<T>(tick)`（[变更追踪](/zh/docs/guide/change-tracking)） |
| 按值查找，或找指向某实体的实体 | `world.Index<T, TKey>().Find(key)`（[索引](/zh/docs/guide/indexes-and-relations)） |

### 过滤器 [#filters]

| 过滤 | 选出 | 对应的 `[ForEach]` 特性 |
| --- | --- | --- |
| `With<T>()` | 还拥有 `T` 的实体（`T` 不作为参数传入） | `[With<T>]` |
| `Without<T>()` | 没有 `T` 的实体 | `[Without<T>]` |
| `WithAny<T>()`，可重复 | 至少拥有其中一个 `WithAny` 组件的实体 | `[WithAny<T>]`，可重复 |
| `Changed<T>(since)` | 被追踪的 `T` 在 `since` 及之后被写过的实体 | `[Changed<T>]`（从系统上次运行算起） |
| `Removed<T>(since)` | 在 `since` 及之后失去被追踪的 `T`、且至今没有补回的实体 | `[Removed<T>]` |
| `InGroup<T>(group)` | `T` 属于某一个[分组](/zh/docs/guide/groups)的实体 | 无；`IGroup` 组件 `Team` 会生成 `filter.InTeam(group)` |
| `Since(tick)` | 同一个过滤器，把其中的 `Changed`、`Removed` 换到另一个 tick | |

所有过滤都可以重复、可以组合。一个过滤器只有一个 tick：其中的 `Changed` 和 `Removed` 必须用同一个（否则抛
`ArgumentException`），`Since(tick)` 会同时移动它们，所以放在字段里的过滤器每次更新后都能接着用：

```csharp
public record struct Armor(int Value) : IComponent, ITrackChanges;

public static class Replication
{
    public static readonly QueryFilter Dirty = QueryFilter.Create().Changed<Armor>(0);
}
```

```csharp
ulong mark = world.ChangeTick;
world.Update();
int dirty = world.Count<Armor>(Replication.Dirty.Since(mark));
```

### `Query`：foreach 循环 [#query-loop]

枚举器和它的元素都是 ref struct，持有指向当前表的 ref，因此：

- 查询循环里不能 `await`，元素也不能保存下来：要保存就存 `item.Entity`；
- `item.Position`（以组件命名）和 `item.Component1` 是同一个 ref；代码里调用过的每种 `Query<...>` 形状都会生成命名成员；
- 元素交出的每个被追踪（`ITrackChanges`）组件都算一次写入，不管循环有没有真的赋值。只读不标记（存盘、发包）时，用
  `Writes => 0` 的结构体 job、带 `in` 参数的 `[ForEach]` 方法，或者 `entity.Read<T>()`
  （见[哪些算写入](/zh/docs/guide/change-tracking#what-counts-as-a-write)）。

循环里可以创建、销毁、添加、移除，规则见[结构变更](/zh/docs/guide/structural-changes)。

### `ForEach`：结构体 job [#foreach-a-struct-job]

实现 `IForEach<T1..Tn>` 的结构体会被 JIT 按类型特化并内联：没有委托，没有闭包，不分配内存。`[ForEach]` 方法编译出来的就是它。

```csharp
public struct Integrate : IForEach<Position, Velocity>, INoStructuralChanges
{
    public static int Writes => 1;          // Position（第 1 个组件）；Velocity 只读

    public void Execute(ref Position p, ref Velocity v)
    {
        p.X += v.X;
        p.Y += v.Y;
    }
}
```

```csharp
var integrate = new Integrate();
world.ForEach<Position, Velocity, Integrate>(ref integrate, Filters.Active);
```

job 按 `ref` 传入，它在字段里累加的东西（总和、计数）调用结束后就能读到。它只接收组件，遍历时不会加载实体行。需要持有
`ref` 或 `Span` 的 job 可以写成 `ref struct`，`*Parallel` 系列调用除外。

#### job 要声明什么：`Writes` [#what-a-job-declares-writes]

job 的参数全是 `ref`，所以用一个可选的 `static int Writes` 说明它真正写哪些组件：第 k 个组件对应第 k - 1 位，默认 -1（全部）。
只有这些组件算作[变更追踪](/zh/docs/guide/change-tracking)里的写入；job 改变了当前实体的原型时，也只有这些组件会被带到新行。
`INoStructuralChanges` 承诺 `Execute` 不创建、不销毁、不添加、不移除：遍历就会跳过保证结构变更安全的那套簿记，并冻结结构，
真做了变更会直接抛异常，而不是把行写坏。生成的 `[ForEach]` job 会根据方法自动设置这两项。

#### 带实体，或按段处理 [#entity-and-batch-jobs]

- `IForEachEntity<T1..Tn>` 配 `world.ForEachEntity`，额外拿到 `Entity`，直接从表的实体行构造，不需要查找。
- `IForEachBatch<T1..Tn>` 配 `world.ForEachBatch`，以 span 的形式拿到成段的连续行：`Execute(EntitySpan entities, Span<T1> …)`，
  方便用 `Vector<T>` 做向量化（JIT 不会自己把循环向量化）。`entities[i]` 只在取下标时才构造。span 直接指向表，所以 job 运行期间做结构变更会抛异常。

```csharp
using System.Numerics;
using System.Runtime.InteropServices;

public struct KillTheWounded : IForEachEntity<Health>
{
    public static int Writes => 0;          // 只读 Health；变更是结构性的（一个标签）

    public void Execute(Entity unit, ref Health hp)
    {
        if (hp.Value <= 0) unit.SetDead();
    }
}

public struct Drift : IForEachBatch<Position, Velocity>
{
    public static int Writes => 1;

    public void Execute(EntitySpan entities, Span<Position> positions, Span<Velocity> velocities)
    {
        // 每个组件两个 float：转成 Vector<float> 的 span 后，每条 lane 就是一个坐标
        var p = MemoryMarshal.Cast<Position, Vector<float>>(positions);
        var v = MemoryMarshal.Cast<Velocity, Vector<float>>(velocities);
        for (int i = 0; i < p.Length; i++) p[i] += v[i];
        var pf = MemoryMarshal.Cast<Position, float>(positions);
        var vf = MemoryMarshal.Cast<Velocity, float>(velocities);
        for (int i = p.Length * Vector<float>.Count; i < pf.Length; i++) pf[i] += vf[i];   // 剩下的行
    }
}
```

```csharp
var kill = new KillTheWounded();
world.ForEachEntity<Health, KillTheWounded>(ref kill, QueryFilter.Create().Without<Dead>());
var drift = new Drift();
world.ForEachBatch<Position, Velocity, Drift>(ref drift, Filters.Active);
```

### 多线程：`ForEachParallel` 和 `ForEachEntityParallel` [#on-several-threads-foreachparallel-and-foreachentityparallel]

实现了 `INoStructuralChanges`、只写自己那一行的 job 可以在多个线程上跑。`ForEachParallel`（`IForEach` job）和
`ForEachEntityParallel`（`IForEachEntity` job）把匹配的行切成块（每个线程大约四块，块大小是 64 行的倍数，介于 1,024 和
`World.ParallelChunkRows` = 16,384 之间），由调用线程加上最多 `WorldOptions.MaxDegreeOfParallelism - 1` 个线程池线程执行。
每个线程拿到 job 的一份副本，字段里累加的状态不会合并回来。不足两块时，直接在调用线程上跑。

```csharp
public struct Heal : IForEach<Health>, INoStructuralChanges
{
    public static int Writes => 1;

    public void Execute(ref Health health) => health.Value = Math.Min(health.Value + 10, 100);
}
```

```csharp
var heal = new Heal();
world.ForEachParallel<Health, Heal>(ref heal, Filters.Active);   // 每一行只跑一次，在某一个线程上
```

job 不能读别的行的 job 会写的东西（别的实体、单例组件），调用期间也不能有其他代码修改 World。
[`[ForEach(Parallel = true)]`](/zh/docs/guide/systems#parallel-methods) 会把系统方法编译成同样的分块执行。

### `Count` 和 `Any` [#count]

`Count` 把匹配表的行数加起来，只有在某些行缺少被查询组件的表里才去数存在位。`Any` 找到第一个匹配就停。两者都不碰组件的值。

## 完整例子 [#full-example]

系统里用过滤条件，系统外用查询、计数和 struct job。三个单位在移动，其中一个被冻住，第四个没有速度。把这几个文件放进一个
引用了 EasyEcs 的控制台项目（`dotnet add package EasyEcs`），用 `dotnet run` 运行。

<Accordions>
<Accordion title="Components.cs">

```csharp title="Components.cs" doccheck=example
using EasyEcs;

public record struct Position(float X, float Y) : IComponent;

public record struct Velocity(float X, float Y) : IComponent;

// 两个状态，都是标签。冻住的单位不移动；冻住或着火的单位会减速。
public struct Frozen : IComponent;

public struct Burning : IComponent;
```

</Accordion>
<Accordion title="Systems.cs">

```csharp title="Systems.cs" doccheck=example
using EasyEcs;

// 冻住、着火或两者都有的单位，速度减半。
public class SlowSystem : EcsSystem
{
    [ForEach, WithAny<Frozen>, WithAny<Burning>]
    static void Slow(ref Velocity velocity)
    {
        velocity = new Velocity(velocity.X / 2, velocity.Y / 2);
    }
}

// 移动所有没被冻住的单位。
[UpdateAfter<SlowSystem>]
public class MoveSystem : EcsSystem
{
    [ForEach, Without<Frozen>]
    static void Move(ref Position position, in Velocity velocity)
    {
        position = new Position(position.X + velocity.X, position.Y + velocity.Y);
    }
}
```

</Accordion>
<Accordion title="Queries.cs">

```csharp title="Queries.cs" doccheck=example
using EasyEcs;

// 过滤条件是一个值：只构建一次，存在 static readonly 字段里。
public static class Filters
{
    public static readonly QueryFilter Moving = QueryFilter.Create().Without<Frozen>();
}

// struct job：系统外最快的遍历方式，没有委托。
public struct SumX : IForEach<Position>
{
    public float Sum;

    public void Execute(ref Position position)
    {
        Sum += position.X;
    }
}
```

</Accordion>
<Accordion title="Program.cs">

```csharp title="Program.cs" doccheck=example
using EasyEcs;

using var world = new World();
world.AddSystem<SlowSystem>();
world.AddSystem<MoveSystem>();

world.CreateEntity(new Position(0, 0), new Velocity(1, 0));
world.CreateEntity(new Position(0, 0), new Velocity(0, 1), new Frozen());
world.CreateEntity(new Position(0, 0), new Velocity(2, 2), new Burning());
world.CreateEntity(new Position(9, 9));

world.Update();

// 系统外：遍历匹配的实体。每个 item 给出指向表里数据的 ref。
foreach (var item in world.Query<Position, Velocity>(Filters.Moving))
{
    Console.WriteLine($"{item.Entity}: {item.Position}");
}

// 计数和判断存在，不读任何组件的值。
int moving = world.Count<Position, Velocity>(Filters.Moving);
bool anyFrozen = world.Any<Frozen>();
Console.WriteLine($"moving: {moving}, any frozen: {anyFrozen}");

// 对所有 Position 跑一遍 struct job，没有速度的单位也算在内。
var sumX = new SumX();
world.ForEach<Position, SumX>(ref sumX);
Console.WriteLine($"sum of X: {sumX.Sum}");
```

</Accordion>
</Accordions>

输出：

```text
Entity 0v1: Position { X = 1, Y = 0 }
Entity 2v1: Position { X = 1, Y = 1 }
moving: 2, any frozen: True
sum of X: 11
```

冻住的单位留在原地，着火的单位以一半速度移动。没有速度的单位不算移动者，但只要求 `Position` 的 job 会把它算进去。

## 怎么用得快 [#how-to-use-it-fast]

| 别这样 | 这样做 | 原因 |
| --- | --- | --- |
| 每个 tick 跑一个 `Query` 循环 | 系统里的 `[ForEach]` 方法 | 生成的结构体 job，参与排序和调度 |
| 每次调用都 `QueryFilter.Create()…` | `static readonly` 过滤器 | 缓存键只建一次 |
| 只读被追踪组件的 `Query` | `Writes => 0` 的 job，或 `in` 参数 | 元素会给交出的行打 tick |
| 很少用到实体却用 `ForEachEntity` | 带 `EntitySpan` 的批处理 job | 只给需要的行构造句柄 |
| 对大量行写标量循环 | 用 `Vector<T>` 的批处理 job | JIT 不会自己向量化 |
| `Count(...) > 0` | `Any(...)` | 找到第一个就停 |
| 扫描查找某个键 | [值索引](/zh/docs/guide/indexes-and-relations) | O(匹配数)，而不是 O(行数) |

## 开销 [#what-it-costs]

- **某个查询形状**（组件加过滤器）**第一次使用时**会把所有表过一遍，建好缓存项。之后新建的表会自动加入它匹配的缓存项。
- **之后每次调用**通过一个按签名的小缓存找到缓存项，超出时做一次哈希查找，然后遍历 O(匹配表数 + 行数)。
- **带过滤的行**按存在位每次测 64 行；全部通过的字每次 SIMD 比较跨过四个，没有匹配的字直接跳过。
- **`Count`** 是 O(匹配表数)，行状态不一致的表再加上每个字一次 popcount。
- **不分配内存**：过滤器是不含对象引用的值，枚举器和元素是 ref struct，job 是结构体。

## 常见陷阱 [#pitfalls]

| 错误 | 后果 | 谁能发现 |
| --- | --- | --- |
| `Query` 循环里 `await` | 编译不过：元素是 ref struct | C# 编译器 |
| 把查询元素存下来 | 编译不过；改存 `item.Entity` | C# 编译器 |
| 只读被追踪组件的 `Query` 循环 | 访问过的每一行都算已写入 | 改用 `Writes => 0` 的 job 或 `Read<T>()` |
| 会改结构的 job 却实现了 `INoStructuralChanges` | 变更处抛 `InvalidOperationException` | 运行时 |
| 批处理 job 里做结构变更 | 抛 `InvalidOperationException`：span 指向表 | 运行时（`[ForEach]` 方法由 [EECS013](/zh/docs/guide/analyzer#eecs013) 检查） |
| 并行 job 写单例组件或别的实体 | 块之间发生竞争 | 代码审查（`[ForEach]` 方法由 [EECS010](/zh/docs/guide/analyzer#eecs010) 检查） |
| 一个过滤器里 `Changed` 和 `Removed` 用了不同的 tick | 抛 `ArgumentException` | 运行时 |
| 在同一个 World 的查询循环里调用 `Update()` | 遍历顺序不确定 | 代码审查 |
