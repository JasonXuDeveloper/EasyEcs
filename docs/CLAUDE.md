# EasyEcs docs site

The website at https://ecs.xgamedev.net: React Router 7 + Fumadocs, fully prerendered (`ssr: false`), Bun, Biome,
deployed to Cloudflare Pages. English and Chinese. How to write a page: `WRITING.md`.

## Commands

```bash
bun install
bun run dev              # http://localhost:5173
bun run check            # tsc, Biome, links + anchors + icons (scripts/lint-links.ts)
bun run build            # Chromium check, git history, benchmark sync, prerender, static files -> build/client, then lint:seo
bun run lint:seo         # titles, descriptions, canonical, hreflang, cards, JSON-LD, sitemap, robots, llms files
bun run sync:benchmarks  # src/data/bench.json from BenchmarkDotNet reports (see Benchmarks)
bun run og:default       # redraw the default social card (public/og.png, the card of /en)
bun run og:github        # redraw the repository's social preview (../.github/social-preview.png)
bun run favicons         # favicons from public/icon.svg
```

Node 22 (`.node-version`), Bun 1.4.2. Dependency versions are pinned; `patches/` holds the patched packages.

                         i18n.ts / i18n-ui.ts, legacy.ts, benchmarks.ts, markdown.tsx (the .md copies)
src/components/          bench-data.tsx (BenchValue, BenchTable, BenchSource), charts/ (visx BarChart, PeerChart,

## Conventions

- Pages follow `WRITING.md`: the anatomy, frontmatter, absolute `/en/docs/...` links, English ids on Chinese
  headings, numbers only through the bench components, mermaid for diagrams.
- A page without a Chinese file is served in English under `/zh/` (Fumadocs' fallback language) with a notice; it is
  `noindex`, canonical to the English page, and left out of the sitemap and the Chinese `llms` files' own entries.
- Legacy `.md` pages stay plain GitHub markdown (no frontmatter, no MDX components, relative links) until they are
  rewritten as `.mdx` + `.zh.mdx`; then the `.md` is deleted.
- A new MDX component needs a Markdown form in `src/lib/markdown.tsx`.
- Page and folder icons are names from lucide's `icons` table, not alias exports; `bun run lint:links` fails on an
  unknown one.
- **Changelog** (`content/changelog.mdx` / `changelog.zh.mdx`): one section per release, newest first, headed with
  the version only: `## 4.1.0 [#v4-1-0]` in both languages (`.github/scripts/release-notes.sh` extracts the English
  section into the GitHub release). Under it the subsections `### New`, `### Performance`,
  `### Changes that need code changes` and `### Fixes` (Chinese: `### 新功能`, `### 性能`, `### 需要修改代码的变更`,
  `### 修复`), an empty one left out, each with the id of its version in both languages (`[#v4-1-0-new]`,
  `-performance`, `-breaking`, `-fixes`; the release notes drop the ids). A section is plain Markdown
  (lists, links, inline code; no JSX components, no typed benchmark numbers: link the performance page or a decision)
  with absolute `/en/docs/...` links. Entries are user-facing only (no CI, tests, benchmarks, docs or refactors); each
  is checked against the EasyEcs source and links the page that documents it, and a change that needs code changes
  says what to write and links the matching section of MIGRATION_GUIDE.md. The sources are the GitHub releases
  (`gh release list -R JasonXuDeveloper/EasyEcs`, `gh release view <tag>`), the commits between tags,
  `MIGRATION_GUIDE.md` and the README's "What's new". At the start of any work here:
  1. A released version without a section: add one from its release and its commits.
  2. User-facing changes merged to `master` after the newest tag: describe them in the section of the coming version,
     written as released (the owner cuts the release right after the merge). Ask for the version number if it is not
     known.

## Benchmarks

- `src/data/bench.json` is the only source of numbers. `scripts/sync-benchmarks.ts` writes it from every
  `*-report.csv` of `EasyEcs.Benchmark` and `EasyEcs.Comparison` (classes, [Params], mean, error, ratio, allocations)
  and the machine from the `*-report-github.md` headers; peer versions come from the comparison project's csproj.
- Input: `BENCH_RESULTS`, else `../BenchmarkDotNet.Artifacts/results`. The committed file is kept when the directory is
  missing (Cloudflare) or lacks classes the committed data has (a filtered local run); `--partial` overrides that.
- After a full run on the reference machine: `BENCH_RESULTS=<results> bun run sync:benchmarks`, check the diff, commit
  the JSON.
- Named numbers for prose are `keys` in `src/lib/benchmarks.ts`; charts and tables take a class
  (`Features.RemovalComparison`) and a [Params] filter.

## SEO and GEO

- Metadata and JSON-LD: `src/lib/seo.ts` (WebSite; SoftwareSourceCode + SoftwareApplication with GitHub, NuGet and
  MIT; TechArticle with dateModified; BreadcrumbList; FAQPage for `faq: true` pages and the landing page). Site facts:
  `src/lib/site.ts`; never put a value there that is not true per the EasyEcs repository.
- hreflang `en`, `zh`, `zh-CN` and `x-default` on every page with both languages.
- `scripts/generate-static.ts` moves pages to `x.html` (slash-less URLs serve 200), writes 404.html, the sitemap
  (hreflang alternates, `lastmod` from git), robots.txt (all crawlers, AI crawlers and Baiduspider named),
  `llms.txt` / `llms-full.txt` and their `.zh` versions, a Markdown copy of every page (`<page>.md`, also served for
  `Accept: text/markdown` by `functions/[[path]].ts`) and the social cards (`scripts/og.ts`).
- `scripts/lint-seo.ts` (last step of `bun run build`) fails on: a `<title>` over 60 characters (a Chinese character
  counts as two) or shared with another page, a description outside 70-160 characters (Chinese 40-90), a missing
  canonical, hreflang, Open Graph / Twitter tag or card, JSON-LD that does not parse or lacks its types, a page missing
  from (or a noindex page in) the sitemap, robots.txt without the AI crawlers, and llms files or Markdown copies
  missing a page. Fix the page's `seoTitle` / `description`; `pending` in the script lists pages being rewritten.
- The GitHub social preview (`.github/social-preview.png`, `bun run og:github`) takes its numbers from
  `src/data/bench.json` and the analyzer's source; upload it in the repository settings after redrawing it.
- Search console verification: `VITE_GOOGLE_SITE_VERIFICATION`, `VITE_BING_SITE_VERIFICATION`,
  `VITE_BAIDU_SITE_VERIFICATION` at build time.

## Live demo

- `content/demo.mdx` runs `demo/EasyEcs.Demo` (.NET in WebAssembly) through `<EcsDemo />`
  (`src/components/demo/`): the runtime loads only on that page, every frame calls `Step(dt)` once and draws the
  frame array straight from the WebAssembly memory. The page includes the demo's C# files, so they are what runs.
- Cloudflare builds with Bun only, so the published runtime is committed in `public/demo/_framework`. After changing
  the demo or EasyEcs.Core: `bun run demo:build` (`scripts/build-demo.sh`: installs the `wasm-tools` workload when
  missing, then `dotnet publish` with Mono AOT, the IL compiled ahead of time to WebAssembly with 128-bit SIMD,
  trimmed, invariant globalization), check the page, commit `public/demo`. Browsers do not run CoreCLR yet (CoreCLR
  on WebAssembly is a preview in .NET 11, interpreter only), so Mono AOT is the fastest .NET runtime there.
- The page draws with WebGL 2 (`src/components/demo/renderer.ts`): one `bufferSubData` of the frame array per frame,
  additive soft points into a half-float light buffer that fades instead of clearing (the trails), tone-mapped over
  the theme's card color. The host alternates the `Batched` and `PerEntity` motion groups each step and times both,
  so the page shows their live cost side by side.
- `/demo/*` bypasses the Pages Function (`public/_routes.json`, `functions/[[path]].ts`); `public/_headers` serves
  `.wasm` as `application/wasm` and caches the fingerprinted files forever (`dotnet.js`, the entry, is revalidated).
  Biome skips `public/demo`.

## Diagrams and page weight

- ```mermaid fences are drawn at build time by `rehype-mermaid` (Mermaid in a headless Chromium through Playwright;
  options in `src/lib/mermaid.ts`): the prerendered page holds the SVG, the browser loads no Mermaid. One drawing in
  Mermaid's grayscale `neutral` theme; the dark site shows it inverted (`src/components/mermaid.tsx`). The `chart`
  attribute keeps the source for the Markdown copies. `bun run dev` and `bun run build` need a Chromium:
  `scripts/chromium.ts` (first step of the build) installs Playwright's headless shell when none starts.
- The browser bundle of a page leaves out `_markdown` and `structuredData` (build-time only, `vite.config.ts`); the
  search dialog loads lazily, then fetches its language's index only.
- Off-screen code blocks skip layout and paint (`content-visibility: auto`, `app/app.css`).
- `public/_headers`: hashed assets immutable, icons and the manifest a day, the search indexes five minutes; HTML keeps
  Cloudflare's default (revalidated).

## Redirects

- `/docs/...` without a language and `/` go to `/{lang}/...` by the language cookie, then the visitor's country
  (`functions/[[path]].ts`); short links and old URLs: `public/_redirects`.
